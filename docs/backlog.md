## C. 置き場所と費用（2026-11-22）

置き場所は GCP のままにした（[決めたことの記録](./decisions.md) 2026-11-22・[置き場所の比べと料金の試算](./hosting-cost.md)）。そのうえで、あとでやることと、まだ決めていないこと。

| # | やること | いつ | メモ |
|---|---|---|---|
| C1 | 独自ドメインを取り、Cloudflare の無料プランを前に置く | 一般に公開するとき | `.com` で年 約10.5ドル。Terraform に Cloudflare のプロバイダーを足す。利用者の IP を `CF-Connecting-IP` から読む（今は `TRUSTED_PROXY_HOPS=1`）。`WEB_URL`・LIFF のエンドポイント・LINE ログインと Threads の OAuth の戻り先を替える。Cloudflare と Cloud Run のつなぎ方（ドメインの割り当てか、転送先の名前の書き換え）は要確認 |
| C2 | Cloudflare のキャッシュの下準備 | C1 の前でもよい | 誰が見ても同じ公開の API に `Cache-Control: s-maxage` を付ける。画面の側で同じデータを取り直さない設定（TanStack Query）を見直す。`index.html` と画面の道（HTML）も覚えさせる Cache Rule を足す（Cloudflare は HTML を既定では覚えない）。Cache Rule は `/api` を除き、**Edge TTL は「Use cache-control header if present」**（「Ignore」にすると、デプロイのあとも古い画面を出し続ける）、**Browser TTL は「Respect origin」**。源は HTML に、ブラウザ向けの `Cache-Control: no-cache` と、Cloudflare だけが読む `Cloudflare-CDN-Cache-Control: max-age=0, stale-if-error=86400` を返すので、源が 5xx を返したときだけ前の画面を出す（core-020）。LIFF・OAuth の戻り（`?liff.state=`・`?code=`）は URL が毎回違うので覚えた画面に当たらない（無料プランで問い合わせの部分を鍵から外せるかは要確認）。Always Online は入れない（入れると `stale-if-error` が効かず、URL が Internet Archive に渡る） |
| C4 | 定期の仕事を軽くする | 1日の利用者が600人を超えたら | まず、やることがない回を1回の問い合わせで切り上げ、片付けを1日1回にする（CPU の時間が減る。間隔は変えない）。それでも気になれば呼ぶ回数を減らす（その頃は利用者の要求が台を温めるので、起動の待ちは増えない） |
| C5 | DB の負荷試験 | 交流会で使う前 | 手元の Docker の DB を db-f1-micro に近く絞り（CPU 0.2・メモリ 600MB ほど）、30人分の同時アクセスを流す |
| C6 | 本番のデプロイの身分を、GitHub の環境 `production`（承認）でも絞る | 本物の環境で WIF を確かめられるとき | 今は `main` のブランチで絞っているので、`main` に入った別の workflow なら承認なしで本番の身分を使える。WIF の属性に `assertion.environment` を足し、本番の身分は「`main` かつ環境 `production`」だけにする（core-019 research R2） |
