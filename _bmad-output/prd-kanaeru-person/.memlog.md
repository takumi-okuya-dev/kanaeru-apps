- (decision) 進め方：PRD を作ってから spec-kit で実装する（試合表と同じ流れ）。ユーザーが選んだ
- (decision) 範囲：自分だけの非公開メモに絞る。名前は自分で入力・ほかの参加者の名簿や情報は出さない・AI に送らない・顔写真は持たない・受付アプリとは自分が参加した交流会を選べる程度。理由：第三者提供と専門家確認の論点を避けて小さく始めるため（調べもの b7）
- (decision) 領域ID は people（道 /people・specs/people/）

- (event) 入力の抜き書き：自分がチェックインした交流会の一覧をほかの領域に出す関数が reception の index.ts にない（findLatestOfAccount は内部だけ）。people には reception 側に小さな追加が要る（持ち主の領域・別 PR）
- (event) 入力の抜き書き：AD-20・Constitution II は人物メモを名指しで外の AI・MCP に渡さないと決めている。範囲の決定と一致
- (event) 入力の抜き書き：0〜8時は DB が止まる（構成 Deferred。暮らしのアプリを出すとき AD-10 を見直す）。人物メモを夜に使うかで論点になる。メモ本文をログに書かない一覧に足すかも決める
- (decision) 困りごと（持ち主の言葉）：IT交流会で会ったことはあるが、話した内容を思い出せず仲が深まらない
- (decision) 残したいこと（持ち主）：見た目の特徴・名前・どこで会ったか・何を話したか・次に話したいこと・連絡先
- (decision) メモを開く場面（持ち主）：IT交流会のとき・相手から連絡が来たとき
- (decision) 使う人：まず持ち主1人。のちに一般の利用者（toC）に広げる。重さは『自分で試す版だが toC に広げられる形』で PRD を作る
- (event) 持ち主が競合アプリの調べを頼んだ。b7（2026-11-19）を土台に、国内の人物メモ系アプリの項目と使い方に絞って追加で調べる
- (decision) PRD の進め方：一節ずつ一緒に考える（コーチング）。持ち主が選んだ
- (decision) 連絡先は SNS などのアカウント（X・connpass・GitHub・LinkedIn・ほかの URL）だけ。電話番号・メールの専用の欄は作らない。理由：Constitution II（電話番号は持たない）と、他人の情報を預かる重さを軽くするため。自由なメモに書くのは利用者の判断
- (decision) 持ち主の理想：メモからその人との個人の LINE（トーク）に飛べること。連絡先のアカウントに LINE ID を含める候補。個人のトークを直接開く公式のリンクはない見込みで、LINE ID からプロフィールを開く形が近い（要確認）
- (decision) メモを書くのは帰り道か家（会場ではない）。スマホで短く書ける形が要る
- (decision) 名前は基本フルネーム。加えて LINE の名前（表示名）があるとなおよい。どちらでも探せる
- (decision) あとで探す手がかりは名前の検索と LINE（の名前）
- (decision) 2回目以降に会ったら、同じ人のメモに続けて書く（会った回ごとの別の記録は持ち主が求めていない）
- (decision) 仲が深まった目印：『前に話した○○、どうなりました？』と自分から言えたとき（持ち主が確かめた）
- (decision) 持ち主が kanaeru の受付アプリを使う交流会はこれから月に一度。会う人の多くは受付アプリを使わない会で会う見込み → 会った場所は自分で書ける欄を基本にし、kanaeru の交流会を選べるのは足し
- (decision) あとで広げる相手は営業・フリーランス（交流会に限らず人に会うことが多い人）
- (event) 論点：持ち主は自分の会の主催者なので、自分の会にはチェックインしない見込み。『チェックインした会』だけでは自分が主催した会が選べない
- (decision) 会った場所の選び方は全部：kanaeru のチェックインした会・自分が主催した会・受付係をした会から選べる＋交流会の名前を手で書ける
- (decision) 持ち主の会は、持ち主のコミュニティの外のサイト（自前の申込みフォーム）で申し込みを受け、当日は受付アプリで受付する運用にしたい。申込みの名簿は kanaeru には入らない（コミュニティの名前は公開リポジトリに書かない）
- (decision) 主催した会では1回に10〜20人に会う → 帰り道に何人も続けて書ける形が要る（競合の調べものでも『いっぺんに登録したい』は空いている所）
- (event) 論点：主催者は自分の会の名簿を受付アプリで見られるが、規約の写し :79『参加者の情報は運営のためだけに使う』と範囲の決定（名簿を出さない）から、人物メモに名簿の名前を出さない方向。持ち主に確かめる
- (decision) 自分の会にチェックインした人の名前（LINE の名前）は人物メモの候補に出さない。名前は自分で打つ。そのかわり交流会を1回選んで何人も続けて足せる形にする（持ち主が決めた。範囲の決定と規約の写し :79 に合わせる）
- (decision) 次に話したいことは自由な文章の欄のまま（チェックで消す一覧にはしない）。話せたら自分で書き直す（持ち主が決めた）
- (decision) 0〜8時に DB が止まるのは今のままでよい（夜0時を過ぎて書くことはあまりない）。一般に広げるときに見直す（持ち主が決めた）
- (decision) 一覧に欲しいもの：交流会ごとに会った人を並べる・タグ・最近書いた／会った順・書き出し（CSV）。名前・LINE の名前・本文まで当たる検索は前提（持ち主が決めた）
- (decision) 成功の基準：『前に話した○○』と自分から言えた回数（月あたり）。持ち主が決めた。数え方と目標の数はこれから
- (decision) 成功の目標：最初の1か月で『前に話した○○』と自分から言えた回数が月3回以上。月に一度、持ち主が振り返って数える
