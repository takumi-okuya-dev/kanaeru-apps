## 1. ねらい

IT交流会で会ったことはあるのに、話した内容を思い出せず、仲が深まらない（持ち主の言葉）。

人物メモには、会った人について次のことを残す。

- 見た目の特徴
- 名前
- どこで会ったか（会った場）
- 何を話したか
- 次に話したいこと
- 連絡先（SNS などのアカウント）

次に会うときや連絡が来たときに開き、「前に話した○○、どうなりました？」と自分から言えるようにする。

**この版の絞り方**：最初の版は、**自分だけの非公開メモ**にする（持ち主が決めた）。

- 相手に見せない。
- ほかの参加者の情報を出さない。
- AI に送らない。
- 顔写真を持たない。

調べもの b7 は「個人情報保護法の専門家に確かめるまで作らない」と判断していた。この形なら、b7 が重いとした第三者への提供が起きない。そのため、専門家に確かめるのは一般に公開する前に回す（7.3）。

## 2. 使う人

### 2.1 片づけたい用事

- **用事**：会った人のことを残す。次に会う前や連絡が来たときに思い出して、話をつなげる。
- **最初の版**：持ち主1人。IT交流会によく出る（持ち主が決めた）。
  - kanaeru の受付アプリを使う会（持ち主が開く会）は、これから月に一度。
  - 人と出会うのは、多くがそれ以外の会（connpass の勉強会・紹介の会など）。
- **あとで広げる相手**：営業・フリーランスなど、交流会に限らず人に会うことが多い人（持ち主が決めた）。
- **背景（持ち主の会）**：申込みは、kanaeru の外の、コミュニティのサイトで受ける。受付アプリで行うのは当日の受付だけ。そのため kanaeru に残るのはチェックインだけで、申込みの名簿は入らない（持ち主が決めた）。

### 2.2 この版で相手にしない人

- 顔写真で人を覚えたい人（持ち主が決めた）。
- 【仮決め】名刺を撮ってデータにしたい人（Eight・myBridge の領分）。
- 【仮決め】チームや会社でメモを分け合いたい人（Sansan の領分）。

### 2.3 使う場面

**UJ-1：交流会で会った人と、次に会ったときに話をつなげる**（主人公：持ち主。IT交流会によく出る）

1. IT交流会の懇親会で、初めて Aさんと話す。その場ではメモしない。
2. 帰りの電車か家で、スマホで人物メモを開く。会った交流会を選び、その会で話した人を続けて足していく。
   - Aさんについて書くこと：フルネーム・よみ・わかれば LINE の名前・見た目の特徴・話したこと・次に話したいこと・X や LINE ID などのアカウント。
   - 名前のほかは空でもよい。
3. 数週間後、**場面A**：次の交流会に向かう途中、来そうな人を名前で検索する。前に話したことと、次に話したいことを読み返す。
4. **場面B**：Aさんから LINE で連絡が来る。
   - LINE の名前で検索してメモを開き、前の話を見てから返事をする。
   - メモに LINE ID があれば、そこから LINE を開く。
5. また会えたら、同じ Aさんのメモに続けて書き足す。書き足した所の頭には、日付と、選んでいれば会った場が入る。
6. **ここで仲が深まる**：「前に話した○○、どうなりました？」と自分から言える。

## 3. ことば

| ことば | 意味 |
|---|---|
| 持ち主 | この PRD を決める主催者。今は kanaeru の運営者も兼ねる |
| 使う人 | 人物メモを使い、メモを書く利用者。最初の版では持ち主1人 |
| 運営者 | kanaeru を動かす人。メモの中身を読まない |
| 人 | メモの相手。使う人が自分で足した、会った人1人。kanaeru の利用者（account）とは結び付けない |
| メモ | 1人について書いたこと全体。次の欄からなる（**メモの欄の正本**）。フルネーム・よみ・LINE の名前・見た目の特徴・アカウント・タグ・話したこと・次に話したいこと・会った場 |
| 会った場 | 使う人の一覧にある1件の会。kanaeru の交流会か、使う人が名前と日付を手で書いた会。1件の会った場に何人もつながり、1人に何件でも付く |
| kanaeru の交流会 | 受付アプリにある交流会のうち、使う人がチェックインした会・主催した会・受付係をした会 |
| アカウント | 相手の X・connpass・GitHub・LinkedIn・LINE ID・そのほかの URL |

## 4. 機能

### 4.1 人を足す・書く

- **FR-P1**：人を足せる。要るのはフルネームだけで、ほかの欄は空でよい（持ち主が決めた）。
- **FR-P2**：1人について、3章のメモの欄を残せる（持ち主が決めた）。それぞれの欄は次のとおり。
  - よみ（ふりがな）
  - LINE の名前（表示名）
  - 見た目の特徴：短い文（例：「眼鏡・背が高い・Go の話」）
  - アカウント（3章）
  - 話したこと：自由な文章
  - 次に話したいこと：自由な文章。話せたら、使う人が自分で書き直す
  - タグ：使う人が自分で付ける印。1人にいくつでも付けられる
- **FR-P3**：2回目以降に会ったら、同じ人の「話したこと」に続けて書き足せる（持ち主が決めた）。
  - 書き足すと、その頭に日付と、選んでいれば会った場が自動で入る（持ち主が決めた）。
  - 「次に話したいこと」は、書き足すのではなく書き直す。
- **FR-P4**：【仮決め】保存に失敗しても、書いた内容は画面に残る。
  - 失敗する場面：電波が切れたとき・夜の停止（0時〜8時に DB が止まる。AD-10）にかかったとき。
  - もう一度保存できる。もう一度押しても、同じ人が二重に足されない。
- **FR-P5**：人を消せる。消したら戻せない【仮決め】。
- **FR-P15**：画面に、次の2つの添え書きを出す【仮決め】。
  - 「このメモを見られるのはあなただけです」
  - 入力の欄に「病気・信条など、相手が知られたくないことは書かないでください」。要配慮個人情報の扱いのため（調べもの b7）

### 4.2 会った場

- **FR-P6**：人に会った場を付けられる。会った場の作り方は2つ（持ち主が決めた）。
  - kanaeru の交流会から選ぶ。同じ交流会は、主催してチェックインもしていても1件として出す【仮決め】。
  - 交流会の名前と日付を手で書く（kanaeru を使わない会）。前に書いた会った場からも選べる。同じ会の名前の書き方が揺れないようにするため【仮決め】。
- **FR-P7**：会った場を1回選んだら、そこで会った人を続けて何人も足せる（1回に10〜20人。持ち主が決めた）。新しい人を足すことも、前に足した人を選ぶこともできる。同じ人に同じ会った場を2回は付けない【仮決め】。
- **FR-P8**：kanaeru の交流会から選んでも、その会にチェックインした人の名前は候補に出さない。名前は使う人が自分で打つ（持ち主が決めた）。理由は2つ。
  - 1章の絞り方（ほかの参加者の情報を出さない）に合わせるため。
  - 規約の下書き（`_bmad-output/legal/terms-draft.md`）の「参加者の情報は運営のためだけに使う」に合わせるため。
- **FR-P9**：kanaeru の交流会が消えたり、使う人が見られなくなったりしても、会った場の名前と日付は残る。試合表（match）の交流会の結び付けと同じ考え（AD-25）。

### 4.3 探す・見返す

- **FR-P10**：検索できる（持ち主が決めた）。
  - 当たる欄：3章のメモの欄のうち、アカウントを除くすべて（会った場はその名前）。
  - 【仮決め】ひらがなとカタカナの違い、全角と半角の違いでは外れない。
  - 【仮決め】当たった箇所を、前後の文と一緒に見せる。書き足していくと本文が長くなるため。
- **FR-P11**：人の一覧は、新しく書いた人・直した人が上に来る（持ち主が決めた）。並べるのにどの時刻を使うかは【仮決め】。一覧では、名前の横に見た目の特徴を出す【仮決め】。
- **FR-P12**：タグで絞れる（持ち主が決めた）。
- **FR-P13**：会った場ごとに、そこで会った人を並べて見られる（持ち主が決めた）。
- **FR-P14**：人のメモを開くと、話したことと次に話したいことが最初に見える【仮決め】。会う前や返事の前に読み返す場面のため（UJ-1 の3・4）。

### 4.4 連絡する

- **FR-P16**：アカウントを押すと、相手のページが開く。
  - そのほかの URL は `http`・`https` だけを受け付ける【仮決め】。
  - LINE ID からは、LINE で相手のプロフィールを開ける。個人のトークを直接開く公式のリンクはない見込み（10章）。

### 4.5 取り出す・やめる

- **FR-P17**：自分のメモを、すべての欄ごとまとめて CSV で書き出せる（持ち主が決めた）。表計算ソフトで開いたとき、欄の中身が式として動かないようにする（CSV インジェクションの対策）。共通の道具 `packages/csv` を使う。
- **FR-P18**：退会したら、人物メモをすべて消す。消すのは、アカウントが消えたときに外部キーで一緒に消える形だけにする。退会の前の手順（AD-22）では消さない。アカウントの削除が途中で止まったとき、メモだけが消えるのを防ぐため。

## 5. 守ること

作らないもの・持たないものは 7.2 にまとめた。ここには、作るものが守ることを書く。

### 個人の情報（原則 II）

- **見られる人**：メモを見られるのは、書いた使う人だけ（持ち主が決めた）。運営者の画面にも、メモの中身を出さない【仮決め】。
- **AI と MCP**：メモを外の AI に渡さない。MCP のツールも作らない（持ち主が決めた）。AD-20・AD-21 は人物メモを名指しで止めている。
- **ログ**：3章のメモの欄すべてと検索の言葉は、ログ・URL・エラーの知らせに出さない【仮決め】。検索の言葉は URL に載せない。サーバーが受けた要求（リクエスト）のログに、URL ごと残るため。
- 【仮決め】本物のメモを、次の場所に入れない。
  - ステージング
  - 公開のリポジトリの PR のスクリーンショット
  - 開発に使う AI
- **暗号**：最初の版は暗号にしない（持ち主が決めた）。そのかわり、運営者は読まないとプライバシーポリシーに書く。暗号の形は、一般に公開する前に決める（7.3）。
- **消すとき**：退会したらすべて消す（FR-P18）。人を消したら、その人のメモも消える（FR-P5）。

### 気軽さ（原則 III）

- 書くのは帰り道か家。スマホの片手で、1人を短く足せる形にする（持ち主が決めた）。
- 交流会の受付（チェックイン）の流れには何も足さない。参加者には人物メモは見えない【仮決め】。

### 費用（原則 V）

- 新しい有料のサービスは使わない。
- 夜の停止の間は「今は使えません」と出す【仮決め】。

### 権限

- すべての記録は、使う人の account で絞る。ほかの使う人のメモの道を開いたら、ないもの（見つからない）として扱う（AD-19）【仮決め】。

## 6. 構成の決めごとと Constitution に要る改訂

- **AD-15（アプリの登録）**：`apps.list.ts` に `person` を1行足す（key は英小文字の単数。持ち主が決めた）。道（URL のパス）は `/person`、表の名前は `person_` で始める。`uses: ["reception"]`。
- **AD-16（公開の状態）**：最初は運営者だけに見える（`operator_only`）。一般に公開するのは、7.3 を済ませてから。
- **AD-2（利用者は account だけ）**：メモの「人」は kanaeru の利用者と結び付けない。相手が kanaeru を使っていても、その人の account は見ない。
- **AD-3・AD-23（ほかの領域を読む）**：受付（reception）と交流会（event）の `index.ts` に、使う人の交流会の一覧を出す関数が要る（7.1 の4・10章）。
- **AD-3（表を作る順）**：表を作る PR の並びでは、人物メモの PR を試合表（match）の PR の後ろに置く。
- **AD-7・AD-19（消したとき）**：人と会った場は、使う人の account が消えたら一緒に消える。交流会が消えたときは FR-P9。
- **AD-22（退会の手順）**：人物メモは退会の前の手順を持たない（FR-P18）。
- **AD-20・AD-21（AI と MCP）**：5章。
- **AD-10（夜の停止）**：最初の版では変えない（7.3）。
- **構成の決めごとに足すこと**：この PRD のあと、`/bmad-architecture` で人物メモの決めごと（AD）を足す。足す中身は次の4つ。
  - 結び付けの形
  - 会った場の形
  - ログに書かないもの（3章のメモの欄すべてと検索の言葉【仮決め】）
  - 表を作る順
- **Constitution**：最初の版では改訂は要らない。一般に公開する前に見直す（7.3）。

## 7. 範囲

### 7.1 作る順【仮決め】

DB の変更のある PR の出し方は、[並行開発の決まり](../../docs/rules/parallel-development.md) 4章のとおり。

1. 人物メモの表を作る PR（DB の変更だけ）。
2. 人を足す・書く・探す・見返す・連絡する（4.1・4.3・4.4）。
3. 手で書く会った場と、続けて何人も足す（4.2）。
4. 受付（reception）と交流会（event）の小さな PR。それぞれ、使う人の交流会の一覧をほかの領域に出す（AD-3）。人物メモの PR には混ぜない。そのあと、kanaeru の交流会を選べるようにする（FR-P6）。
5. 書き出しと退会（4.5）。

### 7.2 この版で作らないもの

**作らないもの・持たないものの正本**。

- 受付アプリの名簿や、チェックインした人の名前を候補に出すこと（持ち主が決めた。FR-P8）
- AI（要約・話題の提案）と MCP（持ち主が決めた）
- 顔写真（持ち主が決めた）
- 名刺の読み取り【仮決め】
- 電話番号とメールの欄（持ち主が決めた。Constitution II の「電話番号は持たない」に合わせ、他人の情報を預かる重さを軽くするため）
- 会った回ごとに分けた記録（持ち主が決めた）
- 次に話したいことを、話せたらチェックで消す一覧（持ち主が決めた）
- 夜の停止の間も使えること（持ち主が決めた）
- 電波がないときに書いておき、後で送ること（持ち主が決めた）
- メモの中身の暗号（持ち主が決めた。7.3）
- 【仮決め】知らせ（会う前のお知らせ・連絡が途切れたときのお知らせ）
- 【仮決め】誕生日
- 【仮決め】ほかの使う人やチームとの共有・組織に入れること・連絡先の取り込み
- 【仮決め】アプリの中のパスコード（LINE ログインのセッションで守る）
- 【仮決め】CSV からの取り込み・自動のバックアップ（書き出しは作る）

### 7.3 一般に公開する前に済ませること

- メモの中身の暗号の形を決めて、作る（持ち主が決めた）。
- 個人情報保護法の専門家に確かめる（調べもの b7）。確かめることは次の3つ。
  - 他人の情報を預かること
  - 運営者が中身を扱わない作り（いわゆるクラウド例外）にできるか
  - 相手から「消してほしい」と頼まれたときの扱い
- 規約とプライバシーポリシーに、人物メモの節を足す。書くことは次の4つ。
  - 見られるのは、メモを書いた使う人だけ
  - 運営者は読まない
  - ほかの人の権利を侵さない
  - 要配慮個人情報（病気・信条など）を書かない
- Constitution を見直す。自由な文章に相手の電話番号が書かれうることと、相手から「消してほしい」と頼まれたときの扱いを決めるため。
- 夜の停止（AD-10）を見直す。
- 値段と、スイートに入れるかを決める。
  - b7 がスイートに入れる理由にしたのは、受付アプリとのつながりだった。この PRD では、受付アプリとのつながりを、なくても使える「おまけ」にした。そのため、理由を見直す。
  - 一般の人に売るときは、b7 が挙げた、ほかのアプリとの違いも生かす：料金をはっきりさせる・カードの登録なしで始められる・解約が1タップ。

## 8. 成功の基準

- **ねらいの基準**：最初の1か月で、「前に話した○○」と自分から言えた回数が **月3回以上**（持ち主が決めた）。
  - 月に一度、持ち主が振り返って数える。
  - 届かなければ、逆の目印（うまくいっていないことを示すしるし。下に書いた）と合わせて原因を見る。書けていないのか、書いても読み返していないのか。そのうえで、次に直す所（足す速さ・探しやすさ・会う前に開く流れ）を決める【仮決め】。
- **逆の目印**【仮決め】：
  - 交流会のあと、会った人をメモしないまま1週間過ぎることが続く（書くのが重すぎる）。
  - 1人を足すのに2分を超える。
