# PRD：kanaeru の組織（スイートの共通）と、Threads のチーム運用

作成：2026-11-20（主催者が決めたこと〈組織単位の契約も見越す・組織は suite が持つ・Threads のチーム運用は組織の上に作る〉をもとに、AI が書いた叩き台。【仮決め】の印は主催者の確かめを待つ）。2026-11-20 直した（主催者の確かめ：持ち主の退会では、組織に入れた運用アカウントを組織の管理者に引き継ぐ・「承認を任せる」を決定にした。13章）

## 0. この文書について

[Constitution](../../.specify/memory/constitution.md) IV（新しいアプリと共通の機能は、先に PRD を作る）に従い、次の2つの範囲を決める。

- **(a) スイートの組織**：どのアプリからも使える人の集まり（組織）と、その人・役割・招待。契約の持ち主を「アカウントか組織」にする形。持ち主は suite の領域（アプリの台帳と同じ）。
- **(b) Threads のチーム運用**：Threads の運用アカウントを組織に入れて、何人かで運用する。めぐる（`meguru-app`）の 011（チームの見直し）・009（このアカウントのチーム）・020（チームの運用状況）を、組織の上に移す。

作りの決めごとは[構成の決めごと](../architecture-kanaeru/architecture-kanaeru.md) AD-22（組織と契約の持ち主。この PRD と同じ日に足した）と、直した AD-16・AD-19。Threads の範囲の正本は [Threads の PRD](../prd-threads/prd-threads.md)（そこでは「チーム運用は移さない」としていた。この PRD で範囲に入れる。9章）。読む人は、主催者と、このあと機能ごとの仕様（spec-kit）を作る人とAI。

移植の元（読むだけ）：めぐるの `specs/011-team-revision`（008 を置き換えた最後の形）・`specs/009-team-roster`・`specs/020-team-monitoring`・`specs/013-billing`（人ごとの払い方と退会）・`docs/team-roles.md`・`apps/api/src/apps/threads/teams/`・`apps/web/src/apps/threads/components/team/`。

## 1. ねらい

- 運用代行の会社やお店の集まりが、1つの「組織」にまとまり、メンバーを招いて、役割（管理者・編集者・メンバー）を決められるようにする。組織はアプリごとに作らず、スイートに1つの仕組みにする。2つ目からのアプリも同じ組織を使う。
- Threads では、お店（持ち主）が自分の運用アカウントを組織に入れ、代行のスタッフ（編集者）が投稿の案を作り、お店が承認する、というめぐるで確かめた運用を kanaeru で続ける。管理者は、手が止まっている人と伸びていないアカウントを、数と日付だけで見つけられる。
- 売り始めたときに「会社でまとめて契約する」形にも応じられるよう、契約の持ち主を最初から「アカウントか組織」にしておく。払うしくみそのものは、売り始めるときに作る。

## 2. 使う人

### 2.1 片づけたい用事

- **組織の管理者**（例：運用代行の会社の担当者）：組織を作り、お店とスタッフを招き、スタッフを編集者にして担当のお店を決める。誰の手が止まっているかを知りたい。
- **持ち主**（例：お店の人。自分の Threads の運用アカウントを持つ）：運用を手伝ってもらいたいが、承認と設定とトークンは自分で持ちたい。必要なら、承認だけを信頼できる担当に任せたい。
- **編集者**（例：代行のスタッフ）：担当のお店の運用アカウントで、投稿の案と戦略を作る。
- **メンバー**：ほかのお店が見せている運用アカウントを読んで、自分の参考にする。

### 2.2 この版で相手にしない人

- 組織の契約を申し込みたい人（払うしくみは売り始めるときに作る。4.5）。
- 受付アプリの受付係（今の受付係〈`event_staff`〉のまま。9章）。
- 機能の切り替え（めぐるの 019）・運営者の画面（026）を使いたい人。

### 2.3 使う場面

- **UJ-1**：A社の田中さんが、設定から組織「飲食チーム」を作る。招待のリンク（と QR）を、カフェの鈴木さん・ベーカリーの山口さん・A社の佐藤さんに送る。開いた人は組織の名前と管理者と、何が誰に見えるかを確かめて、メンバーとして入る。
- **UJ-2**：鈴木さんは Threads で、自分の運用アカウント「カフェB店」を組織に入れる。田中さんは佐藤さんを編集者にし、カフェB店の担当にする。佐藤さんは投稿の案を作り、鈴木さんが承認する。忙しい月は、鈴木さんが佐藤さんに「承認を任せる」。
- **UJ-3**：鈴木さんがカフェB店を「組織に見せる」にすると、山口さん（メンバー）は投稿の案と戦略を読むだけで見られる。
- **UJ-4**：田中さんが Threads の組織の画面で「運用状況」を開き、7日動いていない人と、閲覧が下がったアカウントを見つける。本文や戦略は出ない。
- **UJ-5**：山口さんが組織を抜ける。ベーカリーの運用アカウントとそのデータは、山口さんの個人の運用として残る。田中さんは抜ける前に管理者を鈴木さんに引き継ぐ。

## 3. ことば

| ことば | 意味 |
|---|---|
| 組織 | スイートに1つの、人の集まり。名前・人と役割・招待のリンク1本を持つ。suite の領域が持つ。1人が複数の組織に入れる |
| 組織の人 | 組織に入っている人（管理者・編集者・メンバーのすべて） |
| 管理者 | 組織を作った人か、引き継いだ人。1つの組織に1人。招待・役割の切り替え・人を外す・名前を直す・組織を消す・引き継ぐ |
| 編集者 | アプリの中で「担当」を持てる人。何ができるかは各アプリが決める（Threads は5章） |
| メンバー | 招待のリンクから入った人の初めの役割。アプリの中で、ほかの人が見せたものを読むだけ |
| 持ち主 | アプリの最上位の記録（Threads の運用アカウントなど）の持ち主の kanaeru のアカウント。組織に入れても変わらない（AD-19） |
| 組織に入れる | 持ち主が、自分の記録（Threads の運用アカウント）を1つの組織の中に置くこと。手伝ってもらうことに同意した扱いになる |
| 組織に見せる | 持ち主が、組織に入れた運用アカウントごとに決める設定。オンのとき、組織の人が投稿の案と戦略を読むだけで見られる。初めはオフ |
| 担当 | 管理者が、編集者（と自分）ごとに決める、組織に入っている運用アカウント |
| 承認を任せる | 持ち主が、運用アカウントの担当の人に、承認・却下を任せること。初めはオフ |
| 引き継ぎ（退会のとき） | 持ち主が退会するとき、その人が組織に入れていた運用アカウントの持ち主を、その組織の管理者に替えること（5.7） |
| 運用状況 | 組織に入っている運用アカウントと人ごとの、動きと伸びの数と日付。本文・戦略・設定の中身は含まない |
| 契約の持ち主 | 契約を持つのは、アカウント1つか、組織1つのどちらか |
| 個人の運用 | 組織に入れていない運用アカウント。今の Threads と同じに動く |

## 4. 機能（a）スイート：組織

### 4.1 組織を作る・直す・消す

- **FR-O1**：ログインした人は、設定の「組織」で、名前（1〜50文字）を入れて組織を作れる。作った人が管理者になる。アプリの記録を持っていなくても作れる（めぐるは自分の Threads のアカウントが要ったが、kanaeru の組織はスイートのものなので要らない）。1人が作れる組織は20まで【仮決め】。
- **FR-O2**：管理者は、組織の名前を直せる。
- **FR-O3**：管理者は、確かめのあとに組織を消せる。消すと、組織の人・招待・アプリの中の担当と「組織に入れる」がすべて消える。アプリの記録とそのデータは、持ち主の個人のものとして残る（6章）。
- **FR-O4**：組織の画面（設定 › 組織 › 組織の名前）には、組織の人の表示名・役割・入った日を、組織の人の全員に出す。見ている人には「あなた」の印を付ける（利用者の ID で決める）。

### 4.2 人と役割

- **FR-O10**：役割は、管理者・編集者・メンバーの3つ。管理者は1組織に1人。
- **FR-O11**：管理者は、自分以外の人の役割を、メンバー⇔編集者にいつでも切り替えられる。管理者が自分の役割を下げることはできない（引き継ぎでだけ替わる）。
- **FR-O12**：編集者からメンバーに戻すと、その人のアプリの中の担当は効かなくなる。もう一度編集者にしても、前の担当は戻らない（AD-22）。
- **FR-O13**：1つの組織の人は50人まで、編集者は10人まで【仮決め】（めぐるの上限）。
- **FR-O14**：役割の変化・抜ける・外す・引き継ぐは、次の要求から効く（権限は要求のたびに引き、セッションに写さない。AD-5・AD-22）。
- **FR-O15**：組織の役割で何ができるかは、各アプリが決める（suite は役割を持つだけ）。suite での違いは、4.1・4.3・4.4 の組織の操作が管理者だけであることだけ。

| 組織の操作 | 管理者 | 編集者 | メンバー |
|---|---|---|---|
| 組織を作る | ○（だれでも作れる） | ○ | ○ |
| 人の一覧（表示名・役割・入った日）を見る | ○ | ○ | ○ |
| 招待のリンクと QR を出す・作り直す | ○ | ✕ | ✕ |
| メンバー⇔編集者を切り替える | ○ | ✕ | ✕ |
| 人を外す・管理者を引き継ぐ | ○ | ✕ | ✕ |
| 名前を直す・組織を消す | ○ | ✕ | ✕ |
| 組織の契約を持つ（売り始めたら） | ○【仮決め】 | ✕ | ✕ |
| 組織を抜ける | 引き継いでから | ○ | ○ |

### 4.3 招待（リンクと QR）

- **FR-O20**：組織ごとに、招待のリンクを1本持つ。管理者はいつでも出してコピーでき、QR を出せる。「リンクを作り直す」で前のリンクはすぐ使えなくなる。期限は付けない【仮決め】（めぐるのまま。交流会の受付係の招待と違い、組織には終わりの日がないため）。
- **FR-O21**：リンクと QR には LINEミニアプリの URL を入れ、道の形は参加者が外から開く道と同じ1か所に置く（AD-14）。道は `/join/{token}`【仮決め】。DB には札の SHA-256 だけを持つ。
- **FR-O22**：リンクを開いた人に、ログインを求めたうえで、組織の名前・管理者の表示名・人数・「メンバーとして入ります」と、次の説明を出す確かめの画面を出す。
  - 組織の人どうしで、表示名と役割が見えること。
  - あなたが退会すると、組織に入れたあなたの記録（Threads の運用アカウントなど）は、組織の管理者に引き継がれること（アプリが足す説明に含める）。
  - 各アプリの説明（アプリが足す。Threads は「管理者と、あなたの運用アカウントの担当の編集者は、運用状況〈投稿の数・伸び・最後に動いた日〉を見られます。本文と戦略は、あなたが見せたときだけ読めます」）。見えないアプリ（AD-16）の説明は出さない。
- **FR-O23**：「入る」を押すと、メンバーとして入る。同じ人が同時に押しても1回だけ入る。すでに入っている人には「すでに入っています」と組織の画面への入口を出す。
- **FR-O24**：使えないリンク（作り直された・組織が消えた・人数の上限）を開いた人には、理由と「管理者に新しいリンクを頼んでください」を出し、入れない。

### 4.4 抜ける・外す・引き継ぐ

- **FR-O30**：編集者・メンバーは、確かめのあとにいつでも組織を抜けられる。
- **FR-O31**：管理者は、自分以外の人を、確かめのあとに組織から外せる。
- **FR-O32**：管理者が抜けるときは、先に組織の人の中から新しい管理者を選ぶ。確かめの画面で「管理者がいなくなると、招待や役割の切り替えができなくなるので、引き継ぐ人を選んでください」と出し、選ぶまで「引き継いで抜ける」を押せない。管理者のほかに誰もいなければ、組織を消すよう案内する。
- **FR-O33**：管理者は、抜けずに管理者だけを引き継げる。前の管理者は編集者になる（アプリの中の担当はそのまま効く）【仮決め】（めぐるは担当の有無で編集者かメンバーかを決めたが、suite はアプリの担当を知らないため）。
- **FR-O34**：管理者がいない組織が残らないようにする。管理者が退会したときは、いちばん長くいる人を管理者にし、誰もいなければ組織を消す（めぐる 011 FR-046・013 FR-051 と同じ）。この引き継ぎは、退会の手順の最初に行い、そのあとアプリが記録を新しい管理者に引き継ぐ（FR-O36・5.7。作り方は AD-22）。
- **FR-O36**：退会（と主催者がアカウントを消すとき）は、次の順で行う：(1) suite が、その人が管理者の組織を引き継ぐ（いちばん長くいる人。誰もいなければ組織を消す）→ (2) 各アプリが、その人が組織に入れていた記録を、その組織の今の管理者に引き継ぐ（Threads は 5.7）→ (3) account が、残った本人のデータごとアカウントを消す。どの段も、途中で止まってもやり直せる（2回流しても同じ結果）。
- **FR-O35**：抜けた・外れた人の、アプリの中の担当と、その人が組織に入れていた記録の「組織に入れる」は消える。記録とそのデータは持ち主に残る（6章）。

### 4.5 契約の持ち主（形だけ決める。払うしくみは売り始めるとき）

- **FR-O40**：契約（`entitlement`）の持ち主は、**アカウント1つか、組織1つのどちらか**にする（両方・どちらもなし、はない）。前の決めごと（2026-11-19「持ち主は account。組織か個人かを区別しない」）を、この PRD で直した（AD-16）。
- **FR-O41**：契約は「何に効くか」（アプリの key。スイートの束で売るときの形は、売り方の列を足すときに決める〈AD-16〉）と「持ち主」を持つ。料金・席数・期間・支払いの会社の ID は、売り始めるときに足す列で、今は決めない。
- **FR-O42**：**個人の契約**は、その人が持ち主の記録に効く（組織に入れた記録にも効く）。
- **FR-O43**：**組織の契約**は、その組織に入れた記録に効く。組織の人は、その記録の中で、自分の契約なしに、アプリが役割と担当で許す操作ができる。組織の人が組織に入れていない自分の記録には効かない【仮決め】（席のように「組織の人なら何でも使える」形にすると、会社が払う契約で個人の運用まで使えてしまうため）。
- **FR-O44**：使えるかは、記録ごとに「持ち主の個人の契約」か「記録を入れた組織の契約」のどちらかがあるかで決める。新しい最上位の記録を作るときは、作る人の個人の契約か、作るときに入れる組織の契約で決める。判定は suite の1つの関数だけで行い、アプリは契約の表を読まない（AD-16・AD-22）。売り始める前は、いつも使える。
- **FR-O45**：手伝う人（担当の編集者）・見せてもらう人（メンバー）・受付係・参加者は、契約を要らない（AD-16 のまま）。
- **FR-O46**：組織の契約を持つ（申し込む・やめる）のは管理者だけ【仮決め】。管理者を引き継ぐと、契約の窓口も移る（支払いの会社の側の手続きは売り始めるときに決める）。
- **FR-O47**：契約の持ち主が消えたら、契約も消える（個人は退会・組織は削除）。売り始めたら、消す前に支払いの会社の契約を止める。
- **FR-O48**：組織の操作（招待・役割・人を外す・引き継ぐ・抜ける・消す）と、持ち主の「組織に見せる」の切り替えは、契約の状態で止めない【仮決め】（お金のかからない操作で、ほかの人を止めないため。めぐる 013 FR-044）。契約がないときの記録の振る舞い（読むだけなど）は、売り始めるときに決める。
- **FR-O49**：kanaeru はカードや口座の情報を受け取らない（Constitution I）。

### 4.6 ほかのアプリへの出し方・画面

- **FR-O50**：組織は suite の土台で、業務の共通ではない（AD-18 のまま）。suite が持つのは、人の集まり・役割・招待・契約の持ち主だけ。アプリの記録・担当・「組織に入れる」・「組織に見せる」は、各アプリが自分の領域に持つ。
- **FR-O51**：ほかのアプリは、組織を suite の `index.ts` からだけ読む（役割・入っている組織・組織の人の一覧・外部キーのための表）。suite の表に書かない（AD-22）。
- **FR-O52**：設定に「組織」を足す：入っている組織の一覧と「組織を作る」（`/settings/organizations`）、組織の画面（`/settings/organizations/{id}`。人の一覧・役割の切り替え・招待・外す・引き継ぐ・抜ける・名前・消す）。まとまりは「個人の設定」の下【仮決め】。
- **FR-O53**：組織の画面に、各アプリが自分の組織の画面への入口を出せる（Threads は「Threads の組織の画面」。見えないアプリは出さない）。仕組みは `feature.settings` と同じく、領域の `feature` に1項目を足す形【仮決め】。
- **FR-O54**：退会の確かめの画面に、次を分けて出す（中身は suite と各アプリが出す。AD-22）：
  - 入っている組織と、管理者の組織は「〇〇さんに管理者を引き継ぎます」か「組織を消します（組織に入れた記録も消えます）」。
  - **引き継がれる記録**（アプリごと）：Threads は「〇〇（運用アカウントの名前）は、△△さん（組織の管理者）に引き継がれます。Threads への接続は切れます」。
  - **消える記録**（アプリごと）：組織に入れていない運用アカウントと、消える組織に入れていた運用アカウントの名前と件数。
  - 「元に戻せません」。
- **FR-O55**：知らせは最小にする：管理者に、新しい人が入ったとき、組織の画面に1回だけ出す（通知の一覧は作らない）。

## 5. 機能（b）Threads：組織の上のチーム運用

組織に入れていない運用アカウントは、今と同じに動く（画面・操作・判定を変えない）。

### 5.1 組織に入れる・見せる

- **FR-T1**：持ち主は、運用アカウントの設定で、自分が入っている組織の1つに運用アカウントを入れられる・外せる。1つの運用アカウントは1つの組織にだけ入る（めぐるのまま）。どの組織にも入っていない人には、この区分を出さない【仮決め】。入れるときに「組織の管理者が担当を決めると、担当の人がこの運用アカウントの投稿の案と戦略を作れます。承認・設定・接続は、あなただけです。あなたが退会すると、この運用アカウントは組織の管理者に引き継がれます（Threads への接続は切れます）」と出す。
- **FR-T2**：Threads につないでいない運用アカウントも入れられる【仮決め】（kanaeru は名前だけで運用アカウントを作れるため。運用状況には「接続していません」と出す）。
- **FR-T3**：持ち主は、組織に入れた運用アカウントごとに「組織に見せる」をオン・オフできる。初めはオフ。運用アカウントの設定と、Threads の組織の画面の両方から変えられる。
- **FR-T4**：「組織に見せる」がオンのとき、同じ組織の人は、投稿の案（一覧）と戦略だけを読むだけで見られる。画面の上に「（持ち主の表示名）さんの運用アカウントを見ています（読むだけ）・（組織の名前）」と「組織に戻る」を出す。直す・承認・消す・貼り付けの操作は出さない。反応・分析・設定・操作の記録は見せない。
- **FR-T5**：「組織に見せる」がオフの運用アカウントは、同じ組織の人（担当の人を除く）には、名前・持ち主・「見せていません」だけを出し、開けない。
- **FR-T6**：別の組織の人・関わりのない人には、見せる設定に関わらず出さない（ないのと同じ 404。存在を明かさない）。

### 5.2 関わりと、できること

運用アカウントごとに、今の利用者の関わりを1つに決める（上から順に、最初に当たったもの）：**持ち主**／**担当の人**（その運用アカウントの担当の編集者か、自分を担当にした管理者。承認を任されているかを別に持つ）／**組織の管理者（担当なし）**／**編集者（担当なし）・メンバー**／**関わりなし**（組織に入っていない運用アカウントの持ち主でない人、別の組織の人）。

| 操作 | 持ち主 | 担当の人 | 管理者（担当なし） | 編集者（担当なし）・メンバー | 関わりなし |
|---|---|---|---|---|---|
| Threads の組織の画面で、名前・持ち主・見せる状態を見る | ○ | ○ | ○ | ○ | ✕ |
| 投稿の案（一覧）・戦略を読む | ○ | ○ | 見せているときだけ読むだけ | 見せているときだけ読むだけ | ✕（404） |
| 反応・分析・CSV・プロンプト・設定（読むだけ）・自動投稿の予定を見る | ○ | ○ | ✕ | ✕ | ✕ |
| 投稿の案・戦略・改善のメモ・宣伝・参考の投稿・キーワードを作る・直す、承認待ちの案を消す、プロンプトを作って貼り戻す | ○ | ○ | ✕ | ✕ | ✕ |
| 承認・却下・承認を戻す・承認済みと却下の案を消す | ○ | 任されたときだけ ○ | ✕ | ✕ | ✕ |
| 設定を変える（自動投稿・時間枠・NG ワード・投稿のルール・宣伝の割合・作る件数・時間差のメンション・掲載文の既定値） | ○ | ✕ | ✕ | ✕ | ✕ |
| Threads への接続・切る・運用アカウントを消す・組織に入れる/外す・組織に見せる・承認を任せる | ○ | ✕ | ✕ | ✕ | ✕ |
| 操作の記録を見る | ○ | 管理者のときだけ ○ | ✕ | ✕ | ✕ |
| 「このアカウントのチーム」のカード（5.4） | ○ | ○ | ✕ | ✕ | ✕ |
| 運用状況（数と日付。5.5） | （自分の画面で見る） | 編集者は担当の分だけ・管理者は全部 | ○（全部） | ✕ | ✕ |

組織の中の操作（Threads）：

| 操作 | 管理者 | 編集者 | メンバー |
|---|---|---|---|
| 担当を決める（編集者と自分ごとに、組織に入っている運用アカウントをチェック。自分の運用アカウントは「自分」と出してチェックさせない） | ○ | ✕ | ✕ |
| 運用状況を見る | ○（組織のすべて。見せる設定に関わらない） | 担当の運用アカウントとその持ち主の行だけ | ✕ |
| 自分の運用アカウントを組織に入れる・外す・見せる | ○ | ○ | ○ |

- **FR-T10**：5.2 の判定は、threads の領域の中の**1つの関数**で行い、すべての読み書きの窓口が通す（画面で隠すだけで済ませない）。役割は要求のたびに suite の `index.ts` から引く。権限が足りないときは `403`、関わりがないときは `404`。
- **FR-T11**：どの関わりでも、NG ワードの確かめと人による承認を省かない。承認を任された人の承認も、持ち主の承認と同じ確かめ（承認の時の NG ワード・投稿の直前の確かめ直し・まとめての承認の確かめ）を通る。自動で承認するしくみは作らない。
- **FR-T12**：管理者は、自分の運用アカウントのほかでは、ほかの組織の人と同じ扱いにする。担当の表で自分を担当にした運用アカウントでだけ、担当の人の操作ができる（めぐる 011 のまま。管理は招待・役割・担当だけで、ほかの人の事業の情報に勝手に触れない）。

### 5.3 担当・承認を任せる

- **FR-T20**：管理者は、Threads の組織の画面の「担当を決める」の表で、編集者と自分ごとに担当を付け外しできる。列は組織に入っている運用アカウント。
- **FR-T21**：担当の運用アカウントは、「組織に見せる」に関わらず、担当の人が開ける（組織に入れたときに、手伝ってもらうことに同意した扱い）。
- **FR-T22**：持ち主は、運用アカウントの設定で、担当の人ごとに「承認を任せる」をオン・オフできる。初めはオフ。任せられるのは承認・却下・承認を戻す・承認済みと却下の案を消すだけで、設定・接続・削除・組織の操作は任せられない（2026-11-20 主催者が決めた。めぐる 008 は設定も任せられたが、011 で任せる仕組みをなくした。kanaeru では承認だけを戻す）。
- **FR-T23**：担当が外れた・編集者からメンバーに戻された・組織を抜けた人の「承認を任せる」は消える（もう一度担当になっても戻らない）。
- **FR-T24**：画面の切り替え（運用アカウントの一覧）は、自分の運用アカウントに加えて、担当の運用アカウント（持ち主の表示名つき）を「担当している運用アカウント」として分けて出す。見せてもらっている運用アカウントは一覧に出さず、Threads の組織の画面から開く。担当の運用アカウントは、持ち主の上限（1人10個。Threads の PRD B2）に数えない。

### 5.4 このアカウントのチーム（めぐるの 009）

- **FR-T30**：運用アカウントの設定に、カード「このアカウントのチーム」を出す：組織の名前 → 管理者 → 持ち主 → 担当の人（承認を任されている人には印）を、表示名と役割で上から順につなぐ。見ている人に「あなた」の印（利用者の ID で決める）。
- **FR-T31**：そのアカウントの人だけを出す。担当していない編集者・ほかの運用アカウントの担当は出さない。
- **FR-T32**：組織に入っていない運用アカウントには、カードを出さない。
- **FR-T33**：管理者・編集者・メンバーができることの図（めぐるの役割の図）を、カードの下と、招待の確かめの画面の Threads の説明から開けるようにする。

### 5.5 運用状況（めぐるの 020）

- **FR-T40**：Threads の組織の画面に「運用状況」を、管理者と、担当が1つ以上ある編集者にだけ出す。メンバー・関わりのない人には出さず、直接求めても断る（5.2 の判定の1か所に足す）。
- **FR-T41**：管理者には、組織に入っている運用アカウントと組織の人をすべて出す（見せる設定に関わらない）。編集者には、担当の運用アカウントと、その持ち主の行だけを出す。持ち主の行の動きは、担当の運用アカウントでの動きだけを数える。
- **FR-T42**：人ごと：表示名・役割・最後に動いた日・この7日の動きの数（案を作る・直す・承認・却下）。最後に動いた日から7日より長い人（一度も動いていない人を含む）に「止まっている」の印。
- **FR-T43**：運用アカウントごと：持ち主・接続の状態・最後に投稿した日・この7日の投稿数・承認済みの残り・承認待ちの数・伸び。最後に投稿した日から7日より長い運用アカウントに「止まっている」の印。日数は組織に入れた日より前を数えない。
- **FR-T44**：伸び：直近30日に確定した投稿の閲覧数の中央値を、その前の30日と比べた比（例：×0.6）。0.8以下に「伸びていない」の印【仮決め】（めぐるの仮の値）。どちらかの30日の確定が5件に満たなければ「まだ判定できません」。投稿した日で30日に分け、確定した値だけを使う。
- **FR-T45**：印の付いたものを上に、同じ印の中は止まっている日数の長い順に並べる。スマホの幅でも横にスクロールせずに全部の行に届く。
- **FR-T46**：運用状況には数と日付だけを出す。投稿の本文・戦略・設定の中身・操作の記録の中身・トークンは出さない。新しい記録は取らず、今ある記録（操作の記録・投稿の案・投稿済み・反応）から読むときに作る。

### 5.6 記録・知らせ

- **FR-T50**：組織に入っている運用アカウントでは、誰がしたかを残す：投稿の案の作った人・最後に直した人・承認／却下した人、操作の記録のした人（列を足す。どれも `ON DELETE SET NULL`。6章）。投稿の案のカードに作った人と最後に直した人の表示名を出す。
- **FR-T51**：操作の記録（threads-005）に、組織の操作を足す：組織に入れる・外す・見せるの切り替え・担当の付け外し・承認を任せるの切り替え。その運用アカウントの記録に残す（90日）。suite の組織の操作（入る・抜ける・役割）の記録は、この版では持たない【仮決め】。
- **FR-T52**：知らせは最小にする：編集者に担当が付いたとき、Threads のはじめの画面に1回だけ出す。通知の一覧は作らない。
- **FR-T53**：Threads のナビの「組織」は、どれかの組織に入っている人にだけ出す【仮決め】。

### 5.7 持ち主の退会での引き継ぎ（2026-11-20 主催者が決めた）

- **FR-T60**：持ち主が退会するとき、その人が組織に入れていた運用アカウントは消さず、その組織の管理者に引き継ぐ（管理者が新しい持ち主になる）。組織に入れていない運用アカウントだけを消す。
- **FR-T61**：退会する人がその組織の管理者なら、先に suite が管理者を引き継ぎ（いちばん長くいる人）、運用アカウントは新しい管理者に引き継ぐ。組織にほかに誰もいなければ、組織は消え、その運用アカウントは持ち主と一緒に消える（FR-O36）。
- **FR-T62**：引き継ぐときは、Threads への接続を切る（トークンを消す。前の持ち主のものなので）。接続の状態は「接続し直しが要る」にし、Threads のユーザー名は表示のために残す。自動投稿は切にし、時間差のメンションの待ちは取り消す【仮決め】（新しい持ち主が接続し直してから決める）。
- **FR-T63**：運用アカウントの中の記録（戦略・投稿の案・承認済みの案・投稿済みと反応・宣伝・参考の投稿・NG ワード・設定・操作の記録）は、誰が書いたものでも、そのまま運用アカウントに付いて新しい持ち主に移る。前の持ち主がした記録の「誰がしたか」は「退会した人」になる（SET NULL）。
- **FR-T64**：引き継いだ運用アカウントは、同じ組織に入ったまま。新しい持ち主が自分で担当していた行は消す（持ち主になったため）。ほかの人の担当は残す。「承認を任せる」と「組織に見せる」は、前の持ち主の同意なので、オフに戻す【仮決め】。
- **FR-T65**：引き継ぎで、新しい持ち主の運用アカウントが上限（1人10個。Threads の PRD B2）を超えてもよい。超えている間は新しく作れない【仮決め】。
- **FR-T66**：引き継いだことを、その運用アカウントの操作の記録に残し、新しい持ち主に Threads のはじめの画面で1回だけ知らせる（「〇〇さんの退会で、△△を引き継ぎました。Threads に接続し直してください」）。

## 6. 消すとき・抜けるときの決まり

持ち主は、いつも kanaeru のアカウント（AD-19）。組織は記録の持ち主にならない。組織の人が持ち主の運用アカウントの中に書いたもの（担当が作った投稿の案など）も、持ち主のデータとして扱う。

| 起きること | 組織と役割（suite） | 持ち主の運用アカウントとデータ（threads） | 担当・承認を任せる・組織に入れる（threads） | 誰がしたかの記録 | 契約 |
|---|---|---|---|---|---|
| **持ち主が退会する**〈2026-11-20 直した〉 | 組織の人から消える。管理者なら、先にいちばん長くいる人が管理者になり、誰もいなければ組織が消える | 組織に入れていたものは、その組織の（新しい）管理者に引き継ぐ。接続は切れ、「接続し直しが要る」になる（5.7）。組織に入れていないもの・消える組織に入れていたものは消える。退会の確かめの画面に、引き継がれるものと消えるものを分けて出す（FR-O54） | 引き継いだ運用アカウントでは、ほかの人の担当は残り、新しい持ち主の担当の行と「承認を任せる」「組織に見せる」は外れる。消える運用アカウントの分は消える。その人がほかの人の運用アカウントで持っていた担当・任せるも消える | その人がした記録は、どの運用アカウントでも「退会した人」になる（SET NULL）。中身は運用アカウントに付いたまま | 個人の契約は消える。組織の契約は組織に残り、引き継いだ運用アカウントに効き続ける |
| **組織の人が抜ける・外される**（持ち主でもある人を含む） | 組織の人から消える | 残る。その人が入れていた運用アカウントは組織から外れ、個人の運用に戻る（見せる設定もなくなる） | その人の担当・任せるは消える。その人の運用アカウントでのほかの人の担当・任せるも消える | 残る（その人はまだいるので名前が出る） | 組織の契約は、外れた運用アカウントに効かなくなる（売り始めたら、その運用アカウントは持ち主の個人の契約で判定） |
| **組織を消す**（管理者が消す・最後の1人が退会した） | 組織・組織の人・招待が消える | 残る。組織に入っていた運用アカウントはすべて個人の運用に戻る | すべて消える | 残る | 組織の契約は消える（売り始めたら、先に支払いの会社の契約を止める） |
| **運用アカウントが組織から外れる**（持ち主が外す） | 変わらない | 残る（個人の運用に戻る。見せる設定もなくなる） | その運用アカウントの担当・任せるは消える | その運用アカウントの操作の記録に残る | その運用アカウントに組織の契約が効かなくなる |
| **持ち主が運用アカウントを消す** | 変わらない | 消える | その運用アカウントの分は消える | 一緒に消える | 変わらない |
| **編集者がメンバーに戻される** | 役割が変わる | 残る | 担当・任せるは効かなくなり、もう一度編集者にしても戻らない | 残る | 変わらない |
| **管理者を引き継ぐ** | 選んだ人が管理者、前の管理者は編集者【仮決め】 | 残る | そのまま効く | 残る | 組織の契約の窓口が新しい管理者に移る |

- 退会は止めない（`409` で止めるのは、ほかの人自身の本人の記録が、その人の記録にぶら下がるときだけ。AD-19 を直した）。消すものは退会のときにすぐ消し、元に戻す手段は作らない（めぐる 013 FR-051）。組織に入れた運用アカウントは引き継ぐ（めぐるとの違い。2026-11-20 主催者が決めた）。
- 作り方（suite がほかの領域を触らずに後始末する外部キーと、退会の手順の順番〈suite → アプリ → account。各領域が自分の `index.ts` から出す退会の手順を、組み立てが並べて account に渡す〉）は AD-22。

## 7. 守ること（非機能・Constitution との関係）

### 7.1 個人の情報（Constitution II）

- 持ち主が退会すると、組織に入れた運用アカウントの中身（本文・戦略・反応・設定）は組織の管理者のものになる。このことを、組織に入れるとき（FR-T1）と招待の確かめの画面（FR-O22）で伝える。トークンは引き継がない。
- 組織の管理者が見られるのは：組織の人の表示名・役割・入った日、組織に入っている運用アカウントの名前・持ち主・見せる状態・接続の状態、運用状況の数と日付、自分を担当にした運用アカウントの中身（担当の人として）、持ち主が見せた運用アカウントの投稿の案と戦略（読むだけ）。
- 組織の管理者が見られないのは：見せていない運用アカウントの本文と戦略（担当でないとき）、反応の詳細・分析・設定・NG ワード（担当でないとき）、操作の記録の中身（担当でないとき）、Threads のトークン（誰にも見せない。持ち主にも末尾だけ）、組織に入れていない運用アカウント、ほかの組織、個人の契約の状態と支払いの詳細、LINE のユーザー ID。
- 運用状況（5.5）は、どの人にも数と日付だけを返し、本文・戦略・設定・記録の中身を返さない（めぐる 020 と同じ）。見せる設定に関わらず見えることは、招待の確かめの画面と組織の画面で、入る前と入ったあとに伝える。
- 組織の人の表示名は、kanaeru の表示名（LINE の表示名）だけを使い、組織のために新しい個人の情報を集めない。
- 外の AI（AD-20）：段階1（コピーして貼る）は、担当の人も持ち主の運用アカウントで使える（kanaeru からは何も送らず、持ち主は組織に入れたときに手伝いに同意している）【仮決め】。段階2（自分の API キー）と MCP では、持ち主の記録だけを渡し、担当の人がほかの人の運用アカウントで使う道は作らない（Constitution II のまま）。
- ログに、投稿の本文・戦略・トークン・招待の札を書かない。招待の札は SHA-256 だけを持つ。

### 7.2 権限

- 権限は要求のたびに引く（セッションに写さない）。判定は、組織の操作は suite の中の1か所、Threads の運用アカウントの操作は threads の中の1か所（FR-T10）。
- どの関わりでも、NG ワードの確かめと人による承認を省かない（FR-T11）。

### 7.3 個人の運用を変えない・小さく始める（Constitution IV）

- 組織に入っていない人と、組織に入れていない運用アカウントでは、画面・操作・判定を今と同じにする（今の Threads のテストがそのまま通る）。
- 9章の外は作らない。

### 7.4 費用と DB（Constitution V・AD-10）

- 新しい定期の仕事・常に動く台を足さない。運用状況は読むときに計算する。管理者の引き継ぎと人のいなくなった組織の片付けは、退会の手順の中で行う（AD-22）。
- 0時〜8時は DB が止まるので、組織と Threads の画面も使えない（今と同じ）。

## 8. 今のデータの移し方

- 今の Threads の運用アカウントは、すべて個人の運用のまま残す（組織に入れる行を作らない）。持ち主と、すべてのデータと動きは変わらない。
- DB の変更は足すだけにする：suite の組織の表（先に入れる）→ threads の「組織に入れる」・担当・承認を任せるの表と、誰がしたかの列（あとに入れる）。どれも前の版のアプリで壊れない形で、develop に同時に1本だけ通す（AD-17）。
- 誰がしたかの列は、今ある行では空（`NULL`）にする。個人の運用の画面には出さない。
- 契約の表（`entitlement`）は、まだ作らない。作るときに、4.5 と AD-22 の持ち主の形で作る。
- めぐるのデータは移さない（別のサービス・別の利用者のため）。

## 9. 範囲

### 9.1 作るもの・作る順【仮決め】

1. suite の仕様：組織・人と役割・招待（リンクと QR）・抜ける・外す・引き継ぐ・消す・設定の画面・退会の確かめの画面の足し（FR-O1〜FR-O55。契約は持ち主の形を決めるだけで、表は作らない）。
2. threads の仕様（今ある番号の次）：組織に入れる・見せる・関わりの判定の1か所・担当・承認を任せる・このアカウントのチーム・誰がしたかの記録・知らせ（FR-T1〜FR-T33・FR-T50〜FR-T53）。
3. threads の仕様（その次）：運用状況（FR-T40〜FR-T46）。

Threads の PRD の 4.1（移さないもの）の「チーム運用」は、この PRD で範囲に入れる（Threads の PRD を同じ形に直す。主催者に確かめてから）。

### 9.2 この版で作らないもの

- 払うしくみ（支払いの会社・料金・席数・請求・契約がないときの振る舞い）。売り始めるときに作る（4.5 は形だけ）。
- 組織が記録の持ち主になる形（持ち主はいつも kanaeru のアカウント）。
- 受付アプリの受付係の見直し：今の `event_staff`（交流会ごとの受付係と招待）のまま。受付アプリをほかの主催者に開くとき（構成の決めごと Deferred）に、交流会の持ち主を組織にし、受付係を組織の人から選ぶ形に移せる。そのときに受付アプリの PRD と AD-5 を直す。
- めぐるの機能の切り替え（019）・運営者の画面（026）。
- 1つの運用アカウントを複数の組織に入れること（表の形は広げられるようにしておく）。
- 組織の人どうしのメッセージ・通知の一覧・メールの知らせ。
- 運用状況の期間を選ぶこと（7日・30日に決める）。
- 管理者を複数にすること。

## 10. 成功の基準

- 招待のリンクを開いてから1分以内に、組織に入れる。
- 5.2 の表のすべての組み合わせ（関わり × 操作）で、許さない要求が100%断られる（自動のテスト）。
- 「組織に見せる」をオフにした運用アカウントは、担当の人を除く組織の人（管理者を含む）から、次の要求で開けなくなる。別の組織の人からは、いつも開けない。
- 管理者のいない組織が、どの順の操作（引き継ぎ・抜ける・外す・退会）でも、画面と窓口に現れない。
- 運用状況の答えに、本文・戦略・設定の中身が1つも入らない。編集者には、担当の外の運用アカウントと人の数が1つも返らない。
- 組織に入っている運用アカウントが20あっても、運用状況が3秒以内に出る。
- 個人の運用の画面と操作が、この機能の前と変わらない（今の Threads のテストがそのまま通る）。
- 6章の表の各行が、自動のテストで確かめられる（消える・残るの件数を前後で比べる）。
- 3人のブラウザで「組織を作って招く → 2人が入る → 1人を編集者にして担当 → 持ち主が組織に入れて見せる → メンバーが読む → 担当が案を作る → 持ち主が承認を任せる → 担当が承認する → 管理者が引き継いで抜ける」が通しのテストで通る。
- 持ち主の退会で、組織に入れた運用アカウントが100%管理者に引き継がれ（中の記録の件数が前後で同じ・トークンが1つも残らない）、組織に入れていない運用アカウントは1つも残らない。管理者が1人だけの組織では、組織と運用アカウントが消える。

## 12. 決めきれていないこと

1. **組織の契約で、人数（席）を数えるか**：組織に入れた記録の数で数えるか、組織の人の数で数えるか、定額か。売り始めるときに料金と一緒に決める（表は持ち主の形だけ決めてあり、どれを選んでも作り直しは要らない）。
2. **組織が記録の持ち主になる要望が出たとき**：退会では管理者への引き継ぎで記録が組織に残る（5.7）。ただし、退会せずに組織を抜けた人の運用アカウントは、その人の個人のものに戻る。抜けても会社に残したい・退会の前に別の人へ渡したい、という要望が出たら、AD-19・AD-22 を直してから決める。
