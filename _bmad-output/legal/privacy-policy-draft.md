3. **公表する事項**：法32条（保有個人データに関する事項の公表等）で、名前・住所・代表者（法人のとき）・安全管理の措置などを本人が知りうる状態にする。個人の事業者の住所を載せるか、「求めに応じて遅滞なく答える」とするか（2026-11-26：求めに応じて答える形にした）。

6. **ほかの人の情報**：メンションする人の Threads のユーザー名・参考の投稿を書いた人・外部メディアの連絡先など、利用者が入れる「ほかの人の情報」の扱いを、この書き方（利用者が入れたものだけを持つ・規約で権利を侵さないよう求める）でよいか。
7. **組織の中で見えるもの**：運用状況（数と日付だけ）・見せる・担当・任せるの範囲を、コード（`apps/api/src/modules/threads/access.ts`・`team-status.ts`）に合わせて書いた。画面の言葉と合わせて、分かりやすいか。
8. **保存する期間**：チェックインとアンケートは「使う間」とだけ書いた。期間を決めるか（例：交流会から3年）。バックアップは最大7日（Cloud SQL の毎日のバックアップを7つ残す）。

# プライバシーポリシー

奥家拓海（以下「運営者」）は、アプリのまとまり「PaletKit」（以下「本サービス」）で、利用者の情報を次のとおり扱います。本サービスの使い方の決まりは「利用規約」にあります。

## 1. 集める情報（すべてのアプリ）

| 情報 | いつ・どう集めるか |
|---|---|
| LINE のユーザーID・表示名 | LINE でログインしたとき（LINE から受け取ります。メールアドレスや電話番号は受け取りません） |
| 登録した日 | 初めてログインしたとき |
| ログイン状態を保つための情報（クッキー） | ログインしたとき（30日で切れます） |
| 組織の情報（組織の名前・入っている人と役割・入った日・招待のリンク） | 組織を作ったとき・入ったとき・管理者が変えたとき |
| アクセスの記録（IPアドレス・日時・ブラウザの種類など） | 本サービスを使ったとき（不正な使い方を防ぎ、不具合を調べるため） |

## 2. 受付のアプリで集める情報（受付・アンケート・予約）

| 情報 | いつ集めるか |
|---|---|
| チェックインの情報（お名前・申し込みの方法・交流会を知ったきっかけ・支払い方法・使った割引・参加費の金額・チェックインの日時） | 受付のとき |
| 紹介してくれた人のお名前（紹介割などを選んだときだけ・任意） | 受付のとき（主催者だけが読みます） |
| アンケートの答え（仕事の困りごと・「実現したら月いくらなら使うか」・テスターになるか・仕事の立場・職種） | アンケートに答えたとき（どの設問も任意です） |
| 名簿の情報（お名前・申し込みの媒体・確定やキャンセル待ちなどの申し込みの状態・申し込んだ日時・主催者のメモ） | 主催者が名簿に入れたとき・取り込んだとき、申込みのページで申し込んだとき |
| メールアドレス（LINE を使わずに申し込むときと、予約の知らせの連絡先を入れたときだけ・任意） | 申し込んだとき・連絡先を入れたとき（申込みの確認と予約の知らせだけに使い、主催者には見せません） |
| 案内を受け取るかどうか（主催者や組織からの案内への同意・任意） | 申込みのページで選んだとき |
| 主催者の公式LINE との紐づけ（その公式LINE から見える LINE のユーザーID） | 主催者の公式LINE を友だちに追加して、紐づけたとき |
| 予約の知らせの記録（知らせの種類・送った手段・送れたかどうか） | 予約の知らせを送ったとき |

- 受付係が参加者の代わりに受付やアンケートを入れることがあります。そのときも、集める情報は上と同じです。
- 本サービスはお金を預かりません。支払い方法と金額を記録するだけで、カードや口座の情報は受け取りません。
- アンケートの画面から開ける Google フォームは、主催者が用意した外のページです。そこで答えた内容は本サービスには届かず、Google と主催者の決まりで扱われます。

## 3. 試合表のアプリで集める情報

| 情報 | いつ集めるか |
|---|---|
| 試合表（名前・試合の日・名簿の呼び名とレベルと当日の出欠・組み合わせ） | 利用者が試合表を作ったとき・直したとき |
| QR の受付で入れた呼び名とレベル | 参加者が QR から入れたとき（ログインはいりません） |
| 前に入れたレベル（受付から名簿に入れた、LINE でチェックイン・申し込みをした人だけ） | 試合表でレベルを入れたとき（次に同じ人を名簿に入れるときに使います） |

- 電波がない場所でも開けるよう、試合表の写しを、担当の端末のブラウザにも残します。端末で使う人が替わると、前の人の写しを消します。
- 見るだけのページのリンクや QR を渡された人は、ログインせずに試合表を見られます（受付から入れた人のアカウントの情報は出しません）。

## 4. Threads のアプリで集める情報

| 情報 | いつ集めるか |
|---|---|
| 運用アカウントの設定（名前・投稿の件数と長さ・投稿のルール・NG ワード・自動投稿の時刻） | 利用者が入れたとき |
| 戦略・宣伝（イベントの情報を含む）・参考の投稿・リサーチのキーワード・分析の設定 | 利用者が入れたとき |
| 投稿の案（本文・承認や却下の日時と理由・投稿した日時・Threads の投稿の ID と URL） | 利用者が AI の答えを貼ったとき・承認したとき・投稿したとき |
| Threads のアカウントの情報（Threads のユーザーID・ユーザー名・表示名・プロフィールの画像の URL） | Threads につないだとき・運用アカウントを開いたとき（Threads から受け取ります） |
| Threads のアクセストークン（期限と、許可された範囲を含む） | Threads につないだとき（暗号にして保存します） |
| 投稿の反応（表示・いいね・返信・再投稿・引用・シェアの数）とフォロワーの数 | 投稿のあとと、毎日（Threads から受け取ります） |
| 時間差のメンションの相手（利用者が入れた Threads のユーザー名と呼び名）と、返信の文 | 利用者が入れたとき |
| 外部メディアの掲載文と既定値（事務局名・連絡先など） | 利用者が入れたとき・作ったとき |
| 操作の記録（承認・却下・設定の変更・自動投稿などの種類と数と、30文字までの書き出し） | 操作したとき |
| Meta から届く、連携の解除とデータの削除の知らせ（Threads のユーザーID・確認のコード） | Meta から知らせが届いたとき |

- 本サービスは、投稿の案を作るために、外の AI に情報を送りません。プロンプトをコピーして AI のサービスに貼るのは利用者で、貼った情報はその AI のサービスの決まりで扱われます。
- ほかの人の情報（メンションする人のユーザー名、参考の投稿を書いた人など）は、利用者が入れたものだけを持ちます。

## 5. 使う目的

1. 本人を確かめ、ログインの状態を保つため
2. 交流会の受付と、参加費の清算のため（紹介割などの割引の確認を含む）
3. 交流会の運営をよくするため（どこから申し込み、何で知った方が来ているかを知る）
4. 交流会の名簿と申込みを管理し、申込みの確定・キャンセル待ち・日時や場所の変更・中止などを、公式LINE やメールで知らせるため
5. 主催者が、仕事の困りごとをもとに、勉強会のテーマや、小さなアプリを考えるため
6. 「テスターになる」を選んだ方に、主催者が、試してほしい勉強会やアプリができたことを連絡するため
7. サークルなどの練習会で、試合表を作り、配るため
8. 利用者が承認した投稿を、利用者が決めた時刻に Threads に投稿し、反応を読みこんで分析するため
9. 組織の中で Threads の運用を分担し、運用の状況を組織の管理者に見せるため
10. 不正な使い方を防ぎ、本サービスを安全に動かすため

## 6. 困りごとの扱い

- アンケートの困りごとは、その交流会の主催者だけが読みます。受付係にも見せません。
- 勉強会やアプリのテーマにするときに、お名前を出すことはありません。

## 7. 組織の中で見えるもの

- 組織の人には、組織の人の表示名・役割・入った日が見えます。
- Threads の運用アカウントを組織に入れると、組織の人に、運用アカウントの名前・持ち主・接続の状態が見えます。持ち主が「組織に見せる」をオンにしたときだけ、組織の人が投稿の案（一覧）と戦略を読めます。
- 担当の人は、担当する運用アカウントの投稿の案・戦略・反応・設定を見て、案を作ったり直したりできます。承認は、持ち主が「承認を任せる」にしたときだけです。接続・設定の変更・アカウントを消すことは、持ち主だけができます。トークンは、誰にも見せません。
- 組織の管理者（担当のある編集者は、担当の分だけ）は、運用状況の画面で、人ごと・運用アカウントごとの数と日付（最後に動いた日・この7日の動きの数・最後に投稿した日・承認待ちの数など）を見られます。この画面には、投稿の本文や操作の中身は出しません。
- 持ち主が退会すると、組織に入れていた運用アカウントは、組織の管理者に引き継がれます。そのとき、トークンを消して Threads への接続を切り、自動投稿を止めます。

## 8. ほかの人に渡すこと

運営者は、次のときを除き、集めた情報を本人の同意なく第三者に渡しません。

- 法令にもとづくとき
- 人の生命・身体・財産を守るために必要で、本人の同意を得るのが難しいとき
- そのほか、個人情報保護法で認められているとき

利用者が承認した投稿と返信を Threads に送るのは、利用者の指示によるものです。

## 9. 使っている外のサービス

| サービス | 使い方 |

## 10. 情報を守るために

- 通信は暗号化します。ログイン状態の情報と招待のリンクは、そのものではなく、確かめ用の値を保存します（招待のリンクは、出し直すための写しを暗号にして持ちます）。
- Threads のアクセストークンと、主催者がつないだ公式LINE の鍵は、暗号（AES-256-GCM）にして保存し、画面にも記録にも出しません。
- 困りごとの本文・投稿の本文・ログインの情報は、アクセスの記録に残しません。
- 受付のアプリの情報を見たり直したりできるのは、その交流会の主催者（交流会を作った人と、交流会を入れた組織の管理者・編集者）と、主催者が交流会ごとに招いた受付係だけです（受付係が見られるのは、受付に要る情報だけです）。
- 試合表を見たり直したりできるのは、持ち主と、試合表を入れた組織の管理者・編集者だけです。見るだけのリンクや QR を渡された人は、見ることだけができます。
- Threads の運用アカウントの情報を見られるのは、持ち主と、「組織の中で見えるもの」に書いた組織の人だけです。

## 11. 保存する期間

- チェックイン・アンケート・名簿の情報は、交流会の運営と、勉強会・アプリの企画に使う間、保存します。
- 試合表は、試合の日から90日を過ぎると自動で消えます。
- Threads のアプリの情報は、利用者が消すか、退会するまで保存します。操作の記録は90日、投稿の処理の記録は30日で自動で消えます。
- 退会すると、アカウントと、すべてのアプリのあなたの記録を消します（組織に入れていた Threads の運用アカウントと試合表は、組織の管理者に引き継ぎます）。
- 消した情報も、バックアップには最大7日残り、そのあと消えます。
- アクセスの記録は、90日以内に自動で消えます。

## 12. Threads の連携の解除とデータの削除

- Threads の設定で本サービスとの連携を解くと、Meta から知らせが届きます。本サービスは、その Threads のアカウントへの接続を切り、トークンを消します。
- Meta からデータの削除の要求が届くと、その Threads のアカウントにつないだ運用アカウントと、そこにためた戦略・投稿の案・反応などを消します。削除の状況は、Meta から伝えられる確認のコードの画面で確かめられます。
- 本サービスの中でも、運用アカウントの設定の「アカウントを消す」で、いつでも消せます。

## 13. 見る・直す・消すことを頼むには

ご自身の情報について、見せてほしい・直してほしい・消してほしい・使うのをやめてほしいときは、下の連絡先までお知らせください。ご本人であることを確かめたうえで、すみやかに対応します。退会と、Threads の運用アカウントを消すことは、本サービスの画面からもできます。

## 14. クッキーと、ブラウザに保存するもの

本サービスは、ログイン状態を保つためだけにクッキーを使います。このほか、画面を使いやすくするために、最後に使ったアプリや、メニューを開いているかなどを、お使いの端末のブラウザに保存します。広告や、利用の分析のためのクッキーは使いません。

## 15. このポリシーを変えるとき

内容を変えるときは、本サービスの中でお知らせします。
