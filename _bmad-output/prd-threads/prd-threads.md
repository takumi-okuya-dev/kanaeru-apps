# PRD：kanaeru Threads 運用アプリ（めぐるからの移植）

作成：2026-11-20（同じ日に範囲を広げた。主催者の指示「めぐるの Threads をすべて移す」。9章）

## 0. この文書について

めぐる（別のリポジトリ `meguru-app`）で作った Threads の運用アプリ（めぐるの PRD「ThreadsGrower App」）を、kanaeru のスイートの2つ目のアプリとして作り直すための要求。読む人は、主催者（開発者）と、このあと機能ごとの仕様（spec-kit。`specs/threads/`）を作る人とAI。

- 移植の元：めぐるの `_bmad-output/initiative-threads-grower-app/prd-threads-grower-app/prd-threads-grower-app.md`（2026-11-08 版）と、`apps/api/src/apps/threads/`・`apps/web/src/apps/threads/` のコード。
- このアプリは、**人材版の Threads**（Threads での発信から、転職や副業に本気の人を見つけて人材会社へつなぐ。7章）の土台になる。めぐるで確かめた運用のループと、それを支える機能（宣伝・リサーチ・分析・時間差のメンション・外部メディアの掲載文・操作の記録）を、kanaeru の構成で動かす。料金・テスター・運営者・紹介のリンクは、kanaeru がスイートの単位で作るので移さない（4.1）。チーム運用は、スイートの組織の上に作る（[PRD 組織と Threads のチーム運用](../prd-kanaeru-org/prd-kanaeru-org.md) 5章。2026-11-20 に範囲に入れた）。
- 決めきれないことは仮決めにして【仮】の印を付け、8章に並べた。主催者が確かめたら【決定】に直す。

## 1. ねらい

Threads のアカウントを「戦略を決める → 投稿の案をためる → 承認する → 自動で投稿する → 伸びたかを見る → 次の案に活かす」のループで育てる。投稿の文は、使い慣れた外の AI（ChatGPT・Claude）に、アプリが作ったプロンプトを貼って作ってもらう（kanaeru の AI の段階1。構成の決めごと AD-20）。

kanaeru では、この運用のループを、のちに人材の要素（返信から本気の人を見分ける・人材会社へつなぐ）を足す土台にする。

## 2. 使う人

### 2.1 片づけたい用事

- **自分（開発者・最初の利用者）**：自分の Threads のアカウントの投稿を、案から公開まで手離れよく回したい。
- **代理店（あとで）**：同じ仕組みで自分のアカウントを回し、集まった人を人材会社につなぎたい（7章）。

### 2.2 この版で相手にしない人

- アプリの中の AI に投稿の文を作らせたい人（段階2・MCP は、kanaeru の共通の仕組みができてから。AD-20）
- Threads のほかの SNS を主に運用したい人

### 2.3 使う場面

- **UJ-1**：ログインして運用するアカウントを作り、戦略（ターゲット・悩み・理想像・宣伝・リサーチのメモ）を書く。プロンプトをコピーして外の AI に貼り、返ってきた複数の案を `@@@` で区切ったまま貼り戻すと、案が一度にためられる。
- **UJ-2**：たまった案を見て、似た案（似ている度合いの％）を却下し（理由を残す）、残りを承認する。承認した案は、決めた時間枠で Threads に自動で投稿される。
- **UJ-3**：投稿が1〜2週間たまったら、投稿ごとの反応（閲覧・いいね・返信・リポスト・引用・シェア）を、そのアカウント自身の中央値と比べて「好調・普通・低調」で見る。低調の傾向と却下の理由が、次のプロンプトに「避けること」として入る。
- **UJ-4**：複数のアカウントを一覧から切り替えて運用する。アカウントごとに承認待ちの数が見える。

## 3. ことば

| ことば | 意味 |
|---|---|
| 運用アカウント | 運用する Threads のアカウント1つ分の単位。kanaeru のアカウント（LINE でログインした人）が持ち主になる。名前だけで作れ、Threads への接続はあとでよい |
| 戦略 | 運用アカウントごとの、課題①（ターゲット）・課題②（悩み）・課題③（理想像）・宣伝の内容・リサーチのメモ |
| 投稿の案 | 承認待ち・承認済み・却下・投稿済みの下書き。外の AI の答えを貼って一度に作る |
| 似ている度合い | 案と、ほかの案・投稿済みの文との近さ（％）。80％以上で知らせる【仮】 |
| 時間枠 | 自動投稿する時刻の並び（日本時間）と、1日の上限 |
| 反応の判定 | 投稿ごとの反応を、そのアカウントの中央値と比べた「好調・普通・低調」 |
| 改善のメモ | 低調だった投稿と、利用者が足した傾向のメモ。却下の理由と一緒に次のプロンプトに入る |

### 4.1 移さないもの（めぐるにあって、kanaeru では作らない）

- 料金と契約（めぐるの FR-12・013）：kanaeru ではスイートの契約（AD-16）で売り始めるときに決める。
- チーム運用（FR-13・008〜011・020）は、この PRD では作らず、スイートの組織の上に作る。範囲と要求の正本は [PRD 組織と Threads のチーム運用](../prd-kanaeru-org/prd-kanaeru-org.md)（FR-T1〜FR-T66。2026-11-20 主催者が決めた。前は「運用アカウントは持ち主1人のもの〈AD-19〉。時間が残れば考える」）。
- テスターの招待（024）・運営者の画面（026）・紹介のリンク（017）・機能の切り替えの画面（019）・テストのグループ（016）：kanaeru はスイートの単位で作る。
- めぐるの Google ログイン（001）：kanaeru の LINE ログインを使う。

## 5. 守ること（Constitution との関係）

- **お金を預からない（I）**：この版に料金はない。
- **個人の情報は最小限（II）**：持つのは、持ち主の kanaeru のアカウントの ID・運用アカウントの名前・戦略・投稿の案と投稿の文・反応の数・Threads のユーザー名とトークン（暗号）・持ち主が入れた宣伝と参考の投稿・時間差のメンションの相手の Threads のユーザー名と呼び名（持ち主が入れたもの）・操作の記録（90日）だけ。トークン・投稿の本文はログに出さない。外の AI へは、アプリからは何も送らない（利用者が自分でコピーして貼る）。
- **小さく始める（IV）**：4章の FR-1〜FR-17 の外は作らない。
- **運用費（V）**：自動投稿は Cloud Scheduler から API を5分おきに呼ぶ形にし、常に動く台を足さない【仮】。Cloud Scheduler の仕事は、夜間の停止の2つと合わせて3つ（無料の枠の中）。
- **DB の夜間の停止（AD-10）**：0時〜8時は DB が止まるので、その間の時刻には投稿できない。投稿の時刻は 8時30分〜23時の中から選ぶ【仮】。

## 6. 範囲

- **作る順**：threads-001（ためる・選ぶ）→ threads-002（接続・自動投稿）→ threads-003（反応の判定）→ threads-004（宣伝・リサーチ）→ threads-005（操作の記録・分析・時間差のメンション・外部メディアの掲載文）→ FR-17（時間が残れば）。
- **公開**：スイートの台帳（AD-16）ができるまでは、設定 `DOMAIN_FEATURES` の印 `threads.app` が切なら、Threads の窓口はすべて 404 にする【仮】。本番は切で出し、手元とステージングで入にして確かめる（coding.md 2）。

## 7. このあと（人材版にするとき）

人材版の構想（2026-11-20 の壁打ち）で出た、のちに足す候補。どれも、この PRD を直してから作る。

- 投稿への返信をアプリで読み、AI の下書き＋人の確認で返す（Threads の API の返信の取得と送信）
- 返信や診断の中身から、本気度を高・中・低に分ける（本人の情報をどこまで持つかは、この PRD の5章を先に直す）
- 本気の人を、引き継ぎのカード付きで人材会社へ渡す・誰経由かを記録する
- 同じ仕組みを代理店ごとのアカウントで使えるようにする（契約は AD-16）

## 8. 仮決めの一覧

| 番号 | 仮決め | 理由 |
|---|---|---|
| B1 | 似ている度合いの知らせは80％以上 | めぐるの仮決めのまま |
| B2 | 運用アカウントは1人10個まで | めぐるの既定の上限に近い値。料金がないので歯止めとして置く |
| B3 | 公開は `DOMAIN_FEATURES` の `threads.app` で止める | スイートの台帳がまだないため。台帳ができたら `app_setting` に移す |
| B4 | 自動投稿は Cloud Scheduler から数分おきに API を呼ぶ | 常に動く台を足さないため（原則 V） |
| B5 | Threads への接続は、まずトークンを貼る形だけ | めぐるでも OAuth の審査の前はこの形で回していた |
| B6 | 範囲をめぐるの Threads のすべて（4.1 を除く）に広げる | 主催者の指示（2026-11-20） |
| B7 | 投稿の時刻は 8時30分〜23時（日本時間）から選ぶ | DB が 0時〜8時は止まる（AD-10）。ずらす幅（前後10分）・やり直し（最大30分）・DB が動き出すまでの間を見こむ |
| B8 | 同じ Threads のアカウントは、kanaeru の中で1つの運用アカウントにだけつなげる | 二重の投稿を防ぐ。ほかの人がつないでいても、誰がつないだかは明かさない |
| B9 | 自動投稿・反応の取りこみ・トークンの延長は、1つの定期の仕事（5分おき・8時〜23時台）でまとめて行う | Cloud Scheduler の無料の枠（3つ）に収める |
