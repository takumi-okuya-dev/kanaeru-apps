# 補足：PRD kanaeru 受付アプリ（最初の版）

作成：2026-11-19（[PRD](./prd-kanaeru-reception.md)に書かない、技術の方向の仮決め。構成づくり（`/bmad-architecture`）と最初の `/speckit-plan` で確かめて決める）

調べものの出典と、技術の制約の元は[ブリーフの補足](../brief-kanaeru-apps/addendum.md)。ここでは同じことを繰り返さず、受付アプリでの使い方だけを書く。個人の情報として何を持つかは、PRD 5章。

## 1. 技術の方向（仮決め）

| 層 | 仮決め | 理由 |
|---|---|---|
| 言語・骨組み | TypeScript。product-template の typescript ブランチの骨組み（Hono の API・Vite＋React の画面・PostgreSQL・Drizzle） | リポジトリがこの骨組みを土台にしている |
| 参加者の画面（チェックインの画面） | LINEの中で開くWeb。LIFF か LINEミニアプリで作る（LINE は、新しく作るなら LINEミニアプリとして作ることを勧めている） | 受付QR → LINEログインの流れを1つの画面で終えられる |
| 主催者の画面 | 同じWebの管理の画面。主催者もLINEログインで入り、主催者として登録したLINEのユーザーだけを通す | ログインの仕組みを2つ持たない |
| 置き場所 | GCP の Cloud Run。インフラは Terraform | 無料枠で収まる見込み。主催者が勉強したい技術 |
| DB | Neon の無料プランの PostgreSQL | Cloud SQL には無料枠がない。Supabase の無料プランは使わないと止まり、月1回の交流会では止まりやすい |
| 一覧画面の更新 | 数秒おきに読み直す（ポーリング） | 主催者1人・参加者数十人なら十分。常時つなぐ仕組みは要らない |

## 2. LINE まわり

- LINEログインのチャネルは「開発中」で始まるので、交流会で使う前に公開の状態に切り替える。
- LINEログインの同意の画面で、公式LINEの友だち追加を同時に勧めることができる見込み（PRD の仮決め B4）。
- 1対1のチャットは、公式LINEの無料プランの通数に数えられない。テスターへの連絡に費用はかからない。
- 参加者の識別には、LINEログインで得られるユーザーの識別子を使う。表示名は参加者が直せる。

## 3. 構成づくりで確かめること

- LIFF と LINEミニアプリのどちらで作るか。
- LINEログインで公式LINEの友だち追加を同時に勧める設定が、いまも使えるか。
- Cloud Run の東京リージョンが、無料枠の対象か。
- Neon の無料プランの上限（月100 CU時間・1GB）に、月1回の交流会の使い方で収まるか。
