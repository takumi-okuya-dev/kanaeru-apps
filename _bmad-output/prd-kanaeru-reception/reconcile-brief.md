# 照合：ブリーフ → PRD（kanaeru 受付アプリ）

作成：2026-11-19。照合の元：`brief-kanaeru-apps/brief-kanaeru-apps.md`・`addendum.md`・`.memlog.md`。照合の先：`prd-kanaeru-reception.md`・`addendum.md`。

## 抜け・食い違い

1. **台本・タイムテーブルの段が下がっている**
   - ブリーフ：4章「余裕があれば」（memlog でも Could と決定）
   - PRD：6.2「この版では作らない」に入っている（注記で「余裕があれば」とは書いている）
   - 直し方：4.5 の後に「4.6 余裕があれば（Could）」を作り、FR-18 として置く。6.1 にも「FR-18 は余裕があれば」と書く。

2. **「答えるだけで、実際には払わない」が落ちている**
   - ブリーフ：4章「本気度を測る」の「実現したら月◯円なら使う（答えるだけで、実際には払わない）」。7章「お金の約束は持ち込まない」
   - PRD：FR-9・UJ-2 では選択肢だけを決めていて、払わなくてよいことを参加者に示す要求がない
   - 直し方：FR-9 の確かめ方に「設問に『答えるだけで、支払いは発生しない』と書いてある」を足す。

3. **手でチェックインした参加者の困りごとを集められない（仮決め A9）**
   - ブリーフ：2章で想定するのは年長で非エンジニアの層。LINEを使わない人はこの層に多いと見込まれる。6章の目安は「アンケートで困りごとを書いた参加者 8割」
   - PRD：A9 でこの人たちはアンケートの対象から外れる。SM-2 の分母（参加者全員か、LINEでチェックインした人だけか）も決まっていない
   - 直し方：SM-2 の分母をはっきり書く。主催者が聞き取って入れる道（または紙で集める）を Should として足すかを、A9 といっしょに確かめる。

4. **その先の目安【仮定】が引き継がれていない**
   - ブリーフ：6章「数回の交流会で集まった困りごとから、勉強会のテーマかアプリが1つ決まり、手を挙げた人が勉強会に参加する・アプリを試す」
   - PRD：7章には SM-1〜4 と追いかけない目安しかない
   - 直し方：7章に「その先の目安（この版の外、【仮定】）」として1行足す。FR-13・FR-14 がこの目安の材料になることを書き添える。

5. **ペルソナの仮説を確かめる手段と、「一人の深い困りごとから選ぶ」が反映されていない**
   - ブリーフ：9章「ペルソナの仮説……次の交流会で確かめる」。7章「多数決ではなく、本気度の高い一人の深い困りごとから選ぶ」
   - PRD：UJ-1 は仮説（50代の営業部長）を事実のように扱っている。どの画面・設問でも確かめられない。FR-13 は本気度で並べ替えられず、FR-16「私も」が数の多さで選ぶ方向へ流れるおそれもある
   - 直し方：8章に「ペルソナの確かめ方（設問に入れる／当日の会話で確かめる）」を論点として足す。FR-13 に「月いくらで並べ替えられる」を足す。FR-16 に「『私も』の数は、作るものを選ぶ基準にしない（7章の判断の基準）」と注記する。

**軽微**：FR-6（公式LINEの友だち追加の案内）は、ブリーフの「入れる」になく、Must に上がっている。B4 で同意の画面にも追加の勧めを出すので、「入口は軽く」と張り合う。テスターに「はい」と答えた人にだけ、アンケートを送ったあとで案内する形も考える（A5・B4 を確かめるときに）。

## 正しく引き継がれていること

「入れる」の6項目（FR-1〜14）、「できれば入れる」の3項目（FR-15〜17）、「今回は入れない」の6項目（6.2）。成功の目安4つ（SM-1〜4）。参加者への約束の文言（UJ-2・FR-9 にそのまま）。気軽さ（5章、SM-C1・C2）。困りごとを入口で聞かないこと。登録が受付の副産物であること。LINEを使わない人の逃げ道（FR-7）。スイート共通のアカウントと登録日。まずは無料と運用費ゼロ。決済の連携を持たないこと。補足の技術の制約（TypeScript・GCP・Terraform・Neon・LINEの数える通数）。
