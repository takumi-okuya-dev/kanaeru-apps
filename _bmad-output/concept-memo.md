# 構想メモ：IT交流会発の需要収集アプリ＆スイート型SaaS

作成：2026-11-19（リポジトリを作ったときの、最初のたたき台）

`/bmad-brainstorming`・`/bmad-product-brief`に渡す材料。ここから練った結果は、ブリーフ・PRDとして`_bmad-output/`に別の文書で書き出す。

## 1. 背景と目的

- **開発体制**：Web・モバイルアプリの個人開発。言語は TypeScript を前提にする。
- **持っているもの**：自分で「IT交流会」を主催しており、オフラインでIT関係者やビジネス層と直接つながるコミュニティがある。
- **解きたい課題**：個人開発でいちばん高い壁である「初期ユーザー集め（過疎化）」と「本当に需要があるかの検証（PMF）」を、オフラインの場と連動させることで解きたい。

## 2. 全体のロードマップ（ビジネスモデルと成長戦略）

### フェーズ1：需要収集アプリのリリースと初期ユーザーの獲得

- 「こんなアプリがあったらいいな」「日々の業務で面倒なこと」を集めるアプリを作って公開する。
- 主催する**IT交流会の場**を使い、参加者に初期ユーザーとして使ってもらう（QRコードでの誘導、イベント中の投稿企画など）。
- 「いいね」だけでなく、困りごとの深刻度や課金意欲（「いくらなら払うか」など）を見えるようにする。

### フェーズ2：ニーズのアプリ化と、公式LINEでの告知・ファン化

- 集めた需要の中からニーズの高いものを選び、開発者自身がすばやくアプリにする（MVP開発）。
- **公式LINE**を窓口にして、交流会の参加者をリストにする。
- 公式LINEで「交流会で出た〇〇という要望をもとに、こんなアプリを作りました」とストーリー付きで告知し、試してもらう・声をもらうサイクルを回す。

### フェーズ3：スイート型SaaSへの統合とサブスクリプション

- 作った小さな実用アプリ群を、共通のアカウントとUIでまとめた**スイート型SaaS**として出す。
- アプリごとの課金ではなく、スイート全体を使える**サブスクリプション**で収益にし、交流会の外の一般の利用者にも広げる。

## 3. 議論したい論点

1. **ビジネスモデル・戦略の穴（リスクの検証）**
   - 「需要収集アプリ → 個別のアプリ開発 → スイート型SaaS」という流れで、想定されるボトルネックや失敗パターンは何か。
   - スイート型SaaSにするとき、どのジャンルのアプリ群に絞るべきか（何でもありのツール集になって価値がぼやけるのをどう防ぐか）。
2. **需要収集アプリの中心の設計**
   - 交流会の参加者がその場で気軽に入力でき、かつ「本当に作るべきアプリ」を見極められるデータの項目・UIの工夫。
   - 既存のサービス（Blabo!、ideee、不満買取センターなど）との違い。
3. **公式LINE×アプリの導線**
   - 交流会当日の「LINE友だち追加 → 需要の投稿」から、後日の「新作アプリのリリース通知 → 使い始め」までの離脱を防ぐしくみ（LIFFを使えるか）。
4. **技術選定・アーキテクチャの方向**
   - 将来、複数のミニアプリをスイート型SaaSとしてまとめやすい、認証の基盤・マルチプロダクト構成のよいやり方（テンプレートの TypeScript の骨組みは、ログイン・複数の組織をまだ持たない）。
