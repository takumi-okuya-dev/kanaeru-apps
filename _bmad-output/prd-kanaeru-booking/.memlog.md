- (decision) 受付アプリを広げて申込みと名簿を足す（新しいアプリにしない）。予約するのは参加の申込み
- (decision) 交流会ごとに3段：受付だけ（既定）・名簿を使う（申込みは外）・自前で申込みを受ける。定員・キャンセル待ち・知らせは自前のときだけ
- (decision) 申込みには LINE ログインが必須（ユーザーを得るため）。交流会のページはログインなしで見られる
- (decision) 合計の定員と媒体ごとの枠（任意）。外部媒体の申込みも名簿に入れて数える。満員で自前のページをキャンセル待ちにし、止める媒体のリストを出す
- (decision) 繰り上げは自動確定にせず期限つきの打診。期限は打診から24時間、夜中に切れるなら翌朝9時まで
- (decision) 外部の申込者は手で貼るか CSV。次に段階1（スクショを外の AI に読ませて貼り戻す）。MCP の書き込みは AD-20 に触れるので今はやらない
- (decision) 支払いは現金と PayPay を記録するだけ（Constitution I）。Stripe は作らない。申込みと支払いの状態を分ける
- (decision) 前日のリマインドは入れない。日時の変更・中止の知らせは入れる
- (decision) カレンダー：確定した人に Google カレンダーのリンクと .ics。部の予定の購読 URL は次の候補。Google の API 連携は見送り
- (decision) SaaS として複数の組織・個人に出す。交流会は持ち主の account を持ち、組織に入れられる（AD-19）。主催者＝持ち主か組織の管理者・編集者。メンバー＝部員（見る・予約・部員だけの回）。受付係は交流会ごとの招待のまま
- (decision) LINE 公式アカウントは各組織・個人が設定する。プロバイダーごとにユーザー ID が違うので友だち追加とログインで紐づける
- (decision) メールは kanaeru 共通の送り主（名前に組織名・返信先は組織）。kanaeru のドメインを取る
- (decision) メールアドレスを持つため Constitution II を改訂する（予約の知らせのためだけ・任意・消せる・ログに出さない）
- (decision) ステージングは作らない。守り：申込みは交流会ごとに既定で切・知らせ全体の切り替え・送り先の許可リスト・手元とテストは偽の送り手
- (decision) 試合表は別アプリ（uses reception）として予約の最初の版のあとに別の PRD
- (decision) PRD のあとモックアップを作ってから実装する
- (decision) LINE を使えない人への対策を入れる（ユーザーの要望・Constitution III）
- (assumption) 【仮決め】対策は2段：主催者・受付係が名簿に手で足す（必ず）と、メールで申し込む（確認のメールのリンクで確定・取り消しと繰り上げの返事もメールのリンク。控えめに出す）
