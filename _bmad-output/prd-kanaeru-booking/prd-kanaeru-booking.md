# PRD：受付アプリの予約（申込み・名簿・キャンセル待ち・知らせ）と、交流会の持ち主

作成：2026-11-20（主催者との壁打ちで決めたことをもとに、AI が書いた叩き台。決めたことの記録は [.memlog.md](./.memlog.md)）。2026-11-20 主催者が叩き台とモックアップを見て、よいとした（【仮決め】はこの形で作り、使ってから見直す）。同じ日に、構成の決めごと（AD-23・AD-24）と Constitution 1.2.0 に合わせて直した（FR-B62・6章・11章）。

## 0. この文書について

[Constitution](../../.specify/memory/constitution.md) IV（範囲を変えるときは先に PRD を直す）に従い、受付アプリ（`reception`。領域は event・reception・survey）に**予約**を足す範囲を決める。あわせて、受付アプリを**複数の組織・個人に出せる形**（交流会の持ち主）に変える。

- 受付アプリの今の範囲の正本は [受付アプリの PRD](../prd-kanaeru-reception/prd-kanaeru-reception.md)。この PRD は、そこに足すものと、変えるもの（主催者の決め方）を書く。
- 組織そのもの（人・役割・招待）は [PRD 組織](../prd-kanaeru-org/prd-kanaeru-org.md) のまま使い、変えない。
- この PRD のあと、**モックアップ（画面の見本）を作って確かめてから**、構成の決めごとの改訂（6章）と機能ごとの仕様（spec-kit）に進む。モックアップ（13画面。参加者8・主催者4・受付係1）：https://claude.ai/artifact/C6CFPodPrEC6f6vm28ifHT
- 読む人は、主催者と、このあと仕様を作る人と AI。

参考にするもの（読むだけ）：めぐる（`meguru-app`）の `specs/collect/`（名簿・まとめて貼る・名簿なしの受付・本人の申告と確かめ）・`specs/people/001-people-memo`（Google フォームの CSV の取り込み・同じ人の候補・案内の同意）・`specs/people/003-threads-event-candidates`（Threads の宣伝から交流会を作る）。

## 1. ねらい

- 小さな部やコミュニティの運営が、**どこから来た申込みも1つの名簿にまとめ**、当日の受付で「来た・来なかった」まで分かるようにする。集客の主な入口は Threads と外部のイベント掲載サイトのままでよい。自前の申込みページは、その入口の1つになる。
- 定員のある回（例：コートの数が決まっている練習）で、**キャンセル待ちと期限つきの繰り上げ**を、運営が手で連絡しなくても回るようにする。
- 申込みを LINE ログインで受け、**参加者が kanaeru のアカウントを持つきっかけ**にする。参加の履歴は、組織ごとに一人ずつ残る。
- すでに Google フォームなどで募集している人は、**予約を使わず受付だけ**、または**名簿だけ**を使える。予約はオプションにする。
- 1つの組織に複数の運営がいて、kanaeru を複数の組織・個人に提供できる形にする（SaaS として売る前提）。

## 2. 使う人

### 2.1 片づけたい用事

- **主催者**（組織の運営。例：IT・AI の部やバドミントンの部の運営メンバー）：練習日・勉強会を作り、申込みを集め、定員を守り、当日は名簿で受付したい。外部の掲載サイトの申込みも同じ名簿で見たい。運営は複数人で分担したい。
- **部員**（組織のメンバー）：部の練習日を確かめて、予約したい。部員だけの回にも申し込みたい。
- **外の参加者**（組織に入っていない人）：Threads や掲載サイトで見つけた回に、手軽に申し込みたい。行けなくなったら、すぐ取り消したい。
- **LINE を使わない参加者**：LINE がなくても申し込みたい。
- **受付係**（交流会ごとに招待された人。組織に入っていない助っ人もいる）：当日、名簿を見ながら受付したい。

### 2.2 この版で相手にしない人

- 参加費をオンラインで払いたい人（Constitution I。記録だけ）。
- 試合表を作りたい人（別のアプリとして、別の PRD で作る。4.8）。
- 自分のドメインからメールを送りたい組織（4.6）。

### 2.3 使う場面

- **UJ-1（名簿だけを使う）**：高橋さんは Google フォームで勉強会の申込みを集めている。kanaeru で交流会を作り、使い方を「名簿を使う」にする。フォームの回答の CSV を取り込み、名簿ができる。当日、LINE でチェックインした人は名簿に自動で当たり、受付の終わりに「来なかった人」が3人と分かる。
- **UJ-2（外の人が自前のページで申し込む）**：中村さんは Threads の投稿から、バドミントンの部の練習日のページを開く。ログインせずに日時・場所・残りの席を見て、「申し込む」で LINE ログインする。「次の練習の案内を受け取る」にチェックを入れて申し込むと、申込み完了の画面に「Google カレンダーに追加」と「部の公式 LINE を友だち追加して知らせを受け取る」が出る。
- **UJ-3（満員とキャンセル待ち）**：練習日の定員は16人。自前のページで12人、Peatix で4人が申し込んで満員になる。自前のページは自動で「キャンセル待ち」に切り替わり、主催者の画面に「受付を止める媒体：Peatix」が出る。森さん（部員）がキャンセル待ちに入る。
- **UJ-4（期限つきの繰り上げ）**：Peatix の1人が取り消し、高橋さんが名簿でその人を「取り消し」にする。森さんに部の公式 LINE で「繰り上がりました。明日の12時までに参加するか答えてください」が届く。森さんが「参加する」を押すと、申込みが確定する。森さんが答えないまま期限が過ぎると、次の人に打診が回る。
- **UJ-5（LINE を使わない人）**：小林さんは LINE を使っていない。申込みページの「LINE を使わずに申し込む」から、名前とメールアドレスを入れる。届いたメールのリンクを押すと申込みが確定する。当日は、受付係が手でチェックインし、名簿の小林さんに当てる。
- **UJ-6（運営を分担する）**：高橋さんは交流会を組織「バドミントンの部」に入れる。組織の編集者の森さんも、名簿の取り込みと日時の変更ができる。日時を変えると、申し込んだ全員に「日時が変わりました」が届く。当日は、組織に入っていない助っ人の石井さんが、受付係の招待のリンクで受付をする。

## 3. ことば

| ことば | 意味 |
|---|---|
| 交流会 | 受付アプリで作る1回の会（練習日・勉強会も含む）。今の受付アプリと同じことば |
| 持ち主 | 交流会を作った kanaeru のアカウント。いつも1人。組織に入れても変わらない（AD-19） |
| 組織に入れる | 持ち主が、交流会を1つの組織の中に置くこと。その組織の管理者・編集者も主催者になる |
| 主催者 | その交流会を管理できる人。持ち主と、交流会を入れた組織の管理者・編集者 |
| 部員 | 交流会を入れた組織のメンバー（管理者・編集者でない人） |
| 受付係 | 交流会ごとの招待のリンクで入った人。組織と関係ない。今の受付アプリと同じ |
| 運営者 | kanaeru 全体の運営（アプリの台帳を変える人。設定 `ORGANIZER_LINE_USER_ID`）。この PRD で主催者の役目から外す |
| 使い方 | 交流会ごとの設定。**受付だけ**（既定）・**名簿を使う**・**自前で申込みを受ける**の3つ |
| 申込み | 名簿の1行。1人の参加の申し込み。入口（自前のページ・手で足す・取り込み）と媒体と状態を持つ |
| 名簿 | 1つの交流会の申込みの一覧 |
| 媒体 | 申込みがどこから来たか（自前のページ・Peatix・こくちーず・Google フォーム・そのほか）。今の受付の「申し込みの媒体」と同じ選択肢を使う |
| 自前のページ | kanaeru の申込みページ。使い方が「自前で申込みを受ける」のときだけ開く |
| 定員 | 交流会の席の合計 |
| 媒体の枠 | 定員のうち、外部の媒体に回す席の数（任意） |
| 埋まった席 | 確定の申込みと、打診中の申込みの数 |
| キャンセル待ち | 満員のときに自前のページで申し込んだ人の並び（申し込んだ順） |
| 打診 | 席が空いたとき、キャンセル待ちの先頭の人に「参加するか」を聞くこと。返事の期限を持つ |
| 状態 | 申込みの状態：**確定**・**キャンセル待ち**・**打診中**・**取り消し** |
| 来なかった | 交流会の日が終わっても、チェックインに当たらなかった確定の申込み |
| 部員だけの回 | 部員と主催者にだけ見える交流会。外の人のページには出ない |
| 公式アカウントの設定 | 組織（または個人の持ち主）が自分で入れる、LINE 公式アカウントの Messaging API の値 |
| 紐づけ | 参加者の kanaeru のアカウントと、ある公式アカウントの友だちを結びつけること |
| 知らせ | kanaeru が参加者に送る LINE かメール |
| 案内の同意 | 参加者が「次の会の案内を受け取る」に同意したこと。組織（個人の持ち主なら、その人）ごとに持つ |

## 4. 機能

### 4.1 交流会の持ち主と組織

- **FR-B1**：交流会は、作った人のアカウントを持ち主として持つ。ログインした人は誰でも交流会を作れる（運営者でなくてよい）。売り始めたら、作るときに契約を確かめる（AD-16・AD-22）。
- **FR-B2**：持ち主は、自分が入っている組織の1つに交流会を入れられ、外せる。入れると、その組織の管理者・編集者が主催者になり、メンバーが部員になる。
- **FR-B3**：主催者ができることは、今の受付アプリの主催者と同じ（交流会を作る・直す・割引・受付係の招待・アンケートの開閉・内訳・CSV・削除）に、この PRD の名簿・申込み・知らせの設定を足したもの。交流会を組織に入れる・外すのは持ち主だけ。
- **FR-B4**：受付係は今のまま（交流会ごとの招待のリンク。組織に入っていなくてよい）。受付係は、当日の受付に要る範囲で名簿を見て、手で足し、チェックインを当てられる（4.7）。
- **FR-B5**：持ち主が組織を抜ける・外されると、その人の交流会は組織から外れる。持ち主が退会すると、組織に入れていた交流会は組織の管理者に引き継ぐ（Threads と同じ決まり。PRD 組織 5.7）。組織に入れていない交流会は、今の受付アプリの退会の決まりのまま。
- **FR-B6**：交流会の一覧には、自分が主催者の交流会（持ち主のもの・組織のもの）と、受付係の交流会を出す。組織ごとに絞れる。
- **FR-B7**：運営者（`ORGANIZER_LINE_USER_ID`）は、ほかの人の交流会を管理できない。今の運営者の交流会は、運営者の個人の持ち物として移す（7章）。

### 4.2 使い方の切り替え

- **FR-B10**：主催者は、交流会ごとに使い方を **受付だけ**・**名簿を使う**・**自前で申込みを受ける** から選べる。既定は「受付だけ」で、今の受付アプリと同じに動く。
- **FR-B11**：「名簿を使う」では、申込みは外（Google フォーム・掲載サイトなど）で集め、名簿に入れる（4.3）。定員は人数の目安として見せるだけで、キャンセル待ちと知らせは使わない。
- **FR-B12**：「自前で申込みを受ける」では、名簿に加えて自前のページ・定員・キャンセル待ち・知らせを使う（4.4〜4.6）。
- **FR-B13**：使い方はあとから変えられる。名簿に行がある交流会を「受付だけ」に戻すときは確かめを出し、名簿は消さずに隠す【仮決め】。自前のページを閉じても、すでにある申込みは残る。
- **FR-B14**：チェックインは、どの使い方でも名簿がなくても動く（名簿への当てはなくてよい）。

### 4.3 名簿

- **FR-B20**：主催者と受付係は、名簿に1人ずつ手で足せる（名前・媒体・メモ。電話や口頭での申込み、受付忘れ、LINE を使わない人のため。Constitution III）。満員のときは、定員を超えて足すか、キャンセル待ちに入れるかを選ぶ（自前で申込みを受けるときだけ）。
- **FR-B21**：主催者は、名前の一覧をまとめて貼って名簿に入れられる（1行に1人。媒体を選んで入れる）。めぐるの「まとめて貼る」と同じ形。
- **FR-B22**：主催者は、CSV（Google フォームの回答・掲載サイトの参加者の一覧）を取り込める。名前の列と媒体を選び、取り込む前に入る行を見せる。列の対応は持ち主ごとに覚える【仮決め】。同じ CSV をもう一度取り込んでも、同じ行は増えない。
- **FR-B23**：名簿の行は、名前・媒体・入口（自前のページ・手で足す・取り込み）・状態・申し込んだ日時・来たか（チェックインに当たったか）を持つ。主催者は状態を「取り消し」にでき、戻せる。
- **FR-B24**：同じ名前（今の `normalizeCheckinName` でそろえたもの）の行が2つ以上あるとき、印を付ける。勝手にまとめない。主催者がまとめられる【仮決め】。
- **FR-B25**：名簿は、状態・媒体・来たかで絞れ、媒体ごと・状態ごとの人数を出す。CSV で書き出せる（主催者だけ。今の書き出しと同じ守り）。
- **FR-B26**：主催者には、参加者のメールアドレスを見せない（知らせを送るのは kanaeru。5.1）【仮決め】。

### 4.4 自前の申込みページ

- **FR-B40**：使い方が「自前で申込みを受ける」で、受付中の交流会は、申込みページを持つ。ページは**ログインなしで見られ**、名前・日時・会場・参加費・残りの席（またはキャンセル待ちの人数）・主催する組織の名前を出す。道は参加者が外から開く道の1か所に置く（AD-14）。道の形は `/e/{eventId}`【仮決め】。
- **FR-B41**：「申し込む」を押すと LINE ログインを求め、ログインしたら名前（初めは LINE の表示名）を確かめて申し込む。1つの交流会に1人1つの申込み。文字を打たずに終われる（Constitution III）。
- **FR-B42**：申し込むときに「（組織の名前）から次の会の案内を受け取る」を選べる（初めは外す【仮決め】）。同意は組織ごと（個人の持ち主の交流会なら、その人ごと）に持ち、いつでも外せる。
- **FR-B43**：申込み完了の画面には、状態（確定・キャンセル待ちの何番目か）と、確定なら「カレンダーに追加」（Google カレンダーのリンクと `.ics`）、公式アカウントの設定がある組織なら「公式 LINE を友だち追加して知らせを受け取る」を出す。
- **FR-B44**：参加者は、自分の申込み（今後の回・状態）を一覧で見て、ワンタップで取り消せる。取り消せるのは交流会の始まりまで【仮決め】。
- **FR-B45**：部員だけの回は、部員と主催者だけが見られ、申し込める。ほかの人には「この会は見られません」を出す。
- **FR-B46**：申込みページに、控えめに「LINE を使わずに申し込む」を出す【仮決め】。名前とメールアドレスを入れると確認のメールが届き、リンクを押すと申し込みになる（リンクの期限は24時間【仮決め】）。この人は kanaeru のアカウントを持たない。取り消しと打診への返事は、メールのリンク（本人だけが知る札）から行う。
- **FR-B47**：受付を止める：主催者は、自前のページをいつでも閉じられる。開催の始まりを過ぎると、自動で閉じる。

### 4.5 定員・媒体の枠・キャンセル待ち・繰り上げ

（使い方が「自前で申込みを受ける」のときだけ）

- **FR-B60**：主催者は、定員と、媒体ごとの枠（任意。例：Peatix 4・こくちーず 2）を決められる。
- **FR-B61**：埋まった席は、すべての入口の確定の申込みと、打診中の申込みの数。自前のページの残りの席は「定員 − 埋まった席 − 媒体の枠のうちまだ埋まっていない席」。
- **FR-B62**：残りの席が0になると、自前のページはキャンセル待ちの受付に切り替わる。主催者の画面に「満員です」と、受付を止める媒体（媒体の枠を決めた媒体と、名簿に申込みがある外部の媒体）を出す。媒体の枠には、媒体の管理ページの URL を任意で入れられ、あればリンクを出す【仮決め】（Threads アプリの掲載の記録は読まない。アプリをまたがないため）。
- **FR-B63**：取り込みや手で足したことで定員を超えたら、主催者の画面に「何人超えています」を出す。超えた分を勝手に取り消さない。
- **FR-B64**：席が空くと（取り消し・期限切れ・主催者が定員を増やした）、キャンセル待ちの先頭の人に打診する。打診中の人は席を押さえる。
- **FR-B65**：返事の期限は、打診から24時間。期限が夜中（0時〜9時）に切れるなら、その朝の9時まで（DB が夜は止まるため。AD-10）。期限が交流会の始まりの2時間前より後になるなら、始まりの2時間前にする【仮決め】。
- **FR-B66**：打診を受けた人は、「参加する」「辞退する」で答える。参加するなら確定、辞退するか期限が過ぎたら取り消しにして、次の人に打診する。
- **FR-B67**：始まりまでの時間が短くて打診の期限が1時間を取れないときは、打診をやめ、自前のページに「当日の空き」として残りの席を出し、先着で確定する【仮決め】。キャンセル待ちの人には「当日の空きが出ました」を知らせる。
- **FR-B68**：主催者は、キャンセル待ちの並びを見て、手で打診・確定・取り消しにできる。

### 4.6 知らせ

- **FR-B80**：参加者に送る知らせは、次の6つ：申込みの確定・キャンセル待ちに入った・打診（期限つき）・打診の期限が過ぎた・日時や場所の変更・中止。前日のリマインドは送らない。
- **FR-B81**：送り先は、その組織（個人の持ち主）の公式アカウントと紐づけている人には LINE、紐づけていない人にはメールアドレスがあればメール、どちらもなければ送らない（画面で確かめてもらう）。
- **FR-B82**：持ち主（組織に入れていれば組織の管理者）は、公式アカウントの設定（Messaging API のチャネルの値）を入れられる。値は暗号化して持ち、画面に戻さず、ログに出さない。kanaeru は各組織の公式アカウントから送るので、メッセージの費用は各組織の LINE の契約で払う。
- **FR-B83**：紐づけ：公式アカウントを友だち追加した人に、公式アカウントがリンク付きのあいさつを送る。リンクを開いて kanaeru に LINE ログインすると、その人のアカウントと公式アカウントの友だちが紐づく（LINE のユーザー ID はプロバイダーごとに違うため）。ブロックされたら紐づけを止める。
- **FR-B84**：LINE で申し込んだ人も、任意でメールアドレスを入れられる（公式アカウントを友だち追加しない人のため）。いつでも消せる。
- **FR-B85**：メールは kanaeru 共通の送り主から送る。送り主の名前に組織の名前を入れ、返信先は組織（持ち主）が入れたアドレス（任意）にする。kanaeru のドメインを取って使う。
- **FR-B86**：知らせには、交流会の名前・日時・場所・自分の状態と、取り消し・返事のリンクを入れる。確定の知らせには「カレンダーに追加」を入れる。
- **FR-B87**：送った知らせは、相手・種類・送った時刻・結果だけを記録する（本文の中身とメールアドレスはログに出さない）。主催者は、申込みごとに「何を送ったか」を見られる。
- **FR-B88（ステージングなしの守り）**：知らせ全体を設定で止められ、本番は止めたまま出す。確かめの間は、設定の**送り先の許可リスト**（LINE のユーザー ID とメールアドレス）にだけ送る。手元とテストでは、本物に送らずログに出す偽の送り手を使う。

### 4.7 受付とのつながり

- **FR-B100**：LINE でのチェックインは、その人のアカウントの申込みがあれば自動で当たる。なければ、名前がそろう申込みが1つだけなら当てる候補として受付の画面に出し、受付係が確かめて当てる【仮決め】。参加者の画面に、ほかの人の名前を出さない。
- **FR-B101**：手でのチェックインでは、名簿から人を選ぶ（名前で探す）か、「飛び入り」で名簿に足してチェックインする。
- **FR-B102**：交流会の日が終わったら、当たらなかった確定の申込みを「来なかった」として名簿と内訳に出す。
- **FR-B103**：受付アプリは、ほかのアプリ（例：試合表）が使えるよう、`index.ts` から「その交流会のチェックインした人（名前・チェックインの ID）」と「この人はチェックインしたか」を出す（AD-3・AD-15）。

### 4.8 あとで足すもののための差し込み口（この版では作らない）

- **支払いの状態**：申込みと支払いを別に持つ。支払いの状態（まだ・確かめ待ち・受け取った）は、めぐるの「本人の申告と確かめ」を移すときに足す。オンラインの決済は作らない（Constitution I）。
- **スクショの読み取り（AI の段階1）**：掲載サイトの申込み一覧のスクショから名前を読み取るプロンプトを出し、答えを貼り戻して名簿に入れる（AD-20）。
- **部の予定の購読 URL**：組織の公開の交流会を、カレンダーの購読 URL（iCal）で出す。
- **Threads の宣伝から交流会を作る**：めぐるの people-003 と同じ。
- **試合表**：別のアプリ（`uses: ["reception"]`）として、別の PRD で作る。FR-B103 を使う。

## 5. 守ること（非機能・Constitution との関係）

### 5.1 個人の情報（Constitution II）

- **Constitution II の改訂が先に要る**：今は「メールアドレスや電話番号は持たない」。これを「予約の知らせのためだけに、本人が入れたメールアドレスを持てる（任意・本人がいつでも消せる・ほかの用途に使わない・ログに出さない）」に直す（2026-11-20 主催者が決めた。`/speckit-constitution` で改訂する）。
- 名簿・申込み・参加の履歴・案内の同意は、組織（個人の持ち主）ごとに閉じる。ほかの組織の交流会と名簿には届かないことを、テストで確かめる。
- 外の AI に名簿を渡すツールは作らない（AD-20）。
- 公式アカウントの値・メールの確認の札・取り消しの札は、ハッシュか暗号文で持ち、ログに出さない。

### 5.2 お金（Constitution I）

参加費は支払い方法と金額を記録するだけ。予約のときに先払いを求めない。

### 5.3 気軽さ（Constitution III）

申込みは文字を打たずに終われる。LINE を使わない人も、手で足す・メールで申し込むで参加できる。当日の受付は今のまま止めない。

### 5.4 費用と DB（Constitution V・AD-10）

打診の期限切れと知らせは、DB が動いている時間（8時〜24時）の定時の処理で流す（今の Cloud Scheduler の仕組み）。メールの送信のサービスは無料枠のあるものを選ぶ。LINE のメッセージの費用は各組織が持つ。

### 5.5 権限

主催者・部員・受付係・参加者の判定は、event の領域の1つの関数で、要求のたびに行う（AD-5 を直す。6章）。組織の役割は suite の `index.ts` から引く。

## 6. 構成の決めごとに要る改訂（`/bmad-architecture`）

2026-11-20 に、[構成の決めごと](../architecture-kanaeru/architecture-kanaeru.md) の AD-23（交流会の持ち主・組織に入れる・booking の領域）・AD-24（知らせ）を足し、AD-1・AD-3・AD-5・AD-14・AD-19 を直した。Constitution は 1.2.0（II にメールアドレスの条件を足した）。下の表は、そのときの改訂の元。

| 決めごと | 直すこと |
|---|---|
| Constitution II | メールアドレスを持てる条件を足す（5.1） |
| AD-5（権限） | 主催者を「設定の1人」から「持ち主と、交流会を入れた組織の管理者・編集者」に。部員を足す。運営者は台帳だけ |

## 7. 今のデータの移し方

- 今ある交流会の使い方は「受付だけ」にする。チェックイン・割引・アンケートは変えない。
