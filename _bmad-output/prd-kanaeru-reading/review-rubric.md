# PRD Quality Review — 読書記録（prd-kanaeru-reading）

## Overall verdict
ねらい（散らばったマーカーを、読む習慣を変えずに「話す・書く・やってみる」材料に変える）がはっきりしており、構想から外したこと（LINE に一言）・作らないこと（要約・AI の目次）・仮決め・決めきれていないことが正直に書かれている。段階1の成功の基準と逆の目印も、ねらいを確かめる形になっている。危ういのは、作り始めるときに要る「終わりの形」のほう：中心の成果物である**説明の材料の形**、**取りこみ直しの扱い**、**GoodNotes の PDF をどの端末で・どの大きさまで読むか**が決まっておらず、さらに「段階」ということばが2つの意味で使われているため、段階1のストーリーを切るとき迷いが出る。

## Decision-readiness — adequate
決めごとは「持ち主が決めた」と【仮決め】で区別されている。捨てたものも理由つきで書かれている：0章「読み終えるたびに LINE に一言」を外した理由（見返す姿が浮かばない・アプリ間の移動が面倒）、1章で要約を作らない理由（汎用の AI に置きかえられる・著作権）、FR-R26 で LINE の公式アカウントの知らせをやめた代わりに「思い出すきっかけは、利用者のカレンダーに任せる」。10章の問いも本当に開いた問いで、確かめる時期（段階1の前・段階2の前…）まで付いている。反対する人の言い分が先に書かれている PRD と言える。

足りないのは2点。1つは、壁打ちで出た不都合（夜に読む習慣と夜の停止）が PRD では消えていること。もう1つは、お金の10の方法（4.10）が「すべて入れる」で並び、どれに賭けるのか・どの順で効くと見ているのかが書かれていないこと。段階2に進むかどうかは「自分で試してよかったら」（7.1）だけで、お金の仕組みが成り立つかを段階1でどう確かめるかがない。

### Findings
- **[medium]** 夜に読む習慣と夜の停止がぶつかることを書いていない（§2.3 UJ-2・§5「夜の停止」）— 壁打ち（.memlog）では「通勤中・昼休み・**寝る前**に読む」と決めているのに、2.3 のゆうきは通勤中と昼休みだけになっている。5章は「0時〜8時は DB が止まる…『夜間は止まっています』を出す」と書くだけ。寝る前（0時をまたぐ）に UJ-2「続きを読む前に、前回の内容をつかむ」や UJ-1 の取りこみをしようとすると、毎回止まる。*Fix:* UJ に寝る前の場面を戻し、「夜は使えない（受け入れる）」か「本の画面だけ端末に残して夜も読める」かを決めて書く。受け入れるなら、8章の逆の目印に「夜に開いて止まっていた回」を足す。
- **[medium]** お金の10の方法に、賭けどころと捨てたものがない（§4.10）— 表は段階で並んでいるが、どれが本命か（公開の本棚 #1・#7・#10 なのか、書き出し #2 なのか）、どれが効かなかったら何を諦めるのかがない。どれも「持ち主が決めた」なので、10個を同じ重さで作ることになりやすい。*Fix:* 4.10 の頭に「段階2で確かめる本命は #1・#10（公開の本棚が人を呼び、紹介料が出るか）。ほかは本命が効いたときに足す」のような一文と、本命が効かなかったときの扱いを書く。

## Substance over theater — strong
飾りがほとんどない。ペルソナは「ゆうき」1人で、その特徴（GoodNotes はテキストボックス・コメントの先頭に `?`・輪読会に出ている）が、そのまま FR-R6・FR-R10・UJ-3 を決めている。非機能も製品に固有の値と理由を持っている（5章「マーカー5,000件・ファイル20MB」、「0時〜8時」、著作権の引用の4要件を addendum 4章に結ぶ）。ねらい（1章）は Kindle と GoodNotes に散らばるマーカーという、この利用者だけの状況から書かれており、ほかの読書アプリの PRD に差し替えられない。

1つだけ、差別化の根拠に言い過ぎがある。

### Findings
- **[medium]** Readwise が「日本の Kindle に対応していない」の範囲が広すぎる（§1）— Readwise の公式文書で使えないとしているのは、amazon.co.jp の**自動の同期**（拡張機能）。Kindle のアプリのノートブックをメールで送る取りこみと `My Clippings.txt` の取りこみは別に用意されており、日本の本で使えるかは書かれていない。FR-R5 の主な入れ方（アプリのノートブックの書き出し）は、Readwise のこのメールの取りこみとほぼ同じ手順になる。差別化が「日本の Kindle を読める」だけなら弱い。*Fix:* 1章を「自動の同期は日本の Kindle で使えない（手で送る形は要確認）」に直し、差別化の主を「GoodNotes の PDF も1か所にまとめる」「話す・書く・やってみるの材料に変える」「日本語」に置く。addendum 1章の Readwise の行にも同じことを足す。

## Strategic coherence — adequate
段階1は筋が通っている。ねらい（c 話せる・書ける、b やってみる）→ UJ-3〜UJ-5 → FR-R20〜R29 → 8章の基準（「説明の材料を人に話すか輪読会で使った回が1回以上」「1つ以上を実際にやった」）と、まっすぐつながっている。逆の目印（「取りこみや整理に時間を取られて、読む時間が減っていないか」「本の文の切り貼りばかり」）も、ねらいの失敗の形を正しくとらえている。MVP の型は「困りごとを解く」で、範囲の考え方も合っている。

ただ、4.9〜4.12 のお金の筋は、段階1のねらいとは別の仮説（他人が中身のある感想を公開し、それで本が買われる）に乗っており、その仮説を確かめる手段が8章にない。また段階1は 4.1〜4.8 の30の FR を一度に入れ、GoodNotes の取りこみが駄目だったときの最小の形も決めていない。

### Findings
- **[medium]** 段階2の成功の目印が利用の数だけで、ねらいを確かめていない（§8「段階2のあと」）— 「公開の本棚を出した利用者の数」「自分の ID を設定した利用者の数」は活動の数で、公開のページから本が買われたか・始めた人が残ったかは見ていない。逆の目印もない（例：規約や著作権で止めたページの数、感想が短くて出せなかった回）。*Fix:* 「公開のページ経由で読書記録を始め、2回以上取りこんだ人の数」のような、入口（#10）が効いたかを見る数を足し、逆の目印に「止めたページの数」を置く。
- **[medium]** 段階1の中に、試すのに要るものと後でよいものの区別がない（§7.1 段階1）— 段階1は 4.1〜4.8 をすべて含み、目次の貼り付け（FR-R14）・CSV の書き出し（FR-R30）・自分の ID（FR-R29）まで入る。FR-R29 はお金の筋で、8章のどの基準にも効かない。GoodNotes の取りこみ（FR-R6）が駄目だった場合に、何を残して試すかも書かれていない。*Fix:* 段階1を「8章の基準を確かめるのに要るもの」（FR-R1〜R13・R20〜R25 など）と「同じ版で余裕があれば」に分ける。FR-R6 が駄目なら FR-R7 の貼り付けで試しを始める、と明記する。
- **[low]** 段階1の「よかった」の線が低く、期間も2か所で違う（§7.1・§8）— 「1回以上」「回がある」は4週間でほぼ必ず越える線で、よかったか・考え直すかを分けにくい。7.1 は「2〜4週間」、8章は「4週間」。*Fix:* 期間をそろえ、たとえば「読んでいる本の半分以上で説明の材料を作った」のように、使い続けたかが分かる線にする。

## Done-ness clarity — thin
多くの FR は確かめられる形になっている（FR-R9「取りこむ前に、読み取った件数・本・章を見せて」、FR-R22「既定で2週間後」、FR-R31「既定は出さない」、FR-R32 の出すもの・出さないものの一覧）。しかし、ストーリーを切るとき一番頼られる、段階1の中心の流れに穴がある。説明の材料とブログの下書きは「形を確かめ」て残すのに、その形が決まっていない。取りこみは繰り返すのが前提（8章「2回以上」）なのに、2回目以降の扱いが「重ならない」しか書かれていない。GoodNotes の PDF をどこで読むかと、大きさの上限が食い違っている。

### Findings
- **[high]** 説明の材料（とブログの下書き）の形が決まっておらず、「形を確かめ」られない（§4.6 FR-R20・§4.8 FR-R28・§3 説明の材料）— FR-R20 は「貼り戻した答えは形を確かめ、見せて確かめてから残す（AD-20）」と書くが、何を確かめるのか（項目・見出し・長さ・引用の印と出典の持ち方）がない。ことばの表も「自分の言葉が主の要点」だけ。これはねらい c の中心の成果物で、8章の基準も逆の目印（「本の文の切り貼りばかり」）もこれに乗っている。*Fix:* 説明の材料の形を決める（例：分かりたいことへの答え3〜5点・それぞれに自分の言葉の説明と、出典つきの引用0〜1個・話すときの問い1つ）。引用を本文と分けて持つなら、逆の目印「自分の言葉の割合」も数えられる。ブログの下書きも、少なくとも見出しの並びと出典の書き方を決める。
- **[high]** 取りこみ直しで、直したコメントや付け外した `?` をどう扱うかがない（§4.2 FR-R8・FR-R10）— FR-R8 は「位置と文で同じものと見る」「読む場所の側で消したマーカーは消さない」だけ。読む場所でコメントを書き直した・`?` を外した・マーカーの範囲を少し広げた、という場合に、上書きするのか・両方残すのか・読書記録の側で付けた `?` や「分かったこと」（FR-R19）を守るのかが決まっていない。UJ-1 は区切りごとに取りこむ流れなので、ほぼ毎回起きる。*Fix:* 「位置が同じでコメントが違えば、読む場所の側で上書きし、読書記録で付けたもの（`?` の付け外し・分かったこと）は残す」「範囲がずれたマーカーは別のものとして足す」のように、場合ごとの扱いを FR-R8 に書く。FR-R9 の確かめの画面に「新しい・変わった・同じ」の件数を出す。
- **[high]** GoodNotes の PDF をどの端末で読むか、大きさの上限がどれに効くかが決まっていない（§4.2 FR-R6・§5「取りこみの大きさ」）— FR-R6 は PDF を「端末の中で」読むとするが、端末（iPad の Safari か、PC か）が書かれていない。5章の「ファイル20MB まで」がサーバーに送る分なのか、端末で読む分なのかも分からない。書きこみのある技術書の PDF は、20MB を大きく越えることが多い。端末で読むなら上限の理由（端末のメモリー）が変わり、20MB だと主な用途で弾かれるおそれがある。10章の確かめ（PDF の中の形）とは別の、段階1を止めうる穴。*Fix:* 取りこみに使う端末を決め（例：iPad の Safari と PC のブラウザ）、10章の確かめに「持ち主の実際の技術書の PDF の大きさ」と「その端末で読み切れるか」を足す。上限は「端末で読む PDF」と「サーバーに送るマーカーの件数」に分けて書く。
- **[medium]** 取りこんだマーカーを、どの「本」に入れるかの決まりがない（§4.2 FR-R5〜R7・FR-R9）— Kindle の書き出しには書名があるが、GoodNotes の PDF はファイル名しかないことが多い。UJ-1「どのアプリで読んだ本も、1つの本棚に並ぶ」には、すでに登録した本に結びつける決まりが要る。*Fix:* 「取りこみは本の画面から始め、その本に入れる」か「書名で候補を出し、確かめの画面（FR-R9）で選ぶ」かを決めて FR に書く。
- **[medium]** 「あとで調べる」の印 `?` が全角の「？」を拾うか決まっていない（§2.3・§3「`?` の印」・FR-R10）— 日本語の入力では、先頭の「？」は全角になりやすい。半角だけを拾うと、持ち主の印の多くが落ちる。*Fix:* FR-R10 に「先頭の `?` と `？`（前の空白は無視）を拾う」と書く。
- **[low]** 数と照らし方が決まっていない所がある（FR-R24・FR-R15・FR-R30）— FR-R24「大事なマーカーとコメントを**いくつか**」の数がない。FR-R15「言葉で探せる」は、日本語の部分一致か、かなと漢字の揺れをどう扱うかがない。FR-R30 の CSV は列がない。*Fix:* FR-R24 に既定の数（例：5つ）を【仮決め】で入れ、FR-R15 は「部分一致（大文字小文字・全角半角をそろえる）」と書き、CSV の列は FR-R27 の項目に合わせると書く。

## Scope honesty — strong
省いたものがはっきり書かれている：2.2（紙の本の人・要約だけ読みたい人・読書の SNS）、7.2 の作らないもの、FR-R16（意味で探すのは作らない）。【仮決め】は16か所すべてが9章に集められ、10章は確かめる段階ごとに並んでいる。下書きの段階で、持ち主1人の試しの前という重さを考えると、残っている項目の多さ（仮決め16＋問い9）は妥当で、段階1を止めるのは GoodNotes の確かめ1つだけ、と絞れているのもよい。

黙って省かれているものが2つある。

### Findings
- **[medium]** マーカーを直す・消す・手で足す FR がないのに、5章では「消せる」と約束している（§5「データの安心」・§4.2〜4.3）— 5章「本・マーカーは、本人がいつでも消せる」に対応する FR がない。取りこみの読み違い（GoodNotes の読み取りの崩れ）を直す手段も、取りこめない1つを手で足す手段もない。*Fix:* 4.3 に「マーカーとコメントを直す・消す・手で足す」の FR を足すか、段階1では作らない（取りこみ直しで直す）と【仮決め】で書く。
- **[low]** 段階2以降の細かさと、段階1の重さの差（§4.9〜4.12）— 段階4の FR-R45〜R47 まで書いているのは、壁打ちで決めた「公開まで見越す」重さどおりで問題ない。ただ FR-R45「予約の領域の `index.ts` を通して」のような作り方の話は、段階4の前に変わる見込みが高い。*Fix:* 段階3・4の FR の頭に「段階2が終わったら見直す」と一言書いておく。

## Downstream usability — adequate
ことばの表（3章）があり、FR・UJ の番号は続いていて重なりもない（FR-R1〜R47、UJ-0〜UJ-7）。FR から AD-10・AD-15〜AD-22・core-016 への参照は、どれも docs/architecture.md と specs にあり、たどれる。UJ にはどれも主人公（ゆうき）がいる。

いちばんの問題は「段階」が2つの意味で使われていること。あわせて、構成で決める必要があるのに挙げられていないもの（カレンダーのリンクから開くときのログイン）がある。

### Findings
- **[high]** 「段階」が、作る順と AI の使い方の2つの意味で使われている（§0「印」・§3「段階1・段階2」・FR-R16・§7.2）— 0章は【段階N】を「7.1 の作る順の段階」とし、3章は「段階1・段階2」を AI の使い方（AD-20）としている。FR-R16「段階2（自分の API キー）で考える」、7.2「意味で探す（段階2の自分の API キーで考える）」は、作る順の段階2（公開の本棚）と読める。FR-R20・R28「AI の段階1」も同じ。ストーリーを切るセッションが、意味で探すのを段階2の版に入れてしまうおそれがある。*Fix:* AI の方を「AI の貼り付けの形」「AI の自分のキーの形」のような別のことばに替える（AD-20 のことばに合わせる）か、作る順を「版1〜版4」に替える。どちらかに決めて、全体を置きかえる。
- **[medium]** カレンダーの予定のリンクから開くときのログインが、構成の要るものに挙がっていない（§4.6 FR-R22・§4.7 FR-R24・§6）— 予定の説明に入れたリンクは、スマートフォンの Google カレンダーからふつうのブラウザで開かれることが多い。Constitution の技術の制約では利用者の画面は LIFF で、ふつうのブラウザでログインなしに開けるのは試合表の例外だけ。ログインし直しが要るなら UJ-4 の手間が増え、リンクに鍵を入れるならカレンダーに秘密が残る。*Fix:* 6章の「新しい決めごとの候補」に「カレンダーのリンクから開く道のログイン」を足し、`/bmad-architecture` で決めると書く。
- **[low]** ことばの表に入っていない大事なことばがある（§3）— 「持ち主」「利用者」「運営者」（FR-R35「持ち主（運営者）」。段階1では持ち主が利用者でもある）、段階2の中心の「感想」（コメント・説明の材料との違い）、「大事なマーカー」（UJ-4・FR-R24）、「あとで調べる」「分かったこと」（FR-R19）、「交流会」（FR-R45・R47）。*Fix:* 3章に足す。特に「感想」は FR-R32 の「短すぎると出せない」の対象なので、定義を置く。

## Shape fit — strong
持ち主1人が試す版から始め、ほかの人に配る・売る・チームへと広げる製品に合った形をしている。利用の流れを中心にしたのは正しく（壁打ちでも journey-led と決めている）、UJ-0〜UJ-6 はそれぞれアプリを開く場面1つに対応していて、多すぎない。公開の本棚・アフィリエイト・著作権のように、規約に縛られる所は、規約の条まで addendum.md に結ばれていて、守りの根拠をたどれる。下に UX と構成が続く文書としての細かさも足りている。

### Findings
- **[low]** UJ-7 で本を買う人が主人公になっていない（§2.3 UJ-7）— 公開の本棚で決め手になるのは、ログインなしで来て本を買い、自分も本棚を作る（FR-R38）見る人だが、UJ-7 はゆうきの側からしか書かれていない。*Fix:* 段階2の前に、見る人を主人公にした短い UJ を1つ足す（検索から来る・感想を読む・買う／自分も始める）。

- **仮決めの往復**：本文の【仮決め】（FR-R1・R4・R5・R6・R8・R12・R16・R18・R22・R24・R32〈2か所〉・R45・R46・5章・6章・8章）は、すべて9章に入っている。9章の16項目も、すべて本文にある。

- **期間のずれ**：7.1「2〜4週間」と 8章「4週間」。
- **参照先**：もとにしたものへのリンク（.memlog.md・forge-kanaeru-reading.md・b3-reading.md・addendum.md）はどれもある。「調べもの 3章」「4章」も、b3-reading.md の見出しと合う。
