## 2. くわしく

### 2.1 課金の線引き（#1）

- **調べもの**：レビューの不満「ブクログはフォルダ・並び替えがプレミアム限定（課金 10 件・整理 7 件）。Readee の移住者が『課金しないと使えない』と離れた」。答えは「基本の記録は無料」。
- **共通の部分 4-2**：「無料の範囲は基本の記録。有料は AI 機能・**共有・書き出し**・通知の回数」。
- **PRD**：FR-R30 で「すべての書き出しはデータが消えない安心のため」とし、FR-R41 で線引きを段階3に回した。AI は段階1・2とも kanaeru の費用がないので、共通の部分の「有料は AI 機能」も当てはまりにくい。
- **食い違い**：共通の部分どおりに書き出しを有料にすると、データの安心（FR-R30）とぶつかり、レビューの不満をそのまま再現する。
- **直す案**
  - FR-R41 に足す：「線引きを決める前に、**無料に残すもの**を先に決めておく：本の登録・取りこみ・本の画面・探す・あとで調べる・すべての書き出し（FR-R30）・消す・退会。有料にするのは、それ以外の上乗せ（例：公開の本棚の飾り・組織の本棚・段階2の自動の AI の回数など）から選ぶ」【仮決め】。
  - 5章「データの安心」に足す：「書き出しは、有料にしても無料に残す」。
  - 共通の部分 4-2 の「書き出し」は、読書記録では当てはめないと 10章の段階3に書く（スイートの共通の PRD で線引きを決めるとき、食い違いが分かるように）。

### 2.2 ステマ規制と景品の確かめの時期（#2）

- **調べもの・共通の部分 5-7**：ステマ規制（2023-10）・紹介キャンペーンの景品（総付景品：取引額 1,000 円未満なら 200 円まで、1,000 円以上なら 10 分の 2 まで）。addendum 3章：運営が見返りを付けて感想の中身に関わると、運営の表示とみなされるおそれ。
- **PRD**：10章で、ステマ規制の当てはめを「段階4の前」（FR-R47 と組織の本棚）だけに置いている。
- **抜け**
  - **FR-R37（段階2）**：利用者の感想のページに、**持ち主の ID** のリンクを置き、持ち主が紹介料を得る。持ち主が得をするページの上に利用者の感想が載るので、addendum 3章の「運営の表示とみなされるおそれ」に最も近い。Amazon の開示の文（FR-R37 にある）は Amazon の規約の要件で、景品表示法の「広告と分かる表示」に足りるかは別に確かめる。
  - **FR-R42（段階3）**：紹介の特典（スイートの無料の月）は景品規制（総付景品の上限）の当てはめが要る。さらに「紹介した人が感想を書く・公開の本棚を出す」と結びつくと、ステマの論点にもなる。
- **直す案**
  - 10章「段階2の前に確かめる」に足す：「FR-R37 の持ち主の ID のページで、景品表示法のステマ規制に当たらないか。当たりうるなら、リンクの近くに『広告』『PR』の表示を足す」。
  - 10章「段階3で決める」に足す：「紹介の特典（FR-R42）の景品規制（総付景品の上限）と、特典を感想・公開と結びつけないこと」。
  - FR-R37 に足す：「リンクの近くに『広告』の印を出す（開示の文に加えて）」【仮決め】。

### 2.3 利用規約・プライバシーポリシーと外国の AI（#3）

- **共通の部分 5-5**：外国の AI の API に送るのは「外国にある第三者」への提供（個人情報保護法 28条）の論点。プライバシーポリシーに、利用目的・第三者への提供・外国の AI の会社・消し方を書く（専門家確認）。要配慮個人情報が入らないよう注意書き。
- **今のコード**：`legal-content.ts` の本文は Threads の節を持ち、「本サービスは…外の AI に何も送りません」と書く。読書記録の節はない。
- **PRD**：5章で「外の AI に渡すのは本人の記録だけ（AD-20）。段階1では外に何も送らない」とだけ書く。
- **抜け・食い違い**
  - **段階2（自分の API キー）**：AD-20 では、kanaeru のサーバー（`kernel/ai`）が利用者のキーで外の AI の会社に送る。費用は利用者でも、送るのは kanaeru なので、28条の論点（本人の同意・外国の名前と制度の情報）と、プライバシーポリシーの「何も送りません」の書き直しが要る。FR-R16（意味で探す）を段階2で作るときも同じ。
  - **本人の記録にも他人の情報が入る**：コメント・分かったこと・やってみた結果に、同僚の名前や職場の事情が書かれうる。AD-20 の「本人の記録だけ」でも、中身に他人の情報が混ざる。Threads の節と同じ「ほかの人の個人の情報を AI に貼らないでください」の注意が要る。
  - **公開の本棚（段階2）**：利用者の投稿（感想）をだれでも見られる。投稿の責任・禁止事項・運営が止める決まり（FR-R35 の根拠）・投稿の表示の許し、を利用規約に足す必要がある。
  - **アフィリエイト（段階1〜2）**：持ち主が紹介料を得ること（FR-R37）、書き出しに利用者の ID を入れること（FR-R29）を、利用規約かプライバシーポリシーに書くか。今の本文は「広告…のクッキーは使いません」で、kanaeru が置くリンクそのものはクッキーを足さないが、書き方を確かめる。
  - **特定商取引法の表記・最終確認画面・解約の窓口**（共通の部分 5-1・5-2）：段階3の前提。PRD 6章は「契約はスイートの共通」とするが、7.1 の段階3と 10章に、この前提（表記・最終確認画面・Stripe の解約の窓口・夜の停止の料金ページへの明記）が書かれていない。
- **直す案**
  - 5章「個人の情報」に足す：「段階2の前に、プライバシーポリシーに、外国の AI の会社へ送ること・送る中身・同意のとり方を足す（専門家確認）。段階2を使い始める画面で、送る先の会社を見せて同意をとる」「コメントにほかの人の個人の情報を書かないよう、取りこみと AI の画面に注意を出す」。
  - 6章「共通の PR」に足す：「利用規約とプライバシーポリシー（`legal-content.ts`）に読書記録の節を足す。段階1で1回（取りこみ・持つもの・消し方・書き出しのアフィリエイト）、段階2の前に1回（公開の本棚の投稿・持ち主の ID・外国の AI）。suite の領域なので共通の PR に分ける」。
  - 7.1 段階3 に足す：「前提：スイートの共通で、特定商取引法の表記・最終確認画面・解約の窓口が済んでいること」。

### 2.4 Kindle の取りこみの規約（#4）

- **調べもの**：「Kindle 購入書籍のハイライト自動取り込みは、公式 API がなく規約リスクがある（要確認）。手動の貼り付けとスクショ OCR で代替する」。練った構想も「外へ出す公式の道が細い」として線の取りこみを後に回していた。
- **PRD**：FR-R5 で、Kindle のアプリの公式の「書き出し」と、Web のノートブックのコピー＆貼り付けを主にし、「画面を自動で読む・ログインを預かることはしない」とした。7.2 でも自動の取りこみを作らない。**危うさの大部分は、この形で避けている**。
- **抜け**
  - なぜこの形なら規約の危うさを避けられるのか、の理由が PRD にない（調べものの「要確認」を閉じていない）。
  - Kindle の利用規約（Kindle のコンテンツは個人的・非商業的な利用の許し）の下で、書き出したマーカーの文を**第三者のサーバー（kanaeru）に持つ**こと、**公開の本棚・ブログに引用する**ことの扱いを確かめる項目が 10章にない。10章は「書き出しの形」と「出版社の上限の効き方」だけ。
  - Amazon が書き出しの機能・Web のノートブックの形を変えたり止めたりしたときの備え（FR-R7 の貼り付けに落ちる）が書かれていない。
- **直す案**
  - FR-R5 に足す：「書き出しの形が読めないときは、FR-R7 の貼り付けに切りかえる（GoodNotes の FR-R6 と同じ）」。
  - 10章「段階1の前に確かめる」に足す：「Kindle の利用規約で、利用者が自分で書き出したマーカーを外のサービスに入れて持つこと。持つのは利用者の引いた文だけで、本のファイルは持たない（5章 著作権）」。
  - 10章「段階2の前に確かめる」に足す：「Kindle から取りこんだ文を公開の本棚に引用すること（著作権の引用の要件のほかに、Kindle の利用規約に触れないか）」。
  - 5章「著作権」に一行：「Kindle は、利用者が公式の書き出しか画面のコピーで持ち出したものだけを受ける。自動で読む・ログインを預かる形は作らない（調べもの 4章の規約の危うさへの答え）」。

### 2.5 公開の本棚と夜の停止・費用（#5）

- **共通の部分 2-1・6章**：「夜0〜8時に DB を止める」は有料サービスとして説明しにくい。24時間動かす・バックアップ・監視まで含めて固定費は月 6,000 円くらい（シナリオB）。「DB を24時間動かす、または夜間に止まることを料金ページに明記する」。
- **PRD**：5章「夜の停止」は、アプリの画面とカレンダーの予定のリンクだけを扱う。
- **抜け**
  - 公開の本棚（段階2）は**ログインなし・検索に出す・Amazon に登録したサイト**。夜の8時間、`503` になると、(1) 検索のロボットに落ちたページと見られうる、(2) Amazon アソシエイトのサイトの審査や確かめで開けない、(3) ブログから来た人が買えず、利用者と持ち主の紹介料が減る。収入の仕組み（4.10）の中心のページなので、ほかの画面と同じ扱いでは足りない。
  - 段階3（売り始める）で、24時間動かすか・料金ページに夜の停止を書くかが、7.1 にも 10章にもない。
- **直す案**
  - 5章「夜の停止」に足す：「公開の本棚のページは、DB が止まっていても開けるようにする（例：公開を選んだときに、静的な形に書き出して CDN に置く。または `503` に `Retry-After` を付けて検索の扱いを守る）。どちらにするかは構成で決める」【仮決め】。
  - 6章「新しい決めごとの候補」の「公開の本棚の道」に、「夜の停止の間の出し方」を足す（`docs/decisions.md` の Cloudflare の CDN のキャッシュ〈誰が見ても同じ公開の API だけ〉と合わせて決める）。
  - 10章「段階3で決める」に足す：「DB を24時間動かすか、料金ページに夜の停止を書くか（共通の部分 2-1）」。

### 2.6 書誌の検索の弱さ（#6）

- **調べもの**：最も多い不満（読書メーター 15・ブクログ 11・ビブリア 3）。「タイトルや ISBN で探しても出ない・古い本・専門書・洋書がない・**同じ本が重複登録**」。答えは「書誌は公開の API で済ませ、ここでは勝負しない（利用条件は要確認）」。
- **PRD**：FR-R1 で API の候補と手で書く逃げ道を持つ。10章に「書誌の API の利用条件（書影・保存・商用）」がある。**勝負しない、は守れている**。
- **抜け**
  - **取りこみと本の結びつけ**：Kindle の書き出しには書名・著者はあるが ISBN はない。GoodNotes の PDF は書名さえないことがある。取りこんだマーカーを、どの「本」に入れるか（今の本に合わせる・書誌から探す・新しく作る）が 4.2 にない。FR-R9 の「本を見せて確かめる」だけでは、レビューの不満の「重複登録」をこのアプリでも起こしうる。
  - **重なった本をまとめる**手立てがない（手で書いた本と、あとで書誌で見つかった本など）。
  - **洋書**：技術書は英語の本も多い。FR-R1 は API を「どれか1つ」【仮決め】としているが、国内の出版物が中心の API だけでは洋書が出ない見込み（要確認）。
  - **API の条件の中身**：10章の確かめに、出典の表示（例：Google Books の表示の決まり）・キャッシュして持ってよいか・**アフィリエイトのある公開のページ（商用）で書影を出してよいか**・回数の上限、を具体に書いておくと、構成で迷わない。
- **直す案**
  - 4.2 に FR を足す：「取りこむとき、書き出しの書名・著者から、本棚の本を候補に出して選ぶ。なければ書誌の API で探す・手で書いて新しく作る。同じ書名の本がすでにあれば、新しく作る前に知らせる」。
  - 4.1 に FR を足す：「2冊の本を1冊にまとめられる（マーカー・コメント・分かりたいことを寄せる）」【仮決め】。
  - FR-R1 の【仮決め】を「国内の API と、洋書に強い API を順に引く」に直す案を 9章に。
  - 10章「書誌の API の利用条件」に、上の4点（出典の表示・持ってよいか・商用のページの書影・回数）を並べる。

### 2.7 調べものの判断との食い違いの理由（#7）

- **調べもの 1章・5章・8章、共通の部分 1-3・6章**：「早く作る。ただし交流会・LINE とつなげた形だけ。単独の有料アプリにはしない」「B3 は単独で作らず、交流会のデータか LINE での共有と組み合わせる形だけ」。AI に置きかえられる危うさは「高」。
- **PRD**：交流会とのつながり（FR-R45・FR-R47）は段階4。LINE はログインと段階2の送る（FR-R44）だけ。段階3でスイートの有料プランに入れる。練った構想で「最初の版は交流会とつなげない」と決めたので、**段階1を単独にするのは意図した判断**。
- **抜け**：PRD は「本の要約は作らない」（1章）を AI への答えにしているが、調べものの「単独にしない」との食い違いと、その理由（①たまっていく自分のデータ：散らばったマーカーを1か所に集める・日本の Kindle に非対応の Readwise の穴）を書いていない。段階3で売る前に、この判断を見直す目印もない。
- **直す案**
  - 1章の最後に一行：「調べものは『交流会・LINE とつなげた形だけ』を条件にしていた。この PRD は、散らばったマーカーを集める自分のデータ（共通の部分 1-2 の①）を先に試し、交流会とのつながりは段階4に回す（持ち主が決めた）」。
  - 10章「段階3で決める」に足す：「単独で有料の値打ちがあるか（段階2の目印〈8章〉で見る）。弱ければ、段階4の読みたい本リスト（交流会で紹介された本）を段階3より前に出す」。

### 2.8 AI 要約への反発と、頼む文のリンク（#8）

- **調べもの**：ブクログが利用者の感想を AI で要約するプレミアム機能を足し、「勝手に AI に食わせるな」「オフにさせて」の声。答えは「自分のメモだけを AI 要約」。
- **PRD**：説明の材料・ブログの下書きは本人のマーカーとコメントからで、段階1は利用者が自分で AI に貼る。**中身はすでに答えになっている**。
- **抜け**
  - 「AI は本人が押したときだけ動く。既定では使わない。kanaeru が利用者の記録・公開の感想を勝手に AI にかけない」を、守ることとして明言していない。段階2・MCP（AD-21）・組織の本棚（FR-R46）で、他人の説明の材料や感想を AI にかける機能を足すとき、この決まりがないと反発の形を再現しうる。
  - addendum 2章：Amazon アソシエイトは「生成 AI での使用」を禁止。FR-R28 のブログの下書きは AI の段階1で作り、FR-R29 で ID 付きのリンクを入れる。頼む文にリンクを入れると、利用者が AI にリンクを貼ることになる。
- **直す案**
  - 5章に一行：「AI は本人が押したときだけ使う。ほかの人の感想・説明の材料・公開のページを、kanaeru が AI にかける機能は作らない」。
  - FR-R28 に足す：「頼む文には、アソシエイトのリンクを入れない。リンクと開示の文は、貼り戻した答えに kanaeru が書き出しのときに足す」。

### 2.9 データの消失（#9）

- **調べもの**：ブクログ・Yomoo・ビブリアで「読書メモが消えた」。答えは「書き出しを標準にし、『消えない』を明言する」。Readee のサービス終了（2026-03）もある。
- **PRD**：FR-R30（すべての書き出し）・FR-R8（取りこみ直しで壊さない）・5章「データの安心」。**中心は答えている**。
- **抜け**：DB のバックアップ（構成では Cloud SQL の自動のバックアップ 7日分〈AD-9 の周り〉）を PRD が頼りにしていると書いていない。本・マーカーを消すときの確かめ（まとめて消す・取り消し）がない。サービスを止めるときに、予告して書き出しの期間をとる約束がない。
- **直す案**：5章「データの安心」に足す：「本を消すときは確かめを出す」「DB は毎日バックアップする（構成の決めごと）」「読書記録を止めるときは、前もって知らせ、書き出せる期間をとる」。
