# 突き合わせ：練った構想 → PRD（読書記録）

2026-11-27。[練った構想](../forge-kanaeru-reading/forge-kanaeru-reading.md)とその[記録](../forge-kanaeru-reading/.memlog.md)の決めたこと・捨てたこと・未決を、[PRD](./prd-kanaeru-reading.md)・[addendum.md](./addendum.md)と突き合わせた。PRD の[壁打ちの記録](./.memlog.md)で「change」として変えた3つ（LINE の一言をやめた・主な仕事を c と b に広げた・LINE は送るだけ）は、食い違いに数えない。0章で説明されているかだけ見た。

## 1. 意図した変更が0章で説明されているか

| 変更 | 0章 | 足すこと |
|---|---|---|
| LINE の一言をやめ、マーカーとコメントを入力にした | 書いてある | 構想で「後に回した」線の取りこみを段階1の中心に上げたことを1語足すとよい（構想を読んだ人が「捨てたはず」と迷わないため） |
| 主な仕事を b だけから c と b に広げた | 書いてある | なし（a を「c を支える手段」にしたことは 2.1 にある） |
| LINE はログインと送るだけ（届いた文を受けない） | **書いていない** | 下の「抜け 5」 |

## 2. 抜け・食い違い（大事な順）

### 抜け 1：「どこまで読んだか」を一番後ろのマーカーで決めるのは、部分的に読む前提と食い違う

- **構想**：主催者は2〜5冊を並行し、全部は読まず部分的に読む。だから届いた順・読んだ順は全体像にならず、**章が要**（記録 29〜30行）。
- **PRD**：FR-R12「どこまで読んだかを、いちばん後ろのマーカーの位置で示す」は、前から順に読む前提。部分的に読むと、飛ばした章があっても「そこまで読んだ」と見える。
- さらに FR-R11 は「GoodNotes はページで並べる」。PRD 自身が「技術書は GoodNotes が中心になりうる」（記録 27行）としているので、いちばん使う所で「章ごとの全体像」が落ちる。章が出るのは、目次を貼ったとき（FR-R14・任意）だけ。
- **直すこと**
  - FR-R12 を「マーカーのある章・ない章を示す。一番後ろの位置は目安として小さく出す」に直す。
  - FR-R11 に「GoodNotes の PDF にしおり（目次の情報）があれば、章の見出しで区切る。なければページで並べ、目次の貼り付け（FR-R14）をすすめる」を足す。PDF のしおりの有無は 10章の GoodNotes の確かめに足す。

### 抜け 2：「送り忘れても責めない」「10秒で済む」が FR になっていない

- **構想**：中心の行動は「10秒」。「送り忘れても責めない」（記録 19行）。叩かれても残った弱い所として「やめた人を誰も呼び戻さない（無課金と引きかえ）」を受け入れた。
- **PRD**：入力が一言から取りこみに変わったが、手間の上限も、責めない作りも、FR にない。8章の「取りこみが面倒で1回でやめた」「読む時間が減っていないか」は、あとで見る目印で、作るときの決まりではない。受け入れた弱点（やめた人を呼び戻さない）も書いていない。
- **直すこと**
  - 4.2 に FR を足す：「1回の取りこみは、ファイルを選ぶ（または貼る）→ 確かめる（FR-R9）→ 入れる、の3操作以内・1分以内で終わる。確かめの画面は、問題がなければ1回押すだけ」。数は【仮決め】でよい。
  - 4.1 か 4.7 に FR を足す：「取りこみの間が空いても、催促・連続の日数・『○日取りこんでいません』のような知らせを出さない。久しぶりに開いたときも、責める言い方をせず、すぐ取りこめる入口を出す」。FR-R25 の「まだ」にも「責めない言い方で、次の予定を入れ直す」を足す。
  - 10章（または5章）に、受け入れた弱点として「取りこみをやめた人を、こちらから呼び戻さない（無課金と引きかえ。カレンダーだけが呼び戻し）」を書く。

### 抜け 3：「やってみた？」のもう1つの道（相乗りで聞く）が落ちた

- **構想**：「やる」への返事にカレンダーのリンク。加えて、**次に一言が届いたときの返事でも聞く**（相乗り。記録 24行）。カレンダーに入れなかった・鳴っても開かなかった人の受け皿だった。
- **PRD**：きっかけはカレンダーの予定のリンクから開く「思い出す」の画面（FR-R24〜R26）だけ。「カレンダーに入れる」を押さなかったら、やってみたかを聞く場がない。8章の基準「やってみた（b）」が、カレンダー1本に頼る。
- **直すこと**：4.7 に FR を足す：「予定の日を過ぎた『やってみること』があると、次に取りこんだあと・その本の画面を開いたときに、『やってみた？（やった・まだ・やめた）』を1行で聞く。答えなくても先に進める」。LINE の返事の代わりに、利用者がすでに来る場面に相乗りさせる。

### 抜け 4：kanaeru が稼ぐリンクの前の確かめが、段階2の FR-R37 にかかっていない

- **構想**：kanaeru が稼ぐアフィリエイトは後で必ず作る。**作る前に**景品表示法のステマ規制と Amazon アソシエイトの規約を確かめる（構想「捨てたこと」・記録 38行）。
- **PRD**：段階の置き場（FR-R37 を段階2）は持ち主が決めたので食い違いではない。ただ 10章の「景品表示法のステマ規制の当てはめ」は**段階4の前**だけで、対象も FR-R47 と組織の本棚だけ。段階2の FR-R37（ID のない人の公開のページに持ち主の ID）も kanaeru が稼ぐ形で、しかも利用者の感想のページに持ち主のリンクを置く。addendum 3章の「運営が感想の中身に関わると運営の表示とみなされるおそれ」にいちばん近い（FR-R32 の「感想が短すぎると出せない」も中身への関わりになりうる）。
- **直すこと**：10章の「段階2の前に確かめる」に「景品表示法のステマ規制の当てはめ（FR-R37・FR-R32）」を足す。段階4の項は FR-R47・FR-R46 のまま残す。

### 抜け 5：0章に3つ目の変更がなく、構想の未決が解けたと書いていない

- **変更（記録 32行）**：LINE の役目はログインと「送る」だけ。届いた文を振り分ける共通の PR と、リッチメニューのモード切り替えは読書記録には要らない。6章の末尾と 7.2 には結果だけあるが、0章の「構想から大きく変えたこと」にない。構想では「人物メモ（B7）のセッションと同じ決まりにする」と約束していたので、外したことを0章で言わないと、B7 のセッションが「読書も乗る」前提で共通の PR を作るおそれがある。
- **構想の未決のうち、解けたもの**：「予約の公式アカウントは kanaeru のものと同じか（200通の枠を分け合うか）」と「2026年の LINE の料金」は、公式アカウントから送らず受けもしないので、読書記録では要らなくなった。PRD のどこにも出てこない。
- **直すこと**
  - 0章の「構想から大きく変えたこと」に1文足す：「LINE は、ログインと、利用者自身の LINE から送る（シェアの画面）ことだけに使う。公式アカウントで文を受けない・送らないので、構想で決めた『届いた文を振り分ける共通の PR』と『リッチメニューのモード』は読書記録には要らない（人物メモとそろえる約束は外した）」。
  - 10章の先に「構想の未決のうち、この変更で要らなくなったもの」として上の2つを書く（予約の公式アカウントの件は人物メモの PRD へ渡す、と添える）。
  - LINE でログインすることは FR にも 6章にもない。ほかのアプリと同じログインなら、6章に1行（「ログインはスイートの共通。読書記録で足すものはない」）。

## 3. 小さなもの（直すか持ち主に聞く）

- **取りこんだマーカーをどの本に入れるか**：構想は「本は1冊1回だけ登録」「当たれば0タップ（違う本のボタンで直す）」。PRD は FR-R1 で登録、FR-R5〜R7 で取りこむが、取りこんだマーカーを本にどう結びつけるか（Kindle の書き出しの書名で登録済みの本に当てる・なければその場で登録・GoodNotes の PDF は本を選ぶ）がない。FR-R9 に「読み取った書名から登録済みの本を当てて見せる。外れたら選び直す。なければその場で FR-R1 の登録に進む」を足す。
- **受付のチェックインのあとの案内**：構想は「よかったら、受付のチェックインのあとの案内（2）と、交流会で紹介された本を読みたい本リストへ（3）を検討」。PRD は（3）を FR-R47 に入れたが、（2）がない。段階4の 4.12 に入れるか、7.2 に「作らない」と書くか、持ち主に聞く。
- **夜の停止**：構想の割り切りは「主催者は0時すぎに読まない」が理由で、「ほかの利用者から声が出たら、DB の外にためて朝に移す案を考え直す」が条件だった。PRD は寝る前にも読む流れを書き、段階2でほかの人に配る。5章に、構想の条件と「取りこみの途中で0時を過ぎたら、読み取った結果を端末に残して朝に入れられるか」を、段階2の前に考えることとして足す。
- **カレンダーの2週間後**：構想では決めた値。PRD は FR-R22 で【仮決め】に戻した。カレンダーの役目を「やってみた？」から「思い出す」にも広げた（記録 15行）ので見直すのは筋が通るが、9章に理由（思い出す間隔として合うか確かめる）を書いておくとよい。
- **目次を貼る（FR-R14）**：構想は「後から足すオプション」。PRD では 4.3 に入り、7.1 の段階1（4.1〜4.8）に含まれる。段階1に入れるなら持ち主の確かめ、後に回すなら【段階2】の印を付ける。（抜け 1 で章の扱いを直すと、ここの重みも変わる。）
- **探す（4.4）が戻った**：構想は「検索・索引は主役でなくなる」（記録 13行）。PRD では「仕事で思い出したとき」の場面（記録 19行）のために全部の本をまたいで探す機能が段階1にある。主役ではなく補助として戻したことは筋が通るが、0章か 4.4 の頭に1行あると、構想との違いが分かる。
- **ことばの重なり**：「段階2」が、作る順（7.1）と AI の使い方（3章の段階1・段階2）の両方の意味で出てくる（FR-R16・7.2 の「段階2の自分の API キー」）。AI の方を「AI の段階2」と書き分ける。
- **数えないもの（参考）**：構想の Sally の「記号を打たせない」は LINE のモード切り替えの話。PRD の `?` の印は持ち主が決めたもの（記録 30行）で、すでに引いているコメントに1文字足すだけなので食い違いに数えない。

## 4. 落ちていたもの・揃っていたもの（確かめた範囲）

揃っていた：読む場所を替えさせない／撮って索引を作らない／本の要約と AI の目次を作らない／LINE から呼び戻さない／無課金と AI の費用0（AI を呼ばない＝段階1のコピー）／書き出しの中身と自分のアソシエイトの ID（FR-R27〜R29）／交流会と最初はつなげない（段階1）／読みたい本リストと kanaeru が稼ぐリンクを後で必ず作る（FR-R47）／書誌の API の条件（10章）／夜の停止の画面（5章）。
