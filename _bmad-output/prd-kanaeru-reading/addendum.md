# 補足：読書記録の PRD

PRD（[prd-kanaeru-reading.md](./prd-kanaeru-reading.md)）に入れない、細かい調べものを置く。決めた理由は [.memlog.md](./.memlog.md)、構想を練った場は [練った構想](../forge-kanaeru-reading/forge-kanaeru-reading.md)。この補足の「運営」は、PRD の「持ち主」（PaletKit を運営する人）のこと。

条文の略号：A＝Amazon アソシエイト・プログラムの運営規約（affiliate.amazon.co.jp/help/operating/agreement）、P＝プログラムポリシー（/help/operating/policies。「P 参加要件N条」はその中の参加要件の条）、H＝審査のヘルプ（/help/node/topic/G8TW5AE9XL2VX9VM）。どれも 2026-04-20 の改定のあとの版。条の番号は 2026-11-27 の調べもので読んだ範囲なので、作る前に原文で確かめる。

## 1. 競合の稼ぎ方（2026-11-27 の Web の調べもの）

**全体の傾向**
- 運営の稼ぎ方は、次の3つがほとんど。
  - 有料プラン（広告を消す・機能を足す）
  - 書店へのアフィリエイト
  - 広告
- **利用者がお金を得られる仕組みを持つ例は少ない**。確かめられたのはブクログ・note・Readwise の3つだけ（flier のアフィリエイトは、だれでも flier を宣伝できる仕組みで、利用者の記録から稼ぐ形ではないので数えない）。

| アプリ | 運営の稼ぎ方 | 利用者が稼げる仕組み | 出典 |
|---|---|---|---|
| 読書メーター | アフィリエイト・広告。有料プランは見当たらない | なし（要確認） | bookmeter.com |
| ブクログ | プレミアム（広告を消す・フォルダ分けなど）・広告・アフィリエイト | **自分の Amazon アソシエイトの ID を登録できる**。ただし効くのは、自分のレビューのページや、自分で作った紹介リンクから買われたときだけ（旧ヘルプ。今の条件は要確認） | booklog.zendesk.com/hc/ja/articles/360049362973・booklog-help.jugem.jp/?eid=197 |
| Yomoo | 広告と、広告を消すプレミアム（月350円） | なし（書き出しは CSV だけ） | apps.apple.com/jp/app/id1516860157 |
| ビブリア | 見当たらない（無料） | 不明 | App Store |
| Readwise / Reader | 有料の購読（月5.59〜9.99ドル） | **紹介報酬33%**（自社の購読を紹介したとき） | readwise.io/pricing・docs.readwise.io/affiliates |
| flier | 個人の有料プラン（月550円・2,200円）・法人向け | flier 自身のアフィリエイト（ASP 経由） | flierinc.com/affiliate/service/introduction.pdf |
| note | 有料記事などの手数料。ID のない Amazon のリンクには note の ID を自動で付ける | **有料記事を出せる**。自分の ID のリンクを貼れば、自分の ID が優先される（2019年の記事） | note.com/fladdict/n/n89b8d2883c5d |
| Goodreads・StoryGraph・Fable・Literal | 広告・書店へのアフィリエイト・有料プラン・有料の読書会 | なし（要確認） | goodreads.com/blog/show/1108 ほか |

## 2. Amazon アソシエイト（日本）の置き場所

| 置き場所 | 扱い |
|---|---|
| 自分のサイト | よい。特別リンク（アソシエイトの ID の付いたリンク）は「自分のサイトから直接アクセス」が条件で、自分のサイト以外に向けて作ったり表示したりするのは禁止 |
| メール・SMS・自分の SNS の DM | 受け手が同意していればよい。LINE がここに入るかは4章 |
| アプリ | 承認を受けたモバイルアプリのほかは禁止（承認のないアプリのリンクには紹介料が付かない）。アプリの中で Amazon のページを開く（WebView）のも、生成 AI での使用も禁止 |
| 紙・電子書籍 | 禁止 |

- **開示**（A5条）：「Amazon のアソシエイトとして…適格販売により収入を得ています」を、目立つように書く。利用者がアソシエイトをするときは、景品表示法の対象かどうかに関わらず、この開示の文が要る。
- **2026-04-20 の改定**：有料の広告を経た購入は、紹介料の対象外になった。
- 運営のページの上に利用者の ID を置く扱いと、運営が気をつけることは4章。

## 3. 景品表示法のステマ規制（2023-10-01 から）

出典：caa.go.jp/policies/policy/representation/fair_labeling/stealth_marketing/

- 当たるのは「事業者の表示」で、消費者にそれと分からないもの。「広告」「PR」と書けば分かる表示になる。
- 規制されるのは広告主（商品を売る事業者）。個人の感想は広告に当たらない。
- 運営が見返りを付けて感想の中身に関わると、運営の表示とみなされるおそれがある（例：「レビューを書けばポイント」）。当てはめは要確認。

## 4. 公開のページに利用者の ID を置く扱い（2026-11-27 の 2回目の調べもの）

出典：A・P・H（冒頭）。楽天 affiliate.rakuten.co.jp/guideline/rule/・もしも af.moshimo.com/af/www/terms/shop・バリューコマース valuecommerce.ne.jp/st_affiliate/terms.html。

| 項目 | 判定 | 条件・理由 |
|---|---|---|
| 利用者が自分の ID で、自分のブログに置く | できる | 利用者自身の契約の中で済む。アプリは、ID 付きのリンクを入れた書き出しを作るだけ（PRD FR-R31） |
| 公開のページの Amazon のリンクに、利用者自身の ID を使う | 条件つきでできる | 利用者が自分のページの URL を、アソシエイト・セントラルに「サイト」として登録してから使う（P 参加要件6条(b)：登録していないサイトにリンクを表示しない）。開示の文は、利用者の名前で利用者のページに出す（A5条）。ブクログの本棚の URL で承認された例がある（2020年の個人の記録） |
| ID のないリンクに、運営の ID を付ける（note の形） | 条件つきでできる | 運営のドメインを運営のサイトとして登録する。Web だけなら追加の承認は要らない。開示の文は運営の名前で出す |
| 運営の ID の入った部品を、外のブログに配る | できない | P 参加要件6条(b) |
| リンクを使った人に、ポイントなどの見返りを出す | できない | P 参加要件6条(g)。紹介の特典を「リンクを使ったこと」に結びつけない |
| 中身が要約と引用だけのページ | 紹介料が付かないおそれ | P 参加要件1条「重要な解説、分析、または変容」（2026-04-20 の改定で厳しくなった）。公開のページの主は、利用者自身の感想・説明・実践にする |
| Amazon のリンクを LINE で送る | 要確認 | P 参加要件4条は、受け手が同意したメール・SMS・自分の SNS の DM だけ認める。LINE の名前は出てこない。グループに一方的に流すのは、認められない見込みが高い |
| 楽天 | 条件つきでできる | 登録すれば「ブログサービス（note など）」の上も可。**LINE・DM は名指しで禁止** |
| もしも・バリューコマース | 要確認 | 「自分が管理・運営するメディア」だけ。運営のサービスの上のページを登録できるかは不明 |
| 運営が気をつけること | — | A12条：利用者の違反を「奨励・促進」すると、運営がしたものとみなされる。URL の登録を案内し、開示の文を自動で出し、LINE のシェアにはアソシエイトのリンクを入れない作りにする |

## 5. 著作権

出典：文化庁の著作権テキスト bunka.go.jp/seisaku/chosakuken/textbook/pdf/94081601_01.pdf

- **要約は翻案（27条）に当たりうる**（東京地判平6.2.18 コムライン事件。文化庁の講習会資料に「あらすじは著作物の翻案に該当」）。
  - 自分の言葉で短く紹介するのは、比較的安全。
  - **章ごとの詳しい要約を売るのは危険**（許諾が要る）。
- **引用（32条・48条）の要件**：公表された著作物であること・自分の文と明瞭に区別すること・自分の文が主であること（主従関係）・必要最小限であること・出所を書くこと。

## 6. GoodNotes の書き出しの PDF の形（2026-11-28 に確かめた）

持ち主が GoodNotes 5 から書き出した、買った技術書の PDF を1つ、手元で調べた（357ページ・11MB。PDF はリポジトリに置かない）。マーカーは黄色の1色で 80 か所、テキストボックスは 4 つ。調べた道具は PyMuPDF と pdf.js（4.10。作るときに使う部品）で、どちらも同じ結果だった。

| 何を | どう残っていたか | 拾い方 |
|---|---|---|
| 注釈・しおり | **どちらもない**（作り手は macOS の Quartz。GoodNotes がページに焼きこむ） | しおりには頼らない |
| 本の文 | 文字として残る（日本語は pdf.js の CMap が要る） | そのまま読む |
| マーカー | 半透明（不透明度 0.5）の黄色の太い線（幅 約11〜28pt）。手で引いた形の、点の多い線。1行に2本重なることもある | 線の位置の上下に幅の半分を足した四角に入る文字を、マーカーの文にする。同じ高さの線は1行にまとめ、行の間が 22pt より狭い行は1つのマーカーにまとめる。色ではなく「半透明で太い線」で見分ければ、ほかの色でも拾える |
| テキストボックス | 文字として残る。書体は HiraginoSans-W3（本は RyuminPro などで、使っていない）・色は #1E1B1B | 本の文と違う書体の文をコメントにし、同じページのいちばん近いマーカーに付ける。4つとも正しく付いた（マーカーの上に置いたものも、下に置いたものもあった） |
| 章 | ページの上の柱に、偶数ページは章の名前、奇数ページは節の名前。ページ番号もある（PDF のページ − 25） | 柱の文から章の番号と名前、ページ番号を取る。柱のない章の扉は、前の章を引き継ぐか、扉の大きな章の番号から取る |
| かかった時間 | 357ページを読んで、Mac で 約1.3秒（pdf.js、Node）。記憶は 約400MB まで（Node そのものの分を含む） | iPhone では、ページごとに読んで片づける。大きな PDF の記憶の量は、作るときに実機で確かめる |

- まだ分からないこと：ほかの出版社の本で、柱の位置と書体が違うとき。テキストボックスの書体を利用者が変えたとき（本で使っていない書体を全部コメントとみなすか、確かめの画面で選ばせる）。
- 「?」を書いたコメントは、この PDF にはまだなかった。「ここからあまり良く理解できない」のような、あとで調べたいコメントはあった。
