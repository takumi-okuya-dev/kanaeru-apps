## 1. 結論（先に）

- **生成AIに置き換えられる危険：高（「探して答える」部分）／中（「継続して追い、通知する」部分）**。ChatGPT・Gemini・Claude は、聞けば今週の出演や発売日を答えられる。ただし、AI が公式の告知を定期的に取りに行って通知するかは、製品ごとに確かめが要る（要確認）。
- **お金**：Web 課金で、1人あたりの増える費用は AI 約3円＋インフラ約1円【仮定】。固定費 1,500円なら有料の人は数人で足りる。ただし**大きなコストは「人の情報を集める作業」と「X の API」**で、これは利用者の数ではなく対象の人数で増える。
- **値付け**：既存の配信カレンダーが月¥360前後。B8 単体で売るなら ¥300〜360、スイート（kanaeru プラス 月¥480案）の中の1本にするのが自然。
- **法律で止まりやすい点**：公式サイトの規約（自動の取得）、X の API の料金と規約、チケットの転売に関わる表示、ステマ規制（アフィリエイトの表示）、パブリシティ権（推しの名前・写真の使い方）。**スクレイピングは、対象ごとに規約を確かめるまで始めない。**

## 2. 生成AIに置き換えられる危険（Q：汎用AIでできるか）

### 2-1. 汎用AIにできること（共通の部分の 1-1 と重ねる）

| できること | 状況 | 出典・確認日 |
|---|---|---|
| 会話をまたぐ記憶 | ChatGPT は会話から記憶を更新し、消せる | [OpenAI ヘルプ（メモリFAQ）](https://help.openai.com/ja-jp/articles/8590148-memory-in-chatgpt-faq)（共通の部分 2026-11-19） |
| 外のサービスとつながる | ChatGPT の Apps SDK（日本も対象） | [OpenAI ヘルプ](https://help.openai.com/ja-jp/articles/12515353-build-with-the-apps-sdk)（共通の部分 2026-11-19） |
| 個人のカレンダー・メールを読む | Gemini のパーソナル インテリジェンス（対象アプリは資料で食い違う：要確認） | [Google Japan Blog](https://blog.google/intl/ja-jp/company-news/technology/personalintelligence/)（共通の部分 2026-11-19） |
| 定期の自動実行（決まった時刻に調べて知らせる） | 製品として存在するかは**要確認**。このファイルでは確認していない | 未確認 |

**読み取り**：「来週の○○の出演は？」のような1回の問いは、AI の検索で答えが出る。推しが増えて、毎日の予定を全部確かめるのは大変、という人にとっては、AI の答えは「ふつうの検索」と変わらない。そこで差が出るのは「**継続して、ばらばらの出典を一つの表にまとめ、漏れを知らせる**」部分。

### 2-2. 判定

| 機能 | 判定 | 理由 |
|---|---|---|
| 1回の問いに答える（「今週の出演」） | **高** | AI で足りる。検索の精度は要確認（出典の欠落や古い情報の混入） |
| 推しごとの予定の一覧（カレンダー） | **中〜高** | 一覧の見た目は AI の会話より見やすいが、AI でも表は作れる |
| 継続して取り、通知する | **中** | AI の定期実行の有無は要確認。通知の確実さ・取得元の管理は AI だけでは難しい |
| 声優・舞台俳優など、小さい人の情報を取り続ける | **中** | 公式告知は散らばり、X などはログインや API の壁がある。AI の検索はこの穴を埋めにくい（ただし、アプリでも同じ壁） |
| 雑誌の発売日・グッズの予約（一覧化） | **中** | 出版社・通販の告知を集める手間がある |
| 購入の入口（アフィリエイト） | **低** | AI が直接のアフィリエイトの仕組みを持つわけではない（ただし、AI の会話で商品を紹介する形は今後増える可能性。要確認） |

**総合の判定：高**（「探して答える」が AI で足りるため）。ただし「**小さい人の出演を、出典つきで、漏れなく、継続して追う**」なら中。事業にするなら、この部分だけを売り物にする。

### 2-3. AI だけではできないこと

1. **公式の告知を、ふさわしい頻度で、規約の範囲で取り続けること**（取得の仕組み・規約・壊れたときの直し。対象ごとに違う）
2. **出典つきの確かな一覧を作って、誤りを直すこと**（AI の答えは、出典の確認なしには信用しにくい）
3. **X（旧 Twitter）の告知を取ること**（API は従量課金で、費用が人数で増える。2-4 を参照）
4. **LINE グループなどで、同じ予定を複数人で共有すること**（AI は基本的に1人向け）
5. **課金の管理（解約・更新の通知・返金）**（AI は決済の主体になれない）
6. **推しごとの「通知の好み」を、続けて守ること**（記憶はあるが、通知の確実さは保証できない）

### 2-4. 取得元と費用の大きさ（B8 特有）

- **X の API**：2026年に月額制から従量課金に移ったと報じられている。事前購入のクレジットで、読み取りごとに課金される。投稿1件の読み取りは $0.005 とする第三者サイトの記載がある（**要確認。公式の料金ページは 2026-11-23 に 404 で確認できず**）。出典：[X API 従量課金の解説（第三者）](https://www.getxapi.com/ja/twitter-api-pricing)・[GIGAZINE 2026-02-09](https://gigazine.net/news/20260209-x-api-pay-per-use/)（2026-11-23 に検索結果で確認）。
  - 試算【仮定・要確認】：対象 500 人 × 1日10件の投稿 × 30日 = 15万件の読み取り。$0.005 なら月 $750（約11万円）。**X を取得元にすると、人数が増えるほど費用が跳ね上がる**。
- **YouTube Data API**：既定の割り当ては1日 10,000 ユニット（[Google 割り当て量の解説](https://developers.google.com/youtube/v3/determine_quota_cost?hl=ja)、2026-11-23 検索で確認）。ただし、規約では API Data を解約時に削除すること（§24.3）、割り当てを超えること・回避することの禁止（§15）、「データを別のデータベースや予定表として作る」ことを直接許す条文は見つからなかった（[YouTube API サービス利用規約](https://developers.google.com/youtube/terms/api-services-terms-of-service)、2026-11-23 に確認。開発者ポリシーは参照先で本文未確認。要確認）。
- **公式サイト（声優・舞台・雑誌）**：利用規約とロボット排除（robots.txt）の確認が要る。B8 の調べでは、規約の文言は見つからなかった（[B8 の調べもの](../../../../base/_bmad-output/research-app-ideas/b8-oshi-calendar.md) 4章）。**未確認のまま取得を始めない**。

## 3. 費用（1人あたり・固定費・損益分岐）

使い方（【仮定】）：
- 毎日の要約（入力 1,000・出力 300）× 30日
- 質問への答え（入力 2,000・出力 500）× 月20回

| モデル（入力／出力 per 100万） | 1人・月の AI 費用（典型） | 3倍使う人 |

| Claude Haiku 5.5（$0.10／$0.50） | 約2.5円 | 約7円 |

### 3-2. 対象ごとの取得費用（人数ではなく、追う対象の数で増える）

### 3-3. 1人あたりの増える費用・決済の手数料

### 3-5. 解約率（仮定）と LTV

- **解約率の仮定：月 8%**【仮定】。共通の部分の「消費者向けは 7〜10%」の中間。B8 の既存アプリの解約率は確認していない（要確認）。

  - 980円（Web）：約 11,700円
- CAC（1人を集める費用）の上限の目安：LTV の 3分の1（一般的な目安。出典により違う。要確認）→ 480円で約 1,900円。交流会から来る人は広告費がほぼゼロだが、**kanaeru の交流会の人は推し活の人と重ならない可能性が高い**（【仮定】）。広告で集めるなら、この上限を超えやすい。

## 5. 法律・規約（論点の整理。専門家の確認が前提）

以下は論点であり、結論ではない。全部、弁護士・専門家の確認が要る。

### 5-1. 特定商取引法・消費者契約法（共通の部分 5-1〜5-3 と同じ論点）
- 有料プランの最終確認画面・自動更新・解約の条件、個人の事業者の表示。共通の部分 5-1・5-2 を参照。B8 特有の点はない。
- 消費者契約法：解約の説明の努力義務（2023-06-01 施行）、責任の全部免除の条項は無効になりうる（8条・10条）（共通の部分 5-3）。

### 5-2. 個人情報保護法
- B8 で扱うのは「推しの名前」「見た予定」「通知の設定」。**本人の病歴などの要配慮情報は通常は入らない**が、推しの追っかけの記録（どのイベントに行ったか）は、本人の行動の記録になりうる（要確認）。
- AI の API に送る場合は外国の事業者への提供の論点（共通の部分 5-5）。推しの名前だけなら個人情報に当たらないことが多いが、要確認。
- 取得の最小化：利用者のログイン情報は最小限、アカウントを消すとデータも消す（共通の部分 5-8）。

### 5-3. スクレイピング・API の規約（B8 で一番大事な論点）
- **公式サイトの利用規約**（自動アクセスの禁止・robots.txt）：B8 の調べでは規約の文言を確認できなかった（要確認）。**対象ごとに規約を読んで記録するまで、自動の取得を始めない**。
- **X の API**：従量課金・API の規約（開発者向けの契約）。投稿の保存期間・再配布の条件は要確認。
- **YouTube の API**：API Data の保存と削除の条項（§8・§24.3）。キャッシュ（一時保存）の範囲と、予定表として作ってよいかは、開発者ポリシー（参照先）まで読んで要確認（2-4）。
- 取得元を「公式の告知ページ」「公式の API」に限り、他人のサイトの複製は作らない、という方針が論点を減らす（【仮定】。専門家確認）。

### 5-4. 景品表示法（アフィリエイトの表示・ステマ規制）
- **ステマ規制（2023-10-01 から）**：広告であることを隠した表示は不当表示。アフィリエイトのリンクを置くなら「PR」「広告」の表示が要る（共通の部分 5-7）。
- 楽天・Amazon 等のアフィリエイト規約にも、表示の義務がある（規約の文言は要確認）。
- **料金の表示**：「通常○円→今だけ○円」は、実際の価格の実績が要る（共通の部分 5-7）。

### 5-5. チケットの転売に関わる表示（B8 の「チケット」の導線）
