## おすすめの作る順（仮決め）

2 つの調べものは、それぞれ B3 → B5 → B4 と B6 → B7 → B1 をすすめていた。合わせると **B6 → B3 → B7 → B5 → B4 → B1**。

B2 受付アプリは実装済みで、すべての前提になる玄関（2026-11-25 の交流会から使う）。下の順は、その上に載せるアプリの順。

1. **B6 試合表**：MVP 2〜4 週と一番小さく、AI に置きかえられる危うさも法律の重さも低い。スイート課金・LINE 共有・チェックイン連携の型を試す最初の題材にする。
2. **B3 読書記録**：meetup で紹介された本 → 読みたいリスト → LINE で復習、と受付アプリから一番自然につながる。AI に置きかえられる危うさが高いので、交流会・LINE とつなげた形だけにする。
3. **B7 人物メモ**：受付アプリとの相乗効果は一番強いが、「イベントごとの公開同意」と参加履歴、個人情報保護法の専門家確認がそろってから作る（確認が長引けば B5 を先にする）。
4. **B5 運動管理**：仲間で続ける機能は工数が小さく（3〜4 週）コミュニティの再訪理由になるが、運動メニューづくりは AI で済み、IT 勉強会の本筋ではない。
5. **B4 料理レシピ**：痛みは大きいが、大手と LLM 代替に挟まれ、meetup との相乗効果が弱い。スイートの軽量機能として後から加える。
6. **B1 人材集客の入口**：稼ぐ力は一番高いが、職業安定法の照会・需要の確認・B2B 営業が先に要る。照会と受付アプリの任意アンケートでの需要の確認は、作るのを待たずに並行して始められる。

**別の調べものの一番のおすすめとの関係**：受付アプリ・スイートの市場と競合の調べもの（[B2 のファイル](./b2-reception.md)の 8 章）は、受付の次に作るアプリを「この作業を AI でできるかの診断」「AI への頼み方の型」のような、AI の使い方の壁を越えさせるものからとすすめている（生成AIを使わない理由の「使い方がわからない」が 38.8% で日本が最高、大手が無料で同梱していない領域）。この案はバックログの B にないので、上の順には入れていない。`/app-idea-research` で候補として調べ、B に足すかを決める。足すなら、AI に置きかえられる危うさと受付とのつながりを B6 と比べて、順のどこに入れるかを決め直す。

誰が払うかは「使いたい人が払う」（開発者が決めた）。組織か個人かは区別しない。
