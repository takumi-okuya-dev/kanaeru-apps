# 事業性：B11 流行りに追いつくアプリ

調べた日：2026-11-23。数字・規約には出典と確認日を付けた。**確かめ済み**＝2つ以上のページで一致したもの。**要確認**＝1つのページだけ、または食い違いがあるもの。**抜粋のみ・要確認**＝ページを開けず、検索の抜粋だけで見たもの。法律の部分は論点の整理で、法的な助言ではない。**全部、専門家（弁護士・税理士など）の確認が前提**。

困りごと（主催者の言葉のまま）：私は家にテレビがないので、最近の流行りについて行くことができていません

読み方【仮決め】：ドラマ・バラエティ・CM・流行語・歌・ネットで話題のことを、週1回の短いまとめにして LINE に届ける。交流会の前に「雑談のネタ」として読む使い方も考える。

前提の材料：

- YouTube API の規約の細かい点は [B8 の事業性](../b8-oshi-calendar/business.md) 2-4 で調べたものを参照する。

## 1. 結論（先に）

- **生成AIに置き換えられる危険：高**。ChatGPT は**無料プランでも**「毎週、日本で話題のことをまとめて」という繰り返しのタスクを作れて、プッシュ通知かメールで届く（3件まで・1日1回まで）。Gemini・Claude・Perplexity にも決まった時刻に動く機能がある。さらに AI 以外でも、**LINE NEWS・Yahoo!ニュース・Google トレンドが無料で同じ困りごとに答えている**。一般向けの「今週の流行りまとめ」をお金にするのは厳しい。
- **お金**：まとめは全員に同じものを週1回作るので、AI の費用は1人あたり1円前後（全員分のまとめは月の固定で約4〜210円）。**一番大きい費用は LINE で届ける費用**（友だちの数×届けた回数で数える）と、**X の API**（読んだ投稿1件ごとに $0.005）。LINE の無料プランは月200通なので、週1回なら**46人まで**。それを超えると月5,500円（税込）のライトプランが要り、損益分岐の人数が4〜5倍になる。
- **値付け**：比べられるのは無料のニュースと ChatGPT（無料〜月1,500円）。単独の有料アプリにはせず、**スイートの中の無料の機能か、受付アプリ（B2）の付録（交流会の前の「今日の雑談ネタ」）**にするのがすすめ【仮決め】。
- **残る強み**：その交流会に合った話題・参加者が実際に話したこと・同じネタをその会の全員で持つこと・LINE で押すだけで見られること。どれも AI だけでは出しにくいが、2つ目は個人情報の扱いが重い（5-4）。
- **法律で気をつける点**：ニュース記事・テレビ番組・歌詞の中身を写さないこと（事実だけを自分の言葉で、出所を書く）。新聞協会は「AI による記事の無断の要約」を問題視している。X の API は再配布と AI の学習を禁じている。専門家の確認まで、記事の本文を取り込む作りにはしない。

**読み取り**：困りごとの「流行りを知りたい」だけなら、**LINE の中にすでに無料の答え（LINE NEWS）がある**。B11 が出せる違いは「テレビを見ない人向けに、雑談で使える形に短くしたもの」か「交流会に合わせたもの」に絞られる。

### 2-3. 判定

| 機能 | 危険 | 理由 |
|---|---|---|
| 一般向けの「今週の流行り」まとめ | **高** | ChatGPT の無料のタスクで足りる。LINE NEWS も無料 |
| テレビを見ない人向けの「雑談で使える一言」付きのまとめ | **高〜中** | AI に「雑談で使える形で」と頼めば作れる。ただし毎週の手間がない・LINE で届く点は違い |
| その交流会の参加者に合わせた話題（例：IT の交流会なら技術・業界の話題も混ぜる） | **中** | AI でも頼めば作れるが、「その会の人に向けて、主催者が選んだもの」は AI にない |
| 同じネタを、その会の全員で持つ（共有） | **低〜中** | AI は1人で使う。グループで同じものを見る形は持ちにくい |
| 参加者が実際に話したことを次の会のネタにする | **低** | kanaeru の受付・交流会の現場にしかないデータ。ただし個人情報の扱いが重い（5-4） |

**総合：高**。「交流会と組み合わせた部分」だけが中〜低。

### 2-4. AI だけでは出せないもの

1. **その交流会に合わせた話題**（主催者の選び方・その会の参加者の傾向）
2. **その会の全員で同じネタを持つこと**（LINE グループ・受付の画面に出す）
3. **LINE に届くこと**（ChatGPT のアプリを入れていない人・AI を使わない人にも届く。日本では生成AIを使ったことがある人は26.7%〈共通の部分 1-1〉）
4. **参加者が実際に話したこと**（受付アプリ〈B2〉や交流会の記録。同意の設計が前提）
5. **出所を付けて、誤りを直す手間**（AI の答えは出典の確認なしには信用しにくい）

## 5. 法律・規約（論点の整理。専門家の確認が前提）

以下は論点で、結論ではない。

### 5-1. 著作権（記事・テレビ・歌の中身をまとめるとき）

条文は [e-Gov 法令検索の著作権法](https://laws.e-gov.go.jp/law/345AC0000000048)（API から本文を取って確認、2026-11-23）。解説は [著作権情報センター（CRIC）](https://www.cric.or.jp/qa/hajime/hajime7.html)（2026-11-23）。

- **事実そのもの**：「事実の伝達にすぎない雑報及び時事の報道」は言語の著作物に当たらない（10条2項）。一方、ふつうの報道記事や報道写真には創作性があって著作物になる、という整理もある（[京都産業大学の講義資料](https://www.cc.kyoto-su.ac.jp/~kano/pdf/course/TecSociety6.pdf)、抜粋のみ）。→「何が話題か（事実）」を自分の言葉で書くことと、記事の文章を写すことは別もの。
- **引用（32条）**：「公正な慣行に合致する」「報道、批評、研究その他の引用の目的上正当な範囲内」であること。解説では、引用の必然性・自分の文と引用部分が分かれていること・自分の文が主であること・出所を書くことが挙げられる（CRIC・[リーガルスケープの解説](https://www.legalscape.jp/column/copyright-quotation-requirements)は抜粋のみ）。**まとめの大半が他人の文章なら、引用とは言いにくい**（論点）。
- **情報処理に付随する軽微な利用（47条の5）**：検索・情報解析などの結果を出すときに、「軽微なもの」に限って著作物を使える。政令の基準に従うこと、著作権者の利益を不当に害しないことが条件。**AI でまとめを作るサービスが、これに当たるかは論点**（専門家確認）。
- **新聞協会の見方**：日本新聞協会は2024年7月17日の声明で、記事を材料に答えを作る検索型の生成AIは「著作権侵害に該当する可能性が高い」、「『軽微な利用』とは到底言えない長文の回答」を作ると書き、許諾と対価を原則としている（[新聞協会の声明](https://www.pressnet.or.jp/statement/ai/240717_15523.html)、2026-11-23）。2025年6月・2026年4月にも声明がある（[京都新聞](https://www.kyoto-np.co.jp/articles/-/1699519)・[時事通信](https://www.jiji.com/jc/article?k=2026042000600&g=soc)、抜粋のみ）。→**記事の本文を AI に読ませて要約を配るのは、B11 で一番重い論点**。
- **見出しの利用（YOL 事件・知財高裁 平成17年10月6日）**：記事の見出しは著作物と認められなかったが、多大な手間と費用で作った見出しを大量に使った行為は一般の不法行為（民法）とされた（[著作権弁護士の解説](https://chosakukenhou.jp/yol-jiken/)、2026-11-23。[裁判所の判決の要旨 PDF](https://www.courts.go.jp/assets/hanrei/hanrei-point_pdf-9350.pdf) は本文を読み出せず、**要確認**）。→**著作物でなくても、見出しを大量に並べて配るのは危うい**（論点）。
- **テレビ番組・CM・歌**：番組の画像・CM の映像・歌詞は使わない、を前提にする【仮定】。歌詞は短くても著作物になりうる（要確認）。曲名・番組名を事実として書くことは論点が軽いと見られるが、要確認。
- **作りの案【仮定・専門家確認】**：材料は「何が話題か」の事実（ランキング・題名・人の名前）だけにし、文章は自分で書く。元の記事・公式のページへのリンクを付ける。記事の本文を取り込んで AI に要約させる作りは、専門家の確認と許諾がない限りしない。

### 5-2. ニュースサイト・X・YouTube の規約

- **ニュースサイト**：サイトごとに利用規約と robots.txt を読む（この調べでは個別のサイトは見ていない。要確認）。新聞協会は無断の収集をくり返し問題視している（5-1）。
- **X**：
  - 開発者契約（最終更新 2026-04-27）は「X の API や X のコンテンツを使って基盤モデルを微調整・学習すること」を禁じ（III.A(k)）、許諾された素材の販売・再配布・派生物の作成なども禁じる（III.A(d)）（[X 開発者契約](https://docs.x.com/developer-terms/agreement)、2026-11-23、**要確認**〈1ページ。AI 学習の禁止は [TechCrunch 2025-06-05](https://techcrunch.com/2025/06/05/x-changes-its-terms-to-bar-training-of-ai-models-using-its-content) も報じる・抜粋のみ〉）。
  - 開発者ポリシー：第三者に渡せるのは原則として投稿の ID などだけ。X のコンテンツを表示するなら中身をそのまま保ち、保存したものは X の今の状態に合わせ、削除の求めから24時間以内に消す（[X 開発者ポリシー](https://docs.x.com/developer-terms/policy)、2026-11-23、**要確認**〈1ページ〉）。
  - **論点**：投稿を AI に渡してまとめを作り、利用者に配るのが「再配布」「派生物」に当たるかは、規約からは読み切れない（推論のための一時的な利用の扱いは未解決という第三者の指摘あり。要確認・X に確認）。
- **YouTube**：利用規約は、ロボット・スクレーパーなどの自動の手段でのアクセスと、許可のない複製・ダウンロードを禁じる（[YouTube 利用規約](https://www.youtube.com/static?template=terms&hl=ja&gl=JP)、2026-11-23、**要確認**〈1ページ〉）。**取るなら公式の API だけ**。API の保存・削除の条項は [B8 の事業性](../b8-oshi-calendar/business.md) 2-4。

### 5-3. 特定商取引法・消費者契約法

課金するなら、共通の部分 5-1〜5-3 と同じ（表示・最終確認画面・解約の流れ・責任を全部なくす条項は避ける）。B11 特有の点はない。**無料の入口として出すなら、この論点は課金を始めるときまで来ない**。

### 5-4. 個人情報保護法

- **一般向けのまとめだけなら、持つのは LINE の ID と好み（ジャンル）くらい**で、扱う量は少ない（原則 II に合う）。
- **「参加者が実際に話したこと」を材料にする場合は重い**：誰が何を話したかは個人の情報で、第三者（その場にいない人）の話が混ざることもある。B7 人物メモと同じ論点（[共通の部分 5-5](../business-viability.md)・[B7](../b7-people-notes.md) 5章）。**やるなら、名前を外した「話題の言葉」だけを、同意を取って集める**形を専門家に確認する【仮定】。
- 米国の AI の API に送るなら「外国にある第三者」への提供の論点（共通の部分 5-5）。

### 5-5. LINE の規約（Push・ミニアプリ）

- Push の通数と料金は 3-3（**確かめ済み**）。
- ミニアプリのサービスメッセージは、宣伝・イベントの知らせが禁止で、ユーザーの操作への応答だけ（3-3）。**週1回のまとめを、サービスメッセージで送るのは規約に合わない**と読める（要確認）。
- LINE公式アカウントで送ってよい中身（ガイドライン）と、ミニアプリから外の決済に案内してよいか（共通の部分 4-4）は、この調べでは本文を読んでいない（**要確認**）。
