# kanaeru 受付アプリの振る舞い

作成：2026-11-19（決めた経緯は [.memlog.md](./.memlog.md)。見た目は [DESIGN.md](./DESIGN.md)）。2026-11-19 直した（reception-002：交流会ごとの割引と紹介者の名前。PRD FR-23〜FR-25）

土台は [docs/design/EXPERIENCE.md](../../docs/design/EXPERIENCE.md)（原則・言葉づかい・部品と状態の型・操作・アクセシビリティの下限）。ここには、この版の画面と、土台との違いだけを書く。土台の出典とライセンスは [docs/design/README.md](../../docs/design/README.md) 3・4。

【仮決め】の印は、PRD・構成の決めごと・決めた記録にない所を、この文書を書くときに仮に決めたもの。主な画面の見本（HTML）で確かめて直す。決めきれないことは、最後の「Open Questions」に置く。

## Foundation

| 使う人（PRD 3章） | 形 | 入口 |
|---|---|---|
| 参加者 | スマホ・**LINEの中（LINEミニアプリ）** | 受付QR・アンケートQR（中身はミニアプリのURL。構成 AD-14） |
| 受付係 | スマホ（LINEミニアプリ） | 招待のリンク → 一覧画面 |
| 主催者 | スマホと PC | 交流会の一覧。PC は外のブラウザで使えるかが未確認（構成 Open Questions 3） |

- **UIの土台**：テンプレートの shadcn/ui（Base UI の形）に、`packages/ui` の値（DESIGN.md から写したもの）を当てて使う。振る舞いは土台の EXPERIENCE.md を引き継ぎ、ここは違いだけ。
- **ログイン**：どの画面も LINE ログイン（LIFF）で入る。画面が自分でログインの手続きを持たない（構成 AD-4・AD-12）。
- **言葉**：画面に出す言葉は PRD 3章の用語集のまま（主催者・受付係・参加者・交流会・受付QR・アンケートQR・チェックイン・手でのチェックイン・申し込みの媒体・知ったきっかけ・支払い方法・Googleフォーム・アンケート・困りごと・一覧画面・チェックインの画面）。「本気度」「アカウント」は作り手の言葉なので、参加者の画面には出さない【仮決め】。

## Information Architecture

| ID | 画面 | 道 | 見られる人 | 中身 |
|---|---|---|---|---|
| P1 | **チェックインの画面** | `/e/{eventId}/checkin` | ログインした人なら誰でも（中身は交流会の要約だけ。AD-5） | 交流会の要約 → 名前（初期値あり）→ 申し込みの媒体・知ったきっかけ・支払い方法のチップ →（割引があれば）割引のチップと、紹介者を聞く割引を選んだときだけ紹介者の名前 → 「チェックインする」。済んだら、チェックインのカード・紙の名札の案内・オープンチャットの案内（FR-17）・開いていれば「アンケートに答える」 |
| P2 | アンケートの画面 | `/e/{eventId}/survey` | その交流会にチェックインした参加者 | 困りごと → 月いくら → テスター → 任意（仕事の立場・職種）→ 「送る」→ お礼と「続けて交流会のアンケートへ」 |
| P3 | 受付係の招待 | `/invite/{inviteToken}` | 招待のリンクを持つ人 | 交流会の名前と「受ける」→ 一覧画面へ |
| A1 | 交流会の一覧 | `/admin/events`【仮決め】 | 主催者 | 交流会ごとの名前・日時・会場・参加費。「交流会を追加」 |
| A2 | 交流会の作成・編集 | `/admin/events/new`・`/admin/events/{eventId}/edit`【仮決め】 | 主催者 | 名前・日時・会場・参加費・割引（任意。名前・額・紹介者の名前を聞くか）・GoogleフォームのURL（任意）・LINEグループの招待リンク（任意） |
| A3 | **一覧画面** | `/admin/events/{eventId}`【仮決め】 | 主催者・受付係 | タブ：参加者・合計（困りごと〈主催者だけ〉は外枠のナビの項目で、別の画面 `/admin/events/{eventId}/concerns`）。手でチェックイン、同じ名前の印、直す・取り消すの枠、5秒おきに読み直す |
| A4 | 準備 | `/admin/events/{eventId}/setup`【仮決め】 | 主催者 | 受付QR・アンケートQRの表示と印刷、受付係の招待のリンク（作り直す）と受付係の一覧（外す）【仮決め：一覧と外す】、アンケートを開く・閉じる |
| A5 | 書き出しと削除 | `/admin/events/{eventId}/data`【仮決め】 | 主催者 | 参加者のCSV・困りごとのCSV、参加者のデータを消す |

- P1〜P3 の道は構成 AD-14 のとおり（`packages/contracts/src/core` の1か所で持つ）。A1〜A5 の道は外から開かないので AD-14 の対象外で、上は仮の形。
- **誰が何を見るか**（PRD FR-3）：

| 一覧画面と管理の画面の中身 | 主催者 | 受付係 |
|---|---|---|
| A3 参加者のタブ・合計のタブ | ○ | ○ |
| A3 手でチェックイン・直す・取り消す | ○ | ○ |
| A3 困りごとのタブ・申し込みの媒体と知ったきっかけの内訳（FR-13。合計のタブの下に置く【仮決め】） | ○ | 出さない |
| A3 手でのチェックインの人の回答を代わりに入れる（FR-10・A9） | ○ | 出さない |
| A3 紹介者の名前（一覧・直す枠）と、割引・紹介者の内訳（FR-24・FR-25） | ○ | 入れられるが、保存したあとは出さない【仮決め】 |
| A1・A2・A4・A5 | ○ | 出さない（開けば 403 の状態） |

- **画面のつながり**：主催者は A1 → A3。交流会の中の行き来（A3 の参加者・合計／困りごと／A4 準備）は外枠のナビで行う（下の「外枠のナビ」）。「書き出しと削除」（A5）は A3 と困りごとの見出しの近くのボタン、「交流会を直す」（A2）は A1 と A4 のボタンから開く（どれも主催者にだけ出す）。受付係は P3 → A3 だけで、管理の入口を出さない。
- **外枠のナビ**（core-003。2026-11-19 に開発者が決めた）：
  - 管理の画面（A1〜A5）：PC（752px 以上）は左のサイドバー。上の帯の「メニュー」ボタンで出す・隠すを切り替え、見ている人ごとにブラウザに覚える（はじめは出す）。スマホ（751px 以下）は画面の下のタブバー（スクロールしても残る）。帯の下にナビの行は出さない。
  - 項目：交流会の中（`/admin/events/{eventId}…`）では「交流会の一覧」「参加者・合計」「困りごと」（主催者だけ）「準備」（主催者だけ）。受付係は「交流会の一覧」「参加者・合計」だけ。交流会の外では「交流会の一覧」だけ。各画面の上に、同じ行き来のタブを重ねて出さない。
  - 参加者の画面（P1〜P3）と手元のログイン：ナビなし。上の帯はアプリの名前だけ（押しても移らない）。管理の画面への入口を出さない。
- **スイートの外枠**（core-005。主催者が確かめたモックアップ。【仮決め】は [specs/core/005-app-switcher](../../specs/core/005-app-switcher/spec.md)）：
  - アプリの切り替えは、見えるアプリが2つ以上のときだけ出す（PC：サイドバーの上のボタンとメニュー。スマホ：上の帯の右のボタンと下から出す枠）。1つなら今のまま。ナビには今のアプリの項目だけ。
  - 「すべてのアプリ」（`/apps`）と「設定」（`/settings`。個人の設定・アプリの設定・運営〈運営者だけ〉。スマホは一覧の画面から入る）。設定の入口は、PC は上の帯の右、スマホは切り替えの枠の一番下（切り替えがないときは上の帯の右）。
  - アプリの台帳（運営者だけ）は、チップを押すとすぐ保存し、結果を行のそばに出す。退会は確かめの枠で、消えるものと元に戻せないことを書く。
- 主催者が使えない操作は、受付係の画面では**隠す**。受付係が理由を知る要がないため（土台の「理由と一緒に使えない形で見せる」の例外）【仮決め】。
- 重ねる枠は1段まで（直す・取り消すの枠の上に、さらに枠を重ねない）。

## Voice and Tone

言葉は土台の言葉づかいのとおり。違いは、**相手が年長の非エンジニアの参加者を含む**こと。

- **です・ます**で、短く。カタカナ語と作り手の言葉（ID・トークン・セッション・エラーの code）を画面に出さない。
- 1つの画面で頼むことは1つ。説明は1文で済む所に置く。
- ボタンは、押すと何が起きるかを動詞で書く。

**決めた言葉**（そのまま使う）

| 場面 | 言葉 |
|---|---|
| アンケートを送ったあと | 「あなたの困りごとが、解決する企画やアプリにつながります」 |
| 月いくらの設問の注記 | 「答えるだけで、実際には払いません」 |
| 夜間の停止（503 `DB_UNAVAILABLE`） | 「夜間（0時〜8時）は止まっています」 |
| チェックインの取り消しの確かめ | 「アンケートの回答があれば一緒に消えます」 |
| チェックインが済んだ | 「チェックインしました」と交流会の名前 |
| 受付QRを読み直した | 「チェックイン済み」 |
| 手とLINEで同じ名前 | 「同じ名前があります」 |
| Googleフォームへの案内 | 「続けて交流会のアンケートへ」 |
| P1・A3 のボタン | 「チェックインする」・「アンケートに答える」・「手でチェックイン」 |
| 交流会の参加費を直すとき | 「参加費を直しても、すでにあるチェックインの金額は変わりません」（構成 AD-6 の中身を、画面の言葉にしたもの） |
| 割引の設問（reception-002） | 見出し「割引」・最初のチップ「割引なし」・割引のチップ「紹介割（−1,000円）」・欄「紹介してくれた人の名前」（説明「任意」） |
| 交流会の割引を直すとき | 「割引を直しても外しても、すでにあるチェックインの割引と金額は変わりません」 |

**仮に決めた言葉**【仮決め】

| 場面 | する | しない |
|---|---|---|
| 紙の名札の案内 | 「受付で紙の名札に名前を書いて、お入りください」 | 「名札をご記入の上ご入場くださいますようお願いいたします」 |
| 読みこめない | 「読みこめませんでした。電波の良い所で、もう一度試してください。開かないときは、受付の人に声をかけてください」 | 「通信エラーが発生しました」 |
| 閉じたアンケート | 「アンケートは閉じています」 | 「受付期間外です」 |
| チェックインしていない | 「先にチェックインしてください」と「チェックインの画面へ」 | 「権限がありません」 |
| 招待のリンクが使えない | 「この招待のリンクは使えません。主催者に新しいリンクをもらってください」 | 「トークンが無効です」 |
| 外された受付係（403） | 「この交流会の一覧画面は使えません。主催者に確かめてください」 | 「403 Forbidden」 |
| 選んでいないチップ | 「支払い方法を選んでください」（設問の名前を入れる） | 「必須項目です」 |
| 夜間の停止の続き | 「夜間（0時〜8時）は止まっています。8時からもう一度開いてください」 | 「サービスが利用できません」 |

## Component Patterns

振る舞いの違いだけ。見た目は DESIGN.md の Components。

| 部品 | 使う所 | 振る舞い |
|---|---|---|
| サイドバー | 管理の画面（PC） | 外枠のナビの項目を縦に並べる。今の画面の項目に印（下の画面〈書き出しと削除・QR の印刷・交流会を直す〉では、含む項目に印。交流会を直すは「準備」に含める）。押すと画面が変わり、新しい画面の題にフォーカスが移る |
| メニューのボタン | 管理の画面（PC）の上の帯の左 | 押すとサイドバーを隠す・出す。今の状態を読み上げる（開いている・閉じている）。状態はその人のブラウザに覚え、読みこみ直しても同じ。覚えられないブラウザでも誤りにせず、その画面の間だけ効く。スマホでは出さない |
| タブバー | 管理の画面（スマホ） | 画面の下の段にいつも出て、スクロールするのは上の帯と本文だけ（本文がタブバーの下に潜らず、押せる所やフォーカスが隠れない）。項目はサイドバーと同じで、アイコンと名前。今の項目に印。本文の最後がタブバーに隠れない。重ねる枠（直す・取り消すの枠など）はタブバーの上に開く |
| 選択肢のチップ | P1・P2・A3 の手でチェックインと直すの枠 | 1つの設問で**1つだけ選ぶ**（ラジオの意味）。押すとすぐ選んだ状態になり、別のチップを押すと移る。選択肢と並び順は PRD FR-4・FR-10 のとおり（構成の約束で reception・survey の contracts に持つ） |
| 割引のチップ | P1・A3 の手でチェックインと直すの枠（reception-002） | 交流会に割引があるときだけ、支払い方法のあとに出す。「割引なし」が最初で、最初から選ばれている。割引ごとに「名前（−額）」。直すの枠では、今の割引が使うのをやめたものでも、写した名前と額のチップで選んだ状態に出す。選べない割引を送ると、設問のそばに「この割引は選べなくなりました。…」【仮決め】 |
| 紹介者の名前の欄 | 割引のチップの下 | 選んだ割引が「紹介者の名前を聞く」のときだけ出す（任意・50文字まで）。割引を変えると空にする。P1 の何をどう使うかの1文に「紹介してくれた人の名前は主催者だけが読みます」を足す。直すの枠：主催者は今の名前を出し、空にすると消える。受付係は空の欄で出し「入れると前の名前を置きかえます。空のままなら変えません」【仮決め】 |
| 割引の節 | A2（主催者だけ。reception-002） | 参加費の下。行ごとに「割引の名前」「割引の額（円）」「紹介者の名前を聞く」（チェックの箱）と「外す」、下に「割引を足す」（10まで）。交流会と同じ「作る」「保存」で一緒に保存する。誤りは行の欄のそば（同じ名前は2つ目の名前の欄）。外した割引は消えず、新しいチェックインで選べなくなるだけ【仮決め】 |
| 名前の欄 | P1・手でチェックイン | P1 は初期値あり（前回のチェックインの名前、なければLINEの表示名。構成 AD-6）。**文字を打つのは名前を直すときだけ** |
| 知ったきっかけの初期値 | P1 | 2回目以降は前回の答えを選んだ状態で出す。申し込みの媒体と支払い方法は毎回選ぶ（PRD A4） |
| 「チェックインする」 | P1 | いつも押せる形にする。押したとき選んでいない設問があれば、その設問のそばに誤りを出し、最初の誤りへ動かす（土台の入力の誤りのとおり）。名前・申し込みの媒体・知ったきっかけ・支払い方法はどれも要る【仮決め】。送っている間は二度押しできない |
| チェックインのカード | P1 の済んだ状態 | 済んだら画面の上にカードを出し、画面のいちばん上へ動かす。入力の欄は消す（直したいときは受付係に頼む。参加者が自分で直す機能はない） |
| 「アンケートに答える」 | P1 の済んだ状態 | アンケートが開いている間だけ出す（PRD FR-9）。押すと P2 |
| 友だち追加の案内 | LINE ログインの同意の画面 | P1 に重ねて出さない（PRD FR-6）。しなくてもチェックインできる |
| 何をどう使うかの案内 | P1 の「チェックインする」の近く | 集めるものと使い道を1〜2文で示し、プライバシーポリシーを開くリンク（下線つき）を置く（PRD 5章） |
| アンケートの目的の案内 | P2 の一番上 | 設問の前に、次の文をそのまま出す（2026-11-19 に主催者が決めた）。見出し「仕事の困りごとを聞かせてください」。本文「この交流会では、参加者の仕事の困りごとを集めて、AI活用勉強会のテーマや小さなアプリにしています。」。箇条書き「書いてもらった内容は、主催者だけが読みます。勉強会やアプリにするときに、お名前を出すことはありません。」「1分ほどで終わります。答えにくい設問は、飛ばして大丈夫です。」 |
| アンケートの設問 | P2 | **どれも必須にしない**（PRD A7）。任意の設問（仕事の立場・職種）は「任意」の見出しでまとめる。職種の選択肢は 「エンジニア」「デザイナー」「営業」「マーケティング」「企画・PM」「事務・管理部門（人事・経理・総務など）」「経営」「その他」（PRD A15）。任意で答える4つの設問（月いくら・テスター・仕事の立場・職種）のどれにも「答えない」を入れ、新しい回答では最初にそれが選ばれている（一度選んでも「答えない」に戻せる）【仮決め】 |
| オープンチャットへの案内 | P1 の済んだ状態 | チェックインが済んだら出す。リンク「コミュニティのオープンチャットに参加する」（下線つき）。URL は設定値で1つ（PRD FR-17・A22） |
| LINEグループへの案内 | P1 の済んだ状態・P2 の送ったあと | 交流会にLINEグループの招待リンクがあり、アンケートが開いてから出す。ボタン「交流会のLINEグループに参加する」（二番のボタン）。押すと招待リンクが開く（PRD FR-22・A21） |
| アンケートを送る | P2 | 送ったら、同じ画面をお礼の状態に変える。GoogleフォームのURLがあるときだけ「続けて交流会のアンケートへ」を出し、Googleフォームを開く（PRD A20） |
| アンケートを直す | P2 | 開いている間に開き直すと、前の答えが入った状態で出て、送り直せる（PRD A8）。ボタンは「送り直す」【仮決め】 |
| 手でチェックイン | A3 の参加者のタブ | 参加者のタブの上のボタン。押すと、そのタブの中に入力の欄（名前・3つのチップ）を開く（重ねない）【仮決め】。済んだら欄を閉じ、一覧をその場で読み直す |
| 参加者の行 | A3 | 名前・チェックインの時刻・申し込みの媒体・知ったきっかけ・支払い方法（割引を選んでいれば「PayPay・紹介割」のように名前を添える）。手でのチェックインには、手で入れた印と入れた人（PRD FR-7）。押すと直す・取り消すの枠を開く |
| 直す・取り消すの枠 | A3 | 名前と3つのチップ（と、割引があれば割引のチップ・紹介者の欄）を直して「保存」。支払い方法か割引を直すと金額を決め直す。下に危ないの色で「取り消す」。保存・取り消しのあとは枠を閉じ、一覧と合計をその場で読み直す（支払い方法を直すと合計がすぐ変わる。PRD FR-8） |
| 取り消しの確かめ | 直す・取り消すの枠 | 影響が大きいので確かめる：「このチェックインを取り消します。アンケートの回答があれば一緒に消えます」とボタン「取り消す」（構成 AD-7）。確かめは枠の中で切り替えて出し、枠を重ねない【仮決め】 |
| 同じ名前をまとめる | A3 の同じ名前の印がある行 | まとめるときは**LINEのほうを残し、手のほうを取り消す**（構成 AD-7）。手でのチェックインの行の枠に、その旨の1文を出す【仮決め】 |
| 回答を代わりに入れる | A3 の手でのチェックインの行の枠（主催者だけ） | 「アンケートの回答を入れる」から P2 と同じ設問の欄を開く【仮決め：置き場所】。アンケートが閉じていても入れられる（構成 AD-13） |
| 割引と紹介者の内訳 | A3 の合計のタブの内訳（主催者だけ。reception-002） | 割引があった交流会だけ、申し込みの媒体・知ったきっかけの内訳の下に「割引の内訳」（割引ごとの人数・割引の額の合計・最後に割引なし。使うのをやめた割引は印つき）と、紹介者がいれば「紹介者（主催者だけが読めます）」（紹介者ごとの人数・多い順）。合計のカードは今のまま（チェックインごとの金額の和）【仮決め】 |
| 困りごとのタブ | A3（主催者だけ） | 困りごとごとに、名前・月いくら・テスター・仕事の立場・職種（PRD FR-14）。「テスターに『はい』だけ」の絞りこみと、「月いくらの高い順」の並べ替えを表の上に置く。「分からない」と答えていない人は、高い順の最後【仮決め】 |
| アンケートの開閉 | A4 | 「アンケートを開く」「アンケートを閉じる」。今の状態をことばで出す（「アンケートは開いています」）。閉じると新しい回答を受けない（PRD FR-9） |
| 招待のリンク | A4 | 交流会ごとに1本。写す操作と、「作り直す」。作り直すと前のリンクは使えないので確かめる（構成 AD-5） |
| QRの表示と印刷 | A4 | 受付QRとアンケートQRを並べて出し、それぞれ印刷用に保存できる（PRD FR-2） |
| 書き出す | A5 | 「参加者をCSVで書き出す」「困りごとをCSVで書き出す」（PRD FR-15） |
| 参加者のデータを消す | A5 | 消す人を選び、何が消えるか（アカウント・チェックイン・回答）と元に戻せないことを書いて確かめる。ボタンは「削除」（危ないの色）。アカウントのある参加者では、ほかの交流会のチェックインと回答も消える（構成 AD-7 の消え方を、画面に書く）【仮決め：選び方と文】 |

## Interaction Primitives

- **チップはラジオのまとまり**：1つの設問 = 1つのまとまり（設問の名前が見出し）。キーボードでは矢印で移り、選ぶ。押せる所はどれも**高さ 44px 以上**。
- **スマホの本文は 16px 以上**。入力の欄の文字も 16px 以上（小さいと iOS が欄に寄って拡大するため）。
- **チェックインは文字を打たずに終わる**：名前を直すときだけ打つ。受付QRを読んでから1分以内（PRD A12）。
- **一覧画面は5秒おきに読み直す**（TanStack Query。構成の約束）。手でのチェックイン・直す・取り消しのあとは、その場で読み直す。読み直しで画面の位置・フォーカス・開いている枠を動かさない。
- **結果は押した所の近くに**（土台のとおり）。P1・P2 は同じ画面を済んだ状態に変える。トーストだけで伝えない。
- 下に引いて読み直す操作は置かない（5秒おきに読み直すため）【仮決め】。
- 狭い画面の主のボタンは画面の下の、指の届く所に置いてよい（土台のとおり）。キーボードが開いているときにボタンが欄を隠さないこと（Responsive & Platform）。

## Accessibility Floor

土台（WCAG 2.2 AA）に足すことだけ。

- チップのまとまりは、ラジオのまとまりとして読み上げる（設問の名前・選んだか・何番目か）。選んだことは、色ではなく、読み上げとチェックの印でも伝わる。
- チェックインが済んだら、チェックインのカードの見出しにフォーカスを移し、「チェックインしました」と読み上げる。アンケートを送ったあとも同じく、お礼の文にフォーカスを移す【仮決め】。
- 5秒おきの読み直しは読み上げない（変わるたびに話し出さない）【仮決め】。
- 誤りの文は、その欄・その設問と結びつけて読み上げる（土台の入力の誤りのとおり、送ったときは最初の誤りへ）。
- 年長の参加者のため、端末の文字を大きくした設定でも、チップの文字が切れずに折り返す。
- 夜間の停止・未ログイン・権限なしの文は、画面の見出しとして読み上げる。

## Key Flows

### UJ-1 — 佐藤さんが、受付で行列を作らずに入場する

佐藤さん：50代の非エンジニアの営業部長。connpass で申し込み、知人の紹介で知った。初めての参加。

1. 会場の受付に貼られた受付QRを、スマホのカメラで読む。
2. LINE が開き、LINE ログインの同意の画面が出る。公式LINEの友だち追加も勧められるが、しなくてもよい。同意を押す。
3. P1 チェックインの画面が開く。上に交流会の要約（名前・日時・会場・参加費）。名前の欄には LINE の表示名が入っている。佐藤さんは確かめるだけで、打たない。
4. 申し込みの媒体で「connpass」、知ったきっかけで「知人の紹介」、支払い方法で「PayPay」のチップを押す。押したチップに墨のふちとチェックの印が付く。
5. 何をどう使うかの1文を目にし、「チェックインする」を押す。
6. **山場**：画面が「チェックインしました」と交流会の名前のカードに変わる。同じころ、主催者の一覧画面には、5秒以内の読み直しで佐藤さんの行が PayPay で出て、合計のタブの PayPay の人数と金額が1つ増える。
7. カードの案内のとおり、紙の名札を書いて会場に入る。

例外：佐藤さんのスマホだけ電波が弱く、画面が開かない → 失敗の文の「受付の人に声をかけてください」に従い、主催者か受付係が手でチェックインする（UJ-3）。受付QRを読み直すと「チェックイン済み」が出て、記録は増えない。

### UJ-2 — 佐藤さんが、交流会の終わりに困りごとを書く

1. 主催者が A4 で「アンケートを開く」を押し、「アンケートの時間です」と声をかけて、アンケートQRを出す。
2. 佐藤さんは、チェックインの画面を開き直して「アンケートに答える」を押す（か、アンケートQRを読む）。P2 アンケートの画面が開く。
3. 困りごとの欄に「部下にAIをどう使わせればいいか分からない」と書く。
4. 「実現したら月いくらなら使うか」で「1,000円」を押す。設問の下に「答えるだけで、実際には払いません」とある。
5. 「テスターになる」で「はい」を押し、任意の見出しの下で仕事の立場（管理職）を押す。
6. 「送る」を押す。
7. **山場**：同じ画面が「あなたの困りごとが、解決する企画やアプリにつながります」に変わる。
8. その下の「続けて交流会のアンケートへ」を押し、いつもの Googleフォームに答える。

例外：チェックインしていない人がアンケートQRを読む → 「先にチェックインしてください」と「チェックインの画面へ」。アンケートが閉じたあと → 「アンケートは閉じています」。

### UJ-3 — 主催者が、LINE を使わない参加者を受付する

1. 主催者（か受付係）が A3 一覧画面の参加者のタブで「手でチェックイン」を押す。タブの中に入力の欄が開く。
2. 参加者に聞きながら、名前を打ち、申し込みの媒体・知ったきっかけ・支払い方法のチップを押す。
3. 「チェックインする」を押す。
4. **山場**：欄が閉じ、一覧にその人の行が「手でのチェックイン」の印と入れた人の名前つきで出て、合計がその場で増える。ほかの受付係の端末にも、5秒以内に同じ行と合計が出る。参加者はスマホを出していない。
5. アンケートの時間：主催者がその人の困りごとを聞き取り、行の枠の「アンケートの回答を入れる」から代わりに入れる（閉じたあとでも入れられる）。

例外：あとからその人が LINE でもチェックインした → 2つの行に「同じ名前があります」。手でのチェックインの行の枠から「取り消す」を押し、「アンケートの回答があれば一緒に消えます」を確かめて、LINE のほうを残す。

### UJ-4 — 主催者が、交流会のあとに清算する

1. 主催者が A3 一覧画面を開き、合計のタブを押す。
2. 合計のカードに「PayPay ◯人・◯円」「現金 ◯人・◯円」「無料（招待など）◯人・0円」と、全体の合計が出ている。
3. 受付で支払い方法を間違えた人がいれば、参加者のタブでその行を押し、枠で支払い方法のチップを押し直して「保存」。合計のタブに戻ると、数字がもう変わっている。
4. **山場**：手元の現金を数え、合計のカードの現金の金額と見比べる。同じなら、清算はそれで終わる。手で計算することはない。
5. 困りごとのタブで「テスターに『はい』だけ」に絞り、「月いくらの高い順」に並べて、テスターを頼む人を見る。
6. あとで A5 から、参加者と困りごとを CSV で書き出す。

## Responsive & Platform

**LINEミニアプリ（LINE の中の画面）**

- 上には LINE の見出しの帯（題・閉じる）がある。画面の中に、それと重なる「戻る」「閉じる」を作らない。画面の題は中身の最初の見出しで出す【仮決め】。
- 下の端（ホームの印のある端末）を避けて、主のボタンを置く（安全な余白）。キーボードが開いたら、主のボタンが欄を隠さないよう、欄が見える位置へ送る。
- Googleフォーム・プライバシーポリシー・オープンチャットは、アプリの外のページとして開く。開いたあと、LINE の中の画面に戻れること。
- 交流会の始まる前に、主催者が一度画面を開いて起こす（構成 Deferred のコールドスタート）。最初の読みこみが遅いときも、読みこみの印を出し続け、白い画面にしない。
- 受付QR・アンケートQR は、ミニアプリの URL を開く（構成 AD-14）。
- 参加者の画面（P1〜P3）は、外枠のナビを出さない（帯はアプリの名前だけ）。受付係と主催者がスマホで管理の画面を開くと、画面の下にタブバーが出る（ホームの印を避ける余白つき）。

**主催者の PC（管理の画面）**

- 土台の画面の幅の決まり（751px 以下を狭い画面）を引き継ぐ。
- 広い画面の管理の画面は、左にサイドバー（「メニュー」ボタンで隠せる。隠すと本文が広がる）。狭い画面は下のタブバー（上の「外枠のナビ」）。
- 広い画面の A3：参加者は表（名前・時刻・申し込みの媒体・知ったきっかけ・支払い方法・印）。名前は途中で折り返さない（名前の列は名前の長さまで広げ、印の列が残りを使う）。直す・取り消すの枠は、表の右に開く横の枠にする【仮決め】。狭い画面では行をカードにし、枠は画面の下から開く【仮決め】。
- 広い画面の A4：受付QRとアンケートQRを横に並べる。狭い画面では縦に並べる。
- 書き出し（A5）と QR の印刷は、PC で使うことを主に考える【仮決め】（スマホの LINE の中で使えるかは Open Questions）。

## Open Questions

書いたときの論点のうち、2026-11-19 に仮決めにしたもの（【仮決め】。主催者の指示で、決めきれないことは仮決めにして進める）：

- **管理の画面の道**：A1〜A5 は上の表の仮の形で作り、spec-kit の計画で確かめる。
- **受付係がもう一度一覧画面に入る道**：A1 交流会の一覧に、主催者はすべての交流会、受付係は自分が受付係の交流会だけを出す。受付係は LINE のミニアプリを開けば A1 から戻れる。
- **LINEの中でのCSVの書き出しとQRの印刷**：書き出しと印刷は PC で行う。スマホでは、受付QR・アンケートQRを画面に大きく出して、参加者に読んでもらう（印刷しなくても回せる）。
- **オープンチャットのURL**：コミュニティで1つなので、交流会ごとには持たず、設定値（環境変数）で1つ持つ。
- **任意の設問を「答えない」に戻す**：任意のチップの群れに「答えない」を入れ、最初はそれが選ばれている。

まだ決めていないもの：

1. **友だち追加の案内**：未認証のミニアプリで同意の画面に友だち追加が出ないとき（構成 Open Questions 2）、P1 の済んだ状態に友だち追加のリンクを足す。置く場所と言葉は、そのときに決める。
2. **何をどう使うかの文とプライバシーポリシー**：P1 に出す1〜2文の中身と、プライバシーポリシーの URL は、公開前に主催者が用意する（下書きは Claude。PRD B5）。
3. **申し込みの媒体と知ったきっかけの内訳（FR-13）の置き場所**：合計のタブの下に仮に置いた。見本で確かめる。
4. **参加者のデータを消す相手の選び方**：A5 で、その交流会の参加者から選ぶ形にした。頼まれ方（公式LINE。PRD A13）から人を探しやすいかを、最初の削除の依頼のときに確かめる。
