# PRD：kanaeru スイートの共通（アプリの切り替え・台帳・設定）

作成：2026-11-20（主催者の不在中に AI が書いた叩き台。【仮決め】の印は主催者の確かめを待つ）

## 0. この文書について

[Constitution](../../.specify/memory/constitution.md) IV（新しいアプリと共通の機能は、先に PRD を作る）に従い、スイートの共通の機能（アプリの切り替え・アプリの台帳・スイート全体の設定）の範囲を決める短い PRD。作りの決めごとは[構成の決めごと](../architecture-kanaeru/architecture-kanaeru.md) AD-15・AD-16・AD-19、画面の見た目は主催者が確かめたモックアップ（2026-11-20）、作る仕様は [specs/core/005-app-switcher](../../specs/core/005-app-switcher/spec.md)。

## 1. ねらい

kanaeru は「日常のちょっとした課題を解決するスイート」で、受付アプリのあとに2つ目からのアプリ（Threads の運用など）が並ぶ。1つのアカウントで、見えるアプリを行き来し、運営者はデプロイせずにアプリの公開を切り替えたい。利用者は、どのアプリでも同じ場所でアカウントを確かめ、ログアウトや退会ができるようにしたい。

## 2. 使う人

- **運営者**（設定 `ORGANIZER_LINE_USER_ID` の人。AD-5）：作りかけのアプリを本番で自分だけに見せて確かめ、よければ公開する。まずいときは止める。
- **利用者**（ログインした人すべて。受付アプリの主催者・受付係・参加者を含む）：見えるアプリを行き来し、自分のアカウントを確かめ、ログアウト・退会する。

## 3. 用語

| 言葉 | 意味 |
|---|---|
| アプリ | 売る・公開する単位。1つ以上の領域の束（AD-1）。受付アプリ＝event・reception・survey |
| スイートの共通 | どのアプリにも属さない領域（account・suite） |
| アプリの台帳 | アプリごとの公開の状態の一覧（運営者だけが変える） |
| 公開の状態 | 切（だれにも見えない）・運営者だけ・公開（だれにでも見える） |

## 4. 機能

#### FS-1：アプリを1行で登録する

- アプリは、静的な一覧に1行で登録する（key・名前・短い説明・説明・属する領域・道の頭・使ってよいほかのアプリ・退会で消える記録）。受付アプリを最初の1行にする（今の道 `/admin/events/…`・`/e/…` は変えない）。
- 受け入れ：どの領域も、ちょうど1つのアプリか、スイートの共通に属する。key は一意で、予約語（道の頭と取り合うもの）でない。

#### FS-2：アプリの公開を台帳で切り替える

- 運営者は、設定の「アプリの台帳」で、アプリごとに切・運営者だけ・公開を選ぶ。押すとすぐに効く（デプロイは要らない）。
- 台帳に行がないアプリは「運営者だけ」。受付アプリは「公開」の行を最初から持つ（本番のふるまいを変えない）。
- 見えないアプリの画面と窓口は「ない」（404）。参加者が外から開く画面も同じ。
- 受け入れ：運営者だけが変えられる。変えると、切り替え・ナビ・すべてのアプリにすぐ効く。

#### FS-3：アプリを切り替える

- 見えるアプリが2つ以上のとき、PC はサイドバーの上、スマホは上の帯の右に切り替えを出す。1つのときは今と同じ見た目。
- 切り替えには、見えるアプリ（今のアプリにチェック。運営者には「運営者だけ」の札）と「すべてのアプリ」を出す。スマホは「設定」も出す。
- ナビには、今のアプリの項目だけを出す。
- はじめの画面は、この端末で最後に使ったアプリ。なければ見える最初のアプリ。
- 受け入れ：アプリの名前を外枠に書かない（一覧から出す）。

#### FS-4：すべてのアプリ

- 見えるアプリをカードで並べ、説明と「開く」を出す。運営者には「運営者だけに見えています」の札と、アプリの台帳への入口を出す。

#### FS-5：スイート全体の設定

- 入口：PC は上の帯の右の「設定」、スマホはアプリの切り替えの一番下（切り替えがないときは上の帯の右）【仮決め】。
- まとまり：個人の設定（アカウント。あとで AI の API キー）／アプリの設定（各アプリが自分の項目を出す。見えないアプリの項目は出さない）／運営（運営者だけ。アプリの台帳）。
- アカウント：表示名・ログインの方法（LINE）・登録した日・使えるアプリ・ログアウト・退会。
- 退会：アカウントと、すべてのアプリの本人の記録を消す。消える記録と、元に戻せないことを確かめてから消す（AD-7・Constitution II）。ほかの人が書きこむ記録を持っていれば、消さずに理由を伝える（AD-19）。

## 5. この版で作らないもの

- 契約（`entitlement`）と売り方（スイート・単体）。売り始めるときに作る（AD-16）。台帳の売り方の列も、そのときに足す【仮決め】。
- AI の API キーの画面（AD-20 の機能を作るときに足す）。
- 各アプリの設定の項目（しくみだけ作る。項目はアプリが足す）。
- アプリごとのアイコンの画像（線のアイコンの種類から選ぶ）。

## 6. 成功の基準

- 運営者が、デプロイせずに新しいアプリを自分だけに見せ、公開し、止められる。
- 受付アプリだけの間、受付係と参加者の画面が今と変わらない。
- 利用者が、設定からログアウト・退会できる。
