# 名前の調べもの（brand-name-research）

アプリ・スイート・サービスの名前の候補を渡されたら、**同じ指示をもう一度もらわなくても**、Web・商標（J-PlatPat）・ドメイン・そのほかを一度に回して、使ってよいかを短く報告する。2026-11-25 の名前決め（PaletMate → PaletKit）で、手で何度も繰り返した調べものを型にしたもの。

## 前提として読むもの

- [CLAUDE.md](../../../CLAUDE.md) と `docs/rules/`
- [決めたことの記録](../../../docs/decisions.md)：すでに調べた名前と結果（見送った名前とその理由）。**同じ名前を調べ直さない**
- 名前を変える作業（リポジトリ名・文書の置き換え）は、このスキルの範囲の外。調べた結果を報告し、主催者が決めてから行う

## 守ること

- **答えは日本語**。名前は、綴り（英字）と読み（カタカナ）の両方で扱う。
- **主張には出典**（URL と確かめた日）。確かめきれないものは「要確認」。**「見つからなかった」は「ない」の証明ではない**と、報告に書く。
- **法律の判断はしない**。似ているかどうかの最終判断は、弁理士に任せる。結果は「衝突の可能性が低い／高い」の見立てで書く。
- **自動のアクセスを断るサイトを、回避しない**。J-PlatPat は、curl・ヘッドレスブラウザ（Playwright など）を 403 の拒否ページに飛ばす。User-Agent の偽装などで抜けない。使えるのは、主催者の Chrome を操作する Claude in Chrome だけ。
- **アクセスは最小限**。J-PlatPat は、名前1つにつき検索を数回まで。終わったら開いたタブを閉じる。
- **このリポジトリは公開**。個人の名前・連絡先・メールアドレスは、調べものにも報告にも、検索の語にも入れない。
- 主催者に質問して止まらない。足りない情報は仮決めにして、報告に【仮決め】と書く。
- 名前を決める・リポジトリ名を変える・ドメインを取るのは、主催者の操作。勝手にしない。

## 流れ

### 1. 受け取る

- 候補ごとに、**綴り**（例：`PaletKit`）と**読み**（例：パレットキット）を取り出す。読みが割れる名前（例：Sidy → サイディ／シディ）は、読みを全部挙げる。
- **綴りを確かめる**。1文字違い（例：`palletmate` と `paletmate`）で、まったく別の結果が出る。調べる前に、取り出した綴りをもう一度見る。
- 候補が多いときは、先にドメインと Web（2 と 3）で落とし、残った上位3つだけを J-PlatPat（4）にかける。

### 2. ドメイン

RDAP で確かめる（whois の文面の判定は当てにならない）。**必ず、登録済みのドメイン（`google.com` など）で、「登録済み」が返ることを先に確かめる**。

| ドメイン | 確かめる先 | 登録なし |
|---|---|---|
| .com | `https://rdap.verisign.com/com/v1/domain/<名前>.com` | HTTP 404 |
| .app | `https://pubapi.registry.google/rdap/domain/<名前>.app` | HTTP 404 |
| .io・.ai | `https://rdap.identitydigital.services/rdap/domain/<名前>.io` | HTTP 404（.ai は確度がやや低い） |
| .jp | `whois -h whois.jprs.jp <名前>.jp/e` | `No match` |

- 候補ごとに `.com`・`.app`・`.io`・`.jp` の表にする。登録済みでも、売り物や放置の場合がある（中身は要確認）。
- ドメインの取得は、主催者の操作。取る場所（Cloudflare など）を聞かれたら案内する。

### 3. Web で調べる

WebSearch で、次を調べる。`OR` は効かないことがあるので、名前ごとに分けて検索する。

- 同じ名前・近い名前のアプリ（App Store・Google Play）・サービス・会社・オープンソース（GitHub）
- 読みが同じで綴りが違う名前（例：PaletKit と PaletteKit）
- 同じ分野（AI アシスタント・業務支援など）の有名なサービスとの近さ
- 検索したときに、別のものが上に出て埋もれないか

結果は、「見つからず」「近い名前あり（名前・何か・出典）」「同名あり」に分ける。

### 4. J-PlatPat の商標検索

**Claude in Chrome が必要**。ツール（`mcp__claude-in-chrome__*`）が見えなければ、次を主催者に伝える（前の名前決めで詰まった所）。

1. セッションを `claude --chrome` で始める。または `/chrome` を使い、つながらなければ入れ直す（`/resume` で会話に戻れる）。
2. Claude Desktop の「プラグイン → Claude in Chrome」のスイッチが**有効**であること。
3. Chrome の `chrome://extensions` で、Claude の拡張機能が**有効**であること（無効のままだと、接続されたブラウザが0件になる）。
4. Chrome を完全に終了して開き直し、同じアカウントで claude.ai にログインしている。
5. それでもつながらないときは、**主催者が手で検索して、結果の画面を貼る形**にする（`称呼検索` の手順を伝える）。

**手順**（画面の部品は、`find` で参照を取って確かめる。座標は決め打ちしない）：

1. `tabs_context_mcp`（`createIfEmpty`）→ `https://www.j-platpat.inpit.go.jp/t0100`（商標検索）を開く。3〜4秒待つ。
2. 検索項目が「**称呼(類似検索)**」の行のキーワード欄に、**カタカナの読み**を入れる。
   - 入れられるキーワードは**2個まで**（スペース区切りで OR）。3つ以上は「入力エラー」になるので、分けて検索する。
   - 読みが割れる名前は、両方を入れる（例：`サイディパレット シディパレット`）。
3. ページの下の「検索」を押す。検索ボタンは `find` では見つからない。**ページを最後までスクロールして、スクリーンショットで位置を確かめる**（2026-11-25 の画面では、最後までスクロールした画面の中央より少し下で、座標は (698, 570) だった。画面が変わっていれば取り直す）。結果が出るまで4秒ほど待つ。
4. 結果の「**区分別**」と一覧を見る。`get_page_text` は空になるので、スクリーンショットで読む。
   - 区分別のリンク（`09(9件)` など）を押すと、その区分だけに絞れる。**第9類で絞ると第42類は一覧から消える**ので、第42類は、区分別のリンクを押して別に見る（「全て」を戻さなくても、並んだリンクを直接押してよい）。
   - 上の「検索ヒット件数」は、絞り込んでも全件数のまま変わらない。

**読み方**：

- **見るのは、第9類（ダウンロードするアプリ）と第42類（ソフトウェアの提供・SaaS）**。ほかに、事業に近い区分（第35類 事業の支援・第41類 教育や情報の提供）に、同じ読みがあれば書く。
- 一覧の「称呼（参考情報）」「区分」「権利者」「ステータス（存続・登録・継続など）」を読む。**同じ区分で、読みが同じか、ほぼ同じ登録**があれば、衝突の可能性が高い。
- 称呼の参考情報に、**「パレット」のような短い読み単独**が入っている登録は、「パレット」を含む名前と、略した読みで似ていると見られる余地がある。注意として書く。
- **「パレット」のような共通の語が、第9・42類に多数ある場合**（例：「〇〇パレット」型が10件ほど）は、どれも語頭が違えば、通常は似ていないと見られる。ただし、共通の語が密集している分野は、**審査で似ているとされやすい、あとから出願が増える（出願中の登録が複数ある）**と見て、「△」にして、報告に書く。名前の語頭が、既存の語頭（例：マイ・メタ・メーク）に近いほど、注意を強める。
- 類似検索は、似た読みを広く拾う（件数が多くなる）。ほとんどは別の区分の別のものなので、**第9・42類に絞って**（区分別のリンクで絞れる）内容を読む。
- 「簡易検索」は、検索の対象が限られているので使わない。
- 出願中のものも対象。**これから出願される分は、見えない**。

**サービスの停止**：トップ画面の「重要なお知らせ」に、全サービス停止の予定が出る。停止の前に終える。

**補助の確かめ**（時間があるとき）：綴り（`PaletKit` などの英字）を「商標(検索用)」でも検索する。

### 5. そのほかに調べること

名前の使いやすさと、あとの困りごとを減らすための確かめ。重要なものから、時間の許す範囲で。

- **読みと綴り**：読みが割れないか。日本語の話し言葉で言いやすいか（長すぎないか）。電話や口頭で伝えやすいか。
- **意味と印象**：別の言語で、悪い意味・下品な意味にならないか。一般の語（検索で埋もれる）か、造語か。
- **同じ名前の会社・屋号**（法人番号公表サイトで、会社名を検索）：商標がなくても、広く知られた名前に似せると、不正競争防止法の問題になりうる。
- **SNS のアカウント名**：X・Instagram・GitHub の組織名・Threads・note で、同じ名前が使われていないか（開いて確かめる）。
- **ストアの名前**：App Store・Google Play で、同じ名前のアプリがすでにないか（ストアでは、同じ名前は使えない）。
- **LINE 側**：LINE の公式アカウント・ミニアプリの名前が、規約の上で使えるか（LINE Developers の決まり）。
- **パッケージ名**：公開するライブラリなら、npm などの名前が空いているか。
- **海外**：海外にも出すなら、WIPO の Global Brand Database・米国商標庁（USPTO）・EUIPO で、近い名前を調べる。
- **今の名前との関係**：リポジトリ名・内部の名前（`kanaeru` など）とのずれ。変えるときの影響（Terraform の `github_repository`・認証の条件・文書の置き換え）。

### 6. 報告する

名前ごとに、次の表にする。判定は ◎（問題なし）／○（小さな注意）／△（注意が要る）／✕（避ける）。

| 名前（綴り／読み） | ドメイン | Web | J-PlatPat（第9・42類） | そのほか | 判定 |
|---|---|---|---|---|---|

- 表のあとに、**見た根拠**（いちばん近い登録・サービス：名前・区分・権利者・出典）と、**確かめられていないこと**（J-PlatPat は称呼検索のみ・これから出願される分・弁理士の確認・海外・ストア）を書く。
- **次の一歩**を1〜2行で。例：「この名前で進める → 公開前に Google Play・LINE の類似名を確認。弁理士への相談は任意だが、有料で売る・広告やロゴに費用をかける前なら推奨」「別の候補を出す」。弁理士の確認は義務ではないので、必須のように書かない。
- **決まったら**、`docs/decisions.md`（1行に1つの一覧）に、決めた名前・理由・見送った名前とその理由・確かめていないことを1行で足す。名前を変える作業（リポジトリ名・文書の置き換え）は、主催者の確認のあとに、別の小さな PR として行う（Terraform が apply 済みなら、`github_repository` の更新が先に要る）。
- コミット・push・PR は、[開発の流れの決まり](../../../docs/rules/development-flow.md) 4 のとおり、主催者に頼まれたときだけ行う。
