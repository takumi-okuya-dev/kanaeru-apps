# Feature Specification: 割引・紹介割（reception-002）

**Feature Branch**: `feature/reception-002-discounts`（`feature/core-003-app-shell` の上に積む）

**Created**: 2026-11-19

**Status**: Draft

**Input**: 2026-11-19 に開発者が決めたこと：割引は**交流会ごと**に主催者が登録する（名前と円の額。例：紹介割 1,000円。いくつでも。登録がなければ割引の画面は出さない）。割引ごとに「紹介者の名前を聞く」の印を持つ。**参加者がチェックインのときに選ぶ**（チップ：割引なし／割引ごとに「−1,000円」。既定は割引なし）。受付係・主催者も手でのチェックインで選べ、直す枠で直せる。**紹介者の名前は任意で記録**し、選んだ割引が印を持つときだけ「紹介してくれた人の名前」の欄を出す。これは PRD の決定 B1（参加費は1つの金額・区分なし）を変える。

**この仕様は event の領域も変える**：割引の定義（`event_discount` の表・交流会の入力と答え・A2 の割引の節）は event が持ち、reception はそれを `index.ts` から読んで、チェックインに写す。event の変更と reception の変更は、別のコミットに分ける。

## Clarifications

### Session 2026-11-19

開発者が不在のため、AI が仮に決めた（【仮決め】。理由は [research.md](./research.md)）。金額の決まり（R5）は開発者と合意ずみ。

- Q: 割引は消せるか → A: 消さない。「使うのをやめる」（新しいチェックインで選べなくする）だけ。チェックインに写した名前と額は変わらない【仮決め R1】
- Q: 割引の登録の場所 → A: A2（交流会の作成・編集）のフォームの中の「割引」の節。交流会と一緒に保存する【仮決め R2】
- Q: 金額 → A: 無料なら0円、ほかは max(参加費 − 割引の額, 0)。決めるのは作るときと、支払い方法か割引が変わったときだけ。割引の名前と額はチェックインに写す【合意 R5】
- Q: 割引を変えずに支払い方法だけ直したとき、割引の額は → A: チェックインに写した額を使う（あとで割引を直しても持ち込まない）。参加費はその時のもの【仮決め R5】
- Q: 紹介者の名前をだれが読めるか → A: 主催者だけ（一覧・直す枠・内訳・CSV）。参加者と受付係は入れられるが、保存したあとは読めない【仮決め R7】
- Q: 使うのをやめた割引のチェックインを直すとき → A: 割引を変えなければそのまま保存できる。別の割引に変えるときは、使っている割引だけ選べる【仮決め R6】

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 主催者が交流会に割引を登録する (Priority: P1)

主催者は A2 の「割引」の節で「割引を足す」を押し、名前（紹介割）・額（1,000）・「紹介者の名前を聞く」を入れて保存する。直すと、すでにあるチェックインの割引と金額は変わらない。外した割引は、新しいチェックインで選べなくなる。

**Why this priority**: 割引を選ぶ前提。

**Independent Test**: 主催者で交流会に割引を2つ足し、1つを外して保存すると、要約・交流会の答えに残りの1つだけが出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 主催者, **When** 交流会に「紹介割・1,000円・紹介者の名前を聞く」を足して保存する, **Then** 交流会と要約の `discounts` に出る
2. **Given** 同じ名前の割引を2つ, **When** 保存する, **Then** 2つ目の名前の欄のそばに誤りが出る
3. **Given** 使われた割引, **When** 外して保存する, **Then** 新しいチェックインで選べず、すでにあるチェックインの割引の名前・額・金額は変わらない
4. **Given** 受付係, **When** 交流会の窓口に割引を送る, **Then** 403

---

### User Story 2 - 参加者がチェックインで割引を選び、紹介者の名前を入れる (Priority: P1)

参加者は P1 で、支払い方法のあとの「割引」のチップ（割引なし／紹介割（−1,000円））から選ぶ。「紹介者の名前を聞く」の割引を選ぶと、その下に「紹介してくれた人の名前」（任意）の欄が出る。

**Why this priority**: 割引の本体。

**Independent Test**: 参加費 5,000円・紹介割 1,000円の交流会で、紹介割と紹介者の名前を選んでチェックインすると、金額 4,000円で記録されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 割引のない交流会, **When** P1 を開く, **Then** 割引の設問は出ない
2. **Given** 割引のある交流会, **When** P1 を開く, **Then** 「割引なし」が選ばれていて、紹介者の欄は出ない
3. **Given** 参加費 5,000円・紹介割 1,000円, **When** 紹介割を選び、紹介者の名前を入れてチェックインする, **Then** 金額は 4,000円、割引の名前と額が写る
4. **Given** 参加費 500円・割引 1,000円, **When** チェックインする, **Then** 金額は0円（0より下にしない）
5. **Given** 無料（招待など）, **When** 割引を選んでチェックインする, **Then** 金額は0円
6. **Given** 使うのをやめた割引・別の交流会の割引, **When** その ID で送る, **Then** 400 `DISCOUNT_UNAVAILABLE`（割引の設問のそば）

---

### User Story 3 - 受付係・主催者が手で割引を選び、直す (Priority: P1)

手でのチェックインと直す枠にも割引のチップと紹介者の欄がある。割引か支払い方法を直すと金額を決め直す。受付係は紹介者の名前を入れられるが、保存したあとは一覧にも枠にも出ない。

**Acceptance Scenarios**:

1. **Given** 受付係, **When** 紹介割と紹介者の名前で手でチェックインする, **Then** 一覧の答えの紹介者は null（主催者の一覧には出る）
2. **Given** 割引なしのチェックイン, **When** 紹介割に直す, **Then** 金額を決め直す（参加費 − 割引）
3. **Given** 割引の額をあとで直した, **When** 名前だけ直す, **Then** 金額・割引の額は前のまま
4. **Given** 割引の額をあとで直した, **When** 支払い方法だけ直す, **Then** 割引の額は写したまま、参加費は今のもので決め直す
5. **Given** 受付係が直す枠を開く, **When** 紹介者の欄を空のまま保存する, **Then** 主催者が読む紹介者の名前は変わらない

---

### User Story 4 - 主催者が割引の使われ方と紹介者を見る (Priority: P2)

合計のタブは今のまま（支払い方法ごとの金額の和）。主催者だけの内訳に、割引ごとの人数と割引の額の合計、紹介者ごとの人数が出る。参加者の CSV に「割引」「割引の額」「紹介者」の列が足される。

**Acceptance Scenarios**:

1. **Given** 紹介割で 5,000円の交流会に1人, **When** 合計を見る, **Then** 4,000円
2. **Given** 主催者, **When** 内訳を見る, **Then** 紹介割1人・割引の額 1,000円・紹介者の名前1人が出る
3. **Given** 受付係, **When** 内訳・CSV を呼ぶ, **Then** 403
4. **Given** 主催者, **When** CSV を書き出す, **Then** 割引・割引の額・紹介者の列がある

### Edge Cases

- 割引の額が参加費より大きい：金額は0円。
- 交流会の参加費や割引を直したあと：すでにあるチェックインの金額・割引の名前と額は変わらない。
- 割引なしを選ぶと、紹介者の名前は残さない（送っても空にする）。
- 紹介者の名前は50文字まで・前後の空白を除く・空なら記録しない。ログに出さない。
- 紹介者の名前の本人から消してほしいと頼まれた：主催者が直す枠でその欄を空にする（自動では探せない。research R7）。
- 前の版のアプリ（割引を知らない）が同じ DB で動いても壊れない（足すのは表と空を許す列だけ）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**（event）：event が `event_discount`（交流会・名前・額〈円・1以上〉・紹介者の名前を聞くか・使うのをやめた時刻）を持つ。交流会は `RESTRICT`、行は消さない。
- **FR-002**（event）：交流会の入力に `discounts`（`{ id?, name, amount, asksReferrer }` の並び・10まで・名前は1〜30文字で重ねない）を足す。送らなければ割引は変えない。送った並びにない使っている割引は「使うのをやめる」。
- **FR-003**（event）：交流会（`EventView`）と要約（`EventSummary`）に、使っている割引の並び（`id・name・amount・asksReferrer`。作った順）を足す。event の `index.ts` が `findEventDiscount`・`listEventDiscounts`・`eventDiscountTable`（外部キーのためだけ）を出す。
- **FR-004**：`checkin` に `discount_id`・`discount_name`・`discount_amount`・`referrer_name`（どれも空を許す）を足す。`(event_id, discount_id)` は `event_discount(event_id, id)` を指す（`RESTRICT`。別の交流会の割引を指せない）。
- **FR-005**：チェックインの入力に `discountId`（任意・空なら割引なし）と `referrerName`（任意）を足す。新しいチェックインと割引を変えるときは、その交流会の使っている割引だけ選べる（違えば 400 `DISCOUNT_UNAVAILABLE`）。
- **FR-006**：金額は、無料なら0円、ほかは max(その時の参加費 − 割引の額, 0)。決めるのは作るときと、支払い方法か割引が変わったときだけ（AD-6 を広げる）。割引を変えたときは、その割引の今の名前と額を写す。
- **FR-007**：紹介者の名前は、割引を選んだときだけ記録する。答えに入れるのは主催者のときだけ（受付係・参加者には null）。直すとき `referrerName` を送らなければ、割引が同じなら前の名前を残し、割引が変われば空にする。
- **FR-008**：主催者だけの内訳に、割引ごとの人数と割引の額の合計（無料の人を除く）・割引なしの人数・紹介者ごとの人数を足す。参加者の CSV に「割引」「割引の額」「紹介者」を足す。
- **FR-009**：画面：P1・手でのチェックイン・直す枠に「割引」のチップ（割引なし＋使っている割引〈直す枠では、今の割引が使うのをやめたものでも出す〉）と、選んだ割引が聞くときだけ「紹介してくれた人の名前」（任意）。割引のない交流会には出さない。一覧の行の支払い方法に割引の名前を添える。A2 に割引の節。合計のタブの内訳に割引と紹介者の表。
- **FR-010**：入力の形・エラーの文言は、event の割引は `packages/contracts/src/event/`、チェックインの割引は `packages/contracts/src/reception/`。

### Key Entities

- **割引**（event）：交流会ごとの名前と額。使うのをやめられるが消えない。
- **チェックインの割引**（reception）：選んだ割引の ID と、そのときの名前と額の写し。紹介者の名前（主催者だけが読む）。

## Success Criteria *(mandatory)*

- **SC-001**：`pnpm check` が通る。
- **SC-002**：主催者が紹介割 1,000円を登録 → 参加者が紹介割と紹介者の名前でチェックイン → 5,000円の交流会の合計が 4,000円 → 主催者が CSV と内訳で紹介者を見る、が E2E で通る（1440px・375px で axe の違反0件）。
- **SC-003**：金額の決まり（参加費 − 割引・0で止める・無料は0・写しはあとの直しで変わらない・支払い方法や割引を変えると決め直す）・権限（受付係は紹介者と内訳を読めない）・CSV の列が、本物の PostgreSQL の結合のテストで通る。

## Assumptions

- お金は預からない（Constitution I）。割引も記録するだけ。
- 学割などの「本人の申告」は確かめない（受付で見る）。
- プライバシーポリシーの下書き（別のブランチ）の「集める情報」に、紹介者の名前と割引を足す必要がある（ここでは直さない。research R12）。
- 機能の印では止めない（割引を登録しなければ何も出ない）。
