## User Scenarios & Testing *(mandatory)*

### User Story 1 - 参考の投稿とキーワードを直す (Priority: P1)

参考の投稿を、URL・反応の数・投稿者・メモ・なぜ良いかと一緒に何件かまとめて足し、あとから全部の欄を直す。キーワードも直す。

**Acceptance Scenarios**:

1. **Given** 参考の投稿, **When** 「なぜ良いか：未入力」を押す, **Then** 直す枠が開き、保存すると一覧に出る
2. **Given** ほかで先に直された参考の投稿, **When** 保存, **Then** 409 で、読みこみ直すよう出る
3. **Given** 同じキーワード, **When** 別のキーワードをそれに直す, **Then** 欄のそばに出る

### User Story 2 - ホームから次にやることへ進む (Priority: P1)

`/threads` を開くと最後に開いた運用アカウントのホームへ移り、次にやることと材料の数がわかる。題の上の切り替えから別の運用アカウントへ移れる。

### User Story 3 - 迷わずに Threads へつなぐ (Priority: P2)

5つの手順と詳しい手順を見てトークンを貼る。形が違えば送る前に欄のそばに出る。失敗が続けば待ちの間ボタンが止まる。自分の別の運用アカウントがつないでいれば一覧へ案内される。

### User Story 4 - 戦略を書き進める (Priority: P2)

進みのカードで次におすすめの項目へ移り、活動の軸を5問から整理する。保存せずに離れようとすると確かめ、ほかの画面で先に保存されていれば読みこみ直すか上書きするかを選ぶ。

### User Story 5 - 宣伝にイベントの情報を入れ、カードから止める (Priority: P2)

### User Story 6 - 反応を投稿ごとに CSV で書き出す (Priority: P2)

めぐると同じ列で、案をためたときの材料の版つき。一覧は50件ずつ続きを読む。

### User Story 7 - 設定で投稿できるかを確かめ、消すときは名前を入れる (Priority: P3)

## Requirements *(mandatory)*

- **FR-1**: 直す・状態を変えるはどれも読んだ版と同じときだけ受ける。
- **FR-2**: 持ち主だけ（ほかの人の運用アカウントは 404。開いた記録もほかの人のものは書かない）。
- **FR-3**: 連携の解除は、運用アカウントがなくても受けて残す。ユーザー ID はハッシュだけを持つ。
- **FR-4**: トークン・Threads の答えの本文をログに出さない（ID とエラーの種類だけ）。
- **FR-5**: 消す確かめの名前と、宣伝・参考の投稿の上限は API が確かめる（画面の判定は出すためだけ）。
