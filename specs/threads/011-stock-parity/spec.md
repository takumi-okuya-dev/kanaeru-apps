## User Scenarios & Testing *(mandatory)*

### User Story 1 - 選んだ案をまとめて承認し、できなかったものの理由がわかる (Priority: P1)

承認待ちの案を選んでまとめて承認すると、責任の文と内訳の確かめを経て、承認できるものだけが承認される。結果は「N件を承認しました。M件は承認できませんでした（NGワード 1件・件数の上限 1件）」。

**Acceptance Scenarios**:

1. **Given** NG ワードを含む案とふつうの案, **When** まとめて承認, **Then** ふつうの案だけ承認され、もう1件は理由つきで残る（選んだまま）
2. **Given** 規約に注意の案, **When** 確かめなしで承認を送る, **Then** `POLICY_CONFIRM_REQUIRED`。画面の確かめを経ると承認される
3. **Given** 承認済みが500件, **When** 承認, **Then** `LIMIT`
4. **Given** 同じ requestId の送り直し, **Then** 二重に変えず、記録も1行
5. **Given** 選んだ案のどれも承認できない, **Then** 「選んだN件を承認」は押せない

### User Story 2 - 案を片付ける (Priority: P1)

承認待ち・却下の案を選んで消す（確かめる）。承認済みは選んで承認待ちに戻す。投稿済みは消せない。ためた直後なら「取り消す」で1回分を消し、貼った文が欄に戻る。

### User Story 3 - 承認済みの案を直す (Priority: P2)

承認済みの案を直して保存すると、承認待ちに戻り「もう一度承認してください」と出る。

### User Story 4 - 似ている案を見比べる (Priority: P2)

承認待ちのどの案にも似ている度合い（％）が出る。押すと似ている案を3件まで開き、押すとその案へ移る。似ている案があれば、却下の枠で「似た投稿がある」がはじめから選ばれる。

### User Story 5 - NG ワードをまとめて足す (Priority: P2)

設定で「絶対、必ず儲かる」のように区切って足すと、まとめて足され、もうある語は知らせる。足した語を含む承認済みの案は承認待ちに戻る。数は「N／200語」。

### User Story 6 - 案を作るの流れ (Priority: P2)

開くとプロンプトができ、「プロンプトに入っている情報」で中身の数と直す画面がわかる。貼ってためると画面に残り、結果と「取り消す」が出る。貼った文があるまま離れようとすると確かめる。承認待ちが上限ならためられないことを先に出す。

## Requirements *(mandatory)*

- **FR-1**: 承認・却下・承認待ちに戻すは、案の鍵（ためる・投稿の取り出し・NG ワードを足すと同じ）で1つずつにし、上限は同じ要求で先に変えた分も数える。
- **FR-2**: 承認の確かめ（NG ワード・Threads の上限・規約に注意・上限）は API が行う。画面の判定は出すためだけ。
- **FR-3**: 投稿済みの案は消せない（反応の記録を残す）。
- **FR-4**: まとめて消す・取り消す・まとめて付ける・NG ワードを足す・入れ直しは操作の記録に残す（送り直しで変えていなければ書かない）。
- **FR-5**: 持ち主だけ（ほかの人の案・まとまりは 404 か `NOT_FOUND`）。
