## User Scenarios & Testing *(mandatory)*

### User Story 1 - Threads につなぐ (Priority: P1)

設定の「Threads への接続」に、自分の Meta のアプリで作った長期のアクセストークンを貼って「つなぐ」。つながると「@ユーザー名 につなぎました。」と出て、状態が「接続済み」になる。

**Acceptance Scenarios**:

1. **Given** 未接続, **When** 空のまま「つなぐ」, **Then** 欄のそばに「トークンを貼ってください。」
2. **Given** 期限が1時間のトークン, **When** 貼る, **Then** 「期限が48時間より短いトークンです…」
3. **Given** 10分に5回失敗した, **When** 6回目, **Then** 429 と「少し止めています。10分ほど待ってから…」（Threads に問い合わせない）
4. **Given** 投稿の権限がないトークン, **When** 貼る, **Then** つながり、「自動投稿はできません」と案内する
5. **Given** ほかの運用アカウントがつないでいる Threads のアカウント, **When** 貼る, **Then** 409
6. **Given** つないでいる, **When** 「接続を切る」→ 確かめの枠で「切る」, **Then** 未接続になり、自動投稿がオフになる

### User Story 2 - 自動投稿の時刻を決める (Priority: P1)

設定の「自動投稿」で、オンにして時刻（日本時間）を入れて保存する。

**Acceptance Scenarios**:

1. **Given** 未接続, **When** オンで保存, **Then** 409「Threads に投稿できる状態でないため…」
2. **Given** 07:00 を入れた, **When** 保存, **Then** 欄のそばに「07:00 は選べません。夜間（0時〜8時）は DB が止まるため、08:30〜23:00 の中から…」
3. **Given** つないでいる, **When** 12:00 と 19:30 でオン, **Then** 「自動投稿をオンにしました（1日2回）。」

### User Story 3 - 承認した案が自動で投稿される (Priority: P1)

時刻が来ると、承認済みの案が投稿の順に Threads へ投稿される。投稿の案の画面の上に「次の投稿」と知らせが出る。

**Acceptance Scenarios**:

1. **Given** 承認済みが2件で、2件目に「次に投稿する」, **When** 時刻が来る, **Then** 2件目が投稿され、投稿済みに Threads へのリンクが出る
2. **Given** 承認したあとに NG ワードを足した, **When** 時刻が来る, **Then** その案は承認待ちに戻り、知らせ「投稿の直前に承認待ちへ戻しました（NGワード：…）」
3. **Given** Threads が一時的に失敗し続ける, **When** やり直しと持ち越しを使い切る, **Then** 「投稿に失敗」になり、知らせが出る。「承認し直す」で投稿の順に戻せる
4. **Given** トークンが使えなくなった, **When** 時刻が来る, **Then** 「接続し直しが要る」になり、案は承認済みのまま
5. **Given** 公開の答えが失われた, **When** 次の回, **Then** 二重に投稿せず、投稿の一覧と照らし合わせて投稿済みにする

## Requirements *(mandatory)*

- **FR-1**: トークンは包んで持ち、画面・ログ・エラーに出さない。鍵の設定がなければ接続は 503。
- **FR-2**: 接続の状態は 未接続・接続済み・接続し直しが要る。期限の近いトークンは定期の仕事が延ばす。
- **FR-3**: 投稿の時刻は 08:30〜23:00・10個まで。オンにする前に投稿の権限を確かめる。
- **FR-4**: 自動投稿は上の Clarifications の決まりで進め、同じ時刻を二重に投稿しない。
- **FR-5**: 定期の仕事の窓口は合言葉がなければ 404。
- **FR-6**: 画面は kanaeru の部品と値だけで作り、夜間の停止を画面に書く。
