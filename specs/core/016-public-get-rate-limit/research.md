# Research: ログインなしで読める道の読む要求の回数の制限（core-016）

## R1. 効かせる道の決め方：領域が `publicReadPaths` で出す

- **今**：`app.ts` の IP ごとの制限は `applies: !SAFE_METHODS.test(method) && !BOOKING_WEBHOOK_PATH.test(path)`。読む要求（GET・HEAD・OPTIONS）は数えない。ログインした画面は一覧を5秒おきに読み直す（Consistency Conventions）ので、読む要求をすべて IP ごとに数えると、受付の端末が並ぶ会場（1つの IP）で止まる。だから読む要求は、ログインなしで読める道だけを数えたい。
- **選んだ形**：領域の `index.ts` が `publicReadPaths`（ログインなしで読める道の頭の並び。例 `["/api/v1/match/views/", "/api/v1/match/joins/"]`）を出し、組み立てが `withdrawal`・`eventLinkRestriction` と同じく集める。組み立ては業務を知らず、領域の名前も書かない。
- **頭の形の確かめ**：`/api/v1/<領域>/<道>/` の形（`/` で終わる。`/views` だと `/viewsx` まで入るため）で、名前のある領域は自分の領域の下だけ。領域全体（`/api/v1/<領域>/`）は止める（ログインした画面の読み直しまで数えないため）。合わなければ起動を止める。
- **選ばなかった形**：
  - `app.ts` に道の頭の一覧を書く（`BOOKING_WEBHOOK_PATH` と同じ形）：いちばん短いが、組み立てに業務の道を書くことになり、領域を足すたびに共通のファイルを直す（[並行開発の決まり](../../../docs/rules/parallel-development.md) 3-1）。
  - 道の名前の決まり（`/api/v1/<領域>/public/…`）：試合表の道（`/views/`・`/joins/`）は構成の決めごと AD-26・AD-30 で決まっていて、道を変えると約束と画面を直すことになる。
  - ログインしていない要求（クッキーなし）の GET をすべて数える：クッキーを読むのは account の役目（AD-12）で、組み立てがクッキーの有無で分けると、ログインの切れた端末の読み直しも数えることになる。
  - `createRoute` の `middleware` に領域が付ける：数え方が領域ごとに散り、`trustedProxyHops` などの設定を領域に渡すことになる。

## R2. 数：60秒に600回（IP ごと）【仮決め】

- **見積もり**（1つの IP の後ろの体育館の Wi-Fi・携帯の CGNAT。30人が見るだけのページを開いたまま）：
  - 版の確かめ：30秒おき × 30人 = 1分に60回
  - 版が変わったときの読み直し：1回の変更で30回（運営が1分に1回以上変えても、端末が1台なので多くて1分に数回）
  - 開き直し・受付のページの GET（受付の始めに30人が一度に開く）：数十回
  - 合わせて、ふつうは1分に100回前後。多い時でも200回ほど。
- **選んだ数**：60秒に600回（1秒に10回）。見積もりの3〜6倍の余りがあり、60人ほどが同じ IP から見ても止まらない。札は192ビットの乱数で、総当たりで当てる守りではない（当てられない）。守りたいのは、1つの IP からの読みすぎで DB が重くなること（札の SHA-256 を主キーの索引で引く、軽い命令）。
- **書く操作と別に数える**：同じ数（`RATE_LIMIT_MAX` 100回）を分け合うと、見る人が多い会場で受付の送信（POST）が止まる。別の上限なら、見る要求が多くても受付は書く操作のふつうの上限のまま。
- **設定にしない**：`BOOKING_WEBHOOK_RATE_LIMIT` と同じく定数にした（変えるのは見積もりが外れたときだけ。設定の値を増やすと staging・production の確かめも増える）。入・切は `RATE_LIMIT_ENABLED` に従う。
- **見直す時**：本番で 429 が見るだけのページに出たら（ログの `status: 429` と道の形 `route`）、数を上げるか、版の確かめの間を延ばす。

## R3. ほかの読む要求は数えない

ログインした画面の読み直し（5秒おき）・動いているかの窓口・画面のファイル（`/api` の外）は数えない。今の振る舞いを変えない。

## R4. 試合表の道への当て方（この PR のあと）

試合表の道（`/api/v1/match/views/…`・`/api/v1/match/joins/…`）はまだ `develop` にない（match-004・PR #68）。この PR が入ったあと、試合表の PR で `apps/api/src/modules/match/index.ts` に次の1行を足す（領域のフォルダの中だけ）。

```ts
export const publicReadPaths = ["/api/v1/match/views/", "/api/v1/match/joins/"] as const;
```

受付の POST（`/api/v1/match/joins/{token}`）は、今までどおり書く操作のふつうの上限で数える（読む要求の上限とは別）。
