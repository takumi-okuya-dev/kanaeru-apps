# Research: core-013 試合表の道は LIFF を始めずに開く

2026-11-22 作成。主催者の不在中に AI が作った。【仮決め】は主催者の確かめを待つ。

## R1 どの道で LIFF を始めないか・電波の有無で変えるか

- **Decision**【仮決め】：`/match` と `/match/` で始まる道すべて（見るだけ `/match/view/…`・受付 `/match/join/…`・運営の画面）で始めない。電波の有無（`navigator.onLine` など）では変えない。
- **Rationale**：
  - AD-4 の本文が「試合表の道（`/match/…`）では `liff.init()` を呼ばずにルーターを作る」と書く。運営の画面も含む。
  - `navigator.onLine` は、電波の弱い体育館やつながりの悪い Wi-Fi でも true を返す。つながっていると見て `liff.init()` を待つと、始まりが長く止まるか「読みこめない」になる（ネットなしで開けない、を直す目的に反する）。
  - 同じ URL で、電波によって始まり方が変わると、確かめにくい。
  - 運営の画面で LIFF を始めても得るものが少ない。運営の端末はふつうのブラウザ（AD-27）で、外のブラウザでは `liff.init()` だけではログインしない（[学び：LINE](../../../docs/study/line.md) 2.6）。ログインは前のセッションのクッキーを使う（AD-4）。
- **Alternatives**：
  - 見るだけ・受付だけを始めず、運営の画面はつながっていれば始める：上の理由でやめた。依頼の文の「ネットなしなら飛ばす」は、いつも飛ばす形で満たす。
  - アプリの一覧（`apps.list.ts`）の定義に「LIFF を使わない」の印を足し、`basePath` から決める：アプリの定義（共通の約束）を変えることになり、この PR では広い。試合表のほかに使うアプリが出たら考える。

## R2 何で決めるか

- **Decision**【仮決め】：開いたときの `window.location.pathname` だけで決める（`lib/liff.ts` の `needsLiff`）。大文字と小文字は分ける。頭が似ているだけの道（`/matches`・`/matching/…`）は今までどおり始める。
- **Rationale**：
  - 決め方を1つの関数にして、単体のテストで確かめる。
  - 迷う形の道は、今までどおり LIFF を始める側（今と同じふるまい）に倒す。ルーターは大文字と小文字を分けずに当てるので、`/Match/…` も試合表の画面になるが、LIFF を始めるだけで壊れない。
  - ミニアプリの URL で開いたとき、LINE はエンドポイント（`/`）に `liff.state` を付けて開く。`/` なので今までどおり LIFF を始め、LIFF が `/match/…` へ移す。試合表の QR は画面の源＋道にする（AD-26）ので、ふつうはこの形にならない。
- **Alternatives**：道を小文字にしてから比べる：試合表の画面はどちらでも開くが、LIFF を始めない道が増える向きの変更で、得るものがない。

## R3 LIFF を始めずに開いたあと、LIFF の要る道へ移るとき

- **Decision**【仮決め】：道の根（`lib/router.ts` の `rootRoute`）の `beforeLoad` で `mustReloadForLiff(移る先の道)` を見て、真なら同じ URL でページを読み直す（`redirect({ href, reloadDocument: true, replace: true })`。履歴を増やさない）。読み直すと、組み立てがそこで LIFF を始める（始められなければ「読みこめない」）。
- **Rationale**：
  - 受付アプリなどの画面は、ログインの確かめ（account の `SessionGate`・`loadSession`）などで `getLiff()` を読む。LIFF を始めずに開いたまま移ると、画面が壊れる。
  - 読み直すと、ほかの道の始まり方が今とまったく同じになる（「ほかの道は今までどおり」）。外枠のアプリの切り替え・「はじめの画面へ戻る」など、試合表の道から出るリンクはどれもこれで扱える。
  - 試合表の道で開いて、試合表の中を行き来するときは読み直さない（ネットなしで動く）。
- **Alternatives**：
  - 移るときに、その場で `initLiff()` を待つ：URL を変えたあとで `liff.init()` を呼ぶことになり（LIFF のログインの戻りなどを壊しうる。AD-4 が先に始める理由）、失敗したときの画面も今と変わる。
  - LIFF を始めないときの `getLiff()` に仮の形を返す：本番で「手元のログインへ」が出るなど、ほかの道のふるまいが変わる。
  - ルーターの履歴の `block` で止めて読み直す：戻る・進むの扱いと、離れるときの確かめの枠（beforeunload）の扱いが増える。`beforeLoad` の方が単純。

## R4 LIFF を始めずに開いた道での `getLiff()` とログイン

- **Decision**【仮決め】：`getLiff()` は、理由（「この道は LIFF を始めずに開いたので…」）の文で投げる。試合表の運営の画面で、セッションが切れたときに LINE ログインし直す流れは、この PR では作らない。
- **Rationale**：
  - AD-4 は、試合表の道で LINE ログインが要るときは「LIFF の外のブラウザ向けのログイン（同じチャネル）」を使うとし、【仮決め】にしている。通るかは Open Questions 11 で確かめる前。作り方が決まる前に共通の口を作らない（原則 IV）。
  - 黙って仮の形を返すより、投げる方が、match の領域を作るときに気づける。決まりは `docs/rules/coding.md` 6-3 に書いた（試合表の道で `getLiff()` を読む部品を使わない）。
- **match の仕様への申し送り**：LIFF の `liff.login()` の戻り（`?code=…&liffClientId=…` など）が `/match/…` に来ると、そこでは LIFF を始めないので受け取れない。外のブラウザ向けのログインを作るときは、戻り先を試合表の道の外にするか、この決め方を直す共通の PR を先に出す。

## R5 E2E の試合表の道

- **Decision**【仮決め】：E2E のための試合表の道（仮の画面）は足さない。`/match/view/…`・`/match/join/…` を開いて、外枠の中の「ページが見つかりません」（ルーターが描く）が出ることで、ルーターが動いたことを確かめる。決め方そのもの（LIFF を始められないときに試合表の道は開き、ほかの道は「failed」）は、単体のテスト（`lib/liff.test.ts`）で SDK を差しかえて確かめる。
- **Rationale**：
  - 試合表の領域は別の PR。どのアプリにも属さない道を足すと、組み立ての決まり（`router.test.tsx`・AD-15）にも当たり、仮の画面が本番に出る。
  - E2E は LIFF ID がない（仮の LIFF）ので、E2E で LIFF の失敗を起こせない。読み直しの有無（画面の中に置いた印が消えるか）と、読み直したあとに `getLiff()` を読む画面（「ログインしていません」）が描けるかで、組み立てた画面の流れを確かめる。

## R6 変えないもの

- 「読みこめませんでした」の画面（`shell/StartupErrorPage.tsx`）と、その文。
- `initLiff()`・`getLiff()`（始めた後）・仮の LIFF のふるまい。
- 画面の CSP（試合表の道でも LIFF の SDK の源は残る。読まないだけ）。
