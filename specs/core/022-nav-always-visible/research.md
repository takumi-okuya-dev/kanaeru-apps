# Research: サイドバーの項目を常に出す（core-022）

【仮決め】：主催者が不在でも進められるよう、AI が仮に決めた。

## R1 「直前に開いたもの」の置き場所

- 端末の localStorage に置く。サーバーに持たない（ナビのために問い合わせを始めない。FR-007）。
- 鍵は既存の付け方に合わせる。試合表は `kanaeru.match.last-table`。**`kanaeru.match.` の頭は、試合表の写しの片付け（`account-reset.ts`）が、写しを置いた人と違う人のログイン・ログアウトで消す**ので、片付けを足さずに、前の人の記録が消える。
- 交流会は `kanaeru.event.last`（`{ owner, eventId, role }`）と `kanaeru.event.owner`。試合表と同じ形の片付け（`registerLastEventReset`。`onAccountChange`）を足し、event の入口（`index.ts`）が1度だけ呼ぶ。写しを置いた人（owner）と違う人のログイン、ログアウト（null）で消す。**ログインの知らせは、画面を開くたびに同じ人で届く**（`session.ts` の `authenticated`）ので、知らせのたびに消すと、開き直すたびに記録が消えてしまう。そのため、試合表と同じく、持ち主を比べて消す。

## R2 役目（myRole）も記録する理由

- 交流会は役目で出す項目が違う（受付係は「参加者・合計」だけ）。記録に役目も持てば、外でも今と同じ規則（`availableAdminTabs`）で、出す項目を決められる。役目が古くなっても（降ろされたなど）、押したときの権限の確かめ（EventAccessGate）が断るので、安全の面は変わらない。
- 記録がないとき（役目が分からない）は、登録された3つを薄く出す。

## R3 薄い項目の作り

- `NavItem` に `disabled?: { message: string }` だけを足す（最小の変更。行き先 `to` は、押したときに進む一覧）。
- 描き方は外枠（AppShell）が決める：リンクのまま（Enter・タップで一覧へ進める）に `aria-disabled="true"` を付け、読み上げ用の補足（「交流会を選ぶと開けます」）を足す。押したら、既存の `showNotice`（情報）で、移る先の一覧の上に知らせの帯を出す。**ボタンに替えない**理由：行き先が一覧のリンクとして動く方が、Enter・タップ・中クリックの扱いがそのままで、変更が小さい。
- 薄い項目は、「今の項目」の当たり（`currentNav`）から外す（薄い項目の行き先が一覧と同じで、一覧が「今の項目」でなくならないように）。

## R4 試合表の「外」

- 試合表の画面の外（`/match` の外）は、今までどおり何も出さない（外枠は今のアプリの領域の項目だけ）。試合表の一覧・作るの画面（tableId なし）で、直前の試合表の項目を出す。
- 記録した試合表が消えていたとき：押すと、その試合表の画面の「見つかりません」になる。今回は、記録の掃除（一覧を読んだときに存在を確かめる）はしない（一覧の読みこみのたびの問い合わせを、ナビのために増やさないため）。

## R5 採らなかったこと

- 「いちばん近い交流会へ行く」：交流会の一覧の問い合わせを、ナビのために毎回始める必要がある（FR-007 と合わない）。主催者の選択でもない。
- 「サーバーに最後に開いた交流会を持つ」：テーブルとマイグレーションが増える。端末ごとの記録で足りる。
