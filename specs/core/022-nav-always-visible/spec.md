# Feature Specification: サイドバーの項目を常に出す（core-022）

**Feature Branch**: `feature/core-022-nav-always-visible`

**Created**: 2026-11-25

**Status**: Draft

**Input**: 主催者の依頼（2026-11-25）。「サイドバーの項目は常に表示されている方がいい。受付も試合表も同じように」。今は、受付は「交流会の一覧」だけ（交流会を開くと、参加者・合計／困りごと／準備が出る）、試合表は「試合表の一覧」だけ（試合表を開くと、名簿と設定・試合表・印刷・見るだけのページ・QR で受け付けるが出る）。行き先が交流会（試合表）の ID を道に持つため、選ぶまで出さない作りだった（core-003 の nav-items）。

## Clarifications

### Session 2026-11-25

主催者に選んでもらった。

- Q: 交流会（試合表）を選んでいないとき、項目はどう動くか → A: **直前に開いた交流会（試合表）へ行く**。開いたことがなければ、項目を**薄く表示**し、押すと「先に交流会（試合表）を選んでください」と案内して一覧へ進む。
- Q: いつ入れるか → A: 初めての本番リリース（#106）の前に一緒に入れる。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 受付：交流会の外でも、項目が出ている (Priority: P1)

主催者・受付係が、受付アプリの「交流会の一覧」を開いている。サイドバー（スマホはタブバー）に、「交流会の一覧」に加えて、「参加者・合計」「困りごと」「準備」が出ている。以前に開いた交流会があれば、押すとその交流会のその画面へ進む。なければ、項目は薄く出ていて、押すと「先に交流会を選んでください」と出て、交流会の一覧へ進む。

**Why this priority**: 管理の項目が見えないと、交流会を開いてから探すことになる（主催者の依頼）。

**Independent Test**: 交流会を開いたあと一覧へ戻り、サイドバーに4つ出ていて、「困りごと」が直前の交流会の困りごとへ進むことを確かめる。端末を替えた（記録がない）ときは、薄い項目を押して知らせと一覧を確かめる。

**Acceptance Scenarios**:

1. **Given** 直前に交流会（主催者）を開いた, **When** 一覧など交流会の外の画面を開く, **Then** 「交流会の一覧」「参加者・合計」「困りごと」「準備」が出て、3つの項目は直前の交流会へ進む
2. **Given** 直前に開いた交流会の役目が受付係, **When** 外の画面を開く, **Then** 「交流会の一覧」と「参加者・合計」だけが出る（今までと同じ、役目で出し分ける規則）
3. **Given** 開いたことがない（記録がない）, **When** 外の画面を開く, **Then** 「参加者・合計」「困りごと」「準備」が薄く出て、`aria-disabled` が付き、押すと「先に交流会を選んでください」の知らせが出て、交流会の一覧へ進む
4. **Given** 薄い項目, **When** キーボードで Enter, **Then** 押したときと同じ（知らせと一覧）。読み上げでは「使えない」と、交流会を選ぶと開けることが分かる
5. **Given** 交流会の中を開いている, **When** 画面が交流会を読みこむ, **Then** 項目はその交流会の行き先になり、その交流会が「直前に開いた交流会」として端末に残る
6. **Given** 別の人がログインした・ログアウトした, **When** 次に開く, **Then** 前の人の「直前に開いた交流会」は消えている（共有の端末）

---

### User Story 2 - 試合表：試合表の外でも、項目が出ている (Priority: P1)

試合表アプリの「試合表の一覧」を開いている。サイドバーに、「名簿と設定」「試合表」「印刷」「見るだけのページ」「QR で受け付ける」も出ている。以前に開いた試合表があれば、押すとその試合表のその画面へ進む。なければ薄く出て、押すと「先に試合表を選んでください」と出て、一覧へ進む。

**Why this priority**: 受付と同じ依頼。

**Independent Test**: 試合表を開いたあと一覧へ戻り、サイドバーの6つが出ていて「印刷」が直前の試合表の印刷へ進むことを確かめる。

**Acceptance Scenarios**:

1. **Given** 直前に試合表を開いた, **When** 試合表の一覧・作るの画面を開く, **Then** 6つの項目が出て、5つは直前の試合表へ進む
2. **Given** 記録がない, **When** 一覧を開く, **Then** 5つの項目が薄く出て、押すと「先に試合表を選んでください」と一覧
3. **Given** 試合表を開いている, **When** 読みこむ, **Then** その試合表が直前の記録になる
4. **Given** 別の人がログイン・ログアウト, **When** 次に開く, **Then** 前の人の記録は消えている（試合表の写しの片付けと同じ時に消える）
5. **Given** 試合表の画面の外（受付など）, **When** 開く, **Then** 試合表の項目は出ない（外枠は今のアプリの領域の項目だけを出す決まりは変えない）

---

### User Story 3 - 外枠：薄い項目の見せ方と、今の項目 (Priority: P2)

外枠（PC のサイドバー・スマホのタブバーと「その他」の枠）が、薄い項目を同じ形で出す。薄い項目は「今の項目」に数えない。

**Acceptance Scenarios**:

1. **Given** 項目に薄い印, **When** 描く, **Then** サイドバーとタブバー（「その他」の枠も）で、薄い見た目と `aria-disabled="true"`、読み上げ用の補足が付く
2. **Given** 薄い項目の行き先が一覧と同じ, **When** 一覧を開いている, **Then** 「今の項目」は一覧のまま（薄い項目は今の項目にならない）
3. **Given** 薄い項目を押す, **When** 移る, **Then** 移る先の画面の上に、知らせの帯（情報）が出る（ほかの道へ移ったら消える。既存の仕組み）

### Edge Cases

- 記録した交流会（試合表）が、あとで消えた・権限がなくなった → 押すと、その画面の「見つかりません」「権限がありません」になる（今までの画面）。開き直して別の交流会に入れば、記録は更新される。
- localStorage が使えない → 記録せず、記録がないときと同じ（薄い項目）。
- 交流会の中で、まだ読みこんでいない・失敗した → 直前の記録が同じ交流会ならそれ、なければ薄い項目（ナビのために問い合わせを始めない）。

## Requirements *(mandatory)*

- **FR-001**: 受付のナビは、交流会の外でも、役目で出す項目（参加者・合計／困りごと／準備）を出す。行き先は、直前に開いた交流会。記録がなければ、登録された3つを薄く出す。
- **FR-002**: 試合表のナビは、試合表の画面の中なら、試合表の外（一覧・作る）でも、試合表の項目を出す。行き先は、直前に開いた試合表。記録がなければ、薄く出す。
- **FR-003**: 直前に開いた交流会の ID と役目、直前に開いた試合表の ID を、端末の localStorage に持つ。今の利用者が替わったら（ログアウト・別の人のログイン）消す。
- **FR-004**: 薄い項目を押すと、「先に交流会（試合表）を選んでください」の知らせを出して、一覧へ進む。
- **FR-005**: 薄い項目は、`aria-disabled`・薄い見た目・読み上げの補足を持ち、「今の項目」にならない。
- **FR-006**: 項目の型（NavItem）に足すのは、薄い印と案内の文だけ。受付・試合表以外の領域のナビは変えない。
- **FR-007**: ナビのために、新しい問い合わせを始めない。

### Key Entities

- **直前に開いた交流会**：`{ owner, eventId, role }`（localStorage。`owner` は写しを置いた人の ID）
- **直前に開いた試合表**：試合表の ID（localStorage。試合表の写しの片付けと同じ鍵の頭）

## Success Criteria *(mandatory)*

- **SC-001**: 交流会（試合表）を1度開いたあとは、どの画面からでも、サイドバーの管理の項目を1回押して、その交流会（試合表）の画面へ進める。
- **SC-002**: 共有の端末で、別の人がログインしたあとに、前の人の交流会（試合表）へ進む項目が出ない。
