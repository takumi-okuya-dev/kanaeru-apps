## User Scenarios & Testing *(mandatory)*

### User Story 1 - 運営者が作りかけのアプリを自分だけに見せ、公開する (Priority: P1)

運営者は設定の「アプリの台帳」を開く。アプリごとに、名前と属する領域、公開の状態のチップ（切・運営者だけ・公開）、今見える人が並ぶ。チップを押すと、その場で保存され、行のそばに「「運営者だけ」にしました。」と出る。デプロイは要らない。

**Independent Test**: 運営者で台帳を開き、見本のアプリを「運営者だけ」にして、結果の文と今見える人、切り替えに出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 運営者, **When** 台帳を開く, **Then** 登録されたアプリごとに1行。受付は「公開」、行のないアプリは「運営者だけ」
2. **Given** 台帳, **When** 見本のアプリを「運営者だけ」にする, **Then** すぐ保存され、行のそばに結果、今見える人は「運営者だけ」。切り替えに見本のアプリが出る
3. **Given** 運営者でない人, **When** 台帳を開く, **Then** 「運営者だけが開ける画面です」。窓口は 403
4. **Given** 保存に失敗した, **When** チップを押した, **Then** チップは前の状態に戻り、理由が行のそばに出る

---

### User Story 2 - 見えるアプリを切り替える (Priority: P1)

見えるアプリが2つ以上の人は、PC のサイドバーの上（スマホは上の帯の右）の切り替えから、ほかのアプリやすべてのアプリへ移る。ナビには今のアプリの項目だけが出る。1つの人には、切り替えは出ない。

**Independent Test**: 見本のアプリを「運営者だけ」にして、運営者と利用者で受付の画面を開き、切り替えの有無と中身を確かめる。

**Acceptance Scenarios**:

1. **Given** 見えるアプリが1つ, **When** 受付の画面を開く, **Then** 切り替えは出ない（ナビは今と同じ）。上の帯の右に「設定」
2. **Given** 運営者・見えるアプリが2つ・PC, **When** 切り替えを押す, **Then** メニューに「使えるアプリ」（受付にチェック・見本のアプリに「運営者だけ」）、区切り、「すべてのアプリ」
3. **Given** 同じ・スマホ, **When** 上の帯の切り替えを押す, **Then** 下から出す枠に同じ並びと「すべてのアプリ」「設定」
4. **Given** 利用者（運営者でない）, **When** 受付の画面を開く, **Then** 切り替えは出ない
5. **Given** この端末で最後に受付を使った, **When** はじめの画面（/）を開く, **Then** 受付の最初のナビの項目へ移る

---

### User Story 3 - 見えないアプリは「ない」 (Priority: P1)

公開の状態が切のアプリ（運営者だけのアプリを運営者でない人が開くときも）は、画面も窓口も「ない」。参加者が外から開く画面も同じ。

**Acceptance Scenarios**:

1. **Given** 見本のアプリが切, **When** その窓口を呼ぶ, **Then** だれでも 404
2. **Given** 受付アプリを切にした, **When** 交流会の一覧を開く・窓口を呼ぶ, **Then** 「ページが見つかりません」・404。account と suite の窓口は動く
3. **Given** 運営者だけ, **When** 運営者でない人・ログインの前の人が窓口を呼ぶ, **Then** 404。運営者は通る

---

### User Story 4 - すべてのアプリを見る (Priority: P2)

すべてのアプリの画面に、見えるアプリがカードで並ぶ。この端末で最後に使ったアプリの「開く」が主のボタン。運営者には「運営者だけに見えています」の札と、台帳への入口が出る。

---

### User Story 5 - 設定でアカウントを確かめ、ログアウト・退会する (Priority: P1)

設定の一覧（スマホは一覧の画面、PC はサイドバー）から「アカウント」を開く。表示名・ログインの方法（LINE）・登録した日・使えるアプリが出る。「ログアウト」で出られる。「退会する」は、消える記録と元に戻せないことを確かめの枠で確かめてから消す。

**Acceptance Scenarios**:

1. **Given** 利用者, **When** 設定を開く, **Then** 個人の設定に「アカウント」。運営のまとまりは出ない（運営者には「アプリの台帳」）
2. **Given** アカウント, **When** ログアウトを押す, **Then** すべてのアプリへ移り「ログアウトしました。」。そのあと今の利用者は 401
3. **Given** アカウント, **When** 退会する → 確かめの枠で「退会する」, **Then** アカウントと本人の記録が消え、すべてのアプリへ移り「退会しました。…」
4. **Given** ほかの人が書きこむ記録を持つ, **When** 退会する, **Then** 消さずに、枠の中に理由（409）

### Edge Cases

- 見えるアプリを読めない（夜間の停止）：画面は出し、切り替えは出さない。窓口は API が守る
- アプリの設定の項目：そのアプリが見えないときは出さない（しくみだけ作る。今は項目がない）
- 保存（localStorage）が使えない：最後に使ったアプリを覚えないだけ（はじめの画面は見える最初のアプリ）
- LINE の中で自動でログインした：見えるアプリを読み直す（運営者だけのアプリが出る）

## Requirements *(mandatory)*

- **FR-001**: アプリは `packages/contracts/src/core/apps.list.ts` に1行で登録する（`merge=union`）。key は一意・英小文字・予約語でない。どの領域も、ちょうど1つのアプリか共通（account・suite）に属する（テスト。数は書かない）
- **FR-002**: suite が `app_setting`（アプリの key・公開の状態）を持つ。行がなければ運営者だけ。DB の変更で受付アプリを公開にする
- **FR-003**: `GET /api/v1/suite/apps`（ログインの前でも）・`GET /api/v1/suite/app-settings`（運営者だけ）・`PUT /api/v1/suite/app-settings/{appKey}`（運営者だけ）
- **FR-004**: 組み立てが、アプリに属する領域のすべての道に `requireApp` を付ける。見えなければ 404。`DOMAIN_FEATURES` は非常の切り替えとして残す
- **FR-005**: 画面の外枠：切り替え（見えるアプリが2つ以上のとき）・今のアプリのナビ・設定の入口・見えないアプリの画面は「ページが見つかりません」・最後に使ったアプリを覚える
- **FR-006**: すべてのアプリ（`/apps`）・設定の一覧（`/settings`）・アカウント（`/settings/account`）・アプリの台帳（`/settings/apps`）
- **FR-007**: 退会の窓口（`DELETE /api/v1/accounts/me`。409 `ACCOUNT_OWNS_SHARED_RECORDS`）
- **FR-008**: 画面は WCAG 2.2 AA（両方の幅で axe）・CSP の違反なし

## Success Criteria *(mandatory)*

- **SC-001**: 受付アプリだけの間、受付係と参加者の画面のふるまいが変わらない（今までの E2E がそのまま通る）
- **SC-002**: 運営者が、デプロイせずに見本のアプリを見せる・止める（E2E）
- **SC-003**: 新しい領域を modules.list に足して、アプリの一覧に足し忘れると、テストが落ちる
