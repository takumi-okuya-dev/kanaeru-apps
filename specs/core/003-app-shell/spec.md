# Feature Specification: 外枠のナビ（PC のサイドバーの開閉・スマホの下のタブバー・参加者の画面はナビなし）（core-003）

**Feature Branch**: `feature/core-003-app-shell`（`feature/survey-001-answers` の上に積む）

**Created**: 2026-11-19

**Status**: Draft

**Input**: 開発者の指示（2026-11-19）。今の外枠は、PC の左のサイドバーに「交流会」だけ、スマホでは帯の下に横に並べ、交流会の中の行き来（参加者・合計／困りごと／準備）は各画面の上のタブ（event の `EventAdminNav`）に重ねて出していた。参加者の画面（チェックイン・アンケート・招待）にも管理のナビが出ていた。これを、管理の画面は PC で開閉できるサイドバー・スマホで下のタブバーにまとめ、参加者の画面はナビなしにする。あわせて A3 の参加者の表で名前が途中で折り返す不具合を直す（reception-001 の直し）。画面の決まりは EXPERIENCE.md の Information Architecture・Responsive & Platform、DESIGN.md の Layout（`small`＝751px 以下）。

## Clarifications

### Session 2026-11-19

開発者が選んだもの（1〜4）と、AI が決めたもの（5〜。【仮決め】。理由は [research.md](./research.md)）。

- Q: 管理の画面のナビの形 → A: PC（752px 以上）は左のサイドバー。上の帯のボタンで出す・隠すを切り替え、見ている人ごとにブラウザに覚える（はじめは出す）。スマホ（751px 以下）は画面の下に固定したタブバー（アイコン＋短い名前・押せる高さ 44px 以上・ホームの印を避ける余白・今の項目は墨の印と aria-current）。スマホでは帯の下にナビの行を出さない
- Q: ナビの項目 → A: 交流会の中では「交流会の一覧」「参加者・合計」「困りごと」（主催者だけ）「準備」（主催者だけ）。受付係は「交流会の一覧」「参加者・合計」だけ。交流会の外では「交流会の一覧」だけ。各画面の上のタブは消す。「書き出しと削除」は今のとおり A3 のボタンから開き、ナビに出さない
- Q: 参加者の画面 → A: チェックイン・アンケート・招待・手元のログイン（`/dev/login`）は、サイドバー・タブバー・管理への入口を出さない（上の帯はアプリの名前だけ）。道が変わったら h1 にフォーカスを移す振る舞いは同じ
- Q: A3 の表 → A: PC の参加者の表で、名前を途中で折り返さない
- Q: 外枠の形をどう決めるか → A: 道ごとに、持ち主の領域が自分の道に「ナビなし」と書く（道の静かな値）。書かない道は管理の外枠。参加者の道（`PARTICIPANT_ROUTE_PATTERNS`）はどれもナビなしであることをテストで確かめる【仮決め R1】
- Q: 交流会の中の項目を、共通の外枠がどう知るか → A: 領域が「今の道に合わせた項目」を出す（event が出す）。役目は、画面が読みこんだ交流会（役目つき）から読み、ナビのために新しく問い合わせない。読みこむまでは「交流会の一覧」だけ【仮決め R2】
- Q: 今の項目の決め方 → A: 項目の行き先と同じ画面は「今の画面」（aria-current="page"）。その下の画面（例：書き出しと削除・QR の印刷・交流会を直す）は、いちばん長く当たる項目を「今いる所」（aria-current="true"）にし、見た目は同じ印。交流会を直すは「準備」に含める【仮決め R3】
- Q: タブバーを下に固定する仕組み → A: スマホの管理の画面は、帯と本文だけがスクロールし、タブバーはその下の段にいつも出す（本文がタブバーの下に潜らず、押せる所が隠れない）。重ねる枠（ダイアログ）より下に描く【仮決め R4】

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 主催者が PC でサイドバーを隠して広く使い、開き直しても隠れたまま (Priority: P1)

主催者は PC で交流会の中の画面を開く。左のサイドバーに「交流会の一覧」「参加者・合計」「困りごと」「準備」が並び、今の画面に印がある。表を広く見たいとき、上の帯の「メニュー」ボタンでサイドバーを隠す。読みこみ直しても隠れたまま。もう一度押すと出る。

**Why this priority**: 管理の画面の行き来を1か所にまとめ、表を広く見る（A3・困りごと）。

**Independent Test**: 1440px で交流会の画面を開き、サイドバーの項目と印、ボタンの aria-expanded、隠したあとの読みこみ直しを確かめる。

**Acceptance Scenarios**:

1. **Given** 主催者・PC・交流会の参加者・合計, **When** 開く, **Then** サイドバーに4つの項目がこの順で出て、「参加者・合計」が今の画面（aria-current="page"）。画面の上のタブはない
2. **Given** サイドバーが出ている, **When** 帯の「メニュー」を押す, **Then** サイドバーが隠れ、ボタンは aria-expanded="false"
3. **Given** 隠した, **When** 読みこみ直す, **Then** 隠れたまま。もう一度押すと出る（aria-expanded="true"）
4. **Given** ブラウザの保存が使えない, **When** 開く・切り替える, **Then** 誤りにならず、はじめは出た状態で、切り替えはその画面の間だけ効く

---

### User Story 2 - 受付係と主催者がスマホで下のタブバーから行き来する (Priority: P1)

受付係はスマホで A3 を開く。画面の下に「交流会の一覧」「参加者・合計」の2つのタブが固定して並ぶ。主催者は4つ。押すと画面が変わり、新しい画面の題にフォーカスが移る。帯の下にナビの行はない。

**Why this priority**: 受付の最中に片手で行き来する（UJ-3・UJ-4）。

**Independent Test**: 375px で受付係と主催者の A3 を開き、タブバーの項目・印・押したあとの画面とフォーカスを確かめる。

**Acceptance Scenarios**:

1. **Given** 受付係・スマホ・A3, **When** 開く, **Then** 下のタブバーに「交流会の一覧」「参加者・合計」だけ。「困りごと」「準備」はない
2. **Given** 主催者・スマホ・A3, **When** 開く, **Then** 4つのタブ。「参加者・合計」が今の画面
3. **Given** 主催者・スマホ, **When** 「準備」を押す, **Then** 準備の画面になり、h1 にフォーカスが移り、「準備」に印
4. **Given** スマホ, **When** 一覧画面の下までスクロールする, **Then** タブバーは画面の下に残り、最後の行がタブバーに隠れない
5. **Given** 交流会の外（交流会の一覧）, **When** 開く, **Then** 項目は「交流会の一覧」だけ

---

### User Story 3 - 参加者の画面には管理のナビが出ない (Priority: P1)

参加者は受付QRからチェックインの画面を開く。上の帯にアプリの名前があるだけで、サイドバー・タブバー・管理の画面への入口はない。アンケートの画面・招待の画面・手元のログインの画面も同じ。

**Why this priority**: 参加者に関係のない管理の入口を見せない（EXPERIENCE の P1〜P3）。

**Independent Test**: 両方の幅で P1・P2・P3・`/dev/login` を開き、ナビの目印がないこと、axe が通ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 参加者, **When** P1・P2 を開く, **Then** ナビ（navigation）も「メニュー」ボタンもなく、帯のアプリの名前はリンクでない
2. **Given** 未ログイン, **When** `/dev/login`・P3 を開く, **Then** 同じくナビなし
3. **Given** P1 から P2 へ移る, **When** 道が変わる, **Then** P2 の h1 にフォーカスが移る（今と同じ）

---

### User Story 4 - 主催者が A3 の表で名前を一目で読める (Priority: P2)

PC の A3 の参加者の表で、「佐藤 一郎」のような名前が「佐藤 一 / 郎」と途中で折り返さない。

**Independent Test**: 1440px の A3 で、名前のセルが1行で出ることを確かめる（見た目の確かめ）。

**Acceptance Scenarios**:

1. **Given** PC・A3・参加者がいる, **When** 表を見る, **Then** 名前は1行で、印の列が広がりすぎて名前の列を押しつぶさない

### Edge Cases

- ナビを出す領域が1つもない：サイドバー・タブバー・「メニュー」ボタンを出さない
- 交流会の読みこみが 403・404・夜間の停止で失敗した：項目は「交流会の一覧」だけ（画面は今のとおりの状態を出す）
- 見つからない画面・描けなかった画面：管理の外枠で出す（参加者の道の中で描けなかったときは、その道のとおりナビなし）
- QR の印刷：印刷では帯・サイドバー・タブバーを出さない（今の print.css のとおり）
- 端末の文字を大きくした：タブの名前は切れずに折り返す
- サイドバーを隠したままスマホの幅に縮めた：タブバーは出る（隠すのは PC のサイドバーだけ）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理の画面は、752px 以上で左のサイドバー、751px 以下で画面の下に固定したタブバーにナビの項目を出す。751px 以下では帯の下にナビの行を出さない
- **FR-002**: 752px 以上では、上の帯に「メニュー」ボタン（aria-expanded・aria-controls）を置き、サイドバーを出す・隠す。状態はブラウザに覚え（はじめは出す）、保存が使えなくても誤りにしない
- **FR-003**: 項目は、交流会の中では「交流会の一覧」「参加者・合計」「困りごと」（主催者だけ）「準備」（主催者だけ）、外では「交流会の一覧」だけ。その画面の道が登録されている項目だけを出す
- **FR-004**: 各項目はアイコンと名前。今の画面は aria-current="page"、その下の画面では一番長く当たる項目に aria-current="true"。どちらも墨の印と太字（色だけにしない）
- **FR-005**: タブバーの項目は押せる高さ 44px 以上、端末の下の安全な余白を空ける。本文の最後がタブバーに隠れない
- **FR-006**: 各画面の上にあった交流会の中のタブを消す。「書き出しと削除」は A3（と困りごと）のボタンから開く
- **FR-007**: チェックイン・アンケート・招待・手元のログインは、ナビ・「メニュー」ボタン・管理への入口を出さない。帯はアプリの名前（リンクにしない）だけ
- **FR-008**: 外枠の形（管理・ナビなし）は、持ち主の領域が自分の道に書く。参加者の道は、どれもナビなしになっている
- **FR-009**: 道が変わったら新しい画面の h1 にフォーカスを移す（今の振る舞いを変えない）。ナビの目印には名前（「メイン」）をつける
- **FR-010**: PC の A3 の参加者の表で、名前を途中で折り返さない

### Key Entities

- **ナビの項目**：見える名前・行き先・アイコン・ほかに含める道（任意）。領域が出す
- **外枠の形**：管理（ナビあり）・ナビなし。道ごと
- **サイドバーの開閉**：見ている人のブラウザに覚える出す・隠す

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 1440px で隠したサイドバーは、読みこみ直しても隠れたまま（E2E）
- **SC-002**: 375px のタブバーの項目が、主催者は4つ・受付係は2つで、名前と並びが FR-003 のとおり（E2E）
- **SC-003**: 参加者の画面（P1・P2・P3・`/dev/login`）に navigation の目印が0（E2E）
- **SC-004**: 管理の画面と参加者の画面が、両方の幅で axe の違反0・横のスクロールなし（E2E）
- **SC-005**: `pnpm check` が通る

## Assumptions

- 752px の境目は土台の DESIGN.md の `small`（751px 以下が狭い画面）のまま
- サイドバーの開閉の覚え方は見ている人のブラウザだけ（ほかの端末とは分け合わない）。仮の記録（localStorage）
- LINE の中（スマホ）では、外のブラウザの見出しの帯の下に、この外枠の帯が出る（参加者の画面も帯は残す）
- アイコンは今の部品と同じく、線で描いた小さな SVG（アイコンの部品集を足さない）
