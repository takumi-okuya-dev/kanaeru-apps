## User Scenarios & Testing *(mandatory)*

### User Story 1 - 利用者が MCP 対応の AI から kanaeru に接続する (Priority: P1)

利用者は、MCP に対応した AI のアプリ（Claude など）に kanaeru の接続先を入れる。AI のアプリは kanaeru の認可の窓口へ利用者のブラウザを開く。利用者は LINE でログインし、「どのアプリの、どの範囲を AI に見せるか」の確認画面で同意する。同意すると、AI のアプリは利用者の代わりにツールを使えるようになる。

**Why this priority**: 接続できなければ、MCP の価値（外の AI から本人の記録を使える）が出ない。ほかのすべての話の前提。

**Independent Test**: ステージングで、MCP の標準のテストのクライアント（自動テストの道具）を使い、認可の流れ（ブラウザでのログイン → 同意 → トークン）を最後まで通し、ツールの一覧が返ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 利用者が LINE ログイン済みでない, **When** AI のアプリが接続を始める, **Then** kanaeru のログイン画面が出て、ログインのあとに同意の画面に戻る
2. **Given** 同意の画面, **When** 利用者が範囲を確かめて同意する, **Then** AI のアプリが受け取ったトークンで `/api/mcp` のツール一覧が返る
3. **Given** 同意の画面, **When** 利用者が断る, **Then** AI のアプリにはトークンが渡らず、kanaeru の画面に「接続を止めました」と出る
4. **Given** 認可の途中の `state` が一致しない, **When** 戻ってくる, **Then** トークンは発行されず、エラーの画面を出す

---

### User Story 2 - AI が本人の記録だけを読む (Priority: P1)

接続した AI は、利用者が同意したアプリの範囲で、利用者本人の記録をツールで読む。ほかの人の情報は返らない。見えなくなったアプリ（公開の状態が切）の記録は、読めない。

**Why this priority**: 本人の記録を外に渡すことが、この機能の唯一の価値であり、Constitution II に反したら作らない。

**Independent Test**: 2つのアカウントで同じアプリに記録を作り、片方のトークンで読むツールを流し、自分の記録だけが返り、もう片方の名前・記録が1件も出ないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 利用者 A が同意したトークン, **When** 読むツールを呼ぶ, **Then** A の記録だけが返る
2. **Given** 利用者 A のトークン, **When** 利用者 B の記録の id を指定する, **Then** 見つからない（`404`）と同じ答えを返し、B の存在を知らせない
3. **Given** トークンの範囲が `reception:read` だけ, **When** `reception` の書くツールを呼ぶ, **Then** `403` で断る
4. **Given** アプリが「切」になった, **When** そのアプリの読むツールを呼ぶ, **Then** `404`（AD-16 のとおり、見えないアプリは `404`）

---

### User Story 3 - 利用者が接続を見て、止める (Priority: P2)

利用者は自分のアカウントの画面で、いま接続している AI（接続の名前・範囲・最後に使った日時）を一覧で見て、いつでも取り消せる。退会すると、すべての接続が取り消される。

**Why this priority**: 外に渡した権限を本人が確かめて止められることが、同意の意味を保つ。ただし接続そのものが動いてからでよい。

**Independent Test**: 接続を1つ作り、設定の画面で取り消し、同じトークンで `/api/mcp` を呼んで `401` になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 接続が1つある, **When** 利用者が設定で取り消す, **Then** そのトークンは次の呼び出しから `401` になる
2. **Given** 接続が複数ある, **When** 1つ取り消す, **Then** ほかの接続は使える
3. **Given** 接続がある利用者, **When** 退会する, **Then** すべての接続が取り消され、トークンは使えない

---

### Edge Cases

- LINE ログインのチャネルが「開発中」のとき、Admin と Tester 以外は接続できない（[構成の決めごと](../../../_bmad-output/architecture-kanaeru/architecture-kanaeru.md) Open Questions 6）。本番の前に「公開」にする確かめが要る
- 夜間（0時〜8時）は DB が止まるので、ツールは `503 DB_UNAVAILABLE` を返す（AD-10）
- トークンの期限が切れた途中の呼び出し → `401`。AI のアプリは認可を取り直す
- `resource` が `/api/mcp` でないトークンの要求 → 発行を断る（RFC 8707）
- 別の宛先（別のサーバー）向けに出たトークンを `/api/mcp` で使う → `401`
- `Origin` が許されていない、または欠けている `/api/mcp` の呼び出し（ブラウザからの呼び出しの守り）→ `403`
- 同意したあとに、利用者が範囲の一部のアプリを公開の状態を切にした → そのアプリの記録は読めなくなる。トークンは残る
- 同じ AI のアプリが同じ利用者で二重に接続した → 接続は別々に一覧に出て、別々に取り消せる
- CLI が `http://127.0.0.1:1455/callback` のようにポートを変えて戻ってくる → 受ける（FR-033）。`http://example.com/...` のような登録にない戻り先 → 断る
- DCR で登録されたが、一度も使われない → 期限のあと消える（FR-009）
- クライアントの名前が登録にない → 同意の画面は「名前のない接続」と出し、範囲を読むだけにする（書く範囲は選べない）【仮決め】
- 同意の画面を開いたまま、別のアカウントでログインし直した → 同意は発行されず、ログインのやり直しを求める

## Requirements *(mandatory)*

### Functional Requirements

**窓口と道具**

- **FR-001**: MCP の窓口は `/api/mcp`（Streamable HTTP）の1つだけにする。ツールは、各領域の `index.ts` から出し、1行に1つの一覧（`merge=union`）に登録する（AD-21）
- **FR-002**: ツールは、画面と同じ HTTP の窓口を `app.request` で呼び、利用者の資格（トークン）をそのまま付ける。領域の関数を直接呼ばない（AD-20）
- **FR-003**: SDK は `@modelcontextprotocol/server` と `@modelcontextprotocol/hono` の 2.x を使う（仕様 2026-07-28 の系列。AD-21）

**認可（OAuth 2.1）**

- **FR-004**: 認可サーバーは account の領域が、自前で `/api/oauth/*` に出す。外部の認証のサービスは使わない（費用がかかる。Constitution V）
- **FR-005**: 保護資源のメタデータ（RFC 9728）と認可サーバーのメタデータ（RFC 8414）を、`/.well-known/oauth-protected-resource` と `/.well-known/oauth-authorization-server` で返す。`/api` の外に置いてよいのはこの2つだけ（AD-21）
- **FR-006**: PKCE は S256 を必須にする。`state` は必須にする（AD-21・AD-2）
- **FR-007**: トークンの宛先（RFC 8707 の `resource`）は `/api/mcp` だけにする。ほかの宛先の要求は断る
- **FR-008**: 認可の応答に `iss` を入れる（RFC 9207）
- **FR-009**: クライアントの登録は2つの方法を受ける：CIMD（クライアントが自分の URL の JSON を `client_id` にする）と DCR（RFC 7591 の `/api/oauth/register`）。どちらで来たかは、同意の画面と接続の一覧で区別できるようにする。DCR は登録の数に上限と期限を付ける（使われない登録は消す）【仮決め・2026-11-23 改定：接続先によって CIMD だけ・DCR だけを使うものがあるため、最初の版から両方を受ける。前の【仮決め】（CIMD だけ）は取り消し】
- **FR-032**: 利用者が使う AI のクライアントの種類を、2つに分けて扱う。(a) ブラウザでつなぐ接続先（Claude・ChatGPT など）、(b) CLI の接続先（Codex・Claude Code・ほかの CLI）。どちらも同じ認可の流れで通す。接続先ごとの特別なふるまいは作らない【仮決め】
- **FR-033**: 認可の戻り先（`redirect_uri`）は、登録のとおりに完全一致で確かめる。例外は RFC 8252 のループバック（`http://127.0.0.1:<任意のポート>/…` と `http://[::1]:<任意のポート>/…`）で、CLI が使うポートはどれでも受ける。戻り先が登録にない・ループバック以外の `http` の場合は断る【仮決め】
- **FR-034**: 画面のない環境（ヘッドレスの CLI）のために、デバイス認可（RFC 8628）を後の段階で足せるように、認可サーバーのメタデータと発行の口を用意する。最初の版では出さない（Phase D。【仮決め】）。デバイスの確認の画面も LINE ログインを通す
- **FR-035**: 接続の方法に、事前登録のクライアント（kanaeru が発行する `client_id` と、必要ならシークレット）を加える。Muse のコネクタ審査は OAuth クライアント資格情報を渡す形を想定しているため。事前登録の発行は運営者だけが行い、利用者には出さない【仮決め】
- **FR-036**: ツールの分類は `read`・`write`・`sensitive write` の3つにする。読みと書きを1つのツールに混ぜない。`sensitive write`（お金・個人の重要な情報・取り消せない操作など）は、確認を毎回取り、「常に許可」の設定を作らない【仮決め】
- **FR-037**: 同意の画面では、利用者が読むだけを選べるようにする（FR-014 の範囲の選択。可能な接続では既定を読むだけにする）【仮決め】
- **FR-038**: ツールは、開始した作業を最後まで完了させる（ブラウザへの誘導だけで終わらない）。外のページへのリンク集だけのツールは作らない【仮決め】
- **FR-039**: 外の開発者向けの審査を受けるための運用（事業者の確認・データ処理の説明・プライバシーポリシー・審査の間ずっと使えるテスト用の利用者・ツールの説明文・セキュリティの事故の連絡の窓口）は、仕様の外の運用の作業として `tasks.md` の Phase M に置く。審査は主催者の判断で出す
- **FR-040**: Muse は API で接続する（MCP は使わない）。Muse が呼べるのは、画面と同じ `/api/v1` の窓口のうち、許可リストに載せたものだけ。許可リストの各項目は、道（operationId）・分類（read・write・sensitive write）・必要な範囲を持つ。許可リストにない道は、Bearer があっても `401` で断る（既定は拒否）【仮決め】
- **FR-041**: 許可リストの道の説明（Muse に出すツールの説明文）は、OpenAPI（`operationId` と分類の注釈）から作る。手で別の説明を書かない（Muse の審査の「ツールの文書」に合わせる）【仮決め】
- **FR-042**: Muse の経路で、どの許可リストの道も、他人の記録を返さない・書かない（FR-017・FR-026 と同じ）。Muse に渡す範囲は、利用者が同意の画面で選んだものだけ【仮決め】
- **FR-010**: 本人の確かめは LINE ログイン（Web 用のチャネル。AD-2 と同じプロバイダー）に任せる。LINE のIDトークンはサーバーで確かめ、画面から送られた値を信じない（Constitution II）

**トークンと範囲**

- **FR-011**: アクセストークンは SHA-256 のハッシュだけを DB に持つ。期限を持つ。平文を DB・ログ・画面に出さない（AD-21）
- **FR-012**: 範囲は `<アプリのkey>:read` と `<アプリのkey>:write`。読むだけが既定。書くツールは `write` の範囲が要る（AD-21）。範囲は1つの同意の中にアプリごとに持ち、同意の画面で read と write を別々に選べる（FR-014）。同意は後から範囲を減らせる（FR-031）
- **FR-013**: `/api/mcp` は Bearer のトークンだけで確かめ、クッキーのセッションを受けない。`requireSession` は Bearer も受け、範囲は `requireScope` で確かめる（AD-12・AD-21）。Bearer を受ける `/api/v1` の道は、FR-040 の許可リストに載った道だけ（それ以外の `/api/v1` は Bearer を受けない）
- **FR-014**: 同意の画面は、接続する AI の名前・アプリの名前・範囲を出し、範囲を利用者が確かめて同意する形にする
- **FR-015**: 利用者は設定の画面で接続を一覧し、取り消せる。退会で全部取り消す

**守り**

- **FR-016**: `/api/mcp` の回数の制限はトークンごとにかける。上限の数は計画のときに決める【仮決め】
- **FR-017**: 外の AI に渡してよいのは利用者本人の記録だけ。ほかの人の名前・困りごと・人物メモ・参加者の一覧を返すツールは作らない（Constitution II・AD-20）
- **FR-018**: ツールの呼び出しを記録する。記録するのは、ツールの名前・アカウント・時刻・結果の種類（成功・どの `code` で断ったか）だけ。引数の中身と返した記録の中身は残さない【仮決め】
- **FR-019**: ログに、トークン・認可のコード・IDトークン・クッキー・記録の本文を出さない（Constitution II の一覧）
- **FR-020**: エラーは既存の形（`{error: {code, message, requestId, fields?}}`）。未ログイン・トークンなしは `401 UNAUTHENTICATED`、範囲の不足は `403`、見えないアプリや他人の記録は `404`（AD-16）
- **FR-021**: 夜間の停止（DB が止まる時間）は、ツールも認可も `503 DB_UNAVAILABLE` にする（AD-10）

**ツール（最初の版）**

- **FR-022**: 最初の版のツールは、利用者本人の記録を読むツールだけ。最初の版は、利用者が見えるアプリのうち、アプリの定義に「本人の記録を外へ出してよい」と書かれたものだけを、`<key>:read` の範囲で読めるようにする【仮決め】
- **FR-023**: 書くツールは、最初の版では作らない。ただし型・範囲・同意・記録の仕組みは、この版で作って試験する（FR-025〜031。試験用の書くツールは、テストの中だけに登録する）【仮決め】

**独自ドメイン**

- **FR-024**: `issuer`・LINE ログインの戻り先・利用者が登録する MCP の URL は、源（ホスト名）に結びつく。MCP を一般に公開する前に、独自ドメインを取り、その源を `issuer` とする。ステージングは Cloud Run の既定の URL で確かめる【仮決め】

**書き込みへの備え（v1 は読むだけ。仕組みだけ用意する）**

- **FR-025**: ツールは型で宣言する：`access`（`read` または `write`）・`appKey`・必要な範囲（`<key>:read` か `<key>:write`）・`idempotent`（同じ呼び出しを繰り返してよいか）・`confirmation`（`none` または `required`）。登録のとき、`write` のツールは必ず `:write` の範囲を要求する。範囲と `access` が食い違うツールは登録できない（起動のときに失敗させる）【仮決め】
- **FR-026**: 書くツールも、画面と同じ HTTP の窓口を `app.request` で呼ぶ（AD-20）。書く権限の判定は窓口の既存の権限（`requireApp`・役割・本人の確かめ）に任せ、ツールの側で権限を作り直さない。他人の記録を書く窓口は、どの範囲でも呼ばない（Constitution II）
- **FR-027**: 書く操作は、`confirmation: required` のとき2段階にする。1段階目は差分（何を変えるか）を返すだけで、何も書かない。2段階目は、1段階目が返した確認の値（短い期限付き・1回だけ使える）を付けたときだけ書く。AI の取り違えで書きすぎないための守り【仮決め】
- **FR-028**: 書く操作は冪等キー（呼び出しごとの `idempotencyKey`）を必須にする。同じキーの再送は、二重に書かず前の結果を返す【仮決め】
- **FR-029**: 書く操作の記録（FR-018）は、`access`・ツールの名前・対象の記録の id・結果の種類だけを残す。書いた中身（本文）は残さない
- **FR-030**: 回数の制限は、読むと書くを別々の枠にする。書くの枠は読むより小さい【仮決め】
- **FR-031**: 同意の範囲を、利用者が後から減らせる（書くを外す・アプリを外す）。範囲が減ったら、そのトークンは次の呼び出しから使えない。`write` を含むトークンの期限は、読むだけのものより短くする（期限の数は計画で決める。refresh は範囲を再確認して出す）【仮決め】

### Key Entities *(include if feature involves data)*

- **接続（client）**: AI のアプリの登録（CIMD の URL・名前・ロゴ）。利用者ごとの同意の単位ではない
- **同意（grant）**: 利用者 × 接続 × 範囲 × 作った日時・最後に使った日時。取り消すと、そのトークンはすべて使えなくなる
- **アクセストークン**: 同意から発行される。SHA-256 のハッシュ・期限・範囲・`resource`（`/api/mcp`）を持つ。平文は発行の応答の1回だけ
- **認可のコード（一時）**: 発行まで数分だけ持つ。PKCE の値・`state`・`redirect_uri` と結びつき、1回だけ使える
- **ツールの呼び出しの記録**: ツールの名前・アカウント・時刻・結果の種類。中身は持たない（FR-018）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ステージングで、テストの MCP クライアントが、ブラウザでのログインから同意、ツールの呼び出しまでを、人の手を止めずに最後まで通せる（自動テストで確かめる）
- **SC-002**: `resource` がほかの宛先のトークン、期限切れ、取り消し済みのトークンは、すべて `/api/mcp` で `401` になる（テストで全部の組を確かめる）
- **SC-003**: 読むツールの答えに、ほかの人の名前・記録・参加者の情報が1件も入らない（ツールごとに、2人分のデータでテストする）
- **SC-004**: 取り消しのあと、同じトークンの次の呼び出しから `401` になる
- **SC-005**: PKCE なし・`state` なし・`iss` なしの認可は、どれも通らない
- **SC-006**: 本番の運用費は増えない（外部の認証・有料の API を使わない。Constitution V）。MCP の追加で増えるのは Cloud Run の呼び出しの分だけ
- **SC-007**: 読むだけのトークンで、書くツール（テストの中の試験用）を呼ぶと `403` になり、窓口には届かない。書く範囲のトークンでも、確認の値がない・期限切れ・使用済みの確認の値では書かない（テストで確かめる）
- **SC-008**: CIMD・DCR・ループバックの任意のポート・登録にない戻り先の断り、の各組が自動の試験で確かめられる。Claude（ブラウザ）と Codex CLI の実機で、接続から1回のツール呼び出しまで通る（主催者が挙げるほかの CLI は、確かめの結果を plan.md に書く）

## Assumptions

- 最初の版の確かめの対象は、Claude（ブラウザ）・Codex（CLI）と、そのほか利用者が挙げる AI の CLI。対象の一覧と確かめの結果は plan.md の「クライアントの対応」に書く。「Muse」は Meta のパーソナル AI エージェント（2026-10 に日本で提供開始）。Muse は API で接続する（FR-040）。Muse のコネクタとして公開するには [platform.muse.ai](https://platform.muse.ai/) の審査が要る（Phase M）。Muse が MCP を使うかは確かめない（API で足りるため）
- 利用者の記録が増えても、読むツールは一覧の件数を上限（既定 50 件）で返し、次のページを要求で取る【仮決め】
- 回数の制限の数（FR-016）と、ツールの呼び出しの記録の保存期間（FR-018）は、計画（`/speckit-plan`）のときに決める
- LINE ログインのチャネルは、本番の前に「公開」にする（開発中は Admin と Tester だけ。Open Questions 6）。公開するまでは、ステージングの確かめは Admin と Tester のアカウントで行う
- 利用者への案内（どの AI にどう接続するか）は、画面の中の短い説明と設定の画面の文だけにする。使い方の文書は、公開のときに別に書く
- 外の AI の利用料は利用者が持つ（AD-20・原則 V）。kanaeru は AI の利用料を持たない

## Dependencies

- 認可を作る前に、account の `requireSession`（Bearer を受ける形）と、`requireApp`・`isAppVisible`（core-005・AD-16）が要る。core-005 の後に作る（バックログ A の順番）
- 夜間の停止（AD-10）の扱いは、既存の `503` の仕組みに従う
- `/api` の道の頭（`platform/web` の1つの関数）に `/api/oauth/*` と `/api/mcp` を並べる（AD-21）

## Out of Scope

- 書くツールの実装（【仮決め】この版では作らない。型・範囲・同意・記録の仕組みは FR-025〜031 で作る。書く操作の本番の仕様は別の仕様で決める）
- 段階2（利用者の API キーで kanaeru の中から AI を呼ぶ）と段階1（コピーして貼る）。それぞれの仕様で作る（AD-20）
- ほかの人の情報を返すツール・人物メモの MCP（Constitution II）
- 外部の認証のサービスの利用、DCR の永続の登録の管理画面
- Muse 向けの MCP（Muse は API で接続する。FR-040）
- 独自ドメインの取得と切り替え（バックログ C1。MCP の公開の前に行う【仮決め】）
