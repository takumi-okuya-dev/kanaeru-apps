- Q: 今ある交流会の持ち主を、どう埋めるか（運営者は設定 `ORGANIZER_LINE_USER_ID` で決まり、DB の変更の SQL からは読めない） → A: event の領域の中で「持ち主のない交流会を、運営者のものにする」を1回ずつ流す。流すのは、運営者が交流会の一覧を開いたときと、持ち主のない交流会を運営者が開いたとき。前の版のアプリで交流会を作れたのは運営者だけなので、持ち主のない交流会はすべて運営者のもの。`NOT NULL` は、本番で持ち主のない交流会が0件と確かめてから、別の DB の変更で付ける【仮決め R1】
- Q: 持ち主の外部キーの消し方 → A: `RESTRICT`。退会では event の段が先に、組織に入れた交流会を引き継ぎ、組織に入れていない交流会を消す。残れば account を消せず 409（AD-19 のしくみのまま）【仮決め R2】
- Q: 組織に入れていない交流会にチェックインがあるとき、持ち主自身のチェックインも数えるか → A: 数える（event はチェックインを読めないので、交流会を消すときの外部キーで止まる。どのチェックインかを見分けない）。退会は 409 になり、先に交流会を組織に入れる【仮決め R2】
- Q: 退会の引き継ぎと消すをいつ流すか → A: account を消すのと同じトランザクションの中（退会の段の `finalize`）。409 になったときは、引き継ぎも消すも元に戻る【仮決め R3】
- Q: 部員の役目を、交流会の答え（`myRole`）に入れるか → A: 入れない。判定の関数は「主催者・受付係・部員・どれでもない」を返すが、この版では部員は管理の画面を使えず、交流会の答えの `myRole` は主催者か受付係のまま。予約（booking）が部員を使うときに使う【仮決め R4】
- Q: 組織に入れる・外す窓口の形と、断るとき → A: `PUT /api/v1/events/{eventId}/organization`（`{ organizationId }`。null で外す）。主催者でなければ 403 `FORBIDDEN`、主催者でも持ち主でなければ 403 `EVENT_OWNER_ONLY`、持ち主が入っていない組織は 404 `EVENT_ORGANIZATION_NOT_FOUND`。同じ組織をもう一度送っても何もしない【仮決め R5】
- Q: 持ち主と組織をどの画面で直すか → A: 準備の画面（A4）の「持ち主と組織」の節。持ち主の名前・組織の選択（入っている組織と「入れない（個人）」）・説明の文。持ち主でない主催者には、今の組織と「組織に入れる・外すのは持ち主だけです」を出す【仮決め R6】
- Q: 交流会の一覧の組織での絞りこみ → A: 一覧の答えに行ごとの持ち主と組織を入れ、画面で「すべて・組織ごと・個人」のチップで絞る（窓口に絞りこみの値を足さない。数が少ないため）【仮決め R7】
- Q: 交流会を作るときに契約を確かめるか → A: 確かめない（売り始める前は suite の `hasEntitlement` がいつも通す。threads も作るときに呼んでいないのに合わせ、売り始めるときに足す）【仮決め R8】
- Q: 書き出しと削除（A5）の「参加者のデータを消す」で、アカウントごと消す窓口（account の `DELETE /api/v1/accounts/{accountId}`）は運営者だけ。運営者でない主催者はどうするか → A: 運営者でない主催者は、アカウントのある人も、この交流会のチェックインと回答だけを消す（取り消しの窓口）。ほかの組織・アプリの記録まで消せる窓口を、ほかの主催者に開かない【仮決め R11】

## User Scenarios & Testing *(mandatory)*

### User Story 1 - だれでも交流会を作り、自分の交流会だけを管理する (Priority: P1)

ログインした人は、交流会の一覧から「交流会を追加」で交流会を作れる。作った人がその交流会の持ち主になり、主催者として直す・準備・受付・内訳・CSV を使える。ほかの人の交流会は、運営者でも一覧に出ず、開けない。

**Why this priority**: 受付アプリをほかの組織・個人に出すための前提（FR-B1・FR-B7）。これがないと、ほかの主催者が受付アプリを使えない。

**Independent Test**: 運営者でない人が交流会を作ると 201 で、自分の一覧に出て主催者として開けること、ほかの人（運営者を含む）には一覧に出ず 403 になることを確かめる。

**Acceptance Scenarios**:

1. **Given** ログインした人（運営者でない）, **When** 交流会を作る, **Then** 201 で、持ち主がその人になり、`myRole` が主催者
2. **Given** Aさんの交流会, **When** Bさん（運営者を含む）が一覧を開く・交流会を開く, **Then** 一覧に出ず、開くと 403
3. **Given** 持ち主のない今の交流会, **When** 運営者が一覧を開く, **Then** 運営者が持ち主になり、主催者として出る

---

### User Story 2 - 持ち主が交流会を組織に入れ、組織の運営と分担する (Priority: P1)

持ち主は、準備の画面の「持ち主と組織」で、自分が入っている組織を選んで交流会を入れる。入れると、その組織の管理者・編集者も主催者になる。メンバーは部員で、管理の画面は使えない。持ち主は「入れない（個人）」で外せる。組織に入れる・外すのは持ち主だけ。

**Why this priority**: 1つの組織に複数の運営がいて分担する（FR-B2・FR-B3、UJ-6）。

**Independent Test**: 持ち主が組織に入れると、組織の編集者が交流会を直せて、メンバーは 403、外すと編集者も 403 に戻ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 持ち主が組織 X に入れた交流会, **When** X の管理者・編集者が開く・直す, **Then** 主催者として使える。一覧に出る
2. **Given** 同じ交流会, **When** X のメンバー（部員）が管理の窓口を呼ぶ, **Then** 403。一覧に出ない
3. **Given** 組織に入れた交流会, **When** 編集者が組織を入れ替える・外す, **Then** 403 `EVENT_OWNER_ONLY`
4. **Given** 持ち主, **When** 入っていない組織を選ぶ, **Then** 404 `EVENT_ORGANIZATION_NOT_FOUND`
5. **Given** 組織に入れた交流会, **When** 持ち主が組織を抜ける・外される・組織が消える, **Then** 交流会は組織から外れ、持ち主の個人のものに戻る（FR-B5）
6. **Given** 交流会の受付係, **When** 組織と関係なく受付をする, **Then** 今のまま使える。主催者で受付係でもある人は主催者（FR-B4）

---

### User Story 3 - 一覧で、自分の交流会を組織ごとに見る (Priority: P2)

交流会の一覧には、自分が主催者の交流会（持ち主のもの・組織のもの）と、受付係の交流会が出る。行ごとに持ち主と組織（なければ「個人」）が出て、組織ごとに絞れる（FR-B6）。

**Independent Test**: 自分の交流会・組織の交流会・受付係の交流会が出て、ほかが出ないこと、絞りこみで組織の交流会だけになることを確かめる。

**Acceptance Scenarios**:

1. **Given** 自分の交流会・編集者の組織の交流会・受付係の交流会・関係のない交流会, **When** 一覧を開く, **Then** 関係のない交流会だけ出ない
2. **Given** 一覧, **When** 組織のチップを選ぶ, **Then** その組織の交流会だけが出る。「個人」で組織に入れていない交流会だけ

---

### User Story 4 - 持ち主が退会しても、組織の交流会は残る (Priority: P2)

持ち主が退会すると、組織に入れていた交流会は、その組織の今の管理者が新しい持ち主になる。組織に入れていない交流会は、チェックインもアンケートの回答もなければ一緒に消える。チェックインがあれば退会できず、先に組織に入れるよう伝える（FR-B5・AD-23）。

**Independent Test**: 組織に入れた交流会を持つ人が退会すると持ち主が管理者に替わること、チェックインのある個人の交流会があると 409 で、何も変わらないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 組織 X に入れた交流会の持ち主（管理者でない）, **When** 退会する, **Then** 204 で、交流会の持ち主は X の管理者になる
2. **Given** 持ち主が X の管理者, **When** 退会する, **Then** 管理者を引き継いだ人が新しい持ち主になる。X にほかに誰もいなければ X が消え、交流会は個人のものとして扱う（下の 3・4）
3. **Given** 組織に入れていない交流会（チェックインなし）, **When** 持ち主が退会する, **Then** 交流会と、その受付係・招待のリンク・割引が消える
4. **Given** 組織に入れていない交流会にチェックインがある, **When** 持ち主が退会する, **Then** 409 `ACCOUNT_OWNS_SHARED_RECORDS` で、アカウントも交流会も、組織に入れた交流会の引き継ぎも変わらない
5. **Given** 退会の確かめの画面, **When** 開く, **Then** 引き継がれる交流会（と新しい持ち主）と、消える交流会が分けて出る

### Edge Cases

- 持ち主のない交流会（今の交流会）を、運営者でない人が開く：受付係なら受付係、ほかは 403。運営者が一覧を開くまで、主催者はいない
- 編集者からメンバーに下げられた人：次の要求から部員（主催者でない）。役目は要求のたびに引く
- 組織に入れた交流会の受付係が、その組織の編集者になった：主催者（受付係の行は残るが、主催者が勝つ）
- 引き継ぎの先の管理者が、その交流会の受付係だった：主催者になる（受付係の行は残る）
- 同じ組織をもう一度送る：何もしない（200 で今の状態）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 交流会は持ち主の account（`event.owner_account_id`）を持つ。作った人が持ち主になる。ログインした人は誰でも作れる（FR-B1）。
- **FR-002**: 交流会は1つの組織まで入れられる（`event_organization`）。入れる・外すのは持ち主だけで、持ち主が入っている組織だけを選べる（FR-B2・FR-B3）。
- **FR-003**: 役目は event の1つの関数で、要求のたびに決める：主催者＝持ち主か、入れた組織の管理者・編集者。受付係＝`event_staff`。部員＝入れた組織のメンバー。主催者で受付係でもある人は主催者（AD-5）。
- **FR-004**: event・reception・survey のすべての窓口は、交流会ごとの権限をこの関数で確かめる。設定 `ORGANIZER_LINE_USER_ID`（運営者）は交流会の権限に使わない（FR-B7）。運営者はアプリの台帳（AD-16）だけ。
- **FR-005**: 部員は、この版では管理の画面と窓口を使えない（403）。
- **FR-006**: 交流会の一覧は、自分が主催者の交流会と受付係の交流会を、日時の新しい順に出す。行ごとに持ち主（名前）と組織（名前。なければ null）と、自分が持ち主かを返す。画面は組織ごと・個人で絞れる（FR-B6）。
- **FR-007**: 持ち主が組織を抜ける・外される・組織が消えると、交流会は組織から外れる（外部キーの CASCADE。suite はほかの領域を呼ばない。AD-22）。
- **FR-008**: 退会では、組織に入れた交流会をその組織の今の管理者に引き継ぎ、組織に入れていない交流会を消す。消す交流会にチェックインがあれば、account を消す窓口は 409 `ACCOUNT_OWNS_SHARED_RECORDS` を返し、何も変えない。退会の確かめの中身に、引き継がれる交流会と消える交流会を分けて出す（AD-19・AD-22・AD-23）。
- **FR-009**: 今ある交流会の持ち主は運営者の account にする。組織には入れない（PRD 7章）。DB の変更は前の版のアプリでも壊れない形に分ける（列を空を許して足す → 埋める → 別の DB の変更で `NOT NULL`）。
- **FR-010**: 準備の画面に「持ち主と組織」の節を置く（持ち主の名前・組織の選択か今の組織・説明の文）。一覧の行に持ち主と組織を出す。

### Key Entities

- **交流会（event）**：持ち主の account を足す。持ち主はいつも1人で、組織に入れても変わらない。替わるのは退会の引き継ぎだけ。
- **交流会を組織に入れる（event_organization）**：交流会ごとに1行。組織と、入れた持ち主。持ち主が組織の人でなくなると消える。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 運営者でない人が、運営者の手を借りずに交流会を作り、受付まで終えられる。
- **SC-002**: ほかの人の交流会の管理の窓口は、運営者を含めてすべて 403（結合のテストで、event・reception・survey の主催者の窓口を確かめる）。
- **SC-003**: 組織に入れた交流会を、組織の編集者が直せる。外す・組織を抜けると、次の要求から 403。
- **SC-004**: 持ち主の退会で、組織に入れた交流会が消えずに管理者に引き継がれる。409 のときは何も変わらない。
- **SC-005**: 本番の今の交流会が、運営者が一覧を開いたあとに、すべて運営者の持ち物になっている（`NOT NULL` の DB の変更の前に確かめる）。

## Assumptions

- 組織（人・役割・招待・退会の手順の組み立て）は suite-001 のまま使う。組織の役割は suite の `index.ts` から引く。
- 予約（booking）は次の仕様。部員の使い道（部員だけの回・申込み）はそこで作る。
- 交流会を消す窓口は作らない（退会の段が消すだけ）。
- `NOT NULL` を付ける DB の変更と、持ち主を埋める処理を消す変更は、この仕様の外（本番で確かめてからの小さな PR）。
