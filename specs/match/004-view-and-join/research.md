# Research: 見るだけのページ・入口の QR・QR で受け付ける（match-004）

2026-11-22 作成。答える人がいないため、PRD 試合表アプリ（FR-M18〜M20・M23・M25・M29）・構成の決めごと（AD-26・AD-30）・Constitution 1.3.0・[主な画面の見本](../../../_bmad-output/ux-kanaeru-match/mockups/key-screens.html) の P1・M7・P2・P3・R1・R2 から AI が決めた。表は match-001（札の列・`match_join`）。**【仮決め】はどれも持ち主と運営の方の確かめを待つ。**

## R1. 札の期限は「試合の日と今日の遅いほう」の日本時間の終わり【仮決め】

- AD-26・AD-30 は「その日の終わり（日本時間）」とし、match-001 R5 は「期限は札を作るときに決める」とした。作った日の終わりにすると、前の日に刷った版や入口の QR が試合の日に使えない。試合の日の終わりにすると、試合の日を過ぎてから作った札がすぐ切れる。そこで、遅いほうの終わりにした（`tokens.ts` の `tokenExpiry`）。
- 試合の日より前に作った札は、試合の日まで見られる（ページに「試合表は当日に参加者へ公開されます」と書く。PRD FR-M18）。
- 試合の日をあとで直しても、出した札の期限は変わらない（作り直すと新しい日で決まる）。

## R2. 札そのものは、作った端末の localStorage にだけ置く【仮決め】

- AD-26・AD-30 のとおり DB は SHA-256 だけを持つので、サーバーは札を返し直せない。札は作ったときの答えでだけ返し、作った端末の localStorage（試合表ごと・期限つき）に置く（`link-store.ts`）。試合表を読む窓口は札の状態（期限・締めた時刻）だけを返す（`links`）。
- ほかの端末（担当を受け取った端末など）で QR を出すときは、札を作り直す（前のリンクと刷った QR は使えなくなるので、確かめの枠を出す）。
- 札を作れるのは、試合表の権限のある人（持ち主と、入れた組織の管理者・編集者。AD-25）。担当の端末でなくてもよい（中身を変えないため）。
- ほかの端末が作り直したときに古い QR を出さないよう、窓口は今の札の SHA-256 の頭8文字（`hint`）を返す（試合表の `links.viewHint`・`joinHint`、受付の一覧の `hint`、作ったときの答え）。画面は端末に置いた札の SHA-256 を計算して比べ、合わなければ QR を出さず「この端末の QR は古くなりました」と出す（印刷の版にも入れない）。頭8文字（32ビット）からは札は分からない。

## R3. 道の形は、試合表の領域の `paths.ts` に置く【仮決め】

AD-26 は道の形と URL を作る関数を `packages/contracts/src/core` に置くとする。今は試合表の領域の中（画面）でだけ使うので、共通の PR を足さずに `apps/web/src/features/match/paths.ts` の `matchPaths.view`・`join` に置いた。QR には画面の源＋道を入れる（ミニアプリの URL にしない）。ほかの領域が使うようになったら、共通の PR で core に移す。

## R4. 受付の行は残し、名簿の人の ID を受付の ID から決める【仮決め】

- AD-30 のとおり受付は `match_join` に1行ずつ足し、試合表の中身に直に書かない。担当の端末は、受付の画面（M7。5秒おきに読み直す）か名簿と設定の画面を開いたときに受付の行を読み、まだ名簿にない人を「来る」で名簿に足して送る（版が上がる。`use-joins.ts`）。
- 名簿の人の ID を受付の ID から決める（`joinPlayerId`：uuid の終わりの15文字に `j`）。行を残したままでも同じ人を二度入れない。DB に「取り込んだ」の列を足さずに済む（DB の変更の PR が要らない）。
- 受付の行を消すと（M7 の「消す」）、担当の端末なら名簿からも消す。消している途中の受付は、手元の一覧から先に外し、入れ直さない印を付ける（消したそばから入れ直さないため。`use-joins.ts` の `forgetJoinedPlayer`）。名簿に入りきらない（150人）ときは入れる人がいないので送らず、入りきらない人数を出す。名簿と設定で受付から入った人を消すと、受付の行も消す（消さないと、次に読んだときにまた名簿に入る）。担当でない端末で受付の行を消したときは、名簿の人は残る（担当の端末で消す）。
- 受付の行を直す画面は作らない。名簿に入ったあとは名簿と設定で呼び名とレベルを直す（AD-30 の「運営は受付の行を直せる」は、名簿で直す形にした）。
- 100人の上限は、受付の行の数で数える（消すとまた受ける）。行を押さえてから数え、同時に来ても超えない。
- 同じ名前：呼び名を NFKC にそろえて空白を消し、ほかの受付か名簿（その受付から入れた人を除く）に同じものがあれば、一覧に「同じ名前」の印を付ける（受付は止めない）。名簿と設定の画面でも、同じ呼び名の人に「同じ名前」の印を付ける。参加者の答えには出さない。

## R5. 見るだけのページ：最後に読んだ表をこの端末に置く・自分の名前・FR-M25【仮決め】

- 読んだ表と時刻を localStorage に置き（札ごと）、読めないとき（電波がない・窓口に届かない）はそれを出して「…に読んだ表を出しています」と書く（FR-M23）。ネットなしでページそのものを開く形（Service Worker）は、ネットなしの段（AD-27）。
- 版の番号は、つながっている間だけ30秒おきに確かめ（`/version` の小さな窓口）、変わっていれば読み直す（AD-26）。
- 自分の名前は選ぶ欄（呼び名の一覧）で選び、札ごとに localStorage に置く。印は警告の色（見本 P1 の `.me`）。
- 入口の文は「kanaeru で作った試合表・自分のサークルでも使う」で、`/match`（試合表の一覧。ログインしていなければログインの案内）へ。使い始めた運営の数を数える形（PRD 8章）は、数え方を決めてから足す。
- 見込みで今の試合を出す形（FR-M15 の「最後に読んだ表と1試合の長さから見込み」）は、ネットなしの段で足す（窓口の答えには1試合の長さを入れておいた）。
- ページの `noindex` は、画面が `<meta name="robots">` を足す（`no-index.ts`）。組み立てた画面の HTML に見出しで付ける形は、共通（`platform/web`）を直すので見送った。

## R6. 回数の制限：受け付ける POST は組み立ての制限、読む GET は札の長さで守る【仮決め】

- 組み立ての IP ごとの回数の制限（`app.ts`）は、`/api/v1` の状態を変える道（POST など）に効く。受け付ける POST はこれでそのまま制限される（AD-30）。
- 見るだけ・受付の GET は、組み立ての制限が効かない（読む道は数えない作り）。AD-26 は GET にも IP ごとの制限を求めるが、組み立て（共通の `app.ts`）を直す PR が要るので、この PR では足さない。札は 192ビットの乱数で、総当たりで当てることはできない。30秒おきの読み直しは `/version` の小さな答えにした。GET に制限を足すのは、共通の小さな PR で行う（残り）。

## R6b. いたずらと二重の受付【仮決め】

- 札を知っている人は、IP ごとの制限（組み立ての既定）の中で、受付を上限の100人まで埋められる。担当の端末はそれを確かめずに名簿へ入れる（AD-30 のとおり）。まとめて消す・IP ごとの受付の数の上限は、いたずらが起きたら足す（残り）。今は受付を締めて札を作り直し、1行ずつ消す。
- 送った答えだけが届かなかったとき（電波が切れた）に「もう一度押す」と、同じ人が2行になることがある。「同じ名前」の印が付くので、運営が1行消す。送る側の ID で二重を止める形は、ネットなしの段で参加者の端末に送りを残すときに一緒に考える。
- 呼び名の制御文字・向きを変える文字・幅のない文字（`\p{Cc}`・`\p{Cf}`）は受けない（見るだけのページと運営の画面の見た目を崩さないため）。
- ログインなしの道の答えは、誤り（400・404）にも `X-Robots-Tag` と `no-store` を付ける（道の middleware）。形の違う札も、ない札と同じ code の 404 にする。組み立ての回数の制限の 429 と、`/api` の外の画面の HTML には付かない（共通）。

## R7. P3 の「参加者の QR を運営のカメラで読む」は、ネットなしの段へ【仮決め】

電波がなくて送れないとき、受付のページは「電波がないため、まだ送れていません。電波のある所でもう一度押すか、運営に名前とレベルを伝えてください」と出す。名前とレベルを入れた QR を出し、運営の端末のカメラ（BarcodeDetector か QR を読む道具）で読む形は、電波なしで渡す QR（FR-M24）と一緒に、ネットなしの段で作る（読む道具の選び方が同じため）。

## R8. 画面の置き場所

- 見るだけのページ `/match/view/$viewToken` と受付のページ `/match/join/$joinToken` は、ナビのない外枠（`"bare"`）。試合表の道なので LIFF を始めない（core-013）。ログインを確かめない（`MatchGate` を使わない）。
- 運営の画面は、試合表の中のナビに「見るだけのページ」（`/match/tables/$tableId/view-link`）と「QR で受け付ける」（`/match/tables/$tableId/join`。M7）を足した。M7 の「この QR を印刷」は、入口に貼る1枚（見るだけ）と形が違うので、この PR では作らない（画面の QR を見せるか、リンクを載せる）。
- QR は event・suite と同じ `uqr` で、形（4モジュールの余白・画面で240px）も event の `QrCode` にそろえた。印刷の版の SVG の中に置くため、領域に写した（`qr.tsx`）。新しい依存はない。
