# Research: 名簿・組み方・試合表・印刷（match-002）

2026-11-22 作成。答える人がいないため、PRD 試合表アプリ（FR-M1〜M3・M5〜M13・M15〈チェックだけ〉・M19・M25・M26・M30）・[組み方の補足](../../../_bmad-output/prd-kanaeru-match/addendum.md)・構成の決めごと（AD-4 の例外・AD-19・AD-22・AD-25・AD-28・AD-29）・[主な画面の見本](../../../_bmad-output/ux-kanaeru-match/mockups/key-screens.html) から AI が決めた。**【仮決め】はどれも持ち主と運営の方の確かめを待つ。**

## R1. 組み方は addendum のとおり、入れ物を「出た数がいちばん少ない人」と読みかえる【仮決め】

**決めたこと**：`apps/web/src/features/match/pairing.ts` の `planGames`（状態を持たない関数・くじの種を引数で受け取る。AD-29）。周の入れ物を持たず、「出た数がいちばん少ない人」を入れ物の中身とみなす（全員の出た数が m か m+1 なら、m の人が「この周でまだ出ていない人」）。周の変わり目は、残りの人を必ず入れ、足りない分を m+1 の人から選ぶ（選ばれた人は m+2 になり、次の周の入れ物から外れる）。選び方は「（分けないときだけ）レベルの差の超え → 同じ試合に入った回数の2乗の合計 → 直前の試合に出た人の数 → くじ」の順に比べる。12人より多いときは、くじで12人に絞ってから組み合わせを比べる。説明は `planGames` の docstring（持ち主が決めた）。

**理由**：

- 入れ物を出た数から決めると、組み直し（addendum 2章）で「終わった試合までの入れ物の中身を引き継ぐ」が、終わった試合を数えなおすだけで済む（入れ物を中身に持たなくてよい）。
- 遅れて来た人は、出た数を「出られる人の最大 − 1」まで上げてから入れ物を決める。これで「来た人は今の周の入れ物に入る」「来るまでの試合は数えない」になり、試合の数の差が、いた間の数で1以内に収まる（property-based のテストで確かめる）。
- 周の変わり目でも差が1以内になることは、出た数がいつも m か m+1 であることから言える（addendum 3章の「まれに差が2」は起きない）。

## R2. 試合表を開けるのは、持ち主と入れた組織の管理者・編集者だけ（メンバーは開けない）【仮決め】

AD-25 は「作る・直す・担当の端末を決めるのは、持ち主と、入れた組織の管理者・編集者」と決め、読むだけの人を決めていない。運営の画面は直すための画面で、メンバーに見せたいときは見るだけのページ（AD-26。後の段）を使う形にした。権限は `access.ts` の `requireTableAccess` の1つの関数（AD-19）。試合表がなければ 404 `MATCH_NOT_FOUND`、あって権限がなければ 403 `MATCH_FORBIDDEN`。組織は作るときにだけ選べる（あとから入れる・外す画面は後の段）。

## R3. 一覧を開いたときと作ったときに、自分の90日を過ぎた試合表を消す【仮決め】

AD-25 のとおり定期の仕事は足さない。「試合の日 < 日本時間の今日 − 90日」の、今の利用者が持ち主の試合表を消す（受付の行・組織に入れる行は外部キーで消える）。組織の人の試合表は、その持ち主が開いたときに消える。

## R4. 試合表の道のログインは、クッキーのセッションだけで確かめる【仮決め】

試合表の道は LIFF を始めない（core-013）ので、account の `SessionGate`・`useSession`（`getLiff()` を読む）を使わない。窓口の 401 を `MatchGate` が受け、「ログインしてください」と「ログインする」（`/settings/account`。LIFF を始める道なので、組み立てがページを読み直して LIFF を始め、そこでログインする）を出す。ログインしたら、アプリの切り替えから試合表に戻ってもらう。ログインのあとに試合表へ自動で戻す形と、ログインの前に試せる形（FR-M26）は後の段（core-013 の申し送り：LIFF の戻り先を試合表の道の外にする）。

## R5. 担当の端末の ID は localStorage に置き、送れなかった変更は端末に残さない（今は）【仮決め】

AD-28 の担当の端末の ID は端末の乱数（`d-` と UUID）で、この段は localStorage に置く（読めなければ画面を開いている間だけの値）。直すたびに、中身をまるごと、もとにした版と変更の ID（UUID）を付けて古い順に1つずつ送る。送りの列は試合表ごとに1つで、画面（名簿と設定・試合表・印刷）を移っても続く。409 などで送れなかったら、残りの送りを止めて知らせ、サーバーの試合表を読み直す（直した中身は消える。読み直している間は直せない）。IndexedDB に中身と送っていない変更を持ってネットなしで動く形は、ネットなしで開く段（AD-27）で足す。作った端末が担当で、ほかの端末は「この端末で直す」で担当を受け取れる（権限のある人なら、つながっていればいつでも）。

## R6. 「遅れて来る」「来ない」の人は、組むときに入れない【仮決め】

当日の印は「来る」「遅れて来る」「来ない」の3つ（FR-M3。「帰る」は当日の組み直しの段）。組むときに出られるのは「来る」の人だけ。遅れて来た人が来たら「来る」に直して「組み直す」を押す（終わった試合までは残り、来た人は今の周に入る。R1）。当日の「来なかった・来た・帰る」の操作と、その人の組だけを組み直す形は、当日の組み直しの段（PRD 7.1 の3）。

## R7. 組み直しで残すのは「最後にチェックを付けた試合まで」。分け方・試合の形を変えたら合わない試合を外す【仮決め】

- 「組み直す」「別の組み合わせにする」は、組ごとに、最後にチェックを付けた試合まで（間のチェックのない試合も）をそのまま残し、その先だけを組む（FR-M14 の「今より先の試合だけ」。チェックの付いた試合は決して変えない）。
- レベルの分け方を変えると組が変わる（例：初級と入門 → 初級＆入門）。試合の形を変えると1試合の人数が変わる。中身の形の決まり（組は分け方の組だけ・1試合の人数は形のとおり）を守るため、合わなくなる試合は、終わった試合も外す（変える前に確かめの枠を出す）。当日に分け方や形を変えても終わった試合を残す形（PRD FR-M6・FR-M10 の「まだの試合だけを組み直す」）は、当日の組み直しの段で、終わった試合の持ち方とあわせて決める。
- くじの種は、組ごと・残した試合の数ごとに `deriveSeed(seed, "<組>:<残した数>")` で分ける（組を足し引きしても、ほかの組の表が変わらない）。

## R8. 名簿の読み方と呼び名【仮決め】

- 読む列は見出しで決める：氏名（「氏名」「お名前」「名前」を含む見出し。なければ1列目）・レベル（「レベル」を含む）・タイムスタンプ（「タイムスタンプ」「Timestamp」で始まる）。列の対応を運営が選ぶ画面（FR-M1 の「運営が直せる」）は、見出しが違うフォームが出てきたら足す。
- レベルは先頭の数字 1〜4（全角も）か、上級・中級・初級・入門の言葉。読めなければ空にし、名簿で選ぶまで試合に入れない（中身の `level` は null を許す）。
- 同じ氏名（NFKC・空白を消して比べる）が2回あれば、タイムスタンプの新しいほう（同じか読めなければ下の行）。
- 呼び名：姓（最初の空白の前）。同じ姓が2人以上なら、見分けられるまで名の字を足す（ふつうは1字）。名まで同じなら「2」「3」を足す。空白がない氏名は、氏名をまるごとサーバーに送らないよう、頭の2字を仮の呼び名にして印を付ける（運営に確かめて直してもらう。PRD FR-M2 は「氏名をそのまま」に読めるが、Constitution II を先にした）。すでに名簿にある呼び名とも重ねない。20文字まで。
- 貼り付けは「置きかえる（組み合わせも消える）」か「後ろに足す」を選ぶ（名簿が空なら置きかえる）。CSV のファイルは、名簿が空なら置きかえ、あれば足す。
- 氏名は中身に入れず、貼った画面を開いている間だけ「氏名（貼り付け）」の列に出す（Constitution II・FR-M1）。

## R9. 退会の手順は event の段と同じ形【仮決め】

`withdrawal.ts`：finalize（account を消すトランザクションの中）で、組織に入れた試合表を組織の今の管理者に引き継ぐ（`match_table` と `match_table_organization` の持ち主を替える）。組織に入れていない試合表は外部キー（CASCADE）で消える。確かめの中身に「引き継がれる試合表」と「消える試合表」を分けて出す。

## R10. 印刷は SVG で描き、紙は名前つきのページで選ぶ【仮決め】

- 版は SVG（`viewBox` を刷る範囲の mm にする）。字の大きさは SVG の属性で決めるので、画面の値（tokens.css）を使わず、CSP（`style-src 'self'`）にも当たらない。行は表の高さをちょうど埋め、字は「行の高さの6割」と「いちばん長い呼び名が列に収まる大きさ」の小さいほう。3.5mm（約10ポイント）より小さくなる組があれば、大きい紙をすすめる。
- 紙の大きさと向きは、版の `data-paper` を CSS の名前つきのページ（`@page match-a3-portrait { size: 297mm 420mm }` など）に当てる（`print.css`）。B は日本の JIS の B 列なので mm で書く。名前つきのページを読まないブラウザもあるので、画面に「印刷の画面でも、同じ紙の大きさと向きを選んでください」と書く。
- 見るだけのページの QR は、見るだけのページの段で足す（今は載せない）。下に「kanaeru で作った試合表」（FR-M25）。

## R11. 試合の数と組めない組【仮決め】

- 組ごとの試合の数は「試合の時間 ÷ 1試合の長さ」の切り捨て（組ごとに同じ。FR-M7。上限60）。
- 1試合の人数に足りない組（ダブルスで4人未満など）は組まず、設定の画面と試合表の画面に「一緒にする分け方にしてください」を出す（PRD FR-M6）。

## R12. 新しい依存（fast-check）

組み方の property-based のテストのため、`apps/web` の devDependencies に `fast-check`（4.10.3）を足した（AD-29）。テストだけで使い、画面の束には入らない。`pnpm-lock.yaml` が変わる。学びの文書（property-based のテスト）は、別の小さな文書の PR で足す（[文書の決まり](../../../docs/rules/documents.md) 1）。
