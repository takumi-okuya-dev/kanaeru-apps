## User Scenarios & Testing *(mandatory)*

### User Story 1 - 運営がフォームの回答を貼り付けて名簿を作る (Priority: P1)

運営は試合表を作り（名前・試合の日・任意で組織）、名簿と設定の画面で「フォームから貼り付ける」に、Google フォームの回答のスプレッドシートから見出しごとコピーした表を貼る。氏名・レベル・タイムスタンプだけが読まれ、呼び名（姓。同じ姓は名の1字）とレベルの名簿ができる。CSV のファイルも読め、1人ずつ足せる（FR-M30・M1・M2・M3）。

**Independent Test**: 見出しつきのタブ区切りの表を貼ると、呼び名とレベルの行ができ、メールアドレスなどは画面にもサーバーにも出ないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 試合表, **When** フォームの回答の表（メール・ラケット・要望の列つき）を貼る, **Then** 氏名・レベル・タイムスタンプだけを読み、同じ氏名は新しいほう1人。呼び名は姓、同じ姓は名の1字を足し、空白のない氏名には「姓と名の間に空白がありません」の印
2. **Given** 名簿, **When** 保存された中身を読む, **Then** 呼び名・レベル・当日の印だけで、氏名やメールアドレスはない（サーバーは氏名の欄を受けると 400）
3. **Given** レベルの列がない表, **When** 貼る, **Then** レベルが空の人は「選んでください」で、選ぶまで試合に入らない
4. **Given** 名簿, **When** 1人のレベル・当日の印（来る・遅れて来る・来ない）・呼び名を直す, **Then** すぐ保存される

### User Story 2 - 設定を選んで試合表を作り、進める (Priority: P1)

運営は 1試合の長さ・試合の時間・試合の形（ダブルス・シングルス）・レベルの分け方（4つ・3つ・2つ・分けない）を選び、組ごとの人数と試合の数を見て「試合表を作る」を押す。試合表の画面では組をタブで選び、1行に名前だけが並ぶ。終わった試合にチェックを付けると、今の試合と次の試合が分かる（FR-M5〜M13・M15）。

**Independent Test**: 16人・4つのレベル・8試合の名簿で組むと、組ごとに8行・1行4人で、チェックが保存されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 名簿と設定, **When** 「試合表を作る」, **Then** 組ごとに「試合の時間 ÷ 1試合」の数の試合ができ、1試合に同じ人は入らず、試合の数の差は1以内、「遅れて来る」「来ない」の人は入らない
2. **Given** 4人に足りない組, **When** 作る, **Then** その組は組まず、「一緒にする分け方にしてください」が出る
3. **Given** 分けない, **When** 作る, **Then** 1試合のレベルの差は、組み合わせがあれば2段以内
4. **Given** 試合表, **When** 第1試合にチェックを付ける, **Then** 第2試合が今（墨の地）、第3試合が次（薄い地）になり、読み直しても残る
5. **Given** チェックの付いた試合表, **When** 「組み直す」「別の組み合わせにする」, **Then** 最後にチェックした試合まではそのまま、その先だけが変わる
6. **Given** シングルス, **When** 作る, **Then** 1行に2人

### User Story 3 - 印刷する (Priority: P1)

運営は刷る組と紙（A5〜A2・B5〜B3・縦横）を選び、組ごとに1枚の版を見て印刷する。字の大きさは紙1枚に収まるよう自動で合う（FR-M19・FR-M25）。

**Acceptance Scenarios**:

1. **Given** 試合表, **When** 印刷を開く, **Then** 組ごとに1枚の版が出て、ボタンは「3枚を印刷する（A3 縦）」
2. **Given** 版, **When** 紙と向きを変え、組を外す, **Then** 版の形と枚数が変わる。下に「kanaeru で作った試合表」
3. **Given** 印刷, **When** 刷る, **Then** 版だけが出て、版は選んだ紙の刷る範囲の大きさ

### User Story 4 - 担当の端末だけが直せる (Priority: P2)

試合表を作った端末が担当の端末。ほかの端末は「見るだけ」で、「この端末で直す」で担当を受け取れる（AD-28）。

**Acceptance Scenarios**:

1. **Given** 担当でない端末, **When** 送る, **Then** 409 `MATCH_NOT_EDITOR`
2. **Given** 古い版, **When** 送る, **Then** 409 `MATCH_VERSION_CONFLICT`。同じ変更の ID の送り直しは、書かずに今の試合表を返す

### Edge Cases

- ログインしていない：試合表の画面は「ログインしてください」と、`/settings/account` へのリンク（R4）。
- 権限がない：403、ない試合表：404（R2）。
- 持ち主の退会：組織に入れた試合表は組織の管理者に引き継ぎ、入れていない試合表は消える（R9）。
- 90日を過ぎた試合表：一覧を開くと消える（R3）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 窓口（[contracts/match.md](./contracts/match.md)）：一覧・作る・読む・直す（版・担当の端末・変更の ID）・担当の端末を受け取る・消す・入れられる組織。権限は1つの関数。
- **FR-002**: 中身の形は約束（`MatchTableContent`）で確かめる（[data-model.md](./data-model.md)）。氏名の欄を受けない。
- **FR-003**: 退会の手順（引き継ぎ・確かめの中身）。
- **FR-004**: 組み方は addendum の1〜2章（`planGames`・`buildPlan`）。説明は docstring。property-based のテスト。
- **FR-005**: 画面：一覧・作る・名簿と設定・試合表・印刷と、外枠のナビの項目。

### Key Entities

- **試合表の中身**：設定・名簿（呼び名・レベル・当日の印）・組ごとの試合（入る人・終わったか）。

## Success Criteria *(mandatory)*

- **SC-001**: `pnpm check` が通る（E2E は両方の幅で axe・横のスクロールなし・CSP の違反なし）。
- **SC-002**: 組み方の property-based のテストが、試合の数の差・同じ試合の重なり・来ない人・同じ種・組み直しを確かめる。
- **SC-003**: 22人・3つのレベル・各8試合の試合表が、貼ってから1分以内にできる（PRD 8章。組むのは端末の中で一瞬）。
