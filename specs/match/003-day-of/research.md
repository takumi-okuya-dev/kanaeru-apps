# Research: 当日の組み直し・大きく映す・担当の受け渡し（match-003）

2026-11-22 作成。答える人がいないため、PRD 試合表アプリ（FR-M6・M10・M14〜M17）・[組み方の補足](../../../_bmad-output/prd-kanaeru-match/addendum.md) 2章・構成の決めごと（AD-28・AD-29）・[主な画面の見本](../../../_bmad-output/ux-kanaeru-match/mockups/key-screens.html) の M2・M3 から AI が決めた。match-002 の [research.md](../002-roster/research.md) の R1（入れ物は出た数）・R5（送り方）・R6（遅れて来る人）・R7（組み直しは最後のチェックまで）の上に積む。**【仮決め】はどれも持ち主と運営の方の確かめを待つ。**

## R1. 当日の印に「帰った」を足し、3つのボタンで直す【仮決め】

- 当日の印は「来る」`present`・「遅れて来る」`late`・「来ない」`absent`・「帰った」`left` の4つ。試合に入るのは `present` だけ。「来なかった」は `absent`、「来た」は `present`、「帰る」は `left` にする。
- 選べるボタンは今の印で決める：来る人は「来なかった」「帰る」、遅れて来る人は「来た」「来なかった」、来ない・帰った人は「来た」（戻ってきたとき）。
- 「帰った」を分けたのは、終わった試合に名前が残る人（`absent` だと「来なかった」と読めてしまう）を名簿で見分けるため。名簿の画面の当日の選ぶ欄にも出る。
- 人の選び方は、組ごとに分けた選ぶ欄（`optgroup`）にした（見本 M2 は「人を選んで直す」のボタンだけ）。40人でも1つの欄で探せる。
- 名簿と設定の画面の当日の欄でも「帰った」を選べるが、そこでは組み直さない（「来ない」と同じく、「組み直す」を押してもらう。match-002 の形のまま）。当日は試合表の画面の「人を選んで直す」を使う（名簿の画面の注意書きに書いた）。

## R2. 組み直すのはその人の組だけ。最後のチェックまでと、今の試合（入る人がみな出られるなら）を残す【仮決め】

- PRD FR-M14「その人のレベルの今より先の試合だけを組み直す」の「今より先」を、今の試合（チェックのない最初の試合）の次から、と読んだ。今の試合はもうコートで始まっているかもしれないので、入る人がみな出られるならそのまま残す。入る人が来なかった・帰ったなら、今の試合から組み直す（その人がいないので始まっていない）。
- 最後にチェックした試合までは、間のチェックのない試合（飛ばした試合）も含めて残す（match-002 R7 と同じ）。ただし飛ばした試合に出られない人が入っていれば、その1試合だけを組み直す（終わった試合の場所は変えない）。
- くじの種は試合表の種のまま（`deriveSeed(seed, "<組>:<残した数>")`）。同じ人を「来なかった」にして「来た」に戻すと、もとの表に戻る。
- ほかの組の試合は変えない。名簿と設定の画面の「組み直す」と、試合表の画面の「別の組み合わせにする」は今までどおり（すべての組を、最後のチェックの続きから）。
- 試合の数の差：組み直しは `planGames` に終わった試合（と残した今の試合）を渡すので、出た数を数えなおして続きを組む。ずっといた人どうしは差が1以内、来た人は「来た時のいちばん少ない数」から数えて差が1以内（match-002 R1 の床。property-based のテストで確かめる）。帰った人は数えない。

## R3. 当日に分け方・試合の形を変えたら、終わった試合をできるだけ残す【仮決め】

match-002 R7 では、分け方や試合の形を変えると合わない試合（終わった試合も）を外していた。PRD FR-M6・FR-M10 の「変えると、まだの試合だけを組み直す」に合わせ、終わった試合を残す形にした（`regroup.ts` の `changeSettings`）。

- **そのまま残す組**：試合の形が同じで、新しい分け方にも同じ組（key）があれば、まだの試合も含めてまるごと残す（例：4つ → 3つの上級・中級）。
- **新しい組に移す**：前の組の終わった試合のうち、入った人がみな新しい組のレベル（今のレベル）の試合を移す（組を一緒にしたとき）。並びは前の組の時刻の順（行の番号 − その組の offset）に交互（同じ時間に進んでいたため）。組の中の試合の番号は変わる（確かめの文に書く）。
- **前の分け方で終わった試合**（中身の `archive`）：移せない終わった試合（レベルの混ざった試合・試合の形が変わった試合）は、組から外して前の組の key ごとに残す。試合表の画面の下に畳んで出す（チェックは付け外さない）。組み直すときは、組の人が入った試合を数に入れて、試合の数を均す。印刷・大きく映す・見るだけのページには出さない。
- **行の数**：時間は前の組と同じだけ進んでいるので、新しい組の行の数 = 移した終わった試合 + （設定から決まる試合の数 − 進んだ試合の数）。どの組も同じ時間に進むので、進んだ試合の数は前のすべての組（そのまま残す組も含む）の「最後にチェックした試合の番号 − その組の offset」のいちばん大きいもの（チェックの付け忘れの組があっても、時間はいちばん進んだ組で見る）。差を組の `offset` に持ち、`buildPlan` は「設定の試合の数 + offset」まで組む。あとで試合の時間を変えても、差はそのまま効く。
- まだの試合は外す。試合表の画面では変えたらすぐ組み直し、名簿と設定の画面では「組み直す」を押してもらう（確かめの文で、どちらかを書き分ける）。
- 組を一緒にして終わった試合が1つの組の上限（240行）を超えるときは、古い試合を「前の分け方で終わった試合」に回す（まれ）。
- 組めなかった組（人が足りない）が当日に組めるようになったとき（「来た」・分け方を変えた）も、ほかの組が進んだ分だけ行を減らす（行の数 = 設定の試合の数 − 試合表の進んだ試合の数）。

## R4. 担当の受け渡し：端末の短い名前を出し、つながっているときだけ・確かめてから受け取る【仮決め】

- 担当の端末を見分ける名前は、端末の ID の終わりの4文字（「端末 3F9A」）。端末に名前を付ける欄は作らない（サーバーに持つのは ID だけのまま）。担当の端末には「この端末（端末 3F9A）が担当です」、ほかの端末には「今の担当：端末 3F9A（この端末は 端末 C2D1）」を出す。
- 受け取るのは、つながっているとき（`navigator.onLine`）だけ（AD-28・PRD FR-M16）。つながっていなければボタンを押せなくし、理由を出す。押すと確かめの枠（「担当の端末を持つ人に、声をかけてから移してください」）を出す。
- 前の担当の端末には、その場では知らせない（つなぎっぱなしの仕組みは使わない）。次に送ったときに 409 `MATCH_NOT_EDITOR` を受け、「保存できませんでした。…」と見るだけの帯を出す（送れなかった変更は消える。端末に残すのはネットなしの段。match-002 R5）。
- PRD FR-M16 の「両方の端末がつながっているとき」は、前の担当がつながっていなくても受け取れる形にした（担当の端末をなくしたときに止まらないように）。前の担当の端末がネットなしで直していた変更は、つながったときに 409 で知る。

## R5. 大きく映す：ナビのない画面・幅に合わせた大きな字・担当でない端末は30秒おきに読み直す【仮決め】

- 道は `/match/tables/$tableId/big`。ナビのない外枠（`"bare"`）。題・「全画面にする」（できるブラウザだけ）・「戻る」・組のタブ・今の試合と次の試合（墨の地と薄い地。「今・第n試合」の字も出し、色だけに頼らない）。
- 字の大きさは tokens.css の段（いちばん大きいのが 32px）では足りない。tokens.css に値を足すのは共通の変更になるので、名前の行を SVG で描き、画面の幅に合わせて大きくする（印刷の版と同じく、字の大きさは SVG の単位。広い画面で約 70px、スマホの幅で約 20px。いちばん長い呼び名が列に収まる大きさに下げる）。題と「今・第n試合」は tokens.css の `text-xl`。PRD 4.5「大きく映す画面で足りない文字の大きさは UX で決める」までの仮の形。
- ダブルスの4人も1行に並べる。「次」は今より後のチェックのない最初の試合（飛ばした試合があっても、終わった試合を「次」に出さない）。
- 担当の端末で出すのを基本にする（試合表の画面でチェックを付けると、同じ端末のこの画面がすぐ進む）。担当でない端末は、つながっている間30秒おきに読み直す（見るだけのページと同じ間。AD-26）。電波なしで渡す QR を読む形（FR-M17 の2台目）は、ネットなしの段。

## R6. 中身の形を広げる（DB の変更なし）

当日の印 `left`・組の `offset`・`archive` を約束の `MatchTableContent` に足した（どれも足すだけ。前の中身はそのまま通る）。前の版のアプリは新しい欄の入った中身を読めない（strict なので 500）が、試合表のアプリは台帳で公開する前なので、困る人はいない。DB は JSON の object だけを確かめるので、DB の変更は要らない。
