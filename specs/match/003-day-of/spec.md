## User Scenarios & Testing *(mandatory)*

### User Story 1 - 来なかった・来た・帰るで、その人の組だけを組み直す (Priority: P1)

運営は試合表の画面の「人を選んで直す」で人を選び、「来なかった」「来た」「帰る」を押す。その人の組のこれからの試合だけが組み直され、終わった試合（チェックの付いた試合）は変わらない。画面の上に「組み直しました。斎藤：来た（初級の第4試合から組み直しました）」が出る（FR-M14）。

**Independent Test**: 9人の組で2試合にチェックを付け、今の試合に入っていない人を「帰る」にすると、第1〜第3試合はそのままで、第4試合から先にその人が入らないことを確かめる。

**Acceptance Scenarios**:

1. **Given** チェックの付いた試合表, **When** 人に「帰る」を付ける, **Then** チェックの付いた試合は変わらず、その人はこれからの試合に入らない。ほかの組の試合は変わらない
2. **Given** 今の試合に入っていない人, **When** 「来なかった」「帰る」を付ける, **Then** 今の試合（もう始まっているかもしれない）はそのまま、その次から組み直す
3. **Given** 遅れて来る人, **When** 「来た」を付ける, **Then** 今の周に入り、来るまでの試合は数えずに、試合の数の差が1以内になる
4. **Given** 4人の組, **When** 1人が帰る, **Then** その先は組めず、「人が足りないため、第n試合から先を組めません」と出る
5. **Given** まだ組んでいない試合表, **When** 人を直す, **Then** 当日の印だけが変わる

### User Story 2 - 当日に分け方や試合の形を変えても、終わった試合を残す (Priority: P1)

運営は試合表の画面の「レベルの分け方」で分け方と試合の形を選ぶ。押す前に「変わること」（そのまま残す組・新しい組に移す終わった試合・組から外して残す終わった試合・組み直すまだの試合）が出る。押すと、終わった試合はできるだけ残してまだの試合だけを組み直す（FR-M6・FR-M10）。名簿と設定の画面で変えたときも同じ移し方で、確かめの枠に同じ文が出る。

**Acceptance Scenarios**:

1. **Given** 初級3試合・入門2試合が終わった4つの分け方, **When** 初級＆入門にする, **Then** 上級と中級はそのまま、5試合は初級＆入門に交互に移り、行の数は「5 + 残りの時間の試合」
2. **Given** 分けない表で終わった試合, **When** 2つに分ける, **Then** レベルの混ざった試合は「前の分け方で終わった試合」に残り（試合表の画面の下に畳んで出る）、試合の数を均すときにも数える
3. **Given** シングルスで終わった試合, **When** ダブルスにする, **Then** 終わった試合は組から外して残し、行の数は残りの時間の試合

### User Story 3 - 大きく映す (Priority: P1)

運営は「大きく映す」でコートの横の端末に、組のタブと、今の試合と次の試合だけを大きな字で出す（FR-M17。M3）。担当の端末なら、試合表の画面でチェックを付けるとすぐ進む。担当でない端末は、つながっている間30秒おきに読み直す。

**Acceptance Scenarios**:

1. **Given** 上級の第1試合にチェック, **When** 大きく映す, **Then** 「今・第2試合」「次・第3試合」が大きな字で出て、ナビは出ない
2. **Given** すべて終わった組, **When** そのタブ, **Then** 「すべて終わりました」

### User Story 4 - 担当の端末が分かり、つながっているときに受け取れる (Priority: P2)

担当でない端末には「今の担当：端末 3F9A（この端末は 端末 C2D1）」と「この端末で直す」が出る。押すと確かめの枠が出て、受け取る。つながっていないときは押せず、理由が出る。前の担当の端末は、次に送ったときに「保存できませんでした。この端末は担当の端末でない…」と出て見るだけになる（AD-28）。

## Requirements *(mandatory)*

- **FR-001**: 当日の印に「帰った」を足す（約束）。組めるのは「来る」の人だけ。
- **FR-002**: `markAttendance`（day-of.ts）・`replanGroup`（plan.ts）：1つの組だけを組み直す。残す試合は R2。
- **FR-003**: `changeSettings`（regroup.ts）：分け方・試合の形の変更で、終わった試合を移すか「前の分け方で終わった試合」（`archive`）に残し、行の数の差（`offset`）を持つ。`buildPlan` は `archive` を数に入れ、行の数は「設定の試合の数 + offset」。
- **FR-004**: 画面：試合表の画面の「人を選んで直す」「レベルの分け方」「大きく映す」・組み直したときの帯・前の分け方の試合。大きく映す画面（`/match/tables/$tableId/big`）。担当の帯（端末の短い名前・つながりの確かめ・確かめの枠）。
- **FR-005**: property-based のテスト：組み直しで終わった試合が変わらない・出られない人が入らない・いた間で試合の数の差が1以内・分け方を変えても終わった試合が消えない。

### Key Entities

- **試合表の中身**（match-002 の形を広げる）：当日の印 `left`・組の `offset`・`archive`（[data-model.md](./data-model.md)）。

## Success Criteria *(mandatory)*

- **SC-001**: `pnpm check` が通る（E2E は両方の幅で axe・横のスクロールなし・CSP の違反なし）。
- **SC-002**: 当日の変更1件の組み直しが、押してすぐ（端末の中の計算）終わる（PRD 8章の30秒以内）。
- **SC-003**: property-based のテストが、終わった試合と試合の数の差（いた間で1以内）を確かめる。
