# Research: ネットなしで開く・端末に残して送る・電波なしで渡す QR（match-005）

2026-11-22 作成。答える人がいないため、PRD 試合表アプリ 4.6（FR-M22〜M24）・FR-M15・FR-M29・構成の決めごと（AD-27・AD-28・AD-30）・Constitution III・[主な画面の見本](../../../_bmad-output/ux-kanaeru-match/mockups/key-screens.html) の M4・P1・P3・M7 から AI が決めた。共通の土台（Service Worker の組み立て・カメラの許可・jsQR）は core-015（[research](../../core/015-match-offline-base/research.md)）。match-002 research R5（送れなかった変更は端末に残さない）は、この段で R5 のとおりに変えた。**【仮決め】はどれも持ち主と運営の方の確かめを待つ。iPhone の Safari と Android の Chrome の実機での確かめはまだ（R15）。**

## R1. Service Worker：手で書いた本文・外枠はすぐ返す・新しい版は知らせて入れ替える【仮決め】

- 本文は `features/match/offline/sw.js`（import のないふつうの JS）。組み立ての plugin（core-015）が持つファイルの並びと版の印を埋め、`/match/sw.js` に書き出す。範囲は `/match/`（置いたフォルダが上限なので、ほかのアプリの道に広がらない）。
- 持つのは、外枠（index.html）・入口の束とその静かな読み込み・試合表の画面の束と CSS だけ。ほかのアプリの画面の束・LINE の SDK・API の答えは持たない（AD-27）。外枠は `/match/` の道で取る（`/index.html` で取ると、カメラを止める Permissions-Policy の見出しごと持ってしまうため。core-015 R3）。
- 画面を開く要求には、持っている外枠をすぐ返す（電波の弱い体育館で、取りに行って待たせない）。外枠は版ごとに固まっているので、新しい画面は「新しい版」の流れで入れ替える：ブラウザが `sw.js` の変わり目に気づいて新しい版を入れ、待たせる → 画面の下に「新しい版があります」（読み直す・あとで）→ 押すと `SKIP_WAITING` で入れ替わって読み直す（AD-27）。
- 知らせは、試合表のどの画面（ナビのある外枠・ない外枠）にも同じ形で出すため、画面の木の外に小さな React の根を1つ作って描く（`UpdatePrompt.tsx`）。外枠（共通）を直さずに済む。
- 開いたままの端末のため、つながったときと1時間おきに新しい版を確かめる。
- 外枠は、つながっているときに裏で取り直す（1分に1回まで）。取り直した外枠がこの版の持つ束だけを指すときだけ差しかえる。API の守りの見出し（CSP・Permissions-Policy）だけを変えて出したときも、試合表の端末に届く。
- ほかのタブで「読み直す」が押されると、入れ替わった Service Worker の下で、どのタブも読み直す（古い外枠のタブが、消えた束を取りにいって壊れないため）。開いている枠の入力は消える。

## R2. 止め方：機能の印（画面と本文の両方が見る）と、自分を外すだけの版【仮決め】

- 機能の印 `match.offline`（`DOMAIN_FEATURES`。既定は切）を、ログインなしの窓口 `GET /api/v1/match/offline` で画面に渡す。試合表のどの道でも、開いたときに読み、入なら入れ、切かアプリが見えない（404）なら外して置き場所を消す。届かない（電波がない）ときは今のまま。
- 画面の JS が壊れて動かないときのため、本文も画面を開く要求のときに（10分に1回まで）同じ窓口を読み、切なら自分を外し、置き場所を消し、開いている画面を読み直す。
- 本文そのものが壊れたときは、`sw.js` の `SELF_UNREGISTER` を `true` にして出す（入った途端に自分を外すだけの版。AD-27）。領域のファイルの1行で済む。同時に機能の印も切にする（入のままだと、開くたびに入れ直しては外すをくり返す）。

## R3. 範囲 `/match/` と `/match`（末尾の `/` なし）【仮決め・要確認】

- 範囲は `/match/` にした（AD-27・置いたフォルダの上限）。`/match` そのものは範囲に入らない（Service Worker は道の頭の文字で比べる）。範囲を `/match` に広げるには `Service-Worker-Allowed` の見出し（共通の `platform/web`）が要り、`/matchfoo` のような道も入ってしまう。
- 画面の中の行き来はページを読み直さないので困らない。困るのは、電波がないときに一覧（`/match`）を読み直す・ホーム画面に一覧を置いたとき。運営には、試合表の中の画面（`/match/tables/…`）からホーム画面に置いてもらう（実機で確かめる。R15）。

## R4. 端末の置き場所は IndexedDB。端末の ID は localStorage を正にして IndexedDB にも写す【仮決め】

- IndexedDB `kanaeru-match`：`tables`（試合表ごとの最後の中身〈直したものを含む〉と、最後にサーバーが受けた版・置いた時刻）・`changes`（送っていない変更。足した順の番号で古い順に読む）・`meta`（端末の ID・一覧）。開けないとき（古いブラウザ・プライベートブラウズの一部）は、画面を開いている間だけの置き場所にする。
- AD-28 は端末の ID を IndexedDB に置くとする。今の ID は localStorage で同期に読む形（match-002）で、多くの画面が使う。非同期に変えると広く直すことになるので、localStorage を正にしたまま IndexedDB にも写し、localStorage が消えて IndexedDB に残っていれば戻す（`device.ts` の `syncDeviceId`。試合表の道を開いたときに動く）。
- 置くのは、この端末の運営が開いた試合表だけ（呼び名とレベル。氏名は持たない。Constitution II）。試合表が消された・開けなくなった（403・404）ときは端末の中身と変更を消す。

## R5. 送りの列：変更ごとに中身のまるごと・もとの版をつなぐ・古い順に送り直す・409 は止めて残す【仮決め】

- 直すたびに、中身のまるごとを「変更の ID（乱数）・もとにした版・くじの種・時刻」と一緒に `changes` に足す。もとにした版は、前の変更のもとの版＋1（前の変更がなければ、最後にサーバーが受けた版）。担当は1台なので、ほかが書かなければこの並びでサーバーの版と合う（AD-28）。
- 古い順に1つずつ、置いた値のまま送る。答えが返らなかった送りは、同じ変更の ID で送り直す（サーバーは最後の変更の ID と同じなら今の試合表を返すので、二重にならない）。送れたら消す。
- 変更をまとめて1つにする（途中を捨てる）形は取らない（「古い順に送る」のとおり。変更は100KB までで、IndexedDB の上限には遠い）。
- 待つ：通信の誤り・5xx・429・時間切れ（送りは15秒で切る。弱い電波で「送っています」のまま止まらないため）→ 端末に残し、15秒おきとつながったときに送り直す。401 → 残してログインし直すのを待つ。
- 何も変えなかった直し（QR で同じ人をもう一度読んだなど）は、列に足さない（版を無駄に上げない）。
- 置き場所に足し終える前に送れたときは、足し終えるのを待ってから消す（送った変更を置き場所に残さない）。置き場所を読めないときは、空の列から始める。
- 止める（held）：409 `MATCH_VERSION_CONFLICT`・`MATCH_NOT_EDITOR` と、直せない誤り（400・403・404）→ 送りを止め、変更を端末に残して知らせ、画面にはサーバーの今の中身を読み直して出す。止めている間は直せない（古い中身の上に重ねないため）。運営が選ぶ：
  - 「この端末の変更を捨てる」：変更を消してサーバーの中身に戻す。
  - 「この端末の変更で上書きする」：最後の変更の中身を、サーバーの今の版をもとにした1つの変更にして送る（担当の端末だけ。`MATCH_NOT_EDITOR` のあとは、先に「この端末で直す」で担当を受け取る）。
- 同じ端末の2つのタブで同じ試合表を直す形はそろえない（片方が 409 になり、R5 のとおり止まる）。

## R6. 電波がないときに開く：端末の中身に切りかえる【仮決め】

- 試合表を読む（`loadTable`）：読めたら、送っていない変更があればその中身を重ねて出し（送りを始める）、端末に置く。通信の誤りか 5xx なら、端末に置いた最後の中身（と送っていない変更）を出す。試合表の一覧も最後に読んだものを端末に置き、電波がない・5xx のときに出す。
- 端末の中身と送っていない変更を消すのは、試合表が消された（404 `MATCH_NOT_FOUND`）ときだけ。権限がない（403）・アプリが見えない（組み立ての 404）は一時のことがあるので消さない。
- TanStack Query は既定で、ブラウザが「つながっていない」と知ると問い合わせと送りを止めて待つ（`networkMode: "online"`）。端末の中身に切りかえたい問い合わせ（試合表・一覧・見るだけのページ）と受付の送りは `networkMode: "always"` にした（止めて待つと、画面が「読みこんでいます」「送っています」のまま動かない）。

## R7. 電波がないときの文【仮決め】

- 担当の端末：「電波なし・HH:MM に保存（つながったら送ります）。まだ送っていない変更：N件」（見本 M1 の「電波なし・この端末に保存しました」を、時刻と数が分かる形にした）。端末の中身を開いただけのときは「電波なし・この端末に置いた HH:MM の試合表です。直すと、この端末に保存し、つながったら送ります。」。サーバーが答えないときは「サーバーにつながらないため…（あとで送り直します）」。
- 止めたとき：「保存できませんでした。（サーバーの文）」「この端末に、まだ送っていない変更が N件残っています（HH:MM まで）。画面にはサーバーの今の試合表を出しています。」と、捨てる・上書きする。

## R8. 見るだけのページ：最後に読んだ表・見込みの今の試合・新しいほうを出す【仮決め】

- 最後に読んだ表は今までどおり localStorage（match-004 R5）。QR で受け取った表も同じ所に置き、「QR で受け取った」の印を付ける。
- 読めればサーバーの表を出す。QR で受け取った表は、版がサーバーより大きく、かつ中身の時刻がサーバーの最後の保存より新しいときだけ先に出す（運営が送っていない変更を捨てた・いたずらで大きな版の QR を作られたときも、サーバーで次に保存されればサーバーの表に戻る）。時刻が端末より5分以上先の QR は取り込まない。
- 見込み（FR-M15）：つながらない間は、読んだときの今の試合（チェックのない最初の試合）から、過ぎた時間を1試合の長さで割った数だけ、チェックのない試合を進めて「見込み 今 第N試合」と出す（30秒おきに描き直す）。QR で受け取った表は、受け取った時刻から見込む（運営の端末の進み具合は、渡したときのもの）。

## R9. 電波なしで渡す QR の中身と大きさ【仮決め】

- 入れるもの（AD-28）：版の番号・見るだけの札の SHA-256 の頭8文字（どの試合表かを見分ける。札は分からない。match-004 R2 の hint）・名前と日付・1試合の長さ・中身の時刻・組ごとの呼び名の組み合わせと終わったか。レベル・氏名・名簿の人の ID は入れない。
- 縮め方：呼び名は1度だけ並べて番号で指し、数は可変長の整数、終わったかはビット。deflate（raw。`CompressionStream` があれば。縮まなければそのまま）。文字は Base45（RFC 9285）：QR の英数字の形（1文字 5.5 ビット）に入り、バイトの形より小さく、読み取りの道具が文字として返しても崩れない。
- 測った大きさ：22人・4つの組・各8試合の表（Open Questions 10）は 358 バイト → 446 文字、誤り訂正 L で 11 型（61 マス）の1枚。
- 1枚は 1000 文字まで（L で 18 型・91 マス。画面に一辺 400px で出し、スマホで読める大きさ）。入らなければ、つづきの QR に分ける（どの1枚にも「KM1.<何枚目><全部の枚数>.<束の印>.」の頭。最大16枚。2秒おきに切りかえ、前へ・次へ・止める）。読む側は順を問わず集め、全部そろったら組み立てる。16枚でも入らない表（150人・長い呼び名・60試合の組など）は、渡せないと出し、大きく映す画面か紙を勧める（Open Questions 10 の「レベルごとに分ける」は、取り込みの版の比べ方が複雑になるので取らなかった）。
- 渡す版は、送っていない変更を送り終えたあとにサーバーが持つ版（最後の変更のもとの版＋1）。送りを止めている（held）間は、画面に出しているサーバーの版。
- 読んだ中身は外から作れるので、ありえない値（版0・名前61文字以上・呼び名21文字以上・1試合の長さ0や600分超え）と、戻すと 256KB を超える中身は読まない。読んだ端末は、見るだけの札の印が自分の札と合い、今より新しい版のときだけ取り込む。同じ版・古い版は取り込まずに、その旨を出す。見るだけのリンクがない試合表は渡せない（読めるのは、そのページを開いたことのあるスマホだけなので。FR-M24）。

## R10. QR を読む：BarcodeDetector → jsQR・写真から読む【仮決め】

- カメラ（背面）の映像を 250ms おきに読む。BarcodeDetector があれば使い、なければ jsQR（開いたときに読む。core-015 R4）。
- カメラを使えない（許可しない・ない）ときは、その旨を出す。どのときも「写真から読む」（ファイルを選ぶ。スマホではその場で撮れる）を置く。写真は `createImageBitmap` で読み（`blob:` の URL を作らない。CSP を広げない）、大きな写真は 1280px に縮めてから読む。
- 映像・写真はどこにも送らない・残さない。閉じたらカメラを止める。

## R11. 参加者の QR（P3）を運営の M7 で読む【仮決め】

- 受付を送れなかったとき（通信の誤り）、受付のページは「この QR を運営に見せてください」と、受付の札の印・レベル・参加者の端末の乱数・呼び名を入れた QR を出す（「KJ1.」＋Base45）。乱数は同じ入力の間は変えない。
- 受付の QR の呼び名とレベルは、受付の窓口と同じ約束（`MatchJoinInput`：1〜20文字・制御文字なし）で確かめ、通らなければ読まない（外から作れる QR で、送りの列を 400 で止めないため）。
- 運営の M7 の「参加者の QR を読む」（担当の端末だけ）：受付の札の印が今の受付の札と合うときだけ、名簿に「来る」で入れる。名簿の人の ID は `q` と乱数（2回読んでも1人）。電波がなくても入り、送りは R5 の列に乗る。QR で入れた人は M7 の下に並べる（名簿と設定で直せる・消せる）。
- 受付のページは、つながったら自動で送る（見本 P3「つながったら、自動で送ります」）。運営がもう QR を読んでいると、受付の行からも名簿に入り、同じ名前の印が付く（受付の窓口は呼び名とレベルだけを受ける strict なので、乱数を送って二重を止められない）。運営が1人消す。
- 受付の札を作り直したあとの QR・別の試合表の QR は入れず、名前とレベルを聞いて名簿で入れてもらう。

## R12. テストの範囲

- 単体：送りの列（もとの版のつなぎ方・古い順・電波がないときは残す・同じ変更の ID で送り直す・5xx・401・409 は止めて残す・捨てる・上書き・開き直し）・QR の中身（Base45 の RFC の例・行き来〈property-based〉・大きさ・本物の QR の模様を uqr で作って jsQR で読む・版の比べ方・受付の QR）・見込み。
- E2E（Playwright の `setOffline`）：Service Worker の範囲は `/match/` だけでほかの道は受け持たない・持つファイルに試合表の画面があり、ほかのアプリの画面がない・1度開いた試合表を電波なしで読み直して開ける・直すと「電波なし・HH:MM に保存」・つながると送って版が上がる・電波なしで渡す QR を、ネットなしで開いた見るだけのページが写真から読んで取り込む（同じ版は取り込まない）・参加者の QR を M7 が写真から読んで名簿に入れる（2回読んでも1人）・つながると自動で送る。
- E2E の Chromium にはカメラがないので、画面に出た QR のスクリーンショットを「写真から読む」に渡した（読む道具は同じ）。カメラの映像から読む形と「新しい版があります」の入れ替えは、実機で確かめる（R15）。

## R15. 実機で確かめること（まだ）

- iPhone の Safari・Android の Chrome で、ホーム画面に置いた試合表の画面（`/match/tables/…`）がネットなしで開けるか・IndexedDB と localStorage が残るか（iPhone は使わない日が続くと消すことがある。Open Questions 9）。
- 両方で、カメラから QR（試合表の QR の 18 型まで・つづきの QR・受付の QR）を読めるか。iPhone の Safari に BarcodeDetector がないときに jsQR で読めるか・速さ。
- 体育館の弱い電波（つながっているが届かない）で、送りが待ちに切りかわり、つながったら送れるか。
- 「新しい版があります」から入れ替わるか（ホーム画面から開いたとき）。
