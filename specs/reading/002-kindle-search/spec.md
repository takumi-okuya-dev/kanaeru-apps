## User Scenarios & Testing *(mandatory)*

### User Story 1 - Kindle の書き出しを取りこむ (Priority: P1)

使う人は、Kindle のアプリのノートブックで「書き出し」を押し、メールで届いた HTML を読書記録で選ぶ。端末の中で読み取り、章・ページか位置・ハイライト・メモが出る。reading-001 と同じ確かめの画面で入れる本を確かめて入れる。Web のノートブック（read.amazon.co.jp/notebook）の画面をコピーして貼ってもよい。

**Why this priority**: 持ち主は Kindle と GoodNotes の両方で読む。Kindle が入らないと、記録が1つにまとまらない（PRD 2.1）。

**Independent Test**: 見本の HTML（章2つ・ハイライト3つ・メモ1つ）を選んで入れると、本の画面に3つのマーカーが章ごとに並び、1つにメモがコメントとして付いている。

**Acceptance Scenarios**:

1. **Given** Kindle の書き出しの HTML、**When** 選ぶ、**Then** 書名・著者・ハイライトの数・メモの数・章ごとの数が出て、書名に近い本が選ばれている
2. **Given** ハイライトの直後のメモ、**When** 入れる、**Then** メモはそのハイライトのコメントになる
3. **Given** ページのある本とない本、**When** 入れる、**Then** ページがあればページ、なければ位置で並ぶ
4. **Given** 表示の言葉が日本語の書き出し（「ハイライト」「メモ」「ページ」「位置No.」など）、**When** 選ぶ、**Then** 英語のものと同じに読める（クラスの名前と並びで読むので、言葉に左右されない）
5. **Given** Web のノートブックの画面をコピーして貼る、**When** 確かめる、**Then** ハイライトとメモが読み取られる
6. **Given** 「…」で終わるハイライト、**When** 確かめの画面を見る、**Then** 「出版社の上限で切れたかもしれない」数が出る（切れたとは決めつけない）
7. **Given** Kindle の HTML でないファイル、**When** 選ぶ、**Then** 何が起きたかと、貼り付けで入れる道が出る
8. **Given** 同じ本の書き出しをもう一度入れる、**When** 確かめの画面を見る、**Then** 新しいハイライトだけが「新しいマーカー」に数えられる（reading-001 の重なりの鍵）

---

### User Story 2 - すべての本をまたいで探す (Priority: P1)

仕事中に「この技術、どの本で読んだっけ」と思ったとき、使う人は本棚の上の欄に言葉を入れて探す。マーカーの文・コメント・分かったこと・書名・分かりたいことに当たったものが、本ごとにまとまって出る。押すと、本の画面のそのマーカーへ移る。

**Why this priority**: 「仕事中に本の一部を読み返したいが見つからない」困りごと（バックログ B3）への答え。

**Independent Test**: 2冊の本のマーカーに同じ言葉を入れて探すと、2冊がまとまって出て、押すとそのマーカーの所が開く。

**Acceptance Scenarios**:

1. **Given** 2冊の本に「決め方」を含むマーカー、**When** 「決め方」で探す、**Then** 2冊が本ごとにまとまり、当たった所が分かる形で出る
2. **Given** 全角と半角・大文字と小文字・ひらがなとカタカナだけが違う言葉、**When** 探す、**Then** 当たる
3. **Given** 当たったマーカー、**When** 押す、**Then** 本の画面が開き、そのマーカーが見える所に移る
4. **Given** 「100%」や「a_b」のような記号を含む言葉、**When** 探す、**Then** 記号は文字としてだけ当たる
5. **Given** 言葉を入れて探した、**When** 画面の URL を見る、**Then** URL に言葉が出ない
6. **Given** ほかの使う人の本にだけある言葉、**When** 探す、**Then** 当たらない

---

### User Story 3 - あとで調べるを集めて、自分の AI で調べる (Priority: P2)

使う人は「あとで調べる」を開き、`?` の印のマーカーをすべての本をまたいで見る。1つの「調べる」を押すと、選んだ AI か検索（ChatGPT・Claude・Google）が、調べる文の入った状態で新しいタブに開く。調べ終えたら、分かったことを一言残して「調べた」にする。

**Why this priority**: 「分かりにくい所を一発で調べたい」（持ち主の言葉）。ただし US1・US2 がなくても印は付けられる。

**Independent Test**: 2冊の本に1つずつ `?` のマーカーがあると、「あとで調べる」に2つが並び、「調べる」の開く先の URL に書名・章・文・コメント・分かりたいことが入っている。

**Acceptance Scenarios**:

1. **Given** 2冊の本に `?` の印のマーカー、**When** 「あとで調べる」を開く、**Then** 2つが並ぶ（調べたものは閉じた「調べ終えたもの」の中）
2. **Given** 調べる先に ChatGPT を選んだ、**When** 「調べる」を押す、**Then** ChatGPT が新しいタブで開き、調べる文に書名・章・マーカーの文・コメント・分かりたいことが入る
3. **Given** 調べる先を Google に変えた、**When** 画面を開き直す、**Then** Google のまま（端末に覚える）
4. **Given** 調べる文が長い（URL に入りきらない）、**When** 「調べる」を押す、**Then** 調べる文をコピーする形に切りかわり、そう出る
5. **Given** 「調べる」、**When** 画面を見る、**Then** 「調べる文は、開く先の URL に入ります。PaletKit からは送りません」と出る
6. **Given** 分かったことを書いて「調べた」を押す、**When** 本の画面を開く、**Then** そのマーカーのコメントの下に分かったことが出て、「あとで調べる」では「調べ終えたもの」に移る
7. **Given** 調べたマーカーの本を取りこみ直す、**When** 本の画面を見る、**Then** 分かったことは消えない

---

### User Story 4 - どの章を読んだかが分かる (Priority: P3)

使う人は、本の画面の上で、マーカーのある章の数と、章ごとのマーカーの数を見る。部分的に読む本でも、どこを読んだかが分かる。

**Why this priority**: 「読むのが遅く、全体像を見落とす」困りごと（PRD 2.1）。目次がないので、ない章までは分からない。

**Independent Test**: 3つの章にマーカーのある本を開くと、上に「マーカーのある章 3」と、章の名前とマーカーの数の一覧が出る。

**Acceptance Scenarios**:

1. **Given** 3つの章にマーカーのある本、**When** 本の画面を開く、**Then** 上に「マーカーのある章 3」と、章ごとの数が本の中の順に出る
2. **Given** 章の一覧の1つ、**When** 押す、**Then** その章の所へ移る

### Edge Cases

- **ほかの使う人の記録**：探す・あとで調べる・分かったことを残すは、本人の記録だけ。ほかの人のマーカーの ID は見つからないとして扱う。
- **夜の停止**：0時〜8時は「夜間は止まっています」。分かったことの書きかけは画面に残る。
- **Kindle の書き出しの揺れ**：「Highlight(」の空白の有無・見出しの中の「章名 >」・引用の形を選んだときの `citation`・ページのない本。どれも読める。
- **メモだけ**：直前にハイライトのないメモは、コメントだけのマーカーとして入れる。
- **HTML の中身を信用しない**：HTML はスクリプトを動かさずに読み、文字だけを使う。
- **探す言葉の長さ**：1〜100字。空の言葉では探さない。
- **調べる先の URL**：決まった3つの先だけ（作り手の決めた URL の頭）。利用者が URL を書きかえられない。
- **ログと URL**：探す言葉・マーカーの文・分かったことを、ログ・URL・エラーの知らせに出さない。

## Requirements *(mandatory)*

### Functional Requirements

**Kindle の取りこみ**

- **FR-001**：Kindle のアプリの書き出しの HTML を、端末の中で読み、書名・著者・章・ページか位置・ハイライトの文・メモを拾う。読み方はクラスの名前と並びに頼り、表示の言葉に頼らない（PRD FR-R6・AD-34・補足 7章）。
- **FR-002**：メモは、直前のハイライトのコメントにする。直前にハイライトがなければ、コメントだけのマーカーにする。
- **FR-003**：Web のノートブックの画面をコピーした文を、「色｜位置」（日本語の「黄色のハイライト｜位置: 1,234」など）の行を区切りに読む【仮決め。日本語の実物で確かめる】。
- **FR-004**：「…」で終わるハイライトの数を、「出版社の上限で切れたかもしれない」として確かめの画面に出す（補足 7章）。
- **FR-005**：書き出しの書名に近い本を、入れる本に選んでおく（reading-001 の確かめの画面を使う）。
- **FR-006**：Kindle の HTML でないとき・ハイライトがないときは、何が起きたかと貼り付けの道を出す。

**探す**

- **FR-007**：本人のすべての本をまたいで、マーカーの文・コメント・分かったこと・書名・分かりたいことを言葉で探せる。全角と半角・大文字と小文字・ひらがなとカタカナの違いでは外れない。記号は文字としてだけ当たる（PRD FR-R17）。
- **FR-008**：結果は本ごとにまとめ、当たった所を前後の文と一緒に見せる。押すと本の画面のそのマーカーへ移る。
- **FR-009**：探す言葉は、画面の URL に載せない。

**あとで調べる**

- **FR-010**：`?` の印のマーカーを、すべての本をまたいで並べる。調べたものは閉じた「調べ終えたもの」に分ける（PRD FR-R19）。
- **FR-011**：「調べる」で、選んだ先（ChatGPT・Claude・Google）を、調べる文の入った状態で新しいタブに開く。調べる文は、書名・章・マーカーの文・コメント・分かりたいこと。PaletKit からは何も送らない（PRD FR-R20・AD-20）。
- **FR-012**：調べる文が開く先の URL に入ることを画面で知らせる。長くて入りきらないときは、コピーに切りかえる。
- **FR-013**：調べる先の選び方は、端末に覚える。
- **FR-014**：分かったことを残して「調べた」にできる。分かったことは本の画面のコメントの下に出る。取りこみ直しで消えない（PRD FR-R21）。

**本の画面**

- **FR-015**：本の画面の上に、マーカーのある章の数と、章ごとのマーカーの数を本の中の順に出す。押すとその章へ移る（PRD FR-R14）。

**守り**

- **FR-016**：探す・あとで調べる・分かったことを残すは、持ち主の使う人だけ。ほかの使う人の記録は見つからないとして扱う（AD-32）。
- **FR-017**：探す言葉・マーカーの文・分かったことを、ログ・URL・エラーの知らせに出さない。

### Key Entities *(include if feature involves data)*

- **マーカー（足す列）**：分かったこと（1〜2,000字）・調べた時刻。ほかは reading-001 のとおり。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：Kindle で読んでいる1冊を取りこむのに、書き出しから「入れる」まで1分以内で済む。
- **SC-002**：持ち主が日本語のアプリで書き出した実物の HTML のハイライトとメモが、すべて入る。
- **SC-003**：数百件のマーカーを持つ使う人が言葉で探すと、狙ったマーカーが最初の画面に出る。
- **SC-004**：「あとで調べる」から、1回押すだけで、調べる文の入った AI か検索が開く。
- **SC-005**：最初の2週間で、Kindle と GoodNotes の両方のマーカーを2回以上取りこめた（PRD 8章「集まったか」）。

## Assumptions

- reading-001 の pr1・pr2 が `develop` に入っている（本・マーカー・確かめの画面・束・重なりの鍵）。
- DB の変更（マーカーに2つの列を足す）は、`develop` に向けて同時に1本だけ（AD-17）。
- Kindle の書き出しの HTML の形は、公開されているパーサーと見本から読んだ（補足 7章）。持ち主が日本語のアプリで書き出した実物を1つ渡したら、その形を写した架空の見本を足す。それまでは英語の見本と、言葉に頼らない読み方で作る。
- 調べる先の URL：ChatGPT は `https://chatgpt.com/?q=`、Claude は `https://claude.ai/new?q=`、Google は `https://www.google.com/search?q=`。どれも利用者のブラウザが開くだけで、画面の CSP に関わらない（作るときに、それぞれの先で文が入るかを確かめる）。
- 探すのは DB の部分一致（1人の記録は数千件まで）。そろえ方（NFKC・カタカナをひらがなに・小文字）は、人物メモ（person）と同じ考え方を読書記録の約束に置く（領域どうしで共通にしない。AD-18）。
