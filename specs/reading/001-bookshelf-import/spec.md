## User Scenarios & Testing *(mandatory)*

### User Story 1 - 本を本棚に足す (Priority: P1)

使う人（最初は持ち主）は、読んでいる本を本棚に足す。書名か ISBN を入れると候補が並び、選ぶと書名・著者・ISBN・書影（あれば）が入る。見つからない本（技術書典の本・出版社から買った PDF・洋書など）は、書名と著者を手で書く。分かりたいことを一言残せる。

**Why this priority**: 取りこむ先の本がないと、何も始まらない。

**Independent Test**: 書名で探して1冊足し、もう1冊を手で書いて足すと、本棚に2冊が並ぶ。

**Acceptance Scenarios**:

1. **Given** 本棚が空、**When** 書名「Kubernetes」で探して候補から1冊を選ぶ、**Then** 本棚にその本が出て、書名・著者・ISBN が入っている
2. **Given** ISBN（ハイフンあり・なし、10桁・13桁）を入れる、**When** 探す、**Then** その本が候補に出る
3. **Given** 候補に目当ての本がない、**When** 「手で書く」を選んで書名と著者を入れる、**Then** 本棚にその本が出る
4. **Given** 書影のある本とない本、**When** 本棚を見る、**Then** 書影のない本は、書名を入れた仮の表紙で出る
5. **Given** 書誌の検索の相手が止まっている、**When** 探す、**Then** 「今は探せません」と出て、手で書く道へ進める
6. **Given** 本を足すとき、**When** 分かりたいことを書く（空でもよい）、**Then** 本棚と本の画面に出る。あとから直せる
7. **Given** 本を足す画面、**When** 画面を見る、**Then** 国立国会図書館サーチを使っていることが書いてある

---

### User Story 2 - GoodNotes で引いたマーカーとコメントを取りこむ (Priority: P1)

使う人は、GoodNotes で読んでいる本を区切りのよいところで PDF に書き出し、読書記録で選ぶ。端末の中で読み取り、マーカーの数・コメントの数・章が出る。入れる本を確かめて（合っていなければ選び直すか、新しく登録して）「入れる」を押すと、本の画面に章ごとのマーカーとコメントが並ぶ。本の PDF は PaletKit に送られない。

**Why this priority**: 持ち主の困りごと（マーカーが読む場所ごとに散らばり、眠っている）を片づける芯。

**Independent Test**: マーカー3か所とテキストボックス1つのある見本の PDF を選び、「入れる」を押すと、本の画面に3つのマーカーが章ごとに並び、1つにコメントが付いている。

**Acceptance Scenarios**:

1. **Given** GoodNotes から書き出した PDF（マーカーとテキストボックスあり）、**When** 選ぶ、**Then** 読み取ったマーカーの数・コメントの数・`?` の数・章ごとの数が出る
2. **Given** 読み取りが終わった、**When** 入れる本の候補を見る、**Then** PDF の名前に近い本が選ばれている。違えば、ほかの本を選ぶか、新しく登録できる
3. **Given** 確かめの画面、**When** 「入れる」を押す、**Then** 本の画面に、マーカーが章ごとに本の中の順で並び、テキストボックスの文が近いマーカーのコメントとして付いている
4. **Given** 確かめの画面、**When** コメントの付け先が違う、**Then** 正しいマーカーに付け替えられる。章の名前も直せる
5. **Given** 取りこみの途中で電波が切れた、**When** もう一度「入れる」を押す、**Then** 残りが入り、すでに入った分は2重にならない
6. **Given** 取りこむ、**When** 通信を見る、**Then** 送られるのはマーカーの文・コメント・章・ページだけで、PDF も、マーカーのない本の文も送られない
7. **Given** マーカーもテキストボックスもない PDF・読めない PDF・300MB をこえる PDF、**When** 選ぶ、**Then** 何が起きたかと、貼り付けで入れる道が出る
8. **Given** 5,000 件をこえるマーカーのある PDF、**When** 選ぶ、**Then** 一度に入れられる数の上限が出て、入れない

### User Story 3 - 同じ本を取りこみ直す (Priority: P1)

使う人は、続きを読んだら同じ本の PDF をもう一度書き出して取りこむ。新しいマーカーだけが足され、前に入れたマーカーは2重にならない。読書記録の側で直したコメントは、上書きされない。

**Why this priority**: 区切りごとに取りこむ使い方（PRD UJ-1）なので、取りこみ直しで壊れると使えない。

**Independent Test**: マーカー3つの PDF を入れたあと、マーカー5つ（前の3つを含む）の PDF を入れると、マーカーは5つになる。

**Acceptance Scenarios**:

1. **Given** マーカー32を入れた本、**When** 前の32を含む41のマーカーの PDF を選ぶ、**Then** 確かめの画面に「新しいマーカー 9」と出て、入れると41になる
2. **Given** 読書記録でコメントを直したマーカー、**When** 取りこみ直す、**Then** 直したコメントのまま
3. **Given** 読書記録で直していないマーカーのコメントを、GoodNotes の側で直した、**When** 取りこみ直す、**Then** 新しいコメントになる
4. **Given** GoodNotes の側で消したマーカー、**When** 取りこみ直す、**Then** 読書記録からは消えない
5. **Given** 読書記録で `?` の印を外したマーカー、**When** 取りこみ直す、**Then** 印は外れたまま

---

### User Story 4 - ほかの読む場所のマーカーを貼って取りこむ (Priority: P2)

使う人は、GoodNotes の PDF が読めないときや、ほかのアプリで読んだ本のマーカーを、1行に1つずつ貼って取りこむ。ページは書いても書かなくてもよい。

**Why this priority**: どの読む場所の本も1つにまとめたい（PRD 2.1「記録を1つに」）。読み取れないときの逃げ道にもなる。

**Independent Test**: 3行（うち1行はページつき）を貼って入れると、本の画面に3つのマーカーが並ぶ。

**Acceptance Scenarios**:

1. **Given** 本を選んだ貼り付けの画面、**When** 3行を貼って確かめる、**Then** 3つのマーカーとして読み取られ、件数が出る
2. **Given** 「p.38 Pod には1つずつ IP が付く」のような行、**When** 貼る、**Then** ページ 38 のマーカーとして読み取られる
3. **Given** 行の後ろに「// コメント」を付けた行、**When** 貼る、**Then** 「//」の後ろはコメントになる【仮決め】
4. **Given** 同じ行を2回貼って入れる、**When** 本の画面を見る、**Then** 2重にならない

---

### User Story 5 - 本の画面で読み返し、コメントを直す (Priority: P2)

使う人は、次にその本を開く前に本の画面を開き、前に引いたマーカーとコメントを章の順に読み返す。コメントを直したり足したり、要らないマーカーを消したりする。

**Why this priority**: 「前の内容や全体像を見落とす」困りごと（PRD 2.1）への最初の答え。取りこんだものを確かめる場所でもある。

**Independent Test**: 2つの章にマーカーのある本を開くと、章ごとに本の中の順で並ぶ。1つのコメントを直すと、開き直しても直したまま。

**Acceptance Scenarios**:

1. **Given** 3章と2章にマーカーがある本、**When** 本の画面を開く、**Then** 2章が先、章の中はページ（位置）の順に並ぶ（取りこんだ順ではない）
2. **Given** 章の取れないマーカー、**When** 本の画面を開く、**Then** ページの順に並ぶ
3. **Given** コメントのないマーカー、**When** コメントを書いて保存する、**Then** 付く。`?` で始めると「あとで調べる」の印が付く
4. **Given** マーカー、**When** 消すを選んで確かめる、**Then** 消え、取りこみ直しても戻らない【仮決め】
5. **Given** 分かりたいこと、**When** 本の画面の上を見る、**Then** 分かりたいことが出て、直せる

---

### User Story 6 - 本棚を整える (Priority: P3)

使う人は、本に読む場所と状態（読んでいる・読み終えた・やめた）を付ける。本棚は、読んでいる本が上で、最後に取りこんだ順に並ぶ。2回登録してしまった本は1冊にまとめ、要らない本は消す。

**Why this priority**: 2〜5冊を並行して読むので、読んでいる本がすぐ見つかるとよい。ただし US1〜US5 だけでも使える。

**Independent Test**: 3冊のうち1冊を「読み終えた」にすると、本棚の上は読んでいる2冊になる。

**Acceptance Scenarios**:

1. **Given** 読んでいる本2冊と読み終えた本1冊、**When** 本棚を開く、**Then** 読んでいる2冊が上で、最後に取りこんだ本が先。読み終えた本は閉じた「読み終えた本」の中にある
2. **Given** 1冊を Kindle と GoodNotes の両方で読む、**When** 読む場所を2つ付ける、**Then** 両方が付く
3. **Given** 同じ本が2冊ある、**When** 片方をもう片方にまとめる、**Then** マーカー・コメントが1冊に寄り、同じマーカーは1つになり、もう片方は消える
4. **Given** 本、**When** 消すを選ぶ、**Then** 消えるマーカーの数が出て、確かめると、本とマーカーが消える（戻せない）

### Edge Cases

- **ほかの使う人の記録**：ほかの使う人の本・マーカーの ID を道や本文に入れても、見つからないとして扱う（あると知らせない）。
- **見えないアプリ**：アプリが使う人に見えないとき（台帳で運営者だけ・オフ）は、読書記録の道を開いても見つからない（AD-16）。
- **夜の停止**：0時〜8時に開くと「夜間は止まっています」と出る。取りこみの確かめの画面で止まったら、読み取った中身は画面に残り、朝にもう一度「入れる」を押せる（AD-10）。
- **同じ本の重なり**：マーカーの文の空白の違い（全角と半角の空白・改行）だけが違うものは、同じマーカーとみなす。文が同じでもページが違えば別のマーカー。
- **見出しへのマーカー**：章や節の見出しに引いたマーカーも、ふつうのマーカーとして入れる。
- **コメントだけのテキストボックス**：近くにマーカーのないページのテキストボックスは、そのページの「マーカーのないコメント」として入れる【仮決め】。
- **書影の配信元が見られない**：書影が読めないときは、仮の表紙に切りかえる。
- **長い文**：マーカーの文・コメントが上限をこえると、その行は入れず、確かめの画面にそう出す（ほかの行は入れる）。
- **ログ**：マーカーの文・コメント・分かりたいことを、ログ・URL・エラーの知らせに出さない（PRD 5章）。
- **大きな PDF**：iPhone で読み取りに時間がかかるときは、読んだページの数を見せる。途中でやめられる。
- **書影なしの本の検索**：書名の検索で、同じ本が電子版と紙の版で2つ出ることがある。どちらを選んでもよい。

## Requirements *(mandatory)*

### Functional Requirements

**本棚と本**

- **FR-001**：使う人は、書名か ISBN で書誌を探し、候補から選んで本を足せる。見つからなければ、書名と著者を手で書いて足せる（PRD FR-R1・AD-33）。
- **FR-002**：持つ書誌は、選んだ本の書名・著者・ISBN・書影の URL だけ。検索の結果は持たない（AD-33）。
- **FR-003**：書影は、あるときだけ配信元から出す。ないときは、書名を入れた仮の表紙を出す（AD-33）。
- **FR-004**：本を足す画面に、書誌の出どころ（国立国会図書館サーチ）を書く（補足 8章）。
- **FR-005**：本に、分かりたいことを一言残せる（任意・あとから直せる。PRD FR-R2）。
- **FR-006**：本に、読む場所（Kindle・GoodNotes・そのほか。いくつでも）と、状態（読んでいる・読み終えた・やめた）を付けられる（PRD FR-R3）。
- **FR-007**：本棚は、読んでいる本を上に、最後に取りこんだ順に並べる。読み終えた本・やめた本は閉じておく（PRD FR-R4）。
- **FR-008**：2冊の本を1冊にまとめられる。重なるマーカーは1つにする（PRD FR-R5）。
- **FR-009**：本を消せる。消す前に、消えるマーカーの数を出して確かめる（PRD FR-R5・AD-7）。

**取りこみ**

- **FR-010**：GoodNotes から書き出した PDF を、端末の中で読み、マーカーの下の文・テキストボックスの文・ページ・章を拾う（PRD FR-R7・AD-34・補足 6章）。
- **FR-011**：テキストボックスの文は、同じページのいちばん近いマーカーのコメントにする。近くにマーカーがなければ、マーカーのないコメントにする。
- **FR-012**：章は、ページの上の柱から取る。柱のないページは前のページの章を引き継ぐ。取れなければ、ページで並べる。
- **FR-013**：1行に1つずつ貼った文を、マーカーとして取りこめる。行の頭の「p.38」「P38」「38:」などはページにする。「//」の後ろはコメントにする（PRD FR-R8）。
- **FR-014**：取りこむ前に、読み取った件数（マーカー・コメント・`?`）・章ごとの数・新しいマーカーの数と、入れる本を見せて確かめる。入れる本は選び直すか、新しく登録できる。コメントの付け先と章の名前を直せる（PRD FR-R9）。
- **FR-015**：本のファイルも、マーカーのない本の文も、サーバーに送らない。送るのは、マーカーの文・コメント・ページか位置・章・`?` の印・読む場所だけ（PRD 5章・AD-34）。
- **FR-016**：送るときは、API の本文の上限に収まる束に分けて順に送る。途中で切れても、もう一度送れば残りが入り、2重にならない（PRD 4.2・AD-34）。
- **FR-017**：1回の取りこみは 5,000 件まで、端末で読むファイルは 300MB まで（PRD 4.2）。
- **FR-018**：読み取れないとき（マーカーがない・PDF が壊れている・上限をこえる）は、何が起きたかと、貼り付けで入れる道を出す（PRD FR-R7）。
- **FR-019**：同じ本を取りこみ直したとき、前のマーカーは2重にならない（文と、ページか位置で同じものと見る）。読書記録の側で直したコメントと、付け外した `?` の印は上書きしない。読む場所の側で直したコメントは、読書記録で直していなければ新しくする。読む場所の側で消したマーカーは消さない（PRD FR-R10・AD-32）。
- **FR-020**：`?` で始まるコメント（全角の「？」も）を拾い、マーカーに「あとで調べる」の印を付ける（PRD FR-R11）。

**本の画面**

- **FR-021**：本の画面に、マーカーとコメントを章ごとに、本の中の順（ページか位置）に並べる。章が取れないときはページで並べる（PRD FR-R13）。
- **FR-022**：本の画面で、コメントを直す・足す、マーカーを消すことができる。`?` の印を付け外しできる（PRD FR-R11・FR-R12）。
- **FR-023**：本の画面の上に、分かりたいことを出す（PRD FR-R15 の一部）。

**守り**

- **FR-024**：本とマーカーを見る・直す・消すことは、持ち主の使う人だけができる。ほかの使う人の記録は見つからないとして扱う（AD-19・AD-32）。
- **FR-025**：マーカーの文・コメント・分かりたいことを、ログ・URL・エラーの知らせに出さない（PRD 5章）。
- **FR-026**：退会すると、本とマーカーはすべて消える。退会の確かめの画面に「読書記録（本・マーカーとコメント）」が出る（AD-19・AD-32）。
- **FR-027**：アプリは、台帳に行がない間は運営者だけに見える（AD-16）。最初は運営者（持ち主）だけで使う。

### Key Entities *(include if feature involves data)*

- **本**：使う人の本棚の1冊。持ち主（使う人）・書名・著者・ISBN（あれば）・書影の URL（あれば）・書誌の出どころ（国立国会図書館サーチ・openBD・手で書いた）・分かりたいこと・読む場所（いくつでも）・状態・最後に取りこんだ時刻。
- **マーカー**：本の中で使う人が引いた1か所。本・読む場所・章・ページか位置・本の中の並びの番号・マーカーの文・コメント・コメントを読書記録で直したか・`?` の印と、それを読書記録で付け外したか・重なりを見分ける鍵（文とページか位置から作る）。マーカーの文がなく、コメントだけのものもある。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：GoodNotes で読んでいる1冊を取りこむのに、PDF の書き出しから「入れる」まで1分以内で済む（PRD 4.2）。
- **SC-002**：持ち主が書き出した実際の PDF（357ページ・マーカー80か所・テキストボックス4つ）を取りこむと、80か所すべてが入り、4つのコメントが正しいマーカーに付く。
- **SC-003**：同じ PDF を3回取りこんでも、マーカーの数は変わらない。
- **SC-004**：本の PDF とマーカーのない本の文が、サーバーに1度も送られない（確かめのテストで、送った中身を調べる）。
- **SC-005**：ほかの使う人の本・マーカーを見ようとしたすべての場合（道の ID・本文の ID・まとめる・消す）で、中身が出ない。
- **SC-006**：最初の2週間で、持ち主が読んでいる本のマーカーを2回以上取りこめた（PRD 8章「集まったか」の GoodNotes の分）。

## Assumptions

- 使う人は LINE でログインした PaletKit のアカウントを持つ（AD-4）。最初の版の使う人は持ち主だけで、アプリは台帳に行がない間、運営者だけに見える。
- 取りこむのは主に iPhone の Safari（ふつうのブラウザ）。LINE の中のブラウザでファイルを選べるかは、計画で確かめる（構成の Open Questions 14）。
- 0時〜8時は DB が止まり、使えない（AD-10）。
- 先に入れる共通の PR は、次の順で `develop` に入れる。
  - OAuth の範囲の直し（#169）と予期しない DB のエラーのログの直し（#167）：pr1 より前（pr1 で `apps.list.ts` に足すと、すぐ範囲に出るため。マーカーの文がログに出ないため）。
  - 画面の CSP の書影の源（#176）：pr2 より前。
- DB の変更のある PR は、`develop` に向けて同時に1本だけ。人物メモの #168 が入ってから pr1 を開く（AD-17）。
- GoodNotes の PDF の形は、持ち主の PDF 1つで確かめた（補足 6章）。ほかの出版社の本で柱が違うときは、ページで並べる。テストの見本は、確かめた形を写した架空の PDF で作る（本物の本の PDF はリポジトリに置かない）。
- 書誌の検索は、国立国会図書館サーチ（書名）と openBD（ISBN）。鍵は要らない。続けて使うので、公開の前に持ち主が国立国会図書館の申請のフォームで使い道を知らせる（補足 8章）。
- 説明の材料・やってみること・自分の ID などの表は、それぞれの仕様で足す。
