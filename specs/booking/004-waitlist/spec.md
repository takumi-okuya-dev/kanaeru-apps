## Clarifications

### Session 2026-11-20

答える人がいないため、PRD・構成の決めごと・モックアップと booking-001〜003 の仮決めから AI が決めた（【仮決め】。理由は [research.md](./research.md)）。

- Q: 定員と媒体の枠をどこに持ち、どの使い方で使うか → A: 定員は `booking_setting.capacity`（空＝定員なし。1〜1000）、媒体の枠は `booking_quota`（交流会・媒体〈直接を除く Connpass・Peatix・そのほか〉・席の数・管理ページの URL〈任意〉）。使い方が「名簿を使う」でも定員と枠を入れられ、人数の目安と「何人超えています」だけを出す。キャンセル待ち・打診・知らせは「自前で申込みを受ける」のときだけ【仮決め R1】
- Q: 埋まった席と自前のページの残り → A: 埋まった席＝すべての入口の確定＋打診中。自前の残り＝定員 − 埋まった席 − 枠のまだ埋まっていない席（枠の媒体の確定＋打診中を枠から引いた残り）。一度満員（埋まった席 ≥ 定員）になったら、枠の席は押さえるのをやめる（主催者に「受付を止める媒体」を出したあとなので、空いた席はキャンセル待ちに回す。UJ-4）【仮決め R2】
- Q: 満員の画面 → A: 埋まった席が定員に届いたら「満員です」と、受付を止める媒体（枠を決めた媒体と、名簿に取り消しでない申込みがある直接でない媒体。管理ページの URL があればリンク）を出す。自前の残りだけが0なら「自前のページの席は埋まりました（キャンセル待ちを受け付けています）」と枠の残り。埋まった席が定員を超えたら「n人超えています」（勝手に取り消さない）【仮決め R3】
- Q: キャンセル待ちの並び → A: 状態 `waitlisted` の行を、申し込んだ日時の古い順（同じ時刻は ID の順）。何番目かは読むときに数える。申込みページで残りが0なら申し込んだ人はキャンセル待ちに入る（LINE・メールのどちらも）。主催者が手で足すときは、満員なら「定員を超えて足す」（既定）か「キャンセル待ちに入れる」を選ぶ。取り込みはいつも確定（超えたら「何人超えています」）【仮決め R4】
- Q: 打診の持ち方と同時に走ったとき → A: 打診は `booking_offer`（申込み・期限・状態〈待っている・参加・辞退・期限切れ・取り下げ〉・メールの人の返事の札の SHA-256）。申込みの状態を `offered` にして席を押さえる。待っている打診は申込みごとに1つ（部分の一意）。席の計算と打診は、交流会の設定の行を `FOR UPDATE` で押さえたトランザクションの中で決め直す（同時に走っても二重に打診しない・定員を超えて打診しない）【仮決め R5】
- Q: 返事の期限 → A: 打診から24時間 → 日本時間の0時より後・9時より前（ちょうど0時と9時は含まない）なら、その朝の9時 → 始まりの2時間前より後なら始まりの2時間前 → それが0時より後・9時より前に落ちたら、その日の0時（前の夜の24時。DB が止まって答えられないため）→ 打診の時刻から1時間に足りなければ打診しない（当日の空き）。時刻は日本時間（夏時間なし）で計算する【仮決め R6】
- Q: 当日の空き → A: 期限が1時間取れないときは打診をやめ、自前のページで残りの席を先着で確定する（キャンセル待ちの人も、自分の申込みの「参加する」で先着で確定できる）。キャンセル待ちの人に「当日の空きが出ました」（知らせの種類 `same_day` を足す）を交流会ごとに1回だけ送る【仮決め R7】
- Q: 打診への返事 → A: LINE の人は「自分の申込み」の「参加する」「辞退する」、メールの人は打診の知らせのリンク（返事の札）か申込みのときのリンク（申込みの札）の札のページ。参加で確定（確定の知らせ）、辞退で取り消しにして次の人へ。期限を過ぎた返事は 410。返事・取り消し・期限切れのたびに次の人に打診する【仮決め R8】
- Q: 期限切れを取りこぼさない → A: (1) 定期の窓口 `POST /api/v1/booking/jobs/tick`（Cloud Scheduler が10分おき・9時〜23時台に合言葉つきで呼ぶ。threads と同じ `isJobRequest`・合わなければ 404）。(2) 書く窓口（申し込む・返事・取り消し・主催者の操作）は、まず期限切れを片付けてから決める。(3) 読む窓口は書かずに、期限を過ぎた打診を「期限切れ」として見せ（返事できない・席を押さえない）、ほかの人の申込みが待ちを飛びこさないよう、席が空いてもキャンセル待ちがいれば新しい人はキャンセル待ちに入れる【仮決め R9】
- Q: 日時や場所の変更と中止を何をきっかけに送るか（event は booking を知らない） → A: booking が「最後に知らせた日時と場所」（`booking_setting.notified_starts_at`・`notified_venue`）を持ち、event の要約と比べて変わったかを決める（event・reception を直さない）。主催者は準備の画面と名簿の画面の帯で「変更を知らせる」「知らせずに済ませる」を選べる。主催者が選ばないまま30分たったら、定期の仕事が知らせる。中止は booking の「予約を中止する」（確かめの枠つき）で、確定・打診中・キャンセル待ちの申込みを取り消しにして中止の知らせを送り、申込みページは「中止になりました」になる（戻せない）【仮決め R10・R11】
- Q: 知らせの中身とリンク → A: 確定（カレンダーに追加）・キャンセル待ちに入った（何番目か）・打診（期限と返事のリンク）・期限が過ぎた・日時や場所の変更（前の日時と場所）・中止・当日の空き。LINE の人のリンクは申込みページか自分の申込み、メールの人は札のページ。知らせが送れなくても申込みの処理は成り立つ【仮決め R12】
- Q: 送った知らせの一覧 → A: 主催者は名簿の行ごとに「送った知らせ」（種類・手段・結果・時刻だけ。相手のアドレス・本文は出さない）を開ける（`GET …/entries/{entryId}/notices`）。受付係は見られない【仮決め R13】
- Q: 主催者がキャンセル待ちを手で扱う → A: 名簿の「キャンセル待ち」の絞り込みで、並びの順・何番目か・打診の期限を見て、「打診する」（席がなくても押さえる。期限が1時間取れなければ 409）・「確定にする」（確定の知らせ）・「取り消す」ができる【仮決め R14】

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 主催者が定員と媒体の枠を決め、満員と超えた人数を見る (Priority: P1)

高橋さんは練習日の定員を16、Peatix の枠を4にする。自前のページで12人、Peatix で4人が入ると、準備の画面と名簿に「満員です」と「受付を止める媒体：Peatix（管理ページ）」が出る。電話で申し込んだ人を手で足して17人になると「1人超えています」が出る（FR-B60〜B63・UJ-3）。

**Why this priority**: 定員がないと、キャンセル待ちも繰り上げも動かない。

**Independent Test**: 定員と枠を入れ、確定と打診中の数から自前の残り・満員・止める媒体・超えた人数が答えに出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 自前の交流会, **When** 主催者が定員16・Peatix の枠4（管理ページの URL つき）を保存する, **Then** 設定の答えに定員・枠と、埋まった席0・自前の残り12が出る
2. **Given** 定員16・Peatix 4・自前の確定12, **When** 名簿に Peatix の確定が4人になる, **Then** 「満員です」と、止める媒体に Peatix（URL）が出る。自前の残りは0
3. **Given** 定員16・自前の確定12・Peatix 2, **When** 設定を読む, **Then** 自前の残りは0（Peatix の枠の残り2を押さえる）で「満員です」は出ない。枠の残りが出る
4. **Given** 満員, **When** 主催者が手で1人足す（定員を超えて足す）, **Then** 「1人超えています」が出て、ほかの行は変わらない
5. **Given** 枠の合計が定員を超える入力・直接の枠・同じ媒体を2つ・URL が http(s) でない, **When** 保存する, **Then** 400
6. **Given** 受付係・部員, **When** 定員を変えようとする, **Then** 403。使い方が受付だけなら 409
7. **Given** 名簿を使う交流会, **When** 定員を入れる, **Then** 人数の目安と超えた人数だけを出す（キャンセル待ちにならない）

### User Story 2 - 満員の会に申し込むとキャンセル待ちに入り、何番目かが分かる (Priority: P1)

森さんは満員の練習日のページを開く。ページには「満員です。キャンセル待ち 2人」が出て、申し込むと「キャンセル待ちの3番目」と出る。「キャンセル待ちに入りました（3番目）」の知らせが届き、自分の申込みにも3番目と出る（FR-B61・B62・B43・FR-B80）。

**Why this priority**: 申込みページで残りとキャンセル待ちを見せることが、この版の参加者の中心。

**Independent Test**: 残りが0の交流会に申し込むと状態が `waitlisted` になり、何番目かがページ・完了の画面・自分の申込み・札のページに出て、`waitlisted` の知らせが記録されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 定員のある受付中の会, **When** ログインなしでページを開く, **Then** 「残り n 席」（席があるとき）か「満員です（キャンセル待ち n 人）」が出る。定員がない会は席の欄を出さない
2. **Given** 残りが0, **When** LINE でログインして申し込む, **Then** 状態「キャンセル待ち」・何番目かが出る。名簿にも「キャンセル待ち」で入る。`waitlisted` の知らせを送る
3. **Given** 残りが0, **When** メールで申し込んで確認のリンクで確定する, **Then** 状態「キャンセル待ち」と何番目かが札のページに出る
4. **Given** 残りが1でキャンセル待ちが1人いる（期限切れの直後で、まだ打診していない）, **When** 新しい人が申し込む, **Then** 先にキャンセル待ちの先頭に打診し、新しい人はキャンセル待ちに入る（待ちを飛びこさない）
5. **Given** 同時に2人が最後の1席に申し込む, **When** 2つの要求が並ぶ, **Then** 1人が確定、もう1人がキャンセル待ちになる（定員を超えない）
6. **Given** キャンセル待ちの人, **When** 取り消す, **Then** 取り消しになり、後ろの人の何番目かが1つ繰り上がる

### User Story 3 - 席が空くと、キャンセル待ちの先頭に期限つきで打診し、参加・辞退・期限切れで回す (Priority: P1)

Peatix の1人が取り消し、高橋さんが名簿でその人を「取り消し」にする。森さんに「席が空きました。明日の12時までに答えてください」が届く。森さんが自分の申込みで「参加する」を押すと確定する。答えないまま期限が過ぎると取り消しになり「期限が過ぎました」が届いて、次の人に打診が回る（FR-B64〜B66・UJ-4）。

**Why this priority**: 運営が手で連絡しなくても繰り上げが回ることが、PRD のねらい。

**Independent Test**: 取り消し・定員を増やす・期限切れ・辞退で、キャンセル待ちの先頭が打診中になり、期限が R6 のとおりで、参加で確定・辞退と期限切れで次へ回り、知らせが記録されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 満員でキャンセル待ちがいる, **When** 確定の人が取り消す・主催者が取り消しにする・定員を増やす, **Then** 先頭の人が打診中になり（席を押さえる）、期限つきの打診の知らせ（LINE は自分の申込み、メールは返事の札のリンク）を送る
2. **Given** 打診中, **When** 本人が「参加する」, **Then** 確定になり、確定の知らせを送る
3. **Given** 打診中, **When** 本人が「辞退する」, **Then** 取り消しになり、次の人に打診する
4. **Given** 打診中で期限が過ぎた, **When** 定期の仕事が動く（か、だれかが書く窓口を呼ぶ）, **Then** 取り消しになり、期限が過ぎた知らせを送り、次の人に打診する
5. **Given** 期限が過ぎた打診, **When** 本人が「参加する」, **Then** 410（期限が過ぎました）。読む窓口は「期限が過ぎました」を出す
6. **Given** 定期の仕事が同時に2つ動く, **When** どちらも同じ交流会を見る, **Then** 打診は1つだけ・知らせは1回だけ
7. **Given** 打診の時刻と始まり, **When** 期限を決める, **Then** R6 のとおり（24時間・夜は9時・始まりの2時間前まで・その時刻が夜なら0時・1時間に足りなければ打診しない）。ちょうど0時・ちょうど9時・ちょうど2時間前・ちょうど1時間を単体のテストで固める
8. **Given** 合言葉がない・違う, **When** 定期の窓口を呼ぶ, **Then** 404

### User Story 4 - 始まりが近いときは「当日の空き」として先着にする (Priority: P2)

始まりの2時間半前に1人が取り消す。期限が1時間取れないので打診せず、申込みページに「当日の空き：残り1席（先着）」が出て、キャンセル待ちの人に「当日の空きが出ました」が届く。先に「参加する」を押した人か、先に申し込んだ人が確定する（FR-B67）。

**Independent Test**: 始まりの3時間前より後に席が空くと打診ができず、ページが当日の空きになり、`same_day` の知らせが1回だけ送られ、先着で確定することを確かめる。

**Acceptance Scenarios**:

1. **Given** 始まりまで3時間を切った満員の会, **When** 席が空く, **Then** 打診は作らず、ページは「当日の空き」と残りの席、キャンセル待ちの人に `same_day` の知らせ（交流会ごとに1回）
2. **Given** 当日の空き, **When** キャンセル待ちの人が自分の申込み（か札のページ）で「参加する」, **Then** 席があれば確定、なければ 409（埋まりました）
3. **Given** 当日の空き, **When** 新しい人が申し込む, **Then** 席があれば確定（キャンセル待ちを待たない）

### User Story 5 - 主催者がキャンセル待ちを手で扱い、送った知らせを見る (Priority: P2)

高橋さんは名簿の「キャンセル待ち」で並びと打診の期限を見て、常連の人を「確定にする」、先頭の人に「打診する」、来られない人を「取り消す」。行ごとの「送った知らせ」で、何をいつ送り、届いたか（送った・止めている・送り先がない など）を見る（FR-B68・FR-B87）。

**Independent Test**: 主催者だけが手で打診・確定・取り消しでき、受付係は 403、送った知らせの一覧に相手のアドレスと本文がないことを確かめる。

**Acceptance Scenarios**:

1. **Given** キャンセル待ちが3人, **When** 名簿を「キャンセル待ち」で絞る, **Then** 並びの順に、何番目か・打診中なら期限つきで出る
2. **Given** キャンセル待ちの人, **When** 主催者が「打診する」, **Then** 席がなくても打診中になり（席を押さえる）、打診の知らせを送る。期限が1時間取れなければ 409
3. **Given** キャンセル待ち・打診中の人, **When** 主催者が「確定にする」, **Then** 確定になり、確定の知らせを送る（打診は取り下げ）
4. **Given** 打診中の人, **When** 主催者が「取り消す」, **Then** 取り消しになり、次の人に打診する（知らせは送らない）
5. **Given** 知らせを送った行, **When** 主催者が「送った知らせ」を開く, **Then** 種類・手段・結果・時刻だけが新しい順に出る。受付係は 403

### User Story 6 - 日時や場所が変わったら知らせ、予約を中止したら知らせる (Priority: P2)

森さん（組織の編集者）が練習日の日時を変える。準備の画面と名簿に「日時や場所が変わりました（前：11月28日 19:00）」と「変更を知らせる」が出る。押すと、確定・打診中・キャンセル待ちの人に「日時が変わりました」が届く。押し忘れても、30分たつと定期の仕事が送る。雨でコートが使えなくなった日は「予約を中止する」で、申し込んだ全員に中止の知らせが届く（FR-B80・FR-B86・UJ-6）。

**Independent Test**: event の要約の日時か場所が、booking が最後に知らせたものと違えば帯が出て、知らせると `changed`（前の日時と場所つき）が届き、中止すると申込みが取り消しになって `cancelled_event` が届くことを確かめる。

**Acceptance Scenarios**:

1. **Given** 申込みのある自前の会, **When** 主催者が交流会の日時か場所を直す, **Then** 準備の画面と名簿の帯に、前の日時と場所・今の日時と場所・「変更を知らせる」「知らせずに済ませる」が出る
2. **Given** 帯, **When** 「変更を知らせる」, **Then** 確定・打診中・キャンセル待ちの人に `changed`（前の日時か場所つき）を送り、帯が消える
3. **Given** 帯, **When** 「知らせずに済ませる」, **Then** 送らずに帯が消える（打ちまちがいを直したときなど）
4. **Given** 帯が出たまま30分, **When** 定期の仕事が動く, **Then** 変更の知らせを送る（1回だけ）
5. **Given** 自前の会, **When** 主催者が「予約を中止する」→ 確かめの枠で「中止する」, **Then** 確定・打診中・キャンセル待ちの申込みが取り消しになり `cancelled_event` を送る。申込みページは「この会は中止になりました」で、申し込めない・受付を開けない
6. **Given** 受付係・部員, **When** 変更の知らせ・中止の窓口を呼ぶ, **Then** 403

### Edge Cases

- 定員を減らして埋まった席が定員を超えた：打診中・確定は取り消さず「n人超えています」。新しい打診はしない
- 定員を空にした（定員なし）：キャンセル待ちの人は全員に打診する（席の縛りがなくなるため）
- 打診中の人が「自分の申込み」で取り消す：辞退と同じに次の人へ
- 打診中の人の始まりが過ぎた：返事できない（期限は始まりの2時間前までなので、その前に期限切れになる）
- 交流会の日時が変わり、打診の期限が新しい始まりの2時間前より後になった：期限は変えない。返事は始まりの前までしか受けない【仮決め R6】
- 受付を閉じた会：新しい申込みは受けないが、キャンセル待ちの繰り上げは続ける
- 夜間（0時〜8時）は DB が止まる：定期の仕事も呼ばない（9時〜23時台）。期限は夜に切れないので、朝の最初の回か、最初の書く窓口で片付く
- 知らせの送り先がない（手で足した人）：記録に「送り先がない」。処理は進む
- 中止のあとに主催者が名簿で戻す：戻せる（知らせは送らない）。申込みページは中止のまま
- メールの人の打診の返事の札：打診ごとに1つ・SHA-256 だけ。札のページで申込みの札と同じに使える

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主催者は、名簿を使う・自前の交流会に定員（任意・1〜1000）と媒体の枠（直接を除く媒体ごとに1つ・席の数・管理ページの URL〈任意〉）を決められる。枠の合計は定員まで（FR-B60・B62）。
- **FR-002**: 埋まった席＝すべての入口の確定＋打診中。自前の残り＝定員 − 埋まった席 − 枠のまだ埋まっていない席。一度満員になったら枠の席を押さえない（FR-B61）。
- **FR-003**: 設定の答えに、埋まった席・確定・打診中・キャンセル待ち・自前の残り・満員か・止める媒体（URL つき）・超えた人数を出す（FR-B62・B63）。
- **FR-004**: 自前のページは、残りの席か、満員とキャンセル待ちの人数を出す。残りが0なら申し込んだ人はキャンセル待ちに入る（FR-B40・B62）。
- **FR-005**: 完了の画面・自分の申込み・札のページに、キャンセル待ちの何番目か・打診の期限・返事のボタンを出す（FR-B43）。
- **FR-006**: 席が空くと（取り消し・辞退・期限切れ・定員を増やす・枠を減らす）、キャンセル待ちの先頭に打診し、打診中は席を押さえる（FR-B64）。
- **FR-007**: 返事の期限は R6 の決め方で、日本時間で計算する（FR-B65）。
- **FR-008**: 打診への返事（参加・辞退）を、LINE の人は自分の申込み、メールの人は札のページで受ける。期限の後は受けない（FR-B66）。
- **FR-009**: 期限が1時間取れないときは打診をやめ、自前のページで先着に確定し、キャンセル待ちの人に当日の空きを1回知らせる（FR-B67）。
- **FR-010**: 主催者は、キャンセル待ちの並びを見て、手で打診・確定・取り消しできる（FR-B68）。
- **FR-011**: 期限切れは、定期の窓口（合言葉つき・合わなければ 404）と、書く窓口の前の片付けと、読む窓口の判定の3つで取りこぼさない。同時に走っても二重に打診しない・定員を超えて打診しない。
- **FR-012**: 確定・キャンセル待ちに入った・打診・期限が過ぎた・日時や場所の変更・中止・当日の空きを `sendNotice` で送る（FR-B80・B86）。
- **FR-013**: 日時や場所の変更は、booking が持つ「最後に知らせた日時と場所」と event の要約を比べて決め、主催者が知らせるか済ませるかを選べる。選ばれないまま30分たったら定期の仕事が知らせる。event と reception を直さない（AD-23）。
- **FR-014**: 主催者は予約を中止でき、取り消しでない申込みを取り消しにして中止を知らせる。中止のあとは申し込めない。
- **FR-015**: 主催者は、申込みごとに送った知らせ（種類・手段・結果・時刻だけ）を見られる（FR-B87）。
- **FR-016**: メールアドレス・札・名前・本文をログと主催者の答えに出さない。参加者の画面にほかの人の名前を出さない（Constitution II）。

### Key Entities

- **予約の設定（booking_setting）**：定員・枠を押さえるのをやめた時刻・中止した時刻・最後に知らせた日時と場所・変更に気づいた時刻・当日の空きを知らせた時刻を足す。
- **媒体の枠（booking_quota）**：交流会・媒体・席の数・管理ページの URL。
- **申込み（booking_entry）**：状態に「キャンセル待ち」「打診中」を足す。
- **打診（booking_offer）**：申込み・期限・状態・返事の札の SHA-256・打診した人（自動は空）・返事の時刻。
- **知らせの記録（booking_notice）**：種類に「当日の空き」を足す。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 満員の会で取り消しが出たら、主催者が何もしなくても、次の定期の仕事（10分以内）か、取り消しの要求の中で、キャンセル待ちの先頭に打診が届く。
- **SC-002**: 同じ交流会に定期の仕事と申込みと返事が同時に来ても、埋まった席（確定＋打診中）が自動の処理で定員を超えない（結合のテスト）。
- **SC-003**: 返事の期限が、日本時間の0時〜9時（両端を除く）に落ちることがない（単体のテスト）。
- **SC-004**: 日時や場所を直してから40分以内に、申込みのある人に変更の知らせが届く（主催者が何もしなくても）。
- **SC-005**: 送った知らせの一覧・名簿・ログに、メールアドレス・札・本文が出ない（結合のテスト）。

## Assumptions

- 交流会の日時・場所は event の `getEventSummary`、役目は `requireEventRole`・`getEventRole` から引く（AD-3・AD-5）。event・reception の `index.ts` は直さない。
- 定期の仕事は Cloud Scheduler から呼ぶ（AD-24。core-006 の合言葉 `JOB_TRIGGER_SECRET`）。`infra/` はこの仕様で直さず、要る変更は [quickstart.md](./quickstart.md) に書く。
- 本物のメールの送信のサービスはまだない（booking-003 と同じ）。手元・テスト・E2E は偽の送り手だけ。
- 知らせは `NOTIFY_MODE`（本番の既定は `off`）で止まる。定員・キャンセル待ちは、交流会ごとに主催者が定員を入れたときだけ動く（入れなければ booking-003 と同じ）。
