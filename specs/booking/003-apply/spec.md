## Clarifications

### Session 2026-11-20

答える人がいないため、PRD・構成の決めごと・モックアップと booking-001・002 の仮決めから AI が決めた（【仮決め】。理由は [research.md](./research.md)）。

- Q: 使い方「自前で申込みを受ける」と、受け付けるか・見せる範囲をどう持つか → A: `booking_setting.mode` の CHECK に `self_page` を足し、`accepting`（受付を開いているか。既定は閉じる）と `visibility`（`public`＝誰でも・`members`＝部員だけ。既定は誰でも）の列を足す。「受付中」は「使い方が自前・受付を開いている・始まりの前」を読むときに決める（始まりを過ぎたら自動で閉じる。保存しない）。自前のときも名簿の窓口と画面はそのまま使える【仮決め R1】
- Q: 参加者が開く道 → A: 申込みページ `/e/{eventId}`、メールで申し込んだ人の札のページ `/e/{eventId}/entry/{entryToken}`（どちらも AD-14 のとおり）、自分の申込み `/my-bookings`（AD-14 の一覧に足す。`-` を含むのでアプリの key とぶつからない）。「LINE を使わずに申し込む」は申込みページの中で切り替え、道を足さない【仮決め R2】
- Q: ログインなしで何を見せるか → A: 交流会の名前・日時・会場・参加費・主催（組織に入れていれば組織の名前、なければ持ち主の表示名）・受付の状態。席の残りは出さない（定員は booking-004）【仮決め R3・R17・R18】
- Q: 1交流会1人1つと、申し込み直し → A: LINE で申し込む人は `(event_id, account_id)` の一意（booking-001 で置いたもの）で1つ。取り消したあとに申し込み直すと、同じ行を確定に戻し、申し込んだ日時を今にする。もう確定なら何もしない（同じ答え）。名前の初めの値は、その人の前の申込みの名前、なければ LINE の表示名【仮決め R4】
- Q: 案内の同意をどこに持ち、どう出すか → A: `booking_consent`（同意した人の account・相手は組織か交流会の持ち主のどちらか1つ）。申し込むときのチェック（初めは外す）で作り、すでに同意していればチェックを出さず「受け取っています」と出す。外すのは「自分の申込み」の画面。メールで申し込む人には出さない（メールアドレスは予約の知らせのためだけ。Constitution II）。案内を送る機能はこの版で作らない【仮決め R5】
- Q: 申込み完了の画面 → A: 状態（確定）・「カレンダーに追加」（Google カレンダーのリンクと `.ics`。交流会に終わりの時刻がないので、始まりから2時間とする）・公式アカウントの設定にベーシック ID があれば「公式 LINE を友だちに追加する」（`https://line.me/R/ti/p/{basicId}`）・任意のメールアドレスの欄（`booking_contact`。booking-002 の窓口）・「自分の申込みを見る」【仮決め R6・R16】
- Q: 取り消し → A: 参加者は始まりまで、ワンタップ（確かめの枠を1つ）で取り消せる。状態は「取り消し」になり、行は残る（主催者が名簿で戻せる）。取り消しの知らせは送らない（6つの知らせにない）【仮決め R7】
- Q: 部員だけの回 → A: 見せる範囲が「部員だけ」なら、その交流会の主催者と部員（入れた組織のメンバー）だけが見て申し込める。受付係とほかの人・ログインしていない人には中身を返さず「この会は見られません」（403 `BOOKING_PAGE_MEMBERS_ONLY`）。組織に入れていない交流会では「部員だけ」を選べない（400）。メールでは申し込めない【仮決め R8】
- Q: 「部の予定」のタブ → A: 自分がメンバー（管理者・編集者・メンバーのどれでも）の組織に入れた交流会のうち、使い方が自前で、始まりの日がまだ終わっていないもの（受付の状態と自分の申込みの状態つき）。部員だけの回も出る【仮決め R9】
- Q: LINE を使わずに申し込む流れ → A: 名前とメールアドレスを入れると、確認の待ち（`booking_email_request`。札の SHA-256・24時間）を作り、確認のメール（リンク `/e/{eventId}/entry/{札}`）を送る。リンクを開いて「申込みを確定する」を押す（GET では確定しない。メールの下見の仕組みが開いても確定しないため）と、名簿の行（入口は自前・アカウントは空・連絡のメール・札の SHA-256）ができる。同じ札が、そのあと「申込みを見る・取り消す」の札になる（本人だけが知る札）。答えは、そのアドレスの申込みがあるかどうかにかかわらず同じ【仮決め R10】
- Q: 確認のメールの回数の制限 → A: `/api/v1` の書く道の IP ごとの制限に加え、同じ交流会・同じアドレスへの確認のメールは10分に1通（2回目からは送らずに同じ答え）。交流会ごとの確認の待ちは200件まで（超えたら 429）【仮決め R11】
- Q: 申込みの知らせ → A: 確定したら（LINE で申し込んだ・申し込み直した・メールの申込みを確定した）booking-002 の `sendNotice`（種類は確定）を呼び、「申込みを見る・取り消す」（LINE の人は申込みページ、メールの人は札のページ）と「カレンダーに追加」（Google のリンク）を入れる。メールの申込みの送り先は行の連絡のメール。知らせが送れなくても申込みは成り立つ。確認のメールは知らせの記録（`booking_notice`）に残さず、ログに結果だけを出す【仮決め R12】
- Q: 主催者の画面 → A: 準備の画面の「使い方」に3つ目のカードを出し、自前を選んだ交流会には「申込みページ」の節（受付を開く・閉じる〈既定は閉じる〉・見せる範囲・ページの URL とコピー・始まりを過ぎたら「始まりを過ぎたので閉じました」）を出す。使い方をほかに変えると、申込みページは「ありません」になり、申込みは名簿に残る【仮決め R13】
- Q: 名簿での見え方 → A: 入口「自前」（`self_page`）。メールの申込みも名前だけで、メールアドレスは名簿・CSV・どの答えにも出さない。まとめるときは連絡のメールと札も残す行へ移す【仮決め R14】
- Q: 大きな機能を止める設定 → A: `DOMAIN_FEATURES` の印は足さない。交流会ごとの「受付を開く」（既定は閉じる）が止め口で、知らせは `NOTIFY_MODE`（本番の既定は `off`）で止まる【仮決め R21】

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 外の人が申込みページを見て、LINE ログインで申し込む (Priority: P1)

中村さんは Threads の投稿から練習日のページ（`/e/{eventId}`）を開く。ログインせずに名前・日時・会場・参加費・主催を見て、「LINE でログインして申し込む」を押す。LINE でログインすると、名前（LINE の表示名が入っている）と「（主催）から次の会の案内を受け取る」（外れている）が出て、「申し込む」を押すと申込み完了の画面になる。画面には「確定」「カレンダーに追加」（Google カレンダー・ほかのカレンダー〈.ics〉）、公式アカウントの設定がある組織なら「公式 LINE を友だちに追加する」、任意のメールアドレスの欄が出る（FR-B40〜B43・FR-B84・UJ-2）。

**Why this priority**: 「自前で申込みを受ける」の中心。これがないと PRD 8.1 の6番が使えない。

**Independent Test**: 受付を開いた交流会のページをログインなしで読むと中身が返り、ログインして申し込むと名簿に入口「自前」・確定の行ができ、確定の知らせ（偽の送り手）が記録されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 使い方が自前で受付を開いた交流会, **When** ログインしていない人がページを開く, **Then** 名前・日時・会場・参加費・主催の名前・「受付中」と「LINE でログインして申し込む」「LINE を使わずに申し込む」が出る。席の残りは出ない
2. **Given** 同じページ, **When** LINE でログインして戻る, **Then** 名前の欄（前の申込みの名前か LINE の表示名）・案内のチェック（外れている）・任意ではない欄がなく、「申し込む」を押すだけで終われる
3. **Given** 名前を確かめた, **When** 「申し込む」, **Then** 名簿に入口「自前」・状態「確定」・本人のアカウントの行ができ、申込み完了の画面（確定・カレンダーに追加・友だち追加〈ベーシック ID があるとき〉・メールアドレスの欄・自分の申込みを見る）が出る。確定の知らせを `sendNotice` で送る（守りを通す）
4. **Given** 案内のチェックを入れた, **When** 申し込む, **Then** 組織（組織に入れていなければ持ち主）への案内の同意ができる。もう一度その組織の会を開くと、チェックの代わりに「案内を受け取っています」が出る
5. **Given** もう確定の申込みがある人, **When** ページを開く・もう一度申し込む, **Then** ページは申込みの状態を出し、申し込んでも行は増えない（同じ答え）
6. **Given** 取り消した人, **When** もう一度申し込む, **Then** 同じ行が確定に戻り、申し込んだ日時が今になる
7. **Given** 受付を閉じている・始まりを過ぎた交流会, **When** ページを開く, **Then** 中身と「いまは申込みを受け付けていません」（始まりを過ぎたら「受付を終えました」）が出て、申し込めない（窓口は 409 `BOOKING_PAGE_CLOSED`）
8. **Given** 使い方が自前でない・ない交流会, **When** ページを開く, **Then** 「この会の申込みページはありません」（404 `BOOKING_PAGE_NOT_FOUND`）
9. **Given** 申込み完了の画面, **When** 「Google カレンダー」を押す, **Then** 名前・始まり〜始まりの2時間後・会場の入った Google カレンダーの追加の画面が開く。「ほかのカレンダー」は `.ics` のファイルを返す
10. **Given** 申込み完了の画面, **When** メールアドレスを入れて保存する・消す, **Then** 本人の連絡のメールアドレス（`booking_contact`）が入る・消える。主催者には見えない

### User Story 2 - 主催者が「自前で申込みを受ける」を選び、受付を開く・閉じる (Priority: P1)

主催者は準備の画面の「使い方」で「自前で申込みを受ける」を選ぶ。「申込みページ」の節で受付を開き（既定は閉じる）、見せる範囲（誰でも・部員だけ）を選び、ページの URL をコピーして Threads に貼る。自前の申込みは名簿に入口「自前」で入り、当日 LINE でチェックインした人は同じアカウントの申込みに自動で当たる（FR-B10・FR-B12・FR-B47・FR-B100）。

**Why this priority**: 主催者が受付を開かないと、参加者は申し込めない（ステージングなしの守りとして既定は閉じる）。

**Independent Test**: 主催者だけが使い方と受付を変えられ、受付を開くまでは申し込めず、開いたあと申し込んだ人のチェックインが名簿に自動で当たることを確かめる。

**Acceptance Scenarios**:

1. **Given** 主催者, **When** 使い方を「自前で申込みを受ける」にする, **Then** 「申込みページ」の節が出て、受付は「閉じています」、見せる範囲は「誰でも」、ページの URL とコピーが出る
2. **Given** 閉じている, **When** 「受付を開く」, **Then** ページで申し込めるようになる。「受付を閉じる」でまた申し込めなくなる（すでにある申込みは残る）
3. **Given** 始まりを過ぎた交流会, **When** 準備の画面を開く, **Then** 「始まりを過ぎたので、受付は自動で閉じました」が出る
4. **Given** 組織に入れていない交流会, **When** 見せる範囲を「部員だけ」にしようとする, **Then** 選べない（窓口は 400 `BOOKING_VISIBILITY_NEEDS_ORGANIZATION`）。画面に「組織に入れると選べます」
5. **Given** 受付係・部員, **When** 受付と見せる範囲を変えようとする, **Then** 403
6. **Given** 自前の申込みがある, **When** 名簿を開く, **Then** 入口「自前」の行が出る。メールアドレスは出ない
7. **Given** LINE で申し込んだ人, **When** その人が当日 LINE でチェックインする, **Then** 名簿に当てる画面で自動で当たる（booking-001 の当て方の2）
8. **Given** 自前の交流会, **When** 使い方を「名簿を使う」「受付だけ」に変える, **Then** 申込みページは「ありません」になる。名簿の行は残る（受付だけなら隠れる）

### User Story 3 - 自分の申込みを見て取り消す・部の予定を見る・知らせと案内を変える (Priority: P2)

参加者は「自分の申込み」（`/my-bookings`）で、今後の回の申込みと状態を見て、始まりまでワンタップ（確かめを1つ）で取り消せる。「部の予定」のタブには、自分が入っている組織の会が出る。下の「知らせと案内」で、メールアドレスを入れる・消す、案内を受け取る組織を外せる（FR-B44・FR-B42・FR-B84・PRD 11章の4）。

**Why this priority**: 行けなくなった人がすぐ取り消せないと、当日の名簿が狂う。

**Independent Test**: 自分の申込みだけが一覧に出て、取り消すと状態が変わり、ほかの人の申込みは取り消せない（404）ことを確かめる。

**Acceptance Scenarios**:

1. **Given** 申込みが2つ（今後の確定・過ぎた会）, **When** 自分の申込みを開く, **Then** 始まりの日が終わっていない会だけが、始まりの近い順に、状態・日時・主催・「カレンダーに追加」・「取り消す」つきで出る
2. **Given** 確定の申込み, **When** 「取り消す」→ 確かめの枠で「取り消す」, **Then** 状態が「取り消し」になり、名簿でも取り消しになる
3. **Given** 始まりを過ぎた申込み, **When** 取り消そうとする, **Then** 409 `BOOKING_CANCEL_CLOSED`。画面には「取り消す」が出ない
4. **Given** ほかの人の申込みの ID, **When** 取り消そうとする, **Then** 404（あるかどうかを知らせない）
5. **Given** 組織のメンバー, **When** 「部の予定」を開く, **Then** その組織の自前の会（部員だけの回を含む）が、受付の状態と自分の申込みの状態つきで出る。ほかの組織・個人の会は出ない
6. **Given** 案内の同意が2つ, **When** 「知らせと案内」で1つを外す, **Then** その同意だけが消える（ほかの人の同意は外せない）
7. **Given** ログインしていない人, **When** 自分の申込みを開く, **Then** ログインを求める

### User Story 4 - 部員だけの回 (Priority: P2)

部の運営は、部員向けの練習日を「部員だけ」にする。部員と主催者だけがページを見て申し込め、ほかの人には「この会は見られません」が出る（FR-B45）。

**Independent Test**: 部員だけの回のページと申込み・カレンダーの窓口が、主催者と部員には答え、受付係・外の人・ログインしていない人には 403 で中身を返さないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 部員だけの回, **When** 部員がページを開いて申し込む, **Then** 申し込める
2. **Given** 部員だけの回, **When** ログインしていない人・組織の外の人・受付係が開く, **Then** 「この会は見られません」（名前も日時も出さない）。ログインしていない人には「部員の方は LINE でログインしてください」
3. **Given** 部員だけの回, **When** 外の人が申込み・`.ics`・メールで申し込むの窓口を呼ぶ, **Then** 403 `BOOKING_PAGE_MEMBERS_ONLY`
4. **Given** 部員が組織を抜けた, **When** 部員だけの回を開く, **Then** 見られない（役目は要求のたびに引く）。すでにある申込みは自分の申込みに残り、取り消せる

### User Story 5 - LINE を使わずに、メールで申し込む・取り消す (Priority: P2)

小林さんは LINE を使っていない。申込みページの「LINE を使わずに申し込む」から名前とメールアドレスを入れ、届いた確認のメールのリンクを開いて「申込みを確定する」を押す。確定の知らせ（メール）にも同じリンクが入り、行けなくなったらそのリンクから取り消せる（FR-B46・UJ-5）。

**Independent Test**: 確認のメール（偽の送り手）のリンクの札で確定すると名簿に行ができ、同じ札で取り消せること、札は DB に SHA-256 だけがあり、期限切れ・知らない札は使えないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 受付中の誰でもの会, **When** 名前とメールアドレスを入れて「確認のメールを送る」, **Then** 「確認のメールを送りました」と出て、そのアドレスに確認のメール（リンク `/e/{eventId}/entry/{札}`・24時間）を送る（守りを通す）。DB には札の SHA-256 だけ
2. **Given** 確認のメールのリンク, **When** 開く, **Then** 交流会の名前・日時・入れた名前と「申込みを確定する」が出る（開いただけでは確定しない）
3. **Given** 同じ画面, **When** 「申込みを確定する」, **Then** 名簿に入口「自前」・アカウントなし・確定の行ができ、確定の知らせ（メール。同じリンクと Google カレンダーのリンク）を送る。画面は申込み完了（カレンダーに追加・取り消す）
4. **Given** 確定したリンク, **When** あとで開く, **Then** 状態と「取り消す」（始まりまで）が出る。取り消すと名簿でも取り消しになる
5. **Given** 24時間を過ぎた確認のリンク, **When** 開く, **Then** 「このリンクは期限が切れました。申込みページからもう一度申し込んでください」（410 `BOOKING_ENTRY_TOKEN_EXPIRED`）
6. **Given** 知らない札, **When** 開く, **Then** 「このリンクは使えません」（404 `BOOKING_ENTRY_TOKEN_INVALID`）
7. **Given** 同じ交流会・同じアドレス, **When** 10分のうちにもう一度送る, **Then** 同じ答えで、メールは送らない。10分を過ぎたら新しい札のメールを送り、前の確認の札は使えなくなる
8. **Given** そのアドレスですでに確定した申込み, **When** もう一度申し込んで新しいリンクで確定する, **Then** 行は増えず、札が新しいものに替わる（前のリンクは使えない）。答えは初めての人と同じ
9. **Given** 部員だけの回・受付を閉じた会, **When** メールで申し込む, **Then** 403・409（メールは送らない）

### Edge Cases

- 同じ人が2つの端末で同時に「申し込む」：一意の制約で1行。2つ目は同じ答え
- メールの確定を2回押す：2回目は今の申込みを返す（行は増えない）
- 交流会が消えた（持ち主の退会）：申込み・確認の待ちも消える（CASCADE）。札のページは「使えません」
- 参加者が退会：LINE の申込みと案内の同意は消える（本人のデータ）。メールの申込みはアカウントがないので交流会と一緒に残る
- 公式アカウントの設定がない組織：友だち追加の案内を出さない。知らせはメール（連絡のメールがあれば）か「送り先がない」
- 夜間（0時〜8時）は DB が止まる：ページは「夜間は止まっています」を出す（共通の 503）
- 名前に50文字を超える文字・空：欄のそばに誤り（受付のチェックインの名前と同じ形）
- 申込みページを開いたまま主催者が受付を閉じた：申し込むと 409 で「いまは申込みを受け付けていません」

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 交流会の使い方に「自前で申込みを受ける」（`self_page`）を足す。自前の交流会は、名簿の窓口・画面（booking-001）もそのまま使える（FR-B10・FR-B12）。
- **FR-002**: 主催者は、自前の交流会の受付を開く・閉じる（既定は閉じる）と、見せる範囲（誰でも・部員だけ）を変えられる。部員だけは組織に入れた交流会だけ。始まりを過ぎたら、読むときに閉じたものとして扱う（FR-B47）。
- **FR-003**: 申込みページ（`/e/{eventId}`）は、ログインなしで交流会の名前・日時・会場・参加費・主催の名前・受付の状態を返す。席の残りは返さない（FR-B40）。
- **FR-004**: ログインした人は、受付中の交流会に、名前を確かめて1つだけ申し込める。文字を打たずに終われる（名前の初めの値がある）（FR-B41・Constitution III）。
- **FR-005**: 申し込むときに、案内の同意（初めは外す）を選べる。同意は組織（個人の持ち主の交流会なら持ち主）ごとに1つで、本人がいつでも外せる（FR-B42）。
- **FR-006**: 申込みの答えと完了の画面は、状態・Google カレンダーのリンク・`.ics` の道・公式アカウントの友だち追加の URL（ベーシック ID があるとき）を出す。`.ics` の窓口はページと同じ見せる範囲の決まりで返す（FR-B43）。
- **FR-007**: 参加者は、自分の申込み（始まりの日が終わっていない会）を一覧で見て、始まりまで取り消せる。ほかの人の申込みは読めず、取り消せない（FR-B44）。
- **FR-008**: 「部の予定」は、自分がメンバーの組織に入れた自前の会（部員だけの回を含む）を、受付の状態と自分の申込みの状態つきで返す（PRD 11章の4）。
- **FR-009**: 部員だけの回は、主催者と部員だけが見て申し込める。ほかには中身を返さず 403（FR-B45）。
- **FR-010**: LINE を使わない人は、名前とメールアドレスで確認の待ちを作り、確認のメールのリンク（札の SHA-256 だけを持つ・24時間）から確定する。確定した申込みはアカウントを持たず、同じ札で見る・取り消す（FR-B46・AD-14・AD-24）。
- **FR-011**: 確認のメールの窓口は、アドレスごと・交流会ごとの回数を縛り、そのアドレスの申込みがあるかどうかを答えで知らせない。
- **FR-012**: LINE で申し込んだ人は、任意のメールアドレスを申込み完了の画面と自分の申込みの画面で入れる・消せる（booking-002 の `/me/contact`。FR-B84）。
- **FR-013**: 申込みが確定したら `sendNotice`（確定）を呼び、申込みを見る・取り消すリンクと Google カレンダーのリンクを入れる。メールの申込みの送り先は行の連絡のメール。知らせの結果で申込みを止めない（FR-B86・AD-24）。
- **FR-014**: 名簿の入口に「自前」を足す。参加者のメールアドレスは、名簿・CSV・主催者と受付係のどの答えにも出さない（FR-B26・Constitution II）。
- **FR-015**: LINE のチェックインは、同じアカウントの自前の申込みに自動で当たる（booking-001 の当て方。FR-B100）。
- **FR-016**: 参加者の画面に、ほかの人の名前を出さない。
- **FR-017**: 札・メールアドレス・名前をログに出さない。メールの申込みの札は SHA-256 だけを DB に持つ（PRD 5.1）。

### Key Entities

- **予約の設定（booking_setting）**：使い方に `self_page`、受付を開いているか（`accepting`）・見せる範囲（`visibility`）を足す。
- **申込み（booking_entry）**：入口に `self_page`、メールの申込みの連絡のメール（`contact_email`）と札の SHA-256（`entry_token_hash`）を足す。
- **案内の同意（booking_consent）**：同意した人・相手（組織か持ち主のどちらか1つ）・時刻。
- **確認の待ち（booking_email_request）**：交流会・名前・メールアドレス・札の SHA-256・期限・時刻。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: LINE にログイン済みの参加者が、申込みページを開いてから申込み完了まで、文字を打たずに2回のタップ（申し込む・確定の画面の前のログイン）で終わる。
- **SC-002**: 主催者が使い方を選んでから受付を開くまで、準備の画面だけで1分以内に終わる。
- **SC-003**: 受付を開くまで、どの窓口からも申込みが作れない（結合のテスト）。
- **SC-004**: メールアドレス・札は、名簿・CSV・主催者の答え・ログのどれにも出ない（結合のテストで答えとログを調べる）。
- **SC-005**: 部員だけの回の中身は、主催者と部員のほかには、どの窓口からも読めない（結合のテスト）。

## Assumptions

- 交流会の役目（主催者・部員・受付係）は event の `getEventRole`、組織のメンバーは suite の `listMemberships`、主催の名前は suite の `findOrganization`・account の `findDisplayNames` から引く（AD-3・AD-5・AD-22）。
- 定員・キャンセル待ち・打診・変更と中止の知らせは booking-004。この版の状態は確定と取り消しだけ。
- 本物のメールの送信のサービスはまだない（Open Questions 8）。手元とテストは偽の送り手で、本番はメールの準備ができるまで「メールの準備がない」になる（確認のメールが届かないので、本番で「メールで申し込む」を使えるのはメールの送り手を足してから。quickstart に書く）。
- 申込みページのミニアプリの URL は、画面が組み立てに埋めた LIFF ID で作る（event の QR と同じ）。知らせとメールのリンクは、API が LIFF ID を知らないので画面の源（`WEB_URL`）＋道にする（booking-002 の紐づけと同じ）。
- インフラ（`infra/`）の変更は要らない。要るものは [quickstart.md](./quickstart.md) に書く。
