# Quickstart: 自前の申込みページ（booking-003）

2026-11-20 作成。名前・アドレスはどれも架空のもの。手元（`APP_ENV=local`）では、どの設定でも偽の送り手を使い、本物の LINE とメールには送らない。

## 1. 手元で確かめる

1. `pnpm dev`。手元のログイン（`/dev/login`）で主催者 A としてログインし、交流会を作る。準備の画面の「使い方」で「自前で申込みを受ける」を選ぶ。
2. 「申込みページ」の節で受付が「閉じています」になっていることを見る。ページの URL を別のブラウザ（ログインしていない）で開くと、中身と「いまは申込みを受け付けていません」が出る。
3. 「受付を開く」を押す。ログインしていないブラウザで開き直すと「LINE でログインして申し込む」が出る。手元では「LINE でログインして申し込む」が手元のログインに移る。参加者 B としてログインして戻り、名前を確かめて「申し込む」。申込み完了の画面（確定・カレンダーに追加）が出る。
4. A の名簿に、入口「自前」・確定の B の行が出る。B を LINE でチェックインした形（手元のログインで B の受付の画面）にすると、名簿に当てる画面で自動で当たる。
5. B で `/my-bookings` を開き、「取り消す」→ 確かめの枠で取り消す。A の名簿でも取り消しになる。
6. ログインしていないブラウザで申込みページの「LINE を使わずに申し込む」から名前とメールアドレス（架空の `guest@example.com`）を入れて送る。`NOTIFY_MODE=on` で立ち上げていれば、A でログインしたまま `GET /api/v1/booking/dev/notify-outbox` を開くと確認のメール（`/e/…/entry/…` のリンク）が見える。リンクを開いて「申込みを確定する」を押すと、名簿に入口「自前」の行が名前だけで出る（メールアドレスは出ない）。
7. 準備の画面で「部員だけ」を選ぶには、交流会を組織に入れる（設定 › 組織で組織を作り、準備の画面の「組織に入れる」）。組織に入っていない参加者でページを開くと「この会は見られません」。

## 2. 本番で出すときに要るインフラの変更（この仕様では `infra/` を直さない）

- 新しい設定・秘密・資源はない。
- 確認のメールは本物のメールの送り手が要る（Open Questions 8）。送り手がない本番では、確認のメールは「メールの準備がない」で送られず、メールで申し込む人は確定できない。メールの送信のサービスとドメインが決まるまでは、主催者に「LINE を使わない人は名簿に手で足してください」と案内する（画面の「LINE を使わずに申し込む」は出したまま。送れなかったときも答えは同じなので、本人には届かない）。**メールの送り手を足すときは、`platform/notify` の `EmailSender` と送り主のアドレスの設定を足す（共通の変更）**。
- `NOTIFY_MODE` は本番では `off` のまま出す（booking-002）。`off` の間は確定の知らせも確認のメールも送らない（記録とログだけ）。確かめの間は `allowlist` にして、確かめる人の公式アカウントから見える ID とメールアドレスを `NOTIFY_ALLOWLIST` に入れる。
- Cloud Run の要求の記録（基盤のログ）には、札のページの URL（`/e/…/entry/…`）が残る（research S4）。Cloud Logging を読める人を運営だけにしておく（今の設定のまま）。
- 回数の制限：確認のメールの窓口も `/api/v1` の書く道の IP ごとの制限（既定 60秒に100回）に入る。
