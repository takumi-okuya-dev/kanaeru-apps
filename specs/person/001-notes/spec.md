## User Scenarios & Testing *(mandatory)*

### User Story 1 - 会った人を足して書き、あとで読み返す (Priority: P1)

使う人（最初は持ち主）は、交流会の帰りにスマホで人物メモを開き、会った人を足す。要るのはフルネームだけで、よみ・LINE の名前・見た目の特徴・アカウント・タグ・話したこと・次に話したいことは空でもよい。あとで一覧から開くと、話したことと次に話したいことが最初に見える。

**Why this priority**: 人物メモの芯。これだけで「前に話した○○」を読み返せる。

**Independent Test**: 人を1人足して閉じ、一覧から開き直すと、書いた欄が残り、話したことと次に話したいことが最初に見える。

**Acceptance Scenarios**:

1. **Given** 人物メモに誰もいない、**When** フルネームだけを入れて保存する、**Then** 一覧にその人が出る
2. **Given** フルネームが空、**When** 保存する、**Then** 保存されず、フルネームが要ると出る
3. **Given** 全部の欄を書いた人がいる、**When** 一覧から開く、**Then** 話したことと次に話したいことが画面の最初に出て、ほかの欄はその下に出る
4. **Given** 人物メモを開いた、**When** 画面を見る、**Then** 「このメモを見られるのはあなただけです」と出る。入力の欄には「病気・信条など、相手が知られたくないことは書かないでください」と出る
5. **Given** 次に話したいことを書いた人がいる、**When** 次に話したいことを書き直して保存する、**Then** 前の文は残らず、新しい文だけが出る
6. **Given** 人がいる、**When** 消すと選び、確かめに答える、**Then** その人のメモは消え、戻せない

---

### User Story 2 - 名前や話したことで探す (Priority: P1)

次の交流会の前や、相手から LINE で連絡が来たとき、使う人はフルネーム・よみ・LINE の名前・見た目の特徴・話したこと・次に話したいこと・タグ・会った場の名前のどれかで探す。当たった人が並び、当たった箇所が前後の文と一緒に見える。一覧は、新しく書いた・直した人が上に来て、名前の横に見た目の特徴が出る。タグで絞れる。

**Why this priority**: 連絡が来たとき（UJ-1 の場面B）に、その人のメモにたどり着けないと読み返せない。

**Independent Test**: 3人を足し、それぞれの欄にしかない言葉で探すと、その人だけが当たる。

**Acceptance Scenarios**:

1. **Given** よみに「たなか」と書いた「田中 太郎」がいる、**When** 「タナカ」で探す、**Then** 田中 太郎が当たる（ひらがなとカタカナの違いで外れない）
2. **Given** 話したことに「Go のバックエンド」と書いた人がいる、**When** 「ｇｏ」で探す、**Then** その人が当たり、「Go のバックエンド」の前後の文が見え、当たった所が分かる（全角と半角・大文字と小文字の違いで外れない）
3. **Given** LINE の名前に「たろう🍙」と書いた人がいる、**When** 「たろう」で探す、**Then** その人が当たる
4. **Given** 何人かいる、**When** 一覧を開く、**Then** 最後に保存した人が上に来て、名前の横に見た目の特徴が出る
5. **Given** タグ「AI」を付けた人と付けていない人がいる、**When** タグ「AI」で絞る、**Then** 付けた人だけが出る
6. **Given** 検索の言葉を入れた、**When** 画面の URL を見る・画面を読み直す、**Then** URL に検索の言葉もタグも出ない
7. **Given** 「100%」や「a_b」のような記号を含む言葉、**When** 探す、**Then** 記号は文字としてだけ当たる（何にでも当たる印として扱われない）

### User Story 3 - 会った場を作り、そこで会った人を続けて足す (Priority: P2)

主催した会のあと、使う人は会った場（交流会の名前と日付）を1回作るか、前に作ったものから選び、そこで会った10〜20人を続けて足していく。新しい人を足すことも、前に足した人を選んで会った場を付けることもできる。あとで会った場を開くと、そこで会った人が並ぶ。

**Why this priority**: 1回に10〜20人を書く場面（PRD FR-P7）で、1人ずつ最初から入れるのはつらい。ただし US1・US2 だけでも使える。

**Independent Test**: 会った場を1つ作り、続けて3人（新しい2人と前からいた1人）を足すと、会った場の画面に3人が並ぶ。

**Acceptance Scenarios**:

1. **Given** 会った場がない、**When** 名前「11月の AI 勉強会」と日付を入れて作る、**Then** 会った場の一覧に出る
2. **Given** 同じ名前と日付の会った場がある、**When** もう一度同じ名前と日付で作る、**Then** 新しく作られず、前の会った場が選ばれる（全角と半角・前後の空白の違いでも同じものになる）
3. **Given** 会った場を選んだ、**When** 新しい人を足して保存する、**Then** 続けて次の人を足す画面になり、会った場は選ばれたまま
4. **Given** 会った場を選んだ、**When** 前に足した人を選ぶ、**Then** その人に会った場が付く
5. **Given** その人にすでにその会った場が付いている、**When** もう一度付ける、**Then** 2つにならない
6. **Given** 3人に付いた会った場、**When** 会った場を開く、**Then** 3人が並ぶ
7. **Given** 会った場、**When** 消す、**Then** 会った場と人のつながりは外れ、人のメモは残る

### User Story 4 - また会ったら、同じ人のメモに書き足す (Priority: P2)

2回目以降に会ったら、使う人は同じ人の「話したこと」に続けて書き足す。書き足した所の頭には、書き足した日と、選んでいれば会った場が入る。保存に失敗しても書いた内容は画面に残り、もう一度押しても二重にならない。

**Why this priority**: 何回か会ううちに「いつ何を話したか」が分かると、話をつなげやすい。

**Independent Test**: 話したことを書いた人に書き足すと、前の文の後ろに見出しつきで足される。保存を2回押しても1回分だけ足される。

**Acceptance Scenarios**:

1. **Given** 話したことに「Go の話」と書いた人、**When** 「転職の話」を書き足す、**Then** 話したことは「Go の話」のあとに「2026-12-03」のような書き足した日の見出しと「転職の話」が続く
2. **Given** 会った場「12月の勉強会（2026-12-03）」を選んで書き足す、**When** 保存する、**Then** 見出しに会った場の名前と日付も入り、その人にその会った場が付く
3. **Given** 書き足しを保存したが、返事が届かなかった、**When** もう一度保存を押す、**Then** 書き足しは1回分だけ
4. **Given** 電波が切れている・夜の停止の間、**When** 保存する、**Then** 「保存できませんでした」と出て、書いた内容は画面に残り、もう一度保存できる
5. **Given** 2つの画面で同じ人を開いた、**When** 片方で書き直して保存したあと、もう片方で書き直して保存する、**Then** あとの方は保存されず、「ほかで直されました。読み直してください」と出る（書いた内容は画面に残る）

### User Story 5 - アカウントから相手のページや LINE を開く (Priority: P3)

使う人は、メモの X・connpass・GitHub・LinkedIn・そのほかの URL を押して相手のページを開く。LINE ID を押すと、LINE で相手のプロフィールが開く。

**Why this priority**: 連絡のきっかけを早くする。なくても、メモを読み返す芯は使える。

**Independent Test**: X のアカウント名と LINE ID を入れた人を開き、押すと、それぞれのページが新しいタブで開く。

**Acceptance Scenarios**:

1. **Given** X に「@example」と入れた人、**When** 押す、**Then** その X のページが開く
2. **Given** そのほかの URL に `javascript:` や `tel:` で始まるものを入れる、**When** 保存する、**Then** 保存されず、`http`・`https` の URL だけが使えると出る
3. **Given** LINE ID を入れた人、**When** 押す、**Then** LINE で、その ID のプロフィールが開く（相手が ID で見つけられる設定のとき）

---

### User Story 6 - 自分のメモを書き出す・退会で消える (Priority: P3)

使う人は、自分のメモをすべての欄ごと CSV で書き出せる。退会すると、人物メモはすべて消える。

**Why this priority**: 機種変更やバックアップの安心と、原則 II（消してほしいと頼まれたら消す）のため。

**Independent Test**: 2人と会った場1つを持つ使う人が CSV を書き出すと、2行が出る。退会すると、人と会った場が残らない。

**Acceptance Scenarios**:

1. **Given** 2人を持つ使う人、**When** 書き出す、**Then** 2行の CSV（BOM つき・表計算ソフトで開ける）が落ち、3章の欄と会った場の名前と日付が入る
2. **Given** 話したことが「=1+1」で始まる人、**When** 書き出して表計算ソフトで開く、**Then** 式として動かず、文字のまま出る
3. **Given** ほかの使う人のメモ、**When** 書き出す、**Then** 自分のメモだけが入る
4. **Given** 人物メモを持つ使う人、**When** 退会の確かめの画面を見る、**Then** 「人物メモ（会った人・会った場）」が消えると出る（相手の名前は出ない）
5. **Given** 人物メモを持つ使う人、**When** 退会する、**Then** その人の人と会った場がすべて消える

### Edge Cases

- **ほかの使う人の記録**：ほかの使う人の人・会った場の ID を道や本文に入れても、見つからないとして扱う（あると知らせない）。
- **持ち主の違うメモと会った場**：ほかの使う人の会った場を、自分の人に付けることはできない。
- **見えないアプリ**：アプリが使う人に見えないとき（台帳で運営者だけ・オフ）は、人物メモの道を開いても見つからない（AD-16）。
- **夜の停止**：0時〜8時に開くと「今は使えません」と出る。書きかけは画面に残る（US4 の4）。
- **同じ名前の人**：同じフルネームの人を何人でも足せる。一覧では見た目の特徴で見分ける。
- **長い文**：欄の上限を超えると保存されず、何文字まで書けるかが出る。書き足しで話したことの上限を超えるときも同じ（書き足しは保存されない）。字は、絵文字も1字と数える。
- **ログと URL**：人物メモのどの欄も、検索の言葉も、ログ・URL・エラーの知らせに出ない。予期しないエラーのときも出ない（先に入れる共通の PR が前提）。
- **運営者**：運営者の画面に、ほかの使う人の人物メモの中身は出ない。
- **MCP**：MCP の同意の画面と範囲の一覧に、人物メモは出ない（先に入れる共通の PR が前提）。
- **タグの表記**：「AI」と「ai」と「ＡＩ」は同じタグとして扱う【仮決め】。

## Requirements *(mandatory)*

### Functional Requirements

**人を足す・書く**

- **FR-001**：使う人は、フルネームだけで人を足せる（PRD FR-P1）。
- **FR-002**：1人について、次の欄を残せる（PRD FR-P2）。よみ・LINE の名前・見た目の特徴・アカウント（X・connpass・GitHub・LinkedIn・LINE ID・そのほかの URL）・タグ（いくつでも）・話したこと・次に話したいこと。電話番号とメールの欄は持たない。
- **FR-003**：「話したこと」に書き足せる。書き足すと、頭に書き足した日（日本時間）と、選んでいれば会った場の名前と日付が入る（PRD FR-P3）。同じ書き足しを2回送っても、1回分だけ足される。
- **FR-004**：メモを書き直せる。ほかで先に直されていたら保存せず、そう知らせる。
- **FR-005**：保存に失敗しても、書いた内容は画面に残り、もう一度保存できる（PRD FR-P4）。
- **FR-006**：人を消せる。消したら戻せない（PRD FR-P5）。
- **FR-007**：画面に「このメモを見られるのはあなただけです」と、入力の欄に知られたくないことを書かない注意を出す（PRD FR-P15）。

**会った場**

- **FR-008**：使う人は、名前と日付で会った場を作れる。同じ名前（そろえたもの）と日付の会った場は、新しく作らずに前のものを使う（PRD FR-P6・AD-31）。
- **FR-009**：会った場を1つ選んで、新しい人を続けて足すことも、前に足した人に付けることもできる。同じ人に同じ会った場は1つだけ（PRD FR-P7）。
- **FR-010**：会った場ごとに、そこで会った人を並べて見られる（PRD FR-P13）。
- **FR-011**：会った場を消せる。消すと、人とのつながりだけが外れる。

**探す・見返す**

- **FR-012**：フルネーム・よみ・LINE の名前・見た目の特徴・話したこと・次に話したいこと・タグ・会った場の名前で探せる。ひらがなとカタカナ・全角と半角・大文字と小文字の違いでは外れない。記号は文字としてだけ当たる（PRD FR-P10）。
- **FR-013**：検索の結果では、当たった箇所を前後の文と一緒に見せ、当たった所が分かる（PRD FR-P10）。
- **FR-014**：人の一覧は、最後に保存した人が上に来て、名前の横に見た目の特徴を出す（PRD FR-P11）。
- **FR-015**：タグで絞れる（PRD FR-P12）。
- **FR-016**：人のメモを開くと、話したことと次に話したいことが最初に見える（PRD FR-P14）。
- **FR-017**：検索の言葉・タグ・メモのどの欄の値も、画面の URL に載せない。画面を読み直したら、検索は空に戻ってよい（AD-31）。

**連絡する**

- **FR-018**：アカウントを押すと、相手のページが新しいタブで開く。LINE ID からは LINE のプロフィールを開く。そのほかの URL は `http`・`https` だけを受け付ける（PRD FR-P16）。

**取り出す・やめる**

- **FR-019**：自分のメモを、すべての欄と会った場の名前と日付ごと CSV で書き出せる。式として動かないように守る（PRD FR-P17）。
- **FR-020**：退会すると、人物メモはすべて消える。退会の確かめの画面に「人物メモ（会った人・会った場）」が出る（PRD FR-P18）。

**守り**

- **FR-021**：人と会った場を見る・直す・消す・書き出すことは、持ち主の使う人だけができる。ほかの使う人の記録は見つからないとして扱う（AD-31）。
- **FR-022**：人物メモのどの欄も、検索の言葉も、ログ・エラーの知らせに出さない（AD-31）。
- **FR-023**：人物メモを外の AI に渡す作業と、MCP のツールを作らない（AD-20・AD-21・AD-31）。
- **FR-024**：アプリは、台帳に行がない間は運営者だけに見える（AD-16）。最初は運営者（持ち主）だけで使う。

### Key Entities *(include if feature involves data)*

- **人のメモ**：使う人が足した会った人1人。持ち主（使う人）・フルネーム・よみ・LINE の名前・見た目の特徴・アカウント・タグ・話したこと・次に話したいこと・最後に保存した時刻・版。相手の PaletKit のアカウントとは結び付けない。
- **会った場**：使う人の一覧にある1件の会。持ち主・作り方（この版では手で書いたものだけ）・名前・日付。
- **人と会った場の組**：どの人がどの会った場で会ったか。同じ組は1つだけ。持ち主の違う人と会った場は結べない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：交流会の帰りに、スマホで1人を足す（フルネーム・見た目の特徴・話したこと・次に話したいこと）のが2分以内で済む（PRD 8章の逆の目印）。
- **SC-002**：会った場を選んで10人を続けて足すとき、会った場を選び直さずに済む。
- **SC-003**：100人を持つ使う人が、名前・よみ・LINE の名前・話したことのどれで探しても、狙った人が最初の画面に出る。
- **SC-004**：ほかの使う人の記録を見ようとしたすべての場合（道の ID・本文の ID・会った場の付け替え・書き出し）で、中身が出ない。
- **SC-005**：人物メモの欄と検索の言葉が、ログ・画面の URL に1つも残らない（確かめのテストで、決まった言葉を入れて探す）。
- **SC-006**：最初の1か月で、「前に話した○○」と自分から言えた回数が月3回以上（PRD 8章。持ち主が月に一度振り返って数える）。

## Assumptions

- 使う人は LINE でログインした PaletKit のアカウントを持つ（AD-4）。最初の版の使う人は持ち主だけで、アプリは台帳に行がない間、運営者だけに見える。
- 書くのは帰り道か家のスマホ。会場の電波は前提にしない。電波がないときに端末にためて後で送る形は作らない（PRD 7.2）。
- 0時〜8時は DB が止まり、使えない（AD-10。持ち主が決めた）。
- 先に入れる共通の PR（AD-31）は、次の順で `develop` に入れる。
  - 予期しない DB のエラーのログの直しと OAuth の範囲の直し：pr1 より前（pr1 で `apps.list.ts` に足すと、すぐ範囲に出るため）。
  - import の許す一覧：pr2 より前。
- PaletKit の交流会を会った場に選ぶことは、受付と交流会の小さな PR のあとの別の仕様。この版の会った場は、手で書いたものだけ（作り方の列は、あとで交流会のものを足せる形にしておく）。
- メモの中身は暗号にしない（持ち主が決めた）。一般に公開する前に決める（PRD 7.3）。
- LINE ID から開くリンクは、LINE が出している「ID で友だちを探す」リンクを使う見込み。トークを直接開くリンクはない（計画で確かめる。PRD 10章）。
- 知らせ・誕生日・共有・組織に入れること・連絡先の取り込み・パスコード・CSV の取り込みは作らない（PRD 7.2）。
