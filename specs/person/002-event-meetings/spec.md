## User Scenarios & Testing *(mandatory)*

### User Story 1 - 参加した・開いた交流会を選んで、会った場にする (Priority: P1)

使う人は、交流会の帰り道に人物メモの「会った場」を開く。自分がチェックインした会・主催した会・受付係をした会が並んでいるので、今日の会を押す。会った場ができ、そこで会った人を続けて足す画面が開く。名前と日付を手で打たなくてよい。

**Why this priority**: PRD の困りごと（IT 交流会で会った人を思い出せない）の場面そのもの。持ち主の会は主催するのでチェックインしない。そのため、主催した会・受付係の会も選べないと、持ち主の月1回の会で使えない。

**Independent Test**: 主催した会・受付係をした会・チェックインした会・関係のない会を1つずつ用意する。会った場の画面には初めの3つだけが並ぶ。1つを押すと、その名前と日付の会った場が開く。

**Acceptance Scenarios**:

1. **Given** 使う人が交流会 A にチェックインしている、**When** 会った場の画面を開く、**Then** 「PaletKit の交流会」に A が名前と日付つきで出る。
2. **Given** 使う人が交流会 B の持ち主（主催者）か受付係、**When** 会った場の画面を開く、**Then** B が出る（チェックインしていなくても出る）。
3. **Given** 使う人が組織の管理者・編集者・部員というだけの交流会 C、**When** 会った場の画面を開く、**Then** C は出ない。
4. **Given** A が並んでいる、**When** A を押す、**Then** A の名前と日付（日本時間の日付）の会った場ができ、続けて足す画面が開く。
5. **Given** A の会った場がもうある、**When** もう一度 A を押す、**Then** 新しく作らず、前の会った場が開く。
6. **Given** 主催してチェックインもしている会、**When** 会った場の画面を開く、**Then** その会は1件だけ出る（PRD FR-P6【仮決め】）。

---

### User Story 2 - 交流会の会った場で、会った人を続けて足し、あとで探す (Priority: P1)

交流会から作った会った場は、手で書いた会った場と同じように使える。続けて何人も足せて、前に足した人も付けられる。会った場の名前で探せて、書き足しの見出しにも名前と日付が入る。

**Why this priority**: 交流会から作っても、そのあとの使い方が手で書いたものと違うと迷う。

**Independent Test**: 交流会から会った場を作り、新しい2人と前からいた1人を足す。会った場の画面に3人が並び、会った場の名前で探すと3人が当たる。

**Acceptance Scenarios**:

1. **Given** 交流会から作った会った場、**When** 新しい人を続けて足す・前に足した人を付ける、**Then** 手で書いた会った場と同じように並ぶ（person-001 の US3 と同じ）。
2. **Given** 交流会から作った会った場が付いた人、**When** 書き足しでその会った場を選ぶ、**Then** 見出しに会った場の名前と日付が入る。
3. **Given** 交流会から作った会った場、**When** その名前で探す・CSV を書き出す、**Then** 手で書いた会った場と同じく当たり、名前と日付が出る。

---

### User Story 3 - 交流会が消えても、会った場は残る (Priority: P2)

交流会が消されたり、受付係から外れたりしても、使う人の会った場と、そこで会った人のつながりは残る。

**Why this priority**: メモは使う人の記録。ほかの人の操作で消えると困る（PRD FR-P9・AD-25）。

**Independent Test**: 交流会から会った場を作って人を付ける。交流会を消すと、会った場は名前と日付のまま残り、人も付いたまま。候補の一覧からは消える。

**Acceptance Scenarios**:

1. **Given** 交流会から作った会った場、**When** その交流会が消える、**Then** 会った場の名前・日付・付いた人はそのまま残る。
2. **Given** 交流会から作った会った場、**When** 使う人が受付係から外れる・交流会の名前が直される、**Then** 会った場は作ったときの名前と日付のまま残る。
3. **Given** 交流会が消えた会った場、**When** 会った場の画面を開く、**Then** 消えた交流会は候補に出ず、会った場は一覧に残る。

---

### Edge Cases

- 受付アプリが使う人に見えない（台帳に行がない・止めている）とき：候補の欄を出さず、交流会から作る窓口も「見つからない」と答える（AD-15・AD-31）。
- まだ始まっていない交流会：今日（日本時間）までに始まる会だけを候補に出す【仮決め】。明日以降の会は、その日になれば出る。
- 選べない交流会の ID を送られた（ほかの人の会・ない会・形の違う ID）：会った場を作らず「見つからない」と答える。選べるかは、候補の一覧と同じ条件で確かめ直す（AD-31）。
- 同じ名前と日付の、手で書いた会った場がある：交流会から作るものとは別の会った場として作る（作り方が違うため。一意の決まりも別。AD-31）。
- 候補が多い（受付係を長く続けた）：新しい順に最大50件を出す【仮決め】。古い会は手で書いて作れる。
- 交流会から作った会った場を消した：もう一度その会を押すと、新しい会った場として作り直す。
- 2つの端末から同じ会を同時に押した：会った場は1つだけでき、両方が同じものを開く。

## Requirements *(mandatory)*

### Functional Requirements

**選べる交流会**

- **FR-001**：会った場の画面に「PaletKit の交流会」として、使う人が自分のアカウントでチェックインした会・持ち主（主催者）の会・受付係の会を、名前と日付つきで出す。組織の役割（管理者・編集者・部員）だけの会は出さない（AD-31）。
- **FR-002**：同じ交流会は、いくつの条件に当たっても1件として出す（PRD FR-P6【仮決め】）。
- **FR-003**：候補は、今日（日本時間）までに始まる会を、始まりの新しい順に最大50件出す【仮決め】。会った場をもう作った会には、その印を付ける。
- **FR-004**：候補に、その会にチェックインした人の名前・人数・名簿を出さない（PRD FR-P8）。
- **FR-005**：受付アプリが使う人に見えないときは、候補の欄を出さない（AD-15・AD-31）。

**交流会から会った場を作る**

- **FR-006**：候補の会を選ぶと、その会の名前と、始まりの日付（日本時間）を写した会った場を作り、続けて足す画面を開く（PRD FR-P6・FR-P7）。
- **FR-007**：同じ会の会った場がもうあれば、新しく作らずに前のものを開く。同時に2回選んでも1つだけできる（AD-31）。
- **FR-008**：会った場を作るときに、FR-001 と同じ条件で選べる会かを確かめ直し、選べなければ「見つからない」と答える（AD-31）。受付アプリが見えないときも同じ。
- **FR-009**：交流会から作った会った場は、手で書いた会った場と同じく、人を続けて足す・前の人を付ける・外す・消す・探す・書き足しの見出し・CSV に使える（person-001 FR-008〜FR-013・FR-019）。

**残り方**

- **FR-010**：会った場の名前と日付は作ったときの写しで、交流会があとで直されても変えない（AD-25・AD-31）。
- **FR-011**：交流会が消えても、会った場と、人とのつながりは残る。消えた会は候補に出ない（PRD FR-P9）。
- **FR-012**：使う人が受付係から外れる・チェックインが取り消されるなどで選べなくなっても、作った会った場は残る（PRD FR-P9）。

**守り**

- **FR-013**：人物メモが読むのは、使う人が選べる交流会の ID・名前・始まりだけ。チェックインの中身・ほかの参加者・申込みの名簿を読む仕組みは使わない（AD-31。lint の許す一覧で止める）。
- **FR-014**：交流会の名前を含む会った場の名前も、ログ・エラーの知らせ・画面の URL に出さない（person-001 FR-017・FR-022 と同じ）。

### Key Entities *(include if feature involves data)*

- **選べる交流会**：使う人が会った場に選べる PaletKit の交流会。ID・名前・始まり。人物メモには残さず、画面を開くたびに読む。
- **会った場（交流会から作ったもの）**：person-001 の会った場のうち、作り方が「交流会から」のもの。交流会を指す欄（交流会が消えたら空）と、作ったときの名前と日付の写しを持つ。使う人ごとに、1つの交流会に1つだけ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：交流会の帰りに、会った場の画面を開いてから続けて足す画面に着くまで、2回押すだけで済む（名前と日付を打たない）。
- **SC-002**：持ち主が主催した会・受付係の会・チェックインした会が、どれも候補に出る。関係のない会と、組織の役割だけの会は1つも出ない。
- **SC-003**：候補の欄と会った場の画面に、ほかの参加者の名前・人数が1つも出ない（確かめのテストで、チェックインした人の名前を決まった言葉にして探す）。
- **SC-004**：交流会を消しても、その会から作った会った場と付いた人が100%残る。
- **SC-005**：選べない交流会から会った場を作ろうとしたすべての場合（ほかの人の会・ない会・受付アプリが見えない）で、会った場ができない。

## Assumptions

- 先に入れる共通の PR（AD-31・AD-3）：
  - 受付の `index.ts` に、その人が自分のアカウントでチェックインした交流会の ID を出す関数（`listCheckedInEventIds`）。
  - 交流会の `index.ts` に、その人が持ち主か受付係の交流会と、渡した ID の交流会を、名前と始まりだけでまとめて返す関数（`listAccountEventSummaries`）。
  - lint の許す一覧（person-001 の共通の PR #170）に、上の2つの名前と、受付の `index.ts` を足す。
- DB の変更はない。person-001 の会った場の表に、作り方（`event`）・交流会を指す欄（消えたら空）・使う人と交流会の部分の一意の索引が、すでにある。
- 「受付アプリが見える」かは、PaletKit の今の仕組み（台帳と止め方。AD-15・AD-16）で決める。人物メモは `uses: ["reception"]` を持つ。
- 会った場の日付は、交流会の始まりの日本時間の日付（AD-31・Consistency Conventions の時刻）。
- 人のメモの画面の「会った場を付ける」は、前の版のまま、すでにある会った場から選ぶ。交流会の会った場を付けたいときは、会った場の画面で交流会を選んでから付ける【仮決め】。
- 0時〜8時は DB が止まり、使えない（AD-10）。
