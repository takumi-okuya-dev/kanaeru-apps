# Feature Specification: アンケートの入力の画面に Googleフォームのリンクを出す（survey-002）

**Feature Branch**: `feature/survey-002-form-link`

**Created**: 2026-11-25

**Status**: Draft

**Input**: 主催者の希望（2026-11-25）：「アプリ独自のアンケート → Googleフォームを回答、という流れだが、1つの画面でアプリ独自のアンケートと Googleフォームへのリンクへ飛べる方がよい」。survey-001 の決定 A20（Googleフォームは、アンケートを送ったあとのお礼の状態にだけ出す）を足す形で変える。

## Clarifications

### Session 2026-11-25

主催者の確認済み（案 A）。

- Q: 入力の画面のどこに出すか → A: 「送る」の下に、補助のリンクとして出す。画面の主のボタンは「送る」の1つのまま（DESIGN の決まり）。案 B（いちばん上）と案 C（説明だけ）は選ばなかった。アプリのアンケートの回答率（SM-2）を守るため
- Q: お礼の画面は → A: そのまま。「続けて交流会のアンケートへ」（主のボタン）と LINE グループのボタンを出す。入力の画面のリンクは、お礼の画面では出さない
- Q: URL がないとき → A: 入力の画面にも出さない（今のお礼の画面と同じ）
- Q: 回答済みで開き直したとき → A: 入力の画面なので、リンクを出す

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 参加者が、アンケートの画面から、Googleフォームへも進める (Priority: P1)

交流会に Googleフォームの URL があるとき、参加者は、アプリのアンケートの入力の画面で、「送る」の下に「交流会のアンケート（Googleフォーム）もあります。」と、リンク「交流会のアンケート（Googleフォーム）を開く」を見る。押すと、Googleフォームが外のページとして開く（LINE の中でもアプリの外として開く）。アプリの画面と入れた値は、そのまま残る。

**Why this priority**: 2つのアンケートを1つの画面から行き来できるようにする（主催者の希望）。

**Independent Test**: URL つきの交流会で、チェックイン済みの参加者がアンケートの画面を開き、「送る」の下にリンクがあり、href と外のページとして開く属性があること、URL がなければ出ないこと、送るとお礼の画面に変わり入力用のリンクは消えることを確かめる。

**Acceptance Scenarios**:

1. **Given** Googleフォームの URL がある・アンケートが開いている・チェックイン済み, **When** アンケートの画面を開く, **Then** 「送る」の下に、リンク「交流会のアンケート（Googleフォーム）を開く」が出る。href は交流会の URL で、`target="_blank"`・`rel="noopener noreferrer"`。主のボタンは「送る」（回答済みなら「送り直す」）の1つのまま
2. **Given** Googleフォームの URL がない, **When** 開く, **Then** リンクは出ない
3. **Given** 回答済み, **When** 開き直す, **Then** 前の答えが入った入力の画面に、リンクも出る
4. **Given** 入力の画面, **When** 「送る」, **Then** お礼の画面に変わり、入力用のリンクは消え、「続けて交流会のアンケートへ」（Googleフォームの URL があるとき）と LINE グループのボタン（招待リンクがあるとき）が出る（A20・FR-22 のとおり）
5. **Given** 入力の画面, **When** アクセシビリティを確かめる, **Then** axe の違反がなく、狭い画面で横にはみ出さない

## Requirements

- **FR-001**: 入力の画面は、`EventSummary.googleFormUrl` があるとき、「送る」のあとに補助のリンクの節（`aria-label="交流会のアンケート"`）を出す。
- **FR-002**: リンクは外のページとして開く（`target="_blank"`・`rel="noopener noreferrer"`。お礼の画面の同じリンクと同じ）。
- **FR-003**: 入力の画面の主のボタンは「送る」（回答済みなら「送り直す」）の1つだけにする。リンクは、ボタンではなく、テキストの見た目にする。
- **FR-004**: お礼の画面の表示は変えない。
- **FR-005**: API・DB・約束（contracts）は変えない（`googleFormUrl` はすでに要約に入っている）。

## Success Criteria

- **SC-001**: 画面のテスト（`SurveyPage.test.tsx`）と E2E（`survey.spec.ts`）が、リンクの出る・出ない・お礼で消えるを確かめている。
- **SC-002**: アプリのアンケートの回答率（PRD SM-2）を下げないよう、リンクは主のボタンの下に置く。公開後に、回答率を見て見直す。
