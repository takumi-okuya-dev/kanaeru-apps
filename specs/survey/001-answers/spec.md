## User Scenarios & Testing *(mandatory)*

### User Story 1 - 参加者がアンケートに答え、お礼と案内を見る (Priority: P1)

主催者がアンケートを開くと、チェックインした参加者は、チェックインの画面の「アンケートに答える」かアンケートQRから、アンケートの画面（P2）を開く。一番上に目的の案内（見出し「仕事の困りごとを聞かせてください」と本文・箇条書き2つ）が出る。困りごと（自由に書く）・月いくら（「答えるだけで、実際には払いません」）・テスターになるか・任意の見出しの下に仕事の立場と職種（どちらも最初は「答えない」）に答え、「送る」を押す。同じ画面が「あなたの困りごとが、解決する企画やアプリにつながります」に変わり、GoogleフォームのURLがあれば「続けて交流会のアンケートへ」、LINEグループの招待リンクがあれば「交流会のLINEグループに参加する」が出る。

**Why this priority**: 困りごとを集める（UJ-2・SM-2・SM-3）。

**Independent Test**: チェックインした参加者でアンケートの画面を開き、送るとお礼と2つのボタンが出ること、開き直すと前の答えが入っていて送り直せることを確かめる。

**Acceptance Scenarios**:

1. **Given** アンケートが開いていて、チェックイン済み, **When** アンケートの画面を開く, **Then** 目的の案内と5つの設問が出て、仕事の立場と職種は「答えない」が選ばれている
2. **Given** 何も選ばない, **When** 「送る」, **Then** 誤りは出ず、お礼の状態になる（A7）
3. **Given** 答えを入れた, **When** 「送る」, **Then** 「あなたの困りごとが、解決する企画やアプリにつながります」が出てフォーカスが移り、GoogleフォームのURLがあれば「続けて交流会のアンケートへ」（Googleフォームを開く）、LINEグループの招待リンクがあれば「交流会のLINEグループに参加する」が出る（A20・FR-22）
4. **Given** 回答済み・開いている, **When** 開き直す, **Then** 前の答えが入っていて「送り直す」で直せる（A8）
5. **Given** アンケートが閉じている, **When** 開く, **Then** 「アンケートは閉じています」。答えている途中で閉じたら、送ったときに「送る」の近くでその旨を出し、入れた値は残す
6. **Given** チェックインしていない, **When** 開く, **Then** 「先にチェックインしてください」と「チェックインの画面へ」（AD-13）
7. **Given** 交流会がない, **When** 開く, **Then** 「この交流会は見つかりません。受付の人に声をかけてください」

### User Story 2 - 主催者が困りごとを一覧で見て、絞りこみ・並べ替える (Priority: P1)

主催者は、交流会の管理の画面の上の「困りごと」から困りごとの画面を開く。回答ごとに、チェックインの名前・困りごと・月いくら・テスター・仕事の立場・職種が出る。「テスターに『はい』だけ」に絞りこみ、「月いくらの高い順」に並べ替えられる。受付係には「困りごと」を出さず、開いても使えない。

**Why this priority**: テスターを頼む人と、作るものの手がかりを見る（UJ-4・FR-14）。

**Independent Test**: 主催者で、回答の名前がチェックインの名前であること、絞りこみ・並べ替えの結果を確かめる。受付係では窓口が 403、画面が「この画面は主催者だけが使えます」になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 回答が3つ, **When** 主催者が困りごとの画面を開く, **Then** 回答の新しい順に、名前（チェックインの名前）・困りごと・月いくら・テスター・仕事の立場・職種が出る
2. **Given** テスターに「はい」と「いいえ」の回答, **When** 「テスターに『はい』だけ」, **Then** 「はい」の回答だけになる
3. **Given** 月いくらがばらばらの回答, **When** 「月いくらの高い順」, **Then** 3,000円以上 → 1,000円 → 500円 → 0円 → 分からない → 答えていない の順
4. **Given** 回答がない, **When** 開く, **Then** 「まだ困りごとはありません」。アンケートが閉じていれば準備の画面への入口
5. **Given** 受付係, **When** 困りごとの窓口を呼ぶ・画面を開く, **Then** 403・「この画面は主催者だけが使えます」。管理の画面の上に「困りごと」が出ない
6. **Given** チェックインの名前を直した, **When** 一覧を見る, **Then** 直した名前で出る（AD-6）

### User Story 3 - 主催者が手でのチェックインの人の回答を代わりに入れる (Priority: P2)

主催者は一覧画面（A3）で手でのチェックインの行を押して開く枠の「アンケートの回答を入れる」から、アンケートの画面と同じ設問の欄を開き、聞き取った答えを入れて保存する。アンケートが閉じていても入れられる。

**Why this priority**: LINE を使わない人の困りごとも集める（UJ-3・A9）。

**Independent Test**: 閉じたアンケートで、主催者が代わりに入れた回答が困りごとの一覧に出ること、受付係は窓口が 403 で、枠に節が出ないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 主催者が手でのチェックインの枠を開く, **When** 「アンケートの回答を入れる」, **Then** 同じ設問の欄が開き、前の回答があれば入っている
2. **Given** アンケートが閉じている, **When** 主催者が保存する, **Then** 保存され、困りごとの一覧に出る（AD-13）
3. **Given** 受付係・LINE のチェックイン, **When** 枠を開く, **Then** 節は出ない（窓口は受付係に 403）

---

### User Story 4 - 主催者が困りごとを CSV で書き出す (Priority: P2)

主催者は、書き出しと削除の画面（A5）の「困りごとをCSVで書き出す」で、回答の一覧を CSV（UTF-8 の BOM つき）で保存する。

**Why this priority**: PRD 6.1 の3番目（FR-15）。

**Independent Test**: CSV が BOM で始まり、日本語の見出しと、名前・困りごと・選択肢の言葉を持ち、式の先頭が打ち消されることを確かめる。受付係は 403。

**Acceptance Scenarios**:

1. **Given** 主催者, **When** 「困りごとをCSVで書き出す」, **Then** BOM つきの CSV（名前・困りごと・月いくら・テスター・仕事の立場・職種・入れ方・回答の時刻。回答の古い順）が落ちる
2. **Given** 困りごとが `=` で始まる・改行や `"` を含む, **When** 書き出す, **Then** 先頭に `'` が付き、`"` で囲まれる
3. **Given** 受付係, **When** CSV の窓口を呼ぶ, **Then** 403

### Edge Cases

- 同じ人が同時に2回送っても、回答は1つ（`checkin_id` の一意の制約と、ある行を直す書き方）。
- チェックインを取り消す・本人のアカウントを消す：回答も消える（`ON DELETE CASCADE`。AD-7）。一覧と CSV に出ない。
- 閉じたあとの参加者の送信：409 `SURVEY_CLOSED`（記録は変わらない）。主催者の代わりの入力は受ける。
- チェックインしていない人の送信：403 `SURVEY_NOT_CHECKED_IN`。
- 別の交流会のチェックインの ID で代わりに入れる：404 `CHECKIN_NOT_FOUND`。
- 困りごとが長すぎる（2,000文字より多い）：400 と欄のそばの日本語の理由。前後の空白だけなら空として持つ。
- 困りごとの本文はログに出さない（Constitution II）。
- 夜間の停止（503 `DB_UNAVAILABLE`）：「夜間（0時〜8時）は止まっています」。入れた値は消さない。困りごとの一覧は5秒おきの読み直しを止める。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: survey の領域が `survey_answer`（`checkin_id`・困りごと・月いくら・テスター・仕事の立場・職種・回答の時刻）の表を持つ。`checkin_id` は一意で、reception の `checkinTable` を `ON DELETE CASCADE` で参照する（AD-3・AD-7）。選択肢の列は `text` と CHECK で、答えていない・「答えない」は空（null）。
- **FR-002**: 選択肢（月いくら：0円・500円・1,000円・3,000円以上・分からない／テスター：はい・いいえ／仕事の立場：経営者・管理職・会社員・フリーランス・学生・その他／職種：エンジニア・デザイナー・営業・マーケティング・企画・PM・事務・管理部門（人事・経理・総務など）・経営・その他）は、英語の短い code・画面の言葉・並び順と「月いくらの高い順」を survey の約束に置く。「答えない」の言葉も約束に置く。
- **FR-003**: ログインした人は、その交流会の自分の回答とチェックイン済みかを読める（`GET /api/v1/events/{eventId}/survey-answers/me`）。
- **FR-004**: チェックインした参加者は、アンケートが開いている間、自分の回答を作り・直せる（`PUT …/survey-answers/me`）。開閉は書くたびに event の `getEventSummary` で読む。閉じていれば 409 `SURVEY_CLOSED`、チェックインがなければ 403 `SURVEY_NOT_CHECKED_IN`（AD-13）。どの設問も必須にしない（A7）。
- **FR-005**: 主催者は、その交流会のチェックインの回答を、ID で読み（`GET …/survey-answers/checkins/{checkinId}`）、開閉にかかわらず作り・直せる（`PUT` 同じ道。AD-13・A9）。受付係は 403。
- **FR-006**: 主催者だけが、回答の一覧（`GET …/survey-answers`。`tester=yes` で絞りこみ・`sort=price` で月いくらの高い順・既定は回答の新しい順）と CSV（`GET …/survey-answers/export`。UTF-8 の BOM・CRLF・式の先頭の打ち消し）を読める。名前はいつも reception の `listCheckins` のチェックインの名前（AD-6）。受付係は 403（AD-5）。
- **FR-007**: 画面 P2（`PARTICIPANT_ROUTE_PATTERNS.survey`。`SessionGate`）：目的の案内 → 困りごと → 月いくら（注記つき）→ テスター → 任意（仕事の立場・職種。「答えない」が最初に選ばれている）→ 「送る」（回答済みなら「送り直す」）。送ったら同じ画面をお礼の状態に変え、お礼の文にフォーカスを移す。Googleフォームの URL があれば「続けて交流会のアンケートへ」、LINEグループの招待リンクがあれば「交流会のLINEグループに参加する」。閉じている・チェックインしていない・交流会がない・夜間の停止の状態を出す。
- **FR-008**: 画面「困りごと」（`ADMIN_ROUTE_PATTERNS.eventConcerns`。主催者だけ）：上に event の `EventAdminNav`。絞りこみと並べ替えを表の上に置き、広い画面は表・狭い画面はカード。5秒おきに読み直す（夜間の停止では止める）。
- **FR-009**: reception の差しこみの場所に、A3 の直す枠の節「アンケートの回答を入れる」（`registerCheckinPanelSection`）と、A5 の節「困りごとをCSVで書き出す」（`registerEventDataSection`）を、survey の入口で1度だけ登録する。
- **FR-010**: 困りごとの本文はログに出さない。入力の形・エラーの code と日本語の文言は、約束の survey のフォルダに置く。

### Key Entities

- **アンケートの回答**：チェックイン1つにつき1つ。困りごと・月いくら・テスター・仕事の立場・職種（どれも空でよい）。交流会と名前はチェックインからたどる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全部の確かめ（`pnpm check`）が通る。
- **SC-002**: 主催者がアンケートを開いたあと、参加者がアンケートの画面で答えて送り、お礼と「続けて交流会のアンケートへ」「交流会のLINEグループに参加する」を見ることが、E2E で両方の幅（1440px・375px）のアクセシビリティの違反0件で通る。
- **SC-003**: 主催者が困りごとの画面で、その回答を絞りこみ・並べ替えて見られ、受付係は困りごとの画面を開けないことが、E2E で通る。
- **SC-004**: 開閉の決まり（参加者は閉じると 409・主催者の代わりの入力は受ける）・チェックインしていない人の 403・権限（受付係は一覧・CSV・代わりの入力が 403）・チェックインの取り消しとアカウントの削除で回答が消えること・CSV が、本物の PostgreSQL の結合のテストで通る。

## Assumptions

- 「アンケートに答える」のリンク（P1）と、チェックインの取り消しの確かめの文（「アンケートの回答があれば一緒に消えます」）は reception-001 が置いた。アンケートの開閉とアンケートQRは event-001 が置いた。
- FR-18（「私も」）・FR-19（行方）は、この版で作らない（Should）。
- 機能の印では止めない（アンケートは主催者が開かなければ答えられない。止めたいときは開かない）。
