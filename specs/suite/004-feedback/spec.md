# Feature Specification: 改善点を送る（suite-004）

**Feature Branch**: `feature/suite-004-feedback`

**Created**: 2026-11-26

**Status**: Draft

**Input**: 持ち主の頼み（2026-11-26）「ユーザーがアプリの改善点を開発者に送れる機能があるとよい」。持ち主の答え：全部のアプリ共通・アプリの中の一覧で読む（外のサービスに出さない）・ログインした人だけ。

## Clarifications

### Session 2026-11-26

- Q: どの範囲で使えるか → A: 全部のアプリ共通（suite の機能）
- Q: 開発者はどこで受け取るか → A: アプリの中の一覧（運営者だけが開ける）。メール・外のサービスには送らない
- Q: だれが送れるか → A: ログインした人だけ

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 利用者が改善点を送る (Priority: P1)

利用者は「全体の設定」の「改善点を送る」を開き、どのアプリについてか（任意）を選び、困ったこと・ほしいことを書いて送る。

**Acceptance Scenarios**:

1. **Given** ログインした利用者、**When** 「改善点を送る」でアプリ「試合表」を選び、本文を書いて送る、**Then** 「送りました。ありがとうございます」と出て、欄は空になる
2. **Given** 本文が空・2000文字を超える、**When** 送る、**Then** 欄のそばに誤りが出て送らない
3. **Given** ログインしていない、**When** 開く、**Then** ログインを案内する（送れない）
4. **Given** 1人が短い間にたくさん送る、**When** 1日に20件を超える、**Then** 「今日はこれ以上送れません」と出す

---

### User Story 2 - 運営者が届いた改善点を読む (Priority: P1)

運営者は「全体の設定」の「届いた改善点」で、新しい順の一覧（日時・アプリ・本文・送った人の表示名）を読み、読んだら「済み」の印を付ける。

**Acceptance Scenarios**:

1. **Given** 届いた改善点、**When** 運営者が一覧を開く、**Then** 新しい順に出る。アプリで絞れる
2. **Given** 一覧、**When** 「済み」を付ける、**Then** 済みの印が付き、「まだのものだけ」の絞りから外れる
3. **Given** 運営者でない人、**When** 一覧の道を開く、**Then** 「運営者だけが開ける画面です」。窓口は 403

### Edge Cases

- 退会した人の改善点：本文は残し、送った人は「退会した人」と出す（送った人とのつながりを外す）
- 本文に個人の情報が書かれる：画面に「名前・連絡先など個人の情報は書かないでください」と出す。ログに本文を書かない
- 送ったあとに、送った人は自分の改善点を見られない（この版では作らない）

## Requirements *(mandatory)*

- **FR-001**: ログインした利用者は、本文（1〜2000文字）と、任意でアプリ（台帳のアプリの key）を付けて改善点を送れる
- **FR-002**: 1人が1日（日本時間）に送れるのは20件まで
- **FR-003**: 運営者だけが、届いた改善点の一覧（新しい順・アプリで絞る・まだのものだけ）を読み、「済み」を付け外しできる
- **FR-004**: 本文をログ・外のサービスに出さない（Constitution II）
- **FR-005**: 退会すると、改善点の送った人のつながりを外す（本文は残す）
- **FR-006**: 「全体の設定」に、利用者の「改善点を送る」と、運営者の「届いた改善点」を置く

## Success Criteria *(mandatory)*

- **SC-001**: ログインした利用者が、全体の設定から1分以内に改善点を送れる（E2E）
- **SC-002**: 運営者でない人は、どの道からも届いた改善点を読めない（窓口の試験で 403）

## Assumptions

- 運営者は今の主催者（`ORGANIZER_LINE_USER_ID`）。運営者に知らせる仕組み（メール・LINE）は作らない（一覧を見に行く）
- 送った人への返事の仕組みは作らない
- 表を1つ足す（suite の `suite_feedback`）。DB の変更は小さな PR に分けて先に入れる
